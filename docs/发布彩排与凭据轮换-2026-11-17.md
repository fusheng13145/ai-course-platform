## 2. JWT_SECRET 轮换流程（固化）

**影响**：轮换后所有已签发 JWT 立即失效，所有用户需重新登录；不适合作演示前 30 分钟内做。

1. 停后端（`Ctrl+C` 或 `start.bat` 收子树），确认 8080 释放。
2. 生成 48–64 位随机串（**不要**用 `openssl rand -base64 32`，44 字符虽在 8–32 位口令规则之外但本项只要求长度；用 Python 生成 ASCII）：
   ```powershell
   python -c "import secrets,string; print(''.join(secrets.choice(string.ascii_letters+string.digits) for _ in range(64)))"
   ```
3. 只替换 `.env` 的 `JWT_SECRET=` 行；**不提交、不回显**。
4. 重启后端；`python scripts/acceptance_check.py` 必须全 PASS。
5. 用 `admin/123456`（本机演示账号）登录一次，确认新 token 可签发；再退出重登，确认旧 token 401。
6. 跑 `python scripts/e2e/e2e_verify_network_course.py`（functional 姿态）确认登录链路未坏。
7. 记录轮换时点、执行人、影响窗口；**不记录值**。

**回滚**：保留旧 `.env` 一行到受管密钥库（不是 git），若新 token 全量 401 且无法定位，恢复旧值并重启；旧会话恢复，但轮换目的失败，需重新查因。
