## 一、验证范围、角色矩阵与环境前置

### 1.1 被验证链路（主链路 9 环节）

1. 教师创建课程 2. 管理员审核通过 3. 教师上传资料与视频 4. 布置作业与发布
5. 题库、组卷与发布考试 6. 学生加入课堂（选课） 7. 学生查看资料与视频
8. 学生完成作业 9. 学生参加考试

（另有协同、边界、越权、一致性、分片、退回重交、资源版本等下探维度，见 §三）

### 1.2 角色矩阵

按 **管理员 / 教师（含任课与非任课）/ 学生（含已选课与未选课）/ 匿名** 四类身份交叉验证，越权与 IDOR 用例全部走**负向断言**。

### 1.3 环境与前置条件（实测确认）

- 后端启动**必须显式指定端口**（`--server.port=8080`），否则被外部环境覆盖并报「Port already in use」。
- 必需环境变量：`SPRING_DATASOURCE_PASSWORD`、`JWT_SECRET`，以及 `COOKIE_SECURE=false`、`REQUIRE_HTTPS=false`、`CSRF_ENABLED=false`（本地验证场景）。
- 认证为 **HttpOnly Cookie**（`ai_course_token`），API 测试须维持 CookieJar。
- 脚本启动前须先 `FLUSHDB`：否则经 SQL 直删课程会绕过 `@CacheEvict`，导致新课程复用 id 时读到陈旧缓存对象；同时用于重置限流计数。
- 功能轮放宽 `RATELIMIT_LOGIN_LIMIT=200`；安全轮**去掉覆盖**，以默认配置验证 CSRF 与限流。
- `/api/actuator/health` 在未注入 AI Key 时返回 **503(DOWN)**，但业务功能正常——**不可据此判定服务不可用**。

### 1.4 测试数据准备的三条路径

| 路径 | 方式 | 适用 |
| --- | --- | --- |
| ① | Flyway / 种子数据 | 基础账号与课程 |
| ② | 直接 SQL 注入 | 绕过缺陷接口，保证链路可验证 |
| ③ | 通过 API 构造（**推荐**） | 语义最真实，随接口契约同步演进 |

### 1.5 造数据的三条硬性注意（实测踩坑）

1. `LocalDateTime` 入参须为 **ISO-8601** 格式（配置中的 `yyyy-MM-dd HH:mm:ss` 仅对 `java.util.Date` 生效）。
2. `questions.type` 须**大写**（`SINGLE_CHOICE`/`TRUE_FALSE`…）；`auto-compose.typeRules` 的键须与之一致，否则**静默生成 0 题**。
3. `correct_answers` 为 JSON 列，单值须写成 `"\"B\""`；另：建课/建作业的响应**不回显** DB 默认值。
