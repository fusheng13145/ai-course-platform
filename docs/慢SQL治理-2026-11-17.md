## 1. 度量工具

新增 `scripts/analyze_slow_sql.py`，直接解析拦截器 WARN 行并聚合：

```powershell
cd <repo>
python scripts/analyze_slow_sql.py --log logs/api.log --top 10
python scripts/analyze_slow_sql.py --log .workbuddy/tmp/backend_e2e.log --top 10 --format json
```

- 归并键：`MappedStatement id + SQL 前 120 字符`，避免把同一语句的不同参数拆成多条；
- 输出：次数、平均耗时、最大耗时、阈值、SQL 摘要；
- 解析失败行单独计数，避免「0 命中」其实是格式变化。

## 3. Top-N 与治理动作

当前 **Top-N 为空**，因此本批没有「新增索引 / 改写 SQL」的改动。原因不是「没有问题」，而是：

1. 本机日常流量低，500ms 阈值未触发；
2. 目标环境（云主机/生产姿态）尚未部署，拿不到真实慢日志；
3. 压测脚本 `e2e_stress_verify.py` 主要覆盖任务/答卷/资源，未覆盖考试交卷与 AI 问答并发（B-09 未完成）。

**治后对照规则**（下一轮必须遵守）：

- 同一机器、同一构建、同一并发档位、同一日志级别；
- 改前/改后各保留 `scripts/analyze_slow_sql.py` 的 JSON 输出；
- 只比较 `count / avg_ms / max_ms / p95`，不比较「感觉快了」；
- 若新增索引，必须附 `EXPLAIN` 的 `type/key/rows/Extra` 改前改后对照，并说明写放大风险。
