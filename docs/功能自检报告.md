# 功能自检报告（2026-11-18）

> 范围：学生端、教师端、管理员端已暴露页面与其背后的真实接口。
> 方法：路由与导航清单核对 + 前端 API 导出 × 非测试源码引用比对 + 重点页面深读 + 后端 Controller/DTO/Service 契约核对 + 针对性单测。
> 结论：页面入口基本齐全，但此前存在一批「后端能力存在、界面无真实入口」的断点。本轮继续闭合行政班、教学班名单与教学班生命周期 3 处，并修复行政班前后端双模型错位 1 处；剩余结构性缺口列在第 3 节。

## 1. 判定口径

一个功能点只有同时满足以下四道门，才算「真实可用」：

| 门 | 判据 |
| --- | --- |
| 入口 | 用户能在常规位置找到，不需要知道内部接口名 |
| 读 | 列表/详情来自真实接口，失败与空态可区分 |
| 写 | 有真实写口，成功后刷新，失败保留输入并给出原因 |
| 习惯 | 危险操作二次确认；表单字段、校验、反馈符合常规系统预期 |

「PRD 标 ✅」只代表功能存在，不代表满足上述四道门，本报告不引用 PRD 状态作为可用性证据。
