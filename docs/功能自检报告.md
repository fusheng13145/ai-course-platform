# 功能自检报告（2026-11-18）

> 范围：学生端、教师端、管理员端已暴露页面与其背后的真实接口。
> 方法：路由与导航清单核对 + 前端 API 导出 × 非测试源码引用比对 + 重点页面深读 + 后端 Controller/DTO/Service 契约核对 + 针对性单测。
> 结论：页面入口基本齐全，但此前存在一批「后端能力存在、界面无真实入口」的断点。本轮继续闭合行政班、教学班名单与教学班生命周期 3 处，并修复行政班前后端双模型错位 1 处；剩余结构性缺口列在第 3 节。

## 1. 判定口径

一个功能点只有同时满足以下四道门，才算「真实可用」：

| 门 | 判据 |
| --- | --- |
| 入口 | 用户能在常规位置找到，不需要知道内部接口名 |
| 读 | 列表/详情来自真实接口，失败与空态可区分 |
| 写 | 有真实写口，成功后刷新，失败保留输入并给出原因 |
| 习惯 | 危险操作二次确认；表单字段、校验、反馈符合常规系统预期 |

「PRD 标 ✅」只代表功能存在，不代表满足上述四道门，本报告不引用 PRD 状态作为可用性证据。

## 3. 仍存的结构性缺口

以下不是「页面没画」，而是需要新增后端写口、跨页面串联或产品口径确认，未在本轮擅自扩展。

| 优先级 | 功能点 | 现状 | 缺口 | 建议 |
| --- | --- | --- | --- | --- |
| P0 | 管理员选课与名单调整 | `EnrollmentsBody` 只能通过/驳回 PENDING；`DELETE /enrollments/{id}` 只允许学生本人退课 | 管理员不能改教学班、不能取消已通过选课 | 新增管理员写口（调班/退选）并在选课页加行操作；需先定「是否允许管理员代退」的产品口径 |
| P1 | 正式成绩单 / 学情报告 | 学生成绩明细已可导出 XLSX；教师端有导出成绩 | 盖章成绩单（PDF/模板）与跨课程学情报告聚合未做 | 先定成绩单模板与盖章字段，再接后端导出；不要用前端表格冒充正式成绩单 |
| P1 | 学生成绩页学习路径 | `learningPath.ts` 全量方法未被 UI 引用 | 有数据能力，无入口 | 先确认学习路径算法是否达到可展示质量，再决定入口位置；不要先画空页 |
| P2 | 行政班批量成员 | 班级页已可查看成员、单个移出，用户编辑可单个分班 | 批量加入/批量移出未做 | 在成员弹窗加多选；批量写口复用 `adminClassId`，需先确认是否允许跨班批量移动 |
| P2 | 旧班级模型退役 | `Classroom` / `classrooms` 与 `ClassroomController` 仍在；`users.class_id` 仍有存量 | 新旧模型并存，虽然前端管理面已统一到 `admin_classes`，旧端点仍可写 | 需产品主拍板是否退役 `classrooms`、迁移 `class_id`、给 `users.admin_class_id` 加外键 |
| P2 | 主观题 AI 留痕、通知渠道、前端 XSS 审计、手工验收脚本化 | PRD D4-5、D4-8、D6-9、D7-10 仍未处理 | 非本轮界面主线 | 单独批次处理，避免与教学写口混在一起 |
| P2 | 管理员课程空间数据面 | `classes/content/bank/exams/grades/graph` 多数只读或空态 | 有意权限姿态，不算缺陷 | 保持只读，不为了「看起来丰富」造演示数据 |

- `CourseFolderCard.vue` 本轮未触碰；玻璃口袋、章节抽卡、悬停倾斜动效保持原样。本轮未把课程卡改成静态文字卡。
