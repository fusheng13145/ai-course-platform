# AI 课程平台 — 运维手册

> 版本：v1.0 | 更新日期：2026-07-28 | 适用平台：Windows / Linux (Docker)

---

## 1. 系统架构概览

```
┌──────────┐     ┌──────────────┐     ┌────────┐     ┌───────┐
│  Nginx   │────▶│ Spring Boot  │────▶│ MySQL  │     │ Redis │
│  :80     │     │ :8080 (/api) │     │ :3306  │     │ :6379 │
└──────────┘     └──────────────┘     └────────┘     └───────┘
                        │
                        ▼
                 ┌──────────────┐
                 │ DeepSeek API │
                 │ (外部 HTTPS) │
                 └──────────────┘
```

- **前端**：Vue 3 + Element Plus，Nginx 反向代理，监听 80 端口
- **后端**：Spring Boot 3.4.4 + MyBatis-Plus，监听 8080 端口（context-path `/api`）
- **数据库**：MySQL 8.0，字符集 utf8mb4
- **缓存**：Redis 7，用于会话、限流、缓存
- **AI**：DeepSeek API（可通过配置切换为 OpenAI/Qwen）

## 3. 快速部署

### 3.1 环境变量配置

```bash
# 1. 复制环境变量模板
cp .env.example .env

# 2. 编辑 .env，填入真实值（所有字段必须填写）
#    MYSQL_ROOT_PASSWORD - 强随机密码（≥16位）
#    JWT_SECRET         - 256位 Base64 随机字符串
#    DEEPSEEK_API_KEY   - DeepSeek API Key
```

**生成强密码**：
```bash
# Linux/Mac
openssl rand -base64 32

# Windows PowerShell
[System.Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

### 3.2 Docker Compose 部署（推荐）

```bash
# 启动所有服务（mysql + redis + backend + frontend；backend/frontend 归入 full profile）
docker compose --profile full up -d

# 仅启动基础设施（mysql + redis，供本地后端源码连接）
docker compose up -d mysql redis

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f backend
docker compose logs -f frontend
```

### 3.3 本地开发部署

**前置条件**：MySQL 和 Redis 已在本地运行。

```bash
# Windows
start-backend.bat    # 启动后端（:8080）
start-frontend.bat   # 启动前端（:5173）

# Linux/Mac（手动）
cd backend && ./mvnw spring-boot:run -Dspring-boot.run.profiles=local
cd frontend && npm install && npm run dev
```

## 4. 健康检查

| 端点 | 用途 |
|------|------|
| `GET /api/actuator/health` | 综合健康状态（DB + Redis + Disk） |
| `GET /api/actuator/health/readiness` | K8s Readiness Probe |
| `GET /api/actuator/health/liveness` | K8s Liveness Probe |
| `GET /api/actuator/prometheus` | Prometheus 指标（需 ADMIN 角色） |

Docker Compose 已配置健康探针：
- MySQL：`mysqladmin ping`，10s 间隔，10 次重试
- Backend：`curl /api/actuator/health`，30s 间隔，5 次重试

## 5. 日志分析

### 5.1 日志位置

| 环境 | 位置 |
|------|------|
| Docker | `docker compose logs -f <service>` |
| 本地开发 | 控制台输出 |

### 5.2 日志级别调整

生产环境默认 `INFO`。排查时可通过环境变量临时提级：

```bash
# 提级为 DEBUG（输出 SQL 和详细日志）
export LOG_LEVEL_COM_AICOURSE=DEBUG

# 重启后端服务
```

**注意**：DEBUG 级别会输出 SQL 语句和请求详情，生产环境勿长期开启。

### 5.3 关键日志模式

| 日志内容 | 含义 | 处理 |
|----------|------|------|
| `CSRF 校验失败` | 客户端缺少 XSRF-TOKEN | 确认前端 axios 配置 `withXSRFToken: true` |
| `Rate limit exceeded` | IP 请求过于频繁 | 检查是否有脚本/爬虫；调大 `ratelimit.*.limit` |
| `AI quota exhausted` | 用户 AI 调用配额用尽 | 调大 `ai.quota.daily-request-limit` 或等待次日重置 |
| `WebSocket 消息处理异常` | 客户端发送畸形数据 | WARN 级别，不影响服务，但需关注频率 |

## 6. 常见故障处理

### 6.1 后端启动失败

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| `CommunicationsException: Communications link failure` | MySQL 未启动或密码错误 | 检查 MySQL 状态，确认 `.env` 中 `MYSQL_ROOT_PASSWORD` 正确 |
| `PatternParseException: Invalid mapping pattern` | springdoc 版本不兼容 | 已排除 `SwaggerConfig`，若仍出现检查是否引入了新版 springdoc |
| `JWT signature does not match` | JWT_SECRET 不一致 | 确保所有实例使用相同 `JWT_SECRET` |
| `RedisConnectionFailureException` | Redis 未启动 | 启动 Redis 或检查 `SPRING_DATA_REDIS_HOST` 配置 |

### 6.2 前端无法访问后端

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 跨域错误 (CORS) | 前端 origin 不在白名单 | 检查 `cors.allowed-origins` 配置 |
| 401 未授权 | Cookie 未携带或令牌过期 | 清除浏览器 Cookie 重新登录 |
| 403 CSRF 校验失败 | 前端 axios 未配置 `withXSRFToken` | 确认 `request.js` 中 `withXSRFToken: true` |

### 6.3 AI 功能不可用

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| AI 问答返回"知识库原文" | `DEEPSEEK_API_KEY` 未配置 | 在 `.env` 中设置有效的 API Key |
| AI 调用超时 | 网络问题或 API 服务异常 | 调大 `AI_READ_TIMEOUT`，检查 `api.deepseek.com` 可达性 |
| `AI quota exceeded` | 用户当日调用次数/Token 超额 | 调大 `AI_QUOTA_DAILY_REQUESTS` / `AI_QUOTA_DAILY_TOKENS` |

### 6.4 数据库初始化

```bash
# 手动初始化（如果 Docker 自动初始化失败）
docker exec -i aicourse-mysql mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" ai_course_platform < backend/src/main/resources/index.sql
```

## 7. 备份与恢复

### 7.1 数据库备份

```bash
# Docker 环境
docker exec aicourse-mysql mysqldump -uroot -p"${MYSQL_ROOT_PASSWORD}" --single-transaction --routines --triggers ai_course_platform > backup_$(date +%Y%m%d).sql

# 本地 MySQL
mysqldump -uroot -p --single-transaction ai_course_platform > backup.sql
```

### 7.2 数据库恢复

```bash
# Docker 环境
docker exec -i aicourse-mysql mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" ai_course_platform < backup.sql

# 本地 MySQL
mysql -uroot -p ai_course_platform < backup.sql
```

### 7.3 文件备份

用户上传文件存储在 Docker Volume `backend_uploads` 中：
```bash
# 备份上传文件
docker run --rm -v aicourse_backend_uploads:/data -v $(pwd):/backup alpine tar czf /backup/uploads_backup.tar.gz -C /data .

# 恢复上传文件
docker run --rm -v aicourse_backend_uploads:/data -v $(pwd):/backup alpine tar xzf /backup/uploads_backup.tar.gz -C /data
```

## 8. 安全加固检查清单

- [ ] `.env` 中 `MYSQL_ROOT_PASSWORD` 使用强随机密码（≥16 位）
- [ ] `.env` 中 `JWT_SECRET` 使用 256 位随机密钥
- [ ] `.env` 已加入 `.gitignore`，未提交到版本控制
- [ ] 生产环境 `COOKIE_SECURE=true`（HTTPS 强制）
- [ ] 生产环境 `REQUIRE_HTTPS=true`
- [ ] `DEEPSEEK_API_KEY` 已配置且未公开
- [ ] CORS `allowed-origins` 仅包含实际前端域名
- [ ] MySQL 端口（3306）不对外网暴露（防火墙/Docker 网络隔离）
- [ ] 定期审计操作日志（`/admin/logs` 或 `operation_log` 表）
- [ ] Actuator 的 prometheus 端点仅 ADMIN 角色可访问

## 9. 性能调优

| 参数 | 默认值 | 调优建议 |
|------|--------|---------|
| `TOMCAT_THREADS_MAX` | 500 | AI 并发高于预期时上调至 800-1000 |
| `SPRING_DATASOURCE_HIKARI_MAXIMUM_POOL_SIZE` | 10 | 高并发场景上调至 20-50 |
| `AI_QUOTA_DAILY_REQUESTS` | 100 | 按实际学生数量调整 |
| `AI_READ_TIMEOUT` | 60s | DeepSeek 偶尔慢响应时可上调至 90s |
| `RATELIMIT_AI_LIMIT` | 20/min/IP | 教室共用 IP 场景可上调至 50 |

## 10. 版本升级

1. 备份数据库（参见第 7 节）
2. 拉取新代码：`git pull`
3. 重建镜像：`docker compose build --no-cache`
4. 滚动更新：`docker compose up -d --force-recreate`
5. 验证健康检查：`curl http://localhost:8080/api/actuator/health`
6. 若升级包含数据库 schema 变更，手动执行增量 SQL
