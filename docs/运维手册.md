## 1. 系统架构概览

```
┌──────────┐     ┌──────────────┐     ┌────────┐     ┌───────┐
│  Nginx   │────▶│ Spring Boot  │────▶│ MySQL  │     │ Redis │
│  :80     │     │ :8080 (/api) │     │ :3306  │     │ :6379 │
└──────────┘     └──────────────┘     └────────┘     └───────┘
                        │
                        ▼
                 ┌──────────────┐
                 │ DeepSeek API │
                 │ (外部 HTTPS) │
                 └──────────────┘
```

- **前端**：Vue 3 + Element Plus，Nginx 反向代理，监听 80 端口
- **后端**：Spring Boot 3.4.4 + MyBatis-Plus，监听 8080 端口（context-path `/api`）
- **数据库**：MySQL 8.0，字符集 utf8mb4
- **缓存**：Redis 7，用于会话、限流、缓存（**必选**：应用启动时强校验连通性）
- **AI**：DeepSeek API（可通过配置切换为 OpenAI/Qwen）
- **可选 Python 微服务**：知识图谱 (8001) / RAG (8002) 契约保留未启用，LoRA 微调 (8003) 默认关闭（详见第 11 章）

## 3. 快速部署

### 3.1 环境变量配置

```bash
# 1. 复制环境变量模板
cp .env.example .env

# 2. 编辑 .env，填入真实值（所有字段必须填写）
#    MYSQL_ROOT_PASSWORD - 强随机密码（≥16位）
#    JWT_SECRET         - 256位 Base64 随机字符串
#    DEEPSEEK_API_KEY   - DeepSeek API Key
```

**生成强密码**：
```bash
# Linux/Mac
openssl rand -base64 32

# Windows PowerShell
[System.Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

### 3.2 Docker Compose 部署（推荐）

```bash
# 启动所有服务（mysql + redis + backend + frontend；backend/frontend 归入 full profile）
docker compose --profile full up -d

# 仅启动基础设施（mysql + redis，供本地后端源码连接）
docker compose up -d mysql redis

# 查看状态
docker compose ps

# 查看日志
docker compose logs -f backend
docker compose logs -f frontend
```

> 生产环境请在 `docker-compose.yml` 或 `.env` 中填充 `JWT_SECRET` / `DEEPSEEK_API_KEY` / `MAIL_*`；设置 `REDIS_PASSWORD` 后 Redis 容器自动启用 `--requirepass`（健康检查与后端 `SPRING_DATA_REDIS_PASSWORD` 同步生效），安全开关 `COOKIE_SECURE` / `REQUIRE_HTTPS` / `CSRF_ENABLED` 可经 `.env` 一键开启（详见 `.env.example` 注释）。

### 3.3 本地开发部署

**前置条件**：MySQL 和 Redis 已在本地运行。

```bash
# Windows
start-backend.bat    # 启动后端（:8080，自动激活 local 配置，含本地 DeepSeek Key）
start-frontend.bat   # 启动前端（:5173）

# Linux/Mac（手动）
cd backend && ./mvnw spring-boot:run -Dspring-boot.run.profiles=local
cd frontend && npm install && npm run dev
```

## 5. 日志分析

### 5.1 日志位置

| 环境 | 位置 |
|------|------|
| Docker | `docker compose logs -f <service>` |
| 本地开发 | 控制台输出 |

### 5.2 日志级别调整

生产环境默认 `INFO`。排查时可通过环境变量临时提级：

```bash
# 提级为 DEBUG（输出 SQL 和详细日志）
export LOG_LEVEL_COM_AICOURSE=DEBUG

# 重启后端服务
```

**注意**：DEBUG 级别会输出 SQL 语句和请求详情，生产环境勿长期开启。

### 5.3 关键日志模式

| 日志内容 | 含义 | 处理 |
|----------|------|------|
| `CSRF 校验失败` | 客户端缺少 XSRF-TOKEN | 确认前端 axios 配置 `withXSRFToken: true` |
| `Rate limit exceeded` | IP 请求过于频繁 | 检查是否有脚本/爬虫；调大 `ratelimit.*.limit` |
| `AI quota exhausted` | 用户 AI 调用配额用尽 | 调大 `ai.quota.daily-request-limit` 或等待次日重置 |
| `WebSocket 消息处理异常` | 客户端发送畸形数据 | WARN 级别，不影响服务，但需关注频率 |

## 6. 常见故障处理

### 6.1 后端启动失败

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| `CommunicationsException: Communications link failure` | MySQL 未启动或密码错误 | 检查 MySQL 状态，确认 `.env` 中 `MYSQL_ROOT_PASSWORD` 正确 |
| `PatternParseException: Invalid mapping pattern` | springdoc 版本不兼容 | 已排除 `SwaggerConfig`，若仍出现检查是否引入了新版 springdoc |
| `JWT signature does not match` | JWT_SECRET 不一致 | 确保所有实例使用相同 `JWT_SECRET`（若 `start-backend.bat` 行尾被改写为 LF，会导致 JWT_SECRET 截断触发 WeakKeyException，务必保持 CRLF） |
| `RedisConnectionFailureException` | Redis 未启动 | 启动 Redis 或检查 `SPRING_DATA_REDIS_HOST` 配置 |

### 6.2 前端无法访问后端

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 跨域错误 (CORS) | 前端 origin 不在白名单 | 检查 `cors.allowed-origins` 配置 |
| 401 未授权 | Cookie 未携带或令牌过期 | 清除浏览器 Cookie 重新登录 |
| 403 CSRF 校验失败 | 前端 axios 未配置 `withXSRFToken` | 确认 `request.js` 中 `withXSRFToken: true` |

### 6.3 AI 功能不可用

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| AI 问答返回"知识库原文" | `DEEPSEEK_API_KEY` 未配置 | 在 `.env` 中设置有效的 API Key |
| AI 调用超时 | 网络问题或 API 服务异常 | 调大 `AI_READ_TIMEOUT`，检查 `api.deepseek.com` 可达性 |
| `AI quota exceeded` | 用户当日调用次数/Token 超额 | 调大 `AI_QUOTA_DAILY_REQUESTS` / `AI_QUOTA_DAILY_TOKENS` |

### 6.4 数据库初始化

```bash
# 手动初始化（如果 Docker 自动初始化失败）
docker exec -i aicourse-mysql mysql -uroot -p"${MYSQL_ROOT_PASSWORD}" ai_course_platform < backend/src/main/resources/index.sql
```

## 11. Python 微服务接口契约

> 本节为原 `Python接口契约文档.md`（2026-07-23）全文并入。
> 定义 Java 后端（Spring Boot）与可选的 Python 微服务之间的 HTTP API 契约。
> **状态说明（重要）**：经统一重构后，知识图谱（8001）与 RAG（8002）的 Python 微服务**并未随项目交付**，其能力已由 Java 端**自包含实现**接管，当前**不再调用**外部 Python 进程。仅 **LoRA 微调（8003）** 仍保留真实 Python 集成（默认关闭，启用时调用）。
>
> 本节保留 8001/8002 的完整契约作为**可选扩展基线**：若后续引入 Neo4j / Milvus / Python 向量服务，可按此契约实现并重新开启 `knowledge-graph` / `rag` 配置开关。

### 11.1 当前实现状态总览

| 服务 | 端口 | Java 当前实现 | 是否调用 Python | 配置开关 |
|------|------|--------------|----------------|----------|
| 知识图谱 (8001) | 8001 | `KnowledgeGraphServiceImpl` 直读 MySQL `knowledge_points` / `knowledge_point_relations`，返回 ECharts/D3 兼容图结构 | **否（自包含）** | `application.yaml` 中 `knowledge-graph.base-url` 配置键保留但**当前未使用** |
| RAG 检索增强 (8002) | 8002 | `RAGServiceImpl`：语料取自 `knowledge_points` 表，召回用「Okapi BM25 算法（中文 bigram 分词，k1=1.5/b=0.75）」，生成交由可插拔 `LLMProvider`（DeepSeek/Qwen/OpenAI），未配 Key 时回退展示知识库原文 | **否（自包含）** | `application.yaml` 中 `rag.base-url` 配置键保留但**当前未使用** |
| LoRA 微调 (8003) | 8003 | `LLMFineTuneServiceImpl` 经 `RestClient` 调用 Python | **是（启用时）** | `fine-tune.enabled`（默认 `false`） |

**设计意图**：需求文档中的「分层 RAG（Neo4j + Milvus + Elasticsearch）」与「知识图谱微服务」为规划能力；当前以零外部依赖的自包含实现保证功能可用，后续可无痛替换为 Python 链路（只需替换 `RAGServiceImpl.retrieve` 的召回实现 / 接入 `KnowledgeGraphServiceImpl` 的向量召回）。

### 11.2 服务部署规格（契约基线）

| 服务 | 端口 | 健康检查路径 | 基路径 |
|------|------|-------------|--------|
| 知识图谱服务 | **8001** | `GET /api/v1/graph/health` | `/api/v1/graph` |
| RAG 检索增强服务 | **8002** | `GET /api/v1/rag/health` | `/api/v1/rag` |
| LoRA 微调服务 | **8003** | `GET /api/v1/fine-tune/health` | `/api/v1/fine-tune` |

**通用约定：**
- 所有请求/响应均使用 `Content-Type: application/json`
- 健康检查接口返回 `200 OK` 即可（body 可为空 `{}`）
- 错误响应格式：`{"error": "错误描述", "code": 503}`

### 11.4 RAG 检索增强服务（端口 8002）— 可选契约

> 当前 Java 端不调用此服务，改由 `RAGServiceImpl` 自包含实现（knowledge_points + Okapi BM25 召回 + LLMProvider）。以下为若启用 Python RAG 微服务时应实现的契约。

```
GET /api/v1/rag/health
Response: 200 OK {}
```

```
POST /api/v1/rag/ask
Body: {"question": "什么是梯度下降？", "course_id": 1, "top_k": 5}
Response: {
  "answer": "梯度下降是一种优化算法...",
  "sources": [{"document_id": 1, "document_name": "机器学习基础", "relevance_score": 0.95, "excerpt": "..."}],
  "model": "deepseek-chat", "tokens_used": 512
}
```

**RAG 流程要求：**
1. 向量检索：用 `question` 在 Milvus/FAISS 向量库中检索 top_k 个相关文档片段
2. 上下文拼接：将检索到的文档片段作为上下文拼入 Prompt
3. LLM 生成：调用大模型基于上下文生成答案
4. 返回答案 + 引用来源

```
POST /api/v1/rag/documents
Body: {"course_id": 1, "document_name": "机器学习基础", "content": "..."}
Response: {"document_id": 1, "status": "indexed", "chunks": 5}

### 11.6 配置说明

  base-url: ${RAG_BASE_URL:http://localhost:8002}

  enabled: ${FT_ENABLED:false}
  base-url: ${FT_BASE_URL:http://localhost:8003}
  connect-timeout: 5
  read-timeout: 300
  max-retries: 1
  health-path: /api/v1/fine-tune/health
```

**环境变量覆盖：**
- `KG_BASE_URL` / `RAG_BASE_URL` / `FT_BASE_URL` — 服务地址
- `FT_ENABLED` — 微调服务启用开关（KG/RAG 无独立 enabled 开关，因其当前由 Java 自包含实现）

### 11.7 降级策略（当前实际行为）

| 场景 | 实际行为 |
|------|----------|
| 知识图谱 | Java 自包含直读 MySQL，始终可用；不依赖 Python 8001 |
| RAG 问答 | Java 自包含（knowledge_points + Okapi BM25 召回 + LLMProvider）；未配 LLM Key 时回退展示知识库原文 |
| 微调服务（8003）未启用/不可用 | `LLMFineTuneServiceImpl` 返回 `{"error":"微调服务暂不可用","code":503}` |
