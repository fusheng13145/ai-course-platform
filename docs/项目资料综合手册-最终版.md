## 1.3 五大赛道架构

大赛设 **高教主赛道、「青年红色筑梦之旅」赛道、职教赛道、产业赛道、萌芽赛道** 五个赛道，另有相关同期活动。

### （一）高教主赛道（重点）

- **参赛项目类型（5 类）**：新工科类、新医科类、新农科类、新文科类、**「人工智能+」项目**（紧扣"打造智能经济新形态"，AI 赋能千行百业）
- **参赛组别**：本科生组 / 研究生组，均内设**创意组、创业组**
- **团队要求**：3~15 人（含负责人），须为实际核心成员；允许跨校组建
- **参赛对象条件**：
  - 创意组：项目创意好、有较成型原型或服务模式，通知下发日前未完成工商注册；负责人须为全日制在校本专科生/研究生
  - 创业组：已完成工商注册；负责人须为企业法定代表人且为在校生或毕业 5 年内学生；**法定代表人股权 ≥10%，团队成员股权合计 ≥1/3**
- **入围名额**：中国大陆 2160 个、港澳台 90 个、国际 600 个（高教主赛道合计 2850 个）
- **奖项**：中国大陆设金奖 240、银奖 480、铜奖 1440

## 1.4 参赛要求与纪律红线（务必注意）

**通用参赛要求：**
1. 项目须结合经济社会现实需求，体现新工科/新医科/新农科/新文科建设成果
2. 内容真实、健康、合法，知识产权清晰；涉密内容参赛前须脱敏
3. **参赛人员年龄 ≤35 岁**（1991 年 3 月 1 日及以后出生）；学校教师不得作为团队成员参赛
4. 每人仅可参加 1 个赛道的 1 个项目；**往年总决赛获奖项目不可再报名**
5. 报名后信息修改有严格窗口期限制（详见 1.5）

**纪律红线（"十不准"核心提炼）：**
- **学生"十不准"**：不重复参赛、不伪造身份与贡献、不抄袭侵权、不伪造数据材料、不外包核心工作、不虚假陈述、不买卖参赛资格、不参加违规培训、不购买"保奖"服务、不干扰评审
- **指导教师"十不准"**：不纵容抄袭、不挂名指导、不协助伪造数据、不代写核心内容、不参与买卖资格、不推销保奖服务、不重复指导获奖项目、不教唆虚假陈述、不请托公关、不包庇违规
- **评审专家"十不准"**：不公开身份、不委托评审、不参加利害项目、不泄露细节、不影响他人、不提出要求、不谋利、不暗示、不收受、不散播

## 1.5 报名操作指引（学生操作手册要点）

**报名入口**：全国大学生创业服务网 `https://cy.ncss.cn`（公众号：全国大学生创业服务网 / 中国国际大学生创新大赛）

**关键时间节点（2026 年）：**
- 报名系统开放：**8 月 10 日**
- 报名截止：**9 月 25 日 12 时**（截止后人员、指导教师、组别、类别、名称均不可修改）
- 省级复赛完成：10 月 25 日前；总决赛推荐：10 月 31 日前
- 总决赛：2026 年 11 月

**报名流程（主干道/红旅/职教）：**
1. **注册登录** → 新用户须接受服务条款
2. **完善个人信息 + 学籍学历验证**（学籍校验未通过无法报名；填写须与学信档案一致）
3. **创建项目**：填写必填信息（项目名称不可与库内重复、创建后不可改）→ 添加团队成员（3~15 人，通过"姓名+手机号"搜索邀请，成员须注册且学籍通过验证）→ 添加指导教师（可选）→ 填写知识产权信息（专利/论文/软著/作品著作权/商标/获奖，无则不填）
4. **报名参赛**：选择赛道、组别、类别 → 确认参赛 → 学校审核
5. **红旅赛道额外要求**：须先报名参加"青年红色筑梦之旅"活动

**项目状态流转（信息锁定规则）：**
`未报名 → 项目已提交，待审核 → 校级审核通过/不通过 → 进入校赛 → 推荐省赛 → 进入省赛 → 推荐进入总决赛 → 进入总决赛`

- **校赛阶段**：仅"未报名"和"项目已提交，待审核"两状态可调整内容；进入校级审核后锁定
- **省赛阶段**：仅"推荐省赛"状态可调整；进入省赛后锁定
- **国赛阶段**：仅"推荐进入总决赛"状态可修改；进入总决赛后完全锁定
- **附件上传规则**："项目已提交，待审核"须传项目计划书；"推荐省赛"可补传 PPT/视频；"推荐进入总决赛"必须传 PPT/视频
- **重要提醒**：报名后更换绑定手机号会**自动清除该账号全部项目信息**

**产业赛道报名差异**：企业命题组须上传解决方案而非计划书；可先"与命题企业对接"（需在对接平台另行注册）；命题对策须契合企业命题，企业会进行契合度审核；揭榜项目少于 5 项的命题原则上不列入评审。

## 2.2 项目概述（答辩第一部分）

**项目名称**：基于知识图谱 + LLM 的 AI 助教系统设计

**时代背景**：教育数字化已上升为国家战略；LLM 生成式 AI 带来创新可能；知识图谱为知识结构化表示与逻辑推理提供底层支撑。

**四大现实痛点：**
1. **知识碎片化**：知识点繁杂，传统教材难以直观展示内在逻辑联系
2. **辅导资源不足**：师生比失衡，难以提供及时精准的个性化答疑
3. **大模型"幻觉"**：通用模型缺乏领域深度，存在知识错误，难以满足教学严谨性
4. **管理效率低下**：教师被成绩统计、案例搜索等事务性工作消耗大量精力

**项目意义**：提升教学质量（知识结构化可视化）、实现个性化学习（行为数据+图谱）、增强教学严谨性（RAG 限定回答范围、答案可溯源）、解放教师生产力（自动化成绩管理、智能案例推荐）。

**总体目标**：设计并实现基于知识图谱与大语言模型（LLM）的 AI 助教系统，为专业课程提供智能化教学辅助服务，提升教学互动性与个性化水平。以《计算机网络》为样例课程。

**四大核心内容：**
1. 构建**细粒度课程知识图谱**（从多源异构数据抽取细粒度知识点及复杂关系）
2. 优化**基于 GraphRAG 的问答引擎**（融合知识图谱的检索增强生成）
3. 开发 **AI 助教系统原型**（智能问答、知识可视化、案例推荐、个性化路径规划、成绩管理）
4. **模型微调与系统效果评估**（LoRA 高效微调 + 多维度指标评估）

## 2.3 研究现状与切入点（答辩第二部分）

**现有研究四大不足：**
1. 知识粒度较粗（多为章节/标题级，细粒度抽取能力不足）
2. 隐式关系处理困难（深层依赖、逻辑关联难以用传统 NLP 抽取）
3. RAG 与图谱融合不深（多数研究仅将图谱作为文本源，未利用结构化信息辅助推理）
4. 个性化服务单一（缺乏图谱结构+学生行为数据的深度个性化推荐）

**本项目三大切入点：**
1. **基于大模型的细粒度图谱构建**：利用 LLM 语义理解自动抽取细粒度知识点及属性
2. **深度融合知识图谱的 GraphRAG 框架**：结合图神经网络与检索增强生成，利用图谱结构化信息进行路径推理
3. **智能 AI 助教系统**：更智能、精准、个性化的学习辅助体验

## 2.4 技术方案与创新点（答辩第三部分）

### 系统总体架构
分层架构设计（高内聚、低耦合），核心数据流两条：
- **知识库构建流**：上传课程资料 → 智能文本分块 → 向量化构建 FAISS 向量库 → 实体关系抽取构建知识图谱
- **智能问答流**：用户提问 → 融合历史对话 → HyDE 扩展 → BM25+FAISS 混合检索 → GraphRAG 增强 → Cross-Encoder 重排 → 构建 Prompt → 大模型生成精准回答

### 核心技术一：细粒度知识图谱构建
- **细粒度知识点抽取——两阶段间接提示法（IPA）**：①自主学习（提示大模型模拟学习者阅读教材，深度解析文本语义与内在结构）；②专家指导（模拟领域专家对分析结果归纳总结，精准抽取细粒度知识点）
- **隐式关系抽取——上下文重构策略的 IREM 模型**：①上下文重构（利用大模型改写文本，暴露潜在隐式逻辑关系）；②特征增强（提取共现知识单元特征，增强实体对特征表示与关联度）

### 核心技术二：融合 GraphRAG 的智能问答引擎
- **混合检索架构**：BM25 关键词检索（高召回）+ FAISS 向量检索（语义匹配）
- **高级 RAG 增强**：HyDE 查询扩展（解决模糊/低资源召回）+ Cross-Encoder 重排序（提升精度）
- **GraphRAG 深度融合**：实体链接与子图检索 + 图结构融入大模型逻辑推理

### 核心技术三：基于 LoRA 的领域大模型微调
- **基座模型**：deepseek-r1:7b（开源、中文理解生成能力强）
- **LoRA 参数高效微调**：注入低秩矩阵仅训练约 0.1% 参数，降低硬件门槛、媲美全量微调
- **领域指令数据集**：课程问答、信息抽取、辅导建议等多维度指令数据

### 三大创新点总结
| 维度 | 创新内容 |
|------|----------|
| 方法创新 | 两阶段间接提示法（IPA）突破传统抽取局限；IREM 隐式关系模型解决隐式关系识别难题 |
| 架构创新 | 深度融合的 GraphRAG 引擎，结构化知识推理，提升复杂逻辑问答准确率与可解释性 |
| 应用创新 | 一体化智能助教系统，集成问答、可视化、推荐、规划等核心功能，覆盖"教、学、评、导"全环节 |

## 4.2 杜彩丽《基于大模型的课程知识图谱构建方法研究》

### 研究问题
教科书内容呈非结构化文本、知识点分散且层次复杂（以《计算机网络》协议跨层分布为例）；传统关键词/实体抽取无法捕捉**概念、原理、方法**等细粒度知识点；细粒度知识点间的**隐式关系**难以识别。

### 核心贡献一：细粒度知识点抽取任务 + 两阶段间接提示法（IPA）

- **任务定义**：在教学大纲与考试大纲指导下，从教科书中精准提炼知识基本单元（概念/原理/方法），如"线性表的基本操作"
- **数据集**：自建 ComKnow（计算机：计算机网络/操作系统/数据结构/计算机组成原理，1000 条）与 EduKnow（教育学，1000 条）
- **IPA 方法（三模块）**：
  - 自主学习模块：组合式提示（关键信息识别+逻辑关系梳理+段落主旨），模拟学习者阅读理解
  - 专家指导模块：Sentence-BERT 向量化，模型输出句与标准知识点计算语义相似度，筛选目标句
  - 反馈优化模块：词频统计目标句主干 → 提炼"主语-谓语"高频表达 → 构造标准目标句 → few-shot 示例（2 个）指导输出 → 正则提取知识点
- **实验结果（核心数据）**：
  - ComKnow：IPA 的 ROUGE 65.64（**最优**，超次优 2.85pp）、METEOR 66.14（次优）
  - EduKnow：ROUGE 63.81、METEOR 64.69（均超 EducationGLM 微调模型）
  - 消融实验：去除反馈优化模块后 ComKnow 降 2.5pp（ROUGE），证明第二阶段的专家指导+反馈优化是性能关键
- **代码开源**：github.com/huahua-coder/curriculum_knowledge_graph

### 核心贡献二：基于上下文信息重构策略的隐式关系抽取模型（IREM）

- **五种关系类型**：包含关系、前驱关系、同一关系、兄弟关系、其他关系
- **IREM 四模块**：
  1. 上下文信息重构：大模型按提示模板生成"判断依据"，将隐式关系转化为显式实体提及（如"因特网的组成包含核心部分"）
  2. 共现词汇提取：jieba 分词取两知识点描述中的共现词作为中间知识单元（如"数据/网络/时间"）
  3. 表征学习：BERT 编码重构上下文+共现词，实体嵌入与共现词向量融合（tanh 激活+全连接）
  4. 关系分类：三部分向量拼接 → 全连接 → softmax 五分类（交叉熵损失）
- **数据集**：FKnow-RE（2000 条，含 point1/point2/上下文/关系五字段）
- **实验结果**：IREM 的 P=81.11%、F1=71.14%（**均最优**，P 超 TextRCNN 10.69pp、超 GLM-4 11.52pp）；消融显示上下文重构模块作用最关键（去除后 F1 暴跌至 12.22%）

### 智慧助教系统
基于上述方法开发：课程管理、知识点与关系抽取、图谱展示（力导向图/层级树，节点聚类、路径高亮）、**数字人授课**（生成讲稿→数字人视频）。技术栈：Vue+ECharts 前端、Spring Boot+JPA+Neo4j+MySQL+Redis 后端、Python+Flask 微服务、JWT 鉴权、响应式设计。

## 4.3 孟瑶瑶《大语言模型融合知识图谱的双创实践课AI助教研究与设计》

### 研究问题
高校双创实践课知识体系碎片化、教学指导个性化不足、过程管理效率低下；缺乏专门面向实践课程的智能助教系统。

### 研究路线（与本项目高度同构）
**LoRA 微调大模型抽取三元组 → 构建课程知识图谱 → 融入 GraphRAG 实现智能问答与案例推荐 → 集成 AI 助教系统**

### 关键方法
1. **知识图谱本体构建**：参考斯坦福七步法简化三步（确定本体/关系/属性）；本体含理论单元、实践单元、节、任务、小节、知识点、子知识点、案例、人物、企业；关系含包含、顺序、关联、应用；属性含定义、特点、注意、关联题目、举例、适用场景、作用、影响、原则
2. **LoRA 微调**：基座 Llama3-8B-Chinese-Chat（对比 ChatGLM3-6B 选型）；LLaMA-Factory 工具；参数 r=8、alpha=16、dropout=0.2、lr=5e-5、epoch=10、8bit 量化；指令数据集 Alpaca 格式（instruction/input/output）；任务含实体关系抽取（SPO 三元组）+ 事件抽取（结构化创业案例）
3. **数据集**：DuIE2.0（153431 训练条）+ 自建创新创业领域数据集（1500 余条文本、500 余条事件案例）
4. **SBERT-GraphRAG 智能问答**：Sentence-BERT 问题向量化 + TextRank 关键词提取双表征 → 图谱节点余弦相似度匹配 Top-k → 多跳子图扩展 → 信息结构化 → 提示模板 → LLM 生成；替换生成模块为 LoRA 微调模型
5. **案例推荐**：案例库（创业案例+学生实践 PPT 200 余份+题库），标签体系（案例名称/目标用户/盈利模式/创新模式/应用领域）；标签拼接文本 → SBERT 编码 → 与查询余弦相似度 → Top-K 推荐；存储采用 MongoDB 元数据 + MinIO 对象存储 + Elasticsearch 检索

## 6.7 三端功能需求

**学生端**：智能问答（GraphRAG 课程答疑，答案可溯源）、知识图谱可视化（浏览知识点网络、自主选择学习路径）、个性化路径规划（learning-path/generate）、作业/考试/错题（错题本 + BFS 知识点路径规划）、社区互动（发帖/投票/签到/任务）、成绩与资源（查成绩/看视频/下载资源）。

**教师端**：课程与章节管理、知识点与关系维护、资源管理；作业/试卷/成绩管理（出题、组卷、阅卷、成绩策略）；AI 辅助（智能出题 generate-question、内容总结 generate-summary、学习建议）；查重与监考（作业查重 plagiarism、在线监考）。

## 6.8 AI 实现方案专题

| 能力 | 实现机制 |
|------|----------|
| 问答生成 | AIServiceImpl 调用 LLMProvider（DeepSeek），支持 correct/polish/问答/出题/总结/建议等模式 |

## 6.9 非功能性需求与演进规划

## 7.6 分层 RAG 检索增强生成框架（规划目标）

- **第一层：知识图谱精准检索**——Cypher 结构化检索，支持多跳关系推理 A→B→C 链式查询、依赖路径自动发现。
- **第二层：向量语义检索**——BGE-large-zh 嵌入 + Milvus 向量库 ANN 近似最近邻检索。
- **第三层：全文关键词检索**——Elasticsearch 全文检索兜底，多源数据融合排序。

**RAG 工作流程**：用户提问 → 查询理解与重写 → 分层并行检索 → 结果重排序 → 知识去重融合 → 上下文构建 → Prompt 组装 → 大模型生成。

> **落地现状（2026-08-27）**：当前实际为 Java 自包含 Okapi BM25（中文 bigram）单层检索 + GraphRAG 关系增强；Neo4j / Milvus / Elasticsearch / FAISS / HyDE / Cross-Encoder 均为 P1 规划（见第六章 6.9 与第八章路线图）。

## D.9 AI 沙箱环境 Git 写保护（运维经验）

2026-09-02 期间触发的 Git 事故与本 AI 执行环境的写保护直接相关，关键经验：

- **不可持久**：`git commit` / `git update-ref` / 手动写 `refs/heads/*`（本地分支引用在 AI 沙箱中存在静默拦截）。
- **可持久**：`git fetch`（`refs/remotes/*` 写入）、`.git/HEAD` 文件、`.git/objects` 对象写入。
- **应对**：在 AI 沙箱内的 commit / 分支引用更新需通过 `dangerouslyDisableSandbox` 提权执行；`git push origin <hash>:refs/heads/<branch>` 可绕过本地引用持久化问题；正常终端无此限制，可正常 commit / checkout / push。
- **禁线**：严禁在 AI 沙箱内执行 `git gc --prune=now` 等破坏性命令，曾导致本地历史临时丢失（已通过 `git fetch origin` 恢复）。

详细故障归口见 `运维手册.md` §6 末段「AI 沙箱环境 Git 写保护」。
