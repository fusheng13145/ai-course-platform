## 0. 一句话定位

这是一个**三端（管理员 / 教师 / 学生）教学平台 + AI 助教能力**的全栈项目：

- **前端** `frontend/`：Vue 3.5 + Vite 8 + Pinia + vue-router 4 + axios，element-plus 仍为核心 UI 库（仅把 `el-dialog/el-drawer/el-tabs` 三类原语替换为自建 `components/ui/` 下的 `Modal/Drawer/TabGroup`）。
- **后端** `backend/`：Spring Boot 3.5（Java 21），MyBatis-Plus + MySQL，Redis 缓存/限流，JWT（HttpOnly Cookie）+ CSRF 双提交，Flyway 数据库迁移。
- **Python AI 服务** `python-services/`：三个独立 FastAPI 微服务（知识图谱 8001 / RAG 检索 8002 / LoRA 微调 8003），**全部默认关闭、未容器化**。

## 2. 系统架构（实测）

```
┌─────────────────────────────────────────────────────────────┐
│ 浏览器 → frontend (Vue3, nginx 静态托管 + /api 反代) :80     │
└───────────────────────────┬─────────────────────────────────┘
                            │  /api  (axios, withCredentials, CSRF 双提交)
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ backend (Spring Boot, Tomcat :8080, context-path=/api)        │
│  · JWT 鉴权 (HttpOnly Cookie ai_course_token + Bearer 回退)   │
│  · CSRF DoubleSubmit / RateLimit / Sentinel / AiQuota        │
│  · MyBatis-Plus → MySQL(:3306)   Redis(:6379) 缓存/限流       │
│  · Flyway 迁移 (+ 运行时 SchemaMigration ALTER)               │
└───────┬───────────────────────┬───────────────────┬──────────┘
        │ HTTP (默认关闭)         │ HTTP (默认关闭)    │ HTTP (默认关闭)
        ▼                        ▼                   ▼
  kg_service:8001          rag_service:8002      fine_tune:8003
  (Neo4j 可选后端)         (BM25+向量 RAG,        (PEFT/LoRA 训练)
                            调 DeepSeek 生成)
```

**鉴权链路（实测）**：JWT 优先从 `Authorization: Bearer` 取，缺失时回退到 HttpOnly Cookie `ai_course_token`。会话 `STATELESS`。前端令牌**不落地**（不写 localStorage），由浏览器自动携带；`CSRF` 双提交（`XSRF-TOKEN` Cookie + `X-XSRF-TOKEN` 头）。前端 `Pinia` 仅有一个 `auth` store，其余业务状态全在约 110 个 `composables/use*.ts` 中。

**AI 能力两路调用（实测，易混淆点）**：
- Java 后端 AI 主问答走自己的 `RoutingLLMProvider`（deepseek/openai/qwen 三选一，配 `ai.deepseek.*` 等）。
- Python `rag_service` 内部合成 RAG 答案时**再次**调 DeepSeek（单点，`DEEPSEEK_API_KEY`）。二者是独立 LLM 调用。
- Python 三个服务默认 `enabled: false`；关闭时 KG 走本地 BFS 兜底、RAG 返回 503 且 AI 问答自动回退纯 LLM、FT 返回 503。

## 3. 核心业务流程（实测）

1. **登录与权限**：`/login` → 后端签发 JWT 入 HttpOnly Cookie + 回 `permissions`。路由守卫 `beforeEach` 调用 `authStore.fetchPermissions()`，按回传 `ok/expired/unavailable` 决定放行/跳登录/跳 `/503`（后端不可达时落 503 自带重试，而非误判 403）。`effectiveRole` 防本地篡改 `localStorage.role` 提权。
2. **学生学习流**：`/student` → 我的课程（课程壳嵌套页签）→ 学习中心（课件/任务）→ 课业中心（考试/成绩/错题/讨论）→ AI 助手（接 RAG 或纯 LLM）→ 学习工具（知识图谱/学习路径/日历）。
3. **教师教学流**：`/teacher` → 课程驾驶舱（`/teacher/courses/:id` 含 12 个页签：概览/章节/任务/提交/题库/试卷/监考/成绩/知识/分析/互动/讨论，**管理端 `/admin/courses/:id` 复用同一视图**）→ 题库/试卷 → 教学工具（AI 中心/分析/讨论/互动/知识图谱/知识管理）。
4. **管理与治理**：`/admin` → 用户权限/组织、教学管理（课程/题目/资源/考试/成绩/查重/资源版本）、监管分析（教学督导/考试治理/内容审核/AI 用量）、系统配置（知识库/RAG 文档/通知/AI 供应商/Semester/操作日志/登录日志/会话/文件/提醒）。
5. **AI 问答 / RAG**：学生提问 → 后端 `AIController` → （若 `RAG_ENABLED`）调 `rag_service` 混合检索（BM25+jieba + FAISS 向量，BAAI/bge-small-zh-v1.5，RRF 融合）→ 调 DeepSeek 生成；无 Key 或引擎不可用 → 诚实降级为抽取式（`gen_mode` 字段告知前端），**不伪造成功**。
6. **知识图谱**：知识点 CRUD + 关系 + 最短路径规划（Neo4j Cypher 或内存 BFS）。
7. **考试与防作弊**：`ExamSession` + `ProctorSession/ProctorEvent` 监考事件，`PlagiarismCheck` 查重。

## 7. 运行与部署（实测，含两种路径）

### 7.1 本地开发 / 演示栈（Windows 友好）
- **一键（推荐）**：仓库根 `python scripts/start-all.py`（单窗口拉起缺的、接管在跑的，把五路输出汇总到 `logs/<name>.log`）。
- **分步**：`start-backend.bat`（→ `mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local`）+ `start-frontend.bat`（Vite dev，默认 5173/5174/5175 双栈）+ `python scripts/start-engines.py`（Neo4j→KG→RAG，**只绑 127.0.0.1**，手动导出 env）。
- **前置**：本机 MySQL(:3306) + Redis(:6379) 须手动起；`.env` 须含 `JWT_SECRET` 与 `MYSQL_ROOT_PASSWORD`（缺则 `start-backend.bat` 退出）。
- 前端 dev 代理目标硬编码 `http://127.0.0.1:8080/api`（`vite.config.ts`）。

### 7.2 容器编排（docker-compose，profile 制）
- **默认（不加 profile）**：仅起 `mysql` + `redis` 两个基础设施。
- `docker compose --profile full up -d`：再加 `backend` + `frontend`（构建各自 `Dockerfile`，`SPRING_PROFILES_ACTIVE=prod`）。
- 可选 profile：`monitor`（Prometheus/Grafana/Loki/Promtail/NodeExporter/Alertmanager）、`ops`（mysql-backup 备份守护）、`rag`（Neo4j，供 KG 持久化）。
- ⚠️ **Python 服务无法经 compose 起**：`kg/rag/fine-tune` 服务块**全部注释**，且三个服务均无 Dockerfile（`docker-compose.yml` 明确标注"需队友补充"）。当前只能本地 uvicorn 进程跑。
- ⚠️ **`--profile full` 是明文 HTTP 单机栈**（nginx 只 listen 80、compose 无证书卷）。若未显式 `REQUIRE_HTTPS=false` + `COOKIE_SECURE=false`，`/api/**` 会被 `requiresSecure()` 302 到不存在的 443 → 全站 API 不可用。生产置于 TLS 反代后须保持 `true` 且回传 `X-Forwarded-Proto: https`（协议修正改由 `TrustedForwardedProtoFilter` 完成，非框架 forward-headers）。

### 7.3 环境变量（实测自 `.env.example` 与 compose）
**必填（缺失即启动失败）**：`JWT_SECRET`（≥32 位随机）、`APP_ADMIN_INITIAL_PASSWORD`（prod 强口令）、`MYSQL_ROOT_PASSWORD`、`MYSQL_APP_PASSWORD`、`NEO4J_PASSWORD`（仅 `rag` profile 需要——⚠️ `.env.example` 与当前 `.env` 均**未含** `NEO4J_PASSWORD`，起 `rag` profile 会失败）。

**关键可选（有安全默认）**：`AI_PROVIDER`(deepseek)、`DEEPSEEK_API_KEY`(空则 AI 降级)、`DEEPSEEK_BASE_URL`(api.deepseek.com/v1)、`DEEPSEEK_MODEL`(deepseek-chat)、`REDIS_PASSWORD`、`MAIL_USERNAME/PASSWORD`、`KG/RAG/FT_ENABLED`(默认 false)、`KG/RAG/FT_BASE_URL`、`CORS_ALLOWED_ORIGINS`(空=fail-closed)、`APP_CORS_DEV_FALLBACK`(false)、`CSRF_ENABLED`(true)、`COOKIE_SECURE`(false)、`REQUIRE_HTTPS`(false)、`TRUST_PROXY_HEADER`(true)、`DEMO_ACCOUNTS_ENABLED`(false)、`APP_ACTUATOR_SECURED`(true)+`APP_ACTUATOR_BASIC_USER/PASSWORD`(空=fail-closed)、`GRAFANA_*`、`BACKUP_*`、`ALERTMANAGER_WEBHOOK_URL`、`VITE_MONITOR_ENDPOINT`。

⚠️ **疑似孤儿键**：`.env` 含 `LLM_PROVIDER` / `MODEL` / `OLLAMA_API_URL`，而后端 LLM 配置走 `AI_PROVIDER` + `ai.deepseek/openai/qwen`，这三个键在 compose/后端未见消费，疑为早期 Ollama 方案的残留——接手时请确认是否还有脚本引用。

## 9. 已知问题与依赖风险（实测核查，接手必读）

1. **🔴 Python 服务未容器化**：compose 中 kg/rag/fine_tune 块全注释且无 Dockerfile；`--profile python` 当前不可用。AI 能力只能本地 uvicorn 跑，且后端**启动时**才探测 8001/8002，引擎后起需重启后端。
2. **🔴 双轨数据库迁移**：Flyway（V1–V11，含 V5–V7 演示种子）负责结构，但 `config/SchemaMigration.java` 在运行时又 `ALTER TABLE` 补列（先查 `information_schema`）。两处都可能改表，维护易遗漏/冲突。新库以 Flyway 为准，`index.sql`(91KB) 永不执行（遗留）。
3. **🔴 安全强失败项（部署须满足）**：`JWT_SECRET`、`APP_ADMIN_INITIAL_PASSWORD`、`SPRING_DATASOURCE_PASSWORD` 无默认值；`--profile full` 明文 HTTP 栈须显式 `REQUIRE_HTTPS=false`+`COOKIE_SECURE=false` 否则全站 API 挂；`NEO4J_PASSWORD` 未在 `.env` 模板中（起 `rag` profile 失败）。
4. **🟠 后端包名/坐标不一致**：pom `groupId=com.just`，源码包 `com.aicourse`——不影响运行，但审计/包扫描约定不统一。
5. **🟠 `local` profile 空壳**：主运行读不到 `application-local.*`（只在 `src/test/resources`），任何"本地放宽"依赖除 `start-backend.bat` 直接 set 的 env 外都不会生效。
6. **🟠 Python 版本未钉死**：无 `pyproject.toml`/`setup.py`/`.python-version`；torch/transformers 对 Python 小版本敏感，建议补约束。
7. **🟠 引擎静默配置失效**：`start-engines.py` 只导出白名单内的 env 到引擎进程，改了 `.env` 不在白名单则不生效且不报错（如 `DEEPSEEK_BASE_URL`/`NEO4J_URI` 若未登记）。
8. **🟠 KG 内存图静默降级**：`KG_BACKEND` 默认 `auto`，Neo4j 连不上会静默退回内存图（重启即丢），运维易误以为图已持久化。
9. **🟠 FT 集成不对称**：KG/RAG 在 Java 侧有独立 `Http*Provider`+`Local/Disabled` 降级；FT 的 HTTP 调用直接写在 `LLMFineTuneServiceImpl` 内，无 `integration/ft/` Provider 接口。
10. **🟡 前端命名残留**：大量 `*Dialog.vue` 文件名保留旧称，实际已改用自建 `Modal`；`ElDialog` 仅在 `Gate.p4.test.ts` 迁移看守测试中引用。
11. **🟡 前端无 i18n / 无前端 `.env`**：文案全中文硬编码；配置多硬编码，仅 2 个可选 env。
12. **🟡 可疑孤儿键**：`.env` 的 `LLM_PROVIDER`/`MODEL`/`OLLAMA_API_URL` 疑为早期方案残留（见 §7.3）。
13. **🟡 根目录孤儿 `node_modules`**：仅 `.vite`+`.vitest-cache` 缓存（379KB），非真实依赖，可删；真实依赖在 `frontend/node_modules`。
14. **🟡 注释与实现不符处**：`vite.config.ts` warmup 写 `./src/main.js`（实为 `.ts`）；`mapper-locations` 指向不存在 XML 目录；"local profile 放宽"注释仅覆盖 bat 路径等——均已在对应源码/配置注释中订正，但提醒勿盲信旧注释。

## 12. 结论与建议（基于第一性原理）

本仓库是一套结构清晰、质量门禁完备（CI 含 trivy/gitleaks/OSV/覆盖率棘轮）的全栈教学+AI 平台，核心业务代码（前端三端、后端分层、Python 三服务）均已实证可查。主要风险集中在**部署侧与历史残留**：Python 服务未容器化、数据库双轨迁移、若干安全强失败项配置、以及根目录散落日志/孤儿 `node_modules`/未建的 `archive/`。建议接手后优先：① 补全 Python Dockerfile 并解注 compose；② 统一 `local` profile 与包名；③ 落实 `项目目录整理方案.md` 的清理白名单（注意 `evaluation/`、`calibration/` 不应按缓存处理）；④ 建立 `archive/` 并清理历史日志与根目录孤儿缓存。所有既有文档（含本文件引用的手册与方案）均应视为"线索"而非"权威"，任何结论以 `git` 当前代码与运行事实为准。
