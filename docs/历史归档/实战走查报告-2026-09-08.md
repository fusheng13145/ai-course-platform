## 一、启动体验（实际按 README 操作的坑）

### 1. 🔴 start-backend.bat 在本机会启动失败（高优先级，影响所有新人/评审）

**复现链路（全部实证）：**

- `.env` 中 `REDIS_PASSWORD` 非空（为 Docker 容器设计的强密码）；
- 本机 Redis 7 实测 `CONFIG GET requirepass` 为空 → **无密码模式**（故意错误密码 `PING` 仍返回 PONG 证实）；
- `start-backend.bat` 第 47 行逻辑：「REDIS_PASSWORD 非空 → 透传 `SPRING_DATA_REDIS_PASSWORD`」；
- 后端对无密码 Redis 发 `AUTH` → `RedisStartupValidator` fail-fast → **启动失败**。

本次走查是**手动构造环境变量（不注入 Redis 密码）**才成功启动的。即：照 README 跑一键脚本，在这台机器上起不来。

**改进建议（任选或组合）：**

- 脚本增加 Redis 鉴权探测：`redis-cli ping` 成功则不透传密码（本机无密码场景）；
- 或 `.env` 拆分变量：`REDIS_PASSWORD`（容器用）/ `REDIS_PASSWORD_LOCAL`（默认空），bat 只读后者；
- 或在 README 快速开始处显式注明「本机无密码 Redis 需将 REDIS_PASSWORD 置空」。

### 7. 🟢 mvnw 包装器不完整

`.mvn/wrapper/maven-wrapper.jar` 不存在，`./mvnw.cmd` 无法独立工作；本机靠系统 Maven 3.9.15 兜底启动。换一台没有全局 Maven 的机器，后端起不来。
**建议**：提交 wrapper jar（`mvn wrapper:wrapper` 重新生成），或启动脚本先探测 `mvn -v` 再回退 wrapper。

### 2. 🔴 教师驾驶舱同步阻塞调用 LLM（2.78s 根因已定位）

**根因链（源码 + 日志双重实证）：**

1. `TeacherDashboardComponent.java:320` —— `getTeacherDashboardV2()` 在**响应路径内同步调用** `buildTeacherAIOverview(...)`；
2. 该方法内部请求 DeepSeek → 本环境返回 `402 Insufficient Balance`；
3. `OpenAiCompatibleProvider` 对 402 **依然重试 3 次**（日志 14:18:32.232 → 34.567，约 2.3s 白等）；
4. 耗尽后返回错误文本 → 下游按 JSON 解析 → `AI JSON 解析失败: Unrecognized token 'AI'`。

**影响**：教师打开驾驶舱，首屏被一个非必需的 AI 概要阻塞近 3 秒；LLM 任何故障都直接放大到页面首屏。

**改进建议（按性价比排序）：**

1. **402/401 等不可重试错误跳过重试**——现在每次失败固定烧 3 次重试，纯浪费（一行判断的事）；
2. AI 总览**独立接口 + 前端懒加载**：仪表盘先渲染结构化数据（这部分实测 <50ms），AI 概要异步补充；
3. 至少加 **Redis 缓存**（如同教师 5 分钟 TTL），避免每次进页面都打 LLM。

### 6. 🟡 仪表盘统计的 IO/内存放大

同文件 269–272、316–317 行：`submissionService.list(...)` 把**全部有成绩的提交记录拉进内存**再 `mapToDouble().average()`。提交表增长后，这里会线性变慢且占用堆内存。
**建议**：改 Mapper 层 `SELECT AVG(score)` 聚合，配合缓存。

## 三、健壮性与监控

### 3. 🔴 AI 错误链路不优雅

除第 2 项的重试问题外，**错误报文被当业务 JSON 解析**这一层说明 LLM 调用缺少「传输层错误 vs 业务响应」的分层。LLM 返回任何非 JSON 内容（限流页、网关错误页）都会以 `AI JSON 解析失败` ERROR 收场。
**建议**：Provider 层对非 2xx 直接抛结构化异常（带错误码），业务层只解析 2xx body；前端统一兜底「AI 服务暂不可用，请稍后重试」。

### 4. 🟡 Prometheus 业务指标注册失败（监控缺数据）

启动 WARN 实证：

```
The meter (MeterId{name='aicourse_submissions'...}) registration has failed:
already an existing meter named 'aicourse_submissions' that is a COUNTER.
The meter you are attempting to register is a GAUGE.
```

`BusinessMetricsService.java:45` 以 **GAUGE** 注册 `aicourse_submissions`，与已存在的同名 **COUNTER** 冲突 → 该指标注册失败，`/actuator/prometheus` 里**查不到这个业务量**，Grafana 业务面板会缺一块。
**建议**：GAUGE 更名为 `aicourse_submissions_current`（或语义等价名），一行改动消除冲突。

### 5. 🟡 DeepSeek 余额耗尽 → AI 能力全量不可用

实测所有 AI 链路（问答/出题/批改/学情建议/教师 AI 总览）都因 `402 Insufficient Balance` 失败。非代码缺陷，但**实际演示/评审时是核心功能阻断项**，且目前只有后端日志可见，**前端无显著提示**。
**建议**：管理端 AI 供应商页（`/admin/ai-supplier` 已有底子）增加余额/健康状态展示与告警；AI 功能入口在供应商不可用时给出明确降级文案。

## 四、安全与配置

### 8. 🟢 Flyway × MySQL 版本错位

启动 WARN：`MySQL 8.4 is newer than this version of Flyway ... latest supported is 8.1`。且 `docker-compose.yml` 用 `mysql:8.0`，与本机 8.4 不一致——本地与容器两套环境的 SQL 行为可能存在差异。
**建议**：统一基线到 8.0（本地降版本），或升级 Flyway 至支持 8.4 的版本。

### 9. 🟢 SpringDoc 生产暴露

启动 WARN 自我提示：`/v3/api-docs` 与 `/swagger-ui.html` 默认开启。生产 profile 应显式 `springdoc.api-docs.enabled=false`（本次实测 admin 登录态可拉取全量 388 个接口定义）。
