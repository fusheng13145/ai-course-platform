## 四、本轮新发现并已修复的缺陷

### 🔴 N-01（P0）缓存 VO 读取导致接口「首次正常、之后每次 500」

**现象**：`GET /exam-papers/{id}/detail` 在**第二次及以后**调用时返回 500「服务器内部错误」。

**根因分析**：`CacheConfig` 使用 `GenericJackson2JsonRedisSerializer` + `activateDefaultTyping(NON_FINAL)`，并由 `RedisObjectMapperFactory` 配置 `BasicPolymorphicTypeValidator` 白名单。该白名单只放行 `com.aicourse.entity.` / `java.util.` / `java.lang.` / `java.time.` / `java.math.`，**缺 `com.aicourse.vo.`**。VO 写入缓存时会带上 `"@class":"com.aicourse.vo.ExamPaperDetailVO"`，而**读取**时被 PTV 拒绝：

```
org.springframework.data.redis.serializer.SerializationException: Could not read JSON:
Could not resolve type id 'com.aicourse.vo.ExamPaperDetailVO' as a subtype of
`com.aicourse.vo.ExamPaperDetailVO`: Configured `PolymorphicTypeValidator` … denied resolution
```

**影响面**（凡缓存 VO 的接口）：`GET /exam-papers/{id}/detail`（`ExamPaperDetailVO`）、
`GET /knowledge/points/tree/{courseId}`（`List<KnowledgeTreeNodeVO>`）、`GET /proctor/thresholds`（`ProctorThresholdVO`）。

**修复**：白名单补入 `allowIfSubType("com.aicourse.vo.")`，仍保持「项目自有类型白名单」而非 LaissezFaire（**攻击面不扩大**，CWE-502 防护强度不变）。

**验证**：D4/D5/D6 三个接口「冷→热」两次调用均 200（修复前第二次必 500）。

---

### 🔴 N-02（P1）试卷修改/删除缺归属校验（水平越权 BOLA）

**根因**：`ExamPaperController.update/delete` 仅有 `@PreAuthorize(hasAnyRole(TEACHER,ADMIN))` 角色校验，未校验试卷归属 → **任何教师可改/删他人课程试卷**（与已修 R-06 同源，上一轮只覆盖了 publish/autoCompose）。

**修复**：两处入口补 `examPaperAccessControl.assertCanManage(paper, auth)`（学生拒绝 / 管理员放行 / 教师须为授课教师）。
**验证**：G3c、C 组同类矩阵全绿；`ExamPaperControllerTest` 30 例通过。

---

### 🟠 N-03（P1）试卷更新/删除未失效缓存

**根因**：`getExamPaperDetail` 标 `@Cacheable("examPapers")`，而 `PUT /exam-papers/{id}`、`DELETE /exam-papers/{id}` 走 `IService.updateById/removeById`，**全无失效点** → 改完试卷（改时限/改分/改状态/改标题）后详情在 TTL（30 分钟）内仍返回旧内容。

**修复**：在 `ExamPaperServiceImpl` 覆写 `updateById` / `removeById` 并加 `@CacheEvict(cacheNames="examPapers", key=…)`。
**验证**：D3 —— 改名后立即读详情得到新标题。

---

### 🟠 N-04（P1）选课驳回后记录仍「有效」

**根因**：`CourseEnrollmentController.reject` 只把 `approval_status` 置 `REJECTED`，**未处理 `is_active`**；而下游（资源下载、开考资格、容量统计）均按 `is_active` 判权 → 被驳回学生仍算课程成员、仍占名额。同时 `enrollStudent` 的重复判定按 `(student,course)` 全量查，导致**被驳回/退课后永远无法重新申请**。

**修复**：①驳回同时置 `is_active=false`；②`enrollStudent` 重复判定只看**有效**记录，并**复用**历史行（表上有 `uk(student_id,course_id)`，不能新增行），重新申请时清空上一轮审批痕迹。
**验证**：A4（`REJECTED + is_active=0`）、A5（被驳回不可下载）、A6（可直接重新申请且 rows=1）。

---

### 🟠 N-05（P1）成员资格判定口径不统一

**根因**：资源下载（`ResourceController.canAccessResource`）与开考资格（`ExamSessionAccessControl`）各自按 `is_active=1` 判权 → **待审批(PENDING)**、甚至（修复前）**已驳回**的报名也能获得成员权利。审批型课程（`enrollment_type=APPROVAL`）应「审批通过才算成员」。

**修复**：新增统一入口 `CourseEnrollmentService.hasApprovedEnrollment(studentId, courseId)`（`is_active=1 AND approval_status='APPROVED'`），两条判权链路统一改用它。
**验证**：A2（PENDING 开考 403）、A5（被驳回下载 403）；主链路新增 G2b（教师审批选课）/G2c（非成员下载 403）通过。

---

### 🟡 N-06（P2）资源版本契约自相矛盾

**根因**：`ResourceVersionCreateDTO` 声明**必填** `fileUrl`（`@NotBlank`）与 `resourceId`（`@NotNull`），但控制器 `createNewVersion` 实际读取的是 `url` —— 只传 `url` 过不了校验、只传 `fileUrl` 又被判「资源地址不能为空」；而 `POST /{id}/rollback` 复用同一 DTO，其自身 JavaDoc 明确「仅使用 versionNumber 字段」，却被强制要求 `fileUrl`/`resourceId` → 按文档调用必 400。

**修复**：①控制器 url 缺失时**回退** `fileUrl`；②DTO 的 `fileUrl`/`resourceId` 改为可选，非空校验下移到建版本端点内（缺失仍返回 400 明确提示）。
**验证**：G3（仅 `{versionNumber}` 回滚 → 200）、G3b（仅 `fileUrl` 建版本 → 200）、G4/G4b（缺参 → 400）。

---

### 🟡 N-07（P2）资源版本无归属校验 + 上传者可伪造

**根因**：建版本/回滚仅有角色校验，且 `uploaderId` 取自**请求体**（客户端可伪造为任意用户）。

**修复**：新增 `assertResourceManageable`（资源 → 课程 → 授课教师；管理员放行），`uploaderId` 改为**当前登录人**。
**验证**：G3c → 403。

---

### 🟡 N-08（P2）`extend-deadline` 非 ISO 入参返回 500

**根因**：`TaskController.extendDeadline` 手写 `LocalDateTime.parse(newDueDateStr)`，非 ISO 入参抛 `DateTimeParseException` 落入兜底 500（全局宽松日期反序列化器对 String 字段不生效）。

**修复**：捕获并转为 400 明确提示「截止日期格式不正确，需为 ISO-8601（如 2026-09-20T23:59:59）」；空值单独提示。
**验证**：B10 → 400（修复前 500）。

---

### 🟡 N-09（P2）11 处越权异常使用默认 400

**根因**：`LearningPath/LearningPathNode/Proctor/CourseChapter/Discussion/Notification/SignIn/Vote` 等服务与控制器抛 `new BusinessException("无权…")`，使用默认码 400 → 客户端把「无权限」误判为「参数错误」。

**修复**：全部改为 `ApiCode.FORBIDDEN`（403）。
**验证**：深度用例 C 组 403、主链路 C7/E5 403；2277 单测全绿。

---

### 🟢 N-10（P3）无时限依据的试卷「永不收卷」

**根因**：R-02 修复后，若试卷既无 `time_limit`/`duration` 也无 `end_time`，则无期限依据、永不自动收卷（悬空会话）。

**修复**：新增 `exam.timeout.default-time-limit-minutes`（默认 120，设 0 可关闭），调度器以其兜底。
**验证**：单测 3 例（兜底启用→到期收卷；兜底启用未到期→不收卷；关闭兜底→不收卷）。

| 4 | **`analytics` 缓存不做写失效** | 属 5 分钟 TTL 的派生统计数据，接受短暂陈旧；已在报告中显式记录为设计取舍 |
