## 7. 推进纪律（前端每一批都必须遵守）

1. **判据与状态分离**：验收判据一经落盘不得随执行改写；执行偏差只写状态行。要改判据，必须在**同一次 diff** 里同步判据本体与测试断言，并写明为什么。
2. **棘轮只许向紧**：类型基线（现 0）、覆盖率阈值、`size:gate` 预算只许降／只许收紧。禁止「改方案不改阈值」。
3. **视觉基线纪律**：`anchors` 全表**一律跑两轮且两轮读数都记**；`--update-snapshots` 须显式授权 + 人工逐张看图 + 台账记 commit；禁止拿「基线没动」当视觉改动的生效证据，也禁止用重录吸收未知漂移。像素差异必须先归因（HEAD stash 对照），**不许带病收口**。
4. **免检额引用纪律**：基线现为全页几何（高 1116–2874px），旧的 129.6／648／2592 只在 1440×900 成立；**引用免检额必须带几何**。
5. **过渡类属性不算证据**：基线在 `reducedMotion: reduce` + `animations: 'disabled'` + 冻结时钟下采集，过渡会被强制落到终态；改 `transition-duration`／`timing-function` 不构成可见回归，不得写进「有效性」栏。用 `getComputedStyle` 取证必须先消除冻结时钟影响，否则读到的是历史值。
6. **归因不混批**：一次视觉跑只验证**一个**缺陷批的像素变化；两个基线批不同日混做（K-FE-5）。
7. **单一写者文件**：`anchors.spec.ts`、`visual-helpers.ts`、`ci.yml`、`typecheck-baseline.json`、`eslint.config.js` —— 除非某一批的唯一目的就是它，否则不触碰。
8. **docs 零污染**：跑视觉／e2e 后 `git status --porcelain docs/` 必须为空；证据与临时产物只写 `test-results/`、`e2e/visual/tools/evidence/`（已 gitignore）。
9. **夹具与端口**：`.auth` 与 origin（含端口）绑定；视觉套件固定 5175，流程套件用 `PW_PORT` 显式改口；跑完视觉再跑流程时，按配方重生成 5173 夹具，否则会整批假红（已复发多次，配方固定）。
10. **验证链完整**：每批收尾跑齐 `lint` → `format:check` → `typecheck` → `test` → `build` → `size:gate` → 流程 e2e → 视觉（涉像素时），命令与读数口径见 `docs/测试文档.md` §10。
11. **依赖单独成 commit**（`package.json` + lockfile），便于依赖层与样式层互不牵连地回滚。
12. **仓库纪律**：不用 `git rm`／`git mv`（中文父目录教训）；`.bat` 纯 ASCII + CRLF；推送决策归项目主。
13. **v2 迁移期的唯一临时豁免（2026-10-29 项目主拍定）**：过渡期允许同一能力在旧端与 v2 各有一个入口，**豁免范围止于 §11.5 L 档下线批**；撤销条件＝删除批执行完毕，此后恢复「一个能力只挂一个入口」。豁免期内每条双跑要在 §11.2 三态清单里有归属行，不许出现"两边都没记"的功能。
