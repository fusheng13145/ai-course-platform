- **审计日期**：2026-11-17
- **口径**：以 `backend/src/main/java` 当前源码为准；只统计真实 `@Cacheable` / `@CacheEvict` 与 Redis 原生键写入点。
- **结论**：缓存名注册门禁已建立（`CacheNameRegistrationTest`），本次补齐 `questionSearch` / `questionDetail` 的显式 TTL，并修复「题目编辑/删除绕过缓存失效」的旁路。**未做**：生产环境 Redis 键空间采样与命中率读数（需目标环境）。

### 1.1 缓存成对纪律（写侧必须问的三件事）

1. **写入口是否经过带注解的 Service 代理？** 控制器直接调 `IService#updateById/removeById` 会绕过 `@CacheEvict`；本次题目编辑/删除即此类旁路，已收敛到 `updateQuestion/deleteQuestion`。
2. **写方法内部自调用是否绕过代理？** `this.updateById(...)` 不会触发另一个方法上的注解；需要在外层方法上写全失效集合，或显式 `CacheManager` 清空。
3. **失效键是否与读侧键表达式完全一致？** 例如 `'teacher_' + #teacherId` 与 `'teacher_'+#graderId` 必须同形；`'platform'` 这类无读侧的 evict 是无效动作。

## 2. Redis 原生键（非 Spring Cache）

| 键形态 | 写入方 | TTL / 过期策略 | 失效方 | 结论 |
| --- | --- | --- | --- | --- |
| `ratelimit:<bucket>:<windowStart>` | `RateLimitFilter#tryAcquireRedis`（Lua 原子计数） | `windowSeconds + 1s`，由 Redis 过期 | 无主动失效；窗口滚动自然过期 | 固定窗口 + 1s 缓冲，避免边界丢计数；Redis 故障降级本地 `ConcurrentHashMap` |
| `aiq:req:<userId>:yyyyMMdd` | `AiQuotaService#increment`（Lua 原子计数） | 到当日结束（`secondsUntilEndOfDay`） | 无主动失效；跨日换键 | 配额按自然日重置；无「管理员手动清零」入口，需运营侧注意 |
| `aiq:tok:<userId>:yyyyMMdd` | `AiQuotaService#increment` | 到当日结束 | 无主动失效；跨日换键 | 同上；token 预算为软熔断（先放行本次、超额拦下次） |
| `auth:vc:attempt:<email>` | `AuthVerificationComponent` | 5 分钟 | 无主动失效；窗口自然过期 | 验证码爆破防护，5 次/5 分钟；无 Redis 时降级不计数 |

> 原生键没有统一的「键注册表」，因此本表是人工审计结果；新增键必须在 PR 描述中写明「键形态 / TTL / 失效方式」，否则视为未完成缓存评审。

## 3. 本次整改

| 项 | 改动 | 证据 |
| --- | --- | --- |
| `questionSearch` / `questionDetail` 未登记 TTL | `CacheConfig` 显式登记 10m，与题库写侧失效节奏一致 | `CacheNameRegistrationTest` 自动扫描所有 `@Cacheable` 缓存名，断言均在 `CacheConfig` 出现；2 例通过 |
| 题目编辑/删除绕过缓存失效 | 新增 `QuestionService#updateQuestion/deleteQuestion`，带 `@Caching` 同时清 `questionSearch`（全量）与 `questionDetail`（精确键）；控制器改走新入口 | `QuestionServiceImplTest` 回归；控制器不再直接 `updateById/removeById` |
| 缓存名漏登记无门禁 | 新增 `CacheNameRegistrationTest`，新增 `@Cacheable` 忘登记 TTL 会直接红 | 同上 |

**未整改 / 留档**：
- `questions`、`rag`、`rag-retrieve`、`verificationCode` 四个缓存名当前无读侧使用；保留不删，避免误伤未来接线，但不得据此宣称「这些缓存已生效」。
- `SubmissionServiceImpl` 对 `analytics 'platform'` 的 evict 无对应读侧，属无效动作；不影响正确性，留待下一批次清理。
- `questionSearch` 在 `updateCorrectRate` 后允许 ≤10 分钟滞后（列表中的正确率），属**有意取舍**，详情缓存已精确失效。
