## 2. 快速启动

### 2.1 Windows

```bat
start.bat              :: 全栈单窗口：依赖自愈 + Ollama/MinIO/Neo4j/KG/RAG/FT/API/Web
start.bat backend      :: 除前端外的全量后端栈
start.bat frontend     :: 只起 Vite
start.bat status       :: 只报服务状态，不起进程
```

8080 被占用时：`set API_PORT=8081 && start.bat`。启动器会同时改 `SERVER_PORT` 与 `VITE_PROXY_TARGET`。

### 2.2 Linux/macOS

```bash
./start.sh
./start.sh backend
./start.sh frontend
./start.sh status
```

`start.bat` / `start.sh` 都是薄壳；判定逻辑在 `scripts/start-all.py`。

### 2.3 启动器负责什么

- 依赖自愈、端口探测、8 路日志、Ctrl+C 收整棵子树。
- 按开关编排：`AI_PROVIDER=ollama`、`FT_ENABLED=true`、`MINIO_ENABLED=true`。
- 引擎就绪判据：端口在听 **且** 探针有响应（uvicorn 先绑口后装载）。
- MinIO 就绪判据：`/minio/health/live`。
- 凭据缺失时 fail-fast；**从不打印凭据值**。

### 2.4 端口

| 端口 | 用途 | 注意 |
| --- | --- | --- |
| 8080 | 后端 API | 文档口径；8081 是 e2e 并行端口 |
| 8081 | e2e 后端 | 不与日常 8080 混用 |
| 5173 | 前端 Vite | **必须 `localhost`**；`127.0.0.1` 连不上 |
| 5174 / 5175 | e2e / 视觉 | 5176+ 被 CORS 白名单拒登录 |
| 8001 | KG | |
| 8002 | RAG | 核心链路 |
| 8003 | LoRA 微调 | `FT_ENABLED=true` 时编排 |
| 9000 / 9001 | MinIO API / Console | 本机原生，非 Docker |
| 11434 | Ollama | 缺模型只告警 |
| 3306 / 6379 / 7687 | MySQL / Redis / Neo4j | Redis 为必选依赖 |

## 3. 配置与密钥

### 3.1 文件

- `.env`：本地实际配置，**不入库**。
- `.env.example`：模板；新增键必须同步。
- `deploy/secrets/`：Compose/生产密钥文件；权限最小化。
- 任何凭据值不得出现在日志、命令输出、对话或 diff 中。

### 3.2 关键键组

| 组 | 键 |
| --- | --- |
| 数据库 | `MYSQL_*`、`SPRING_DATASOURCE_*`、`REDIS_*` |
| 鉴权 | `JWT_SECRET`、`APP_ADMIN_INITIAL_PASSWORD`、`DEMO_ACCOUNTS_ENABLED` |
| AI | `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`AI_PROVIDER` |
| RAG | `RAG_ENABLED`、`RAG_PROVIDER`、`RAG_SERVICE_URL`、`RAG_HYDE_ALLOW_OLLAMA` |
| 存储 | `MINIO_ENABLED`、`MINIO_ROOT_USER`、`MINIO_ROOT_PASSWORD`、`MINIO_BUCKET`、`AICOURSE_DATA_DIR` |
| 引擎 | `FT_ENABLED`、`KG_SERVICE_URL`、`NEO4J_*` |
| 前端 | `VITE_API_BASE`、`VITE_PROXY_TARGET` |

### 3.3 密钥纪律

- 密码 8–32 位，含大小写、数字、特殊字符四类。
- `DEEPSEEK_API_KEY` 必须纯 ASCII 且以 `sk-` 开头；键值行不要写中文备注。
- 不要用 `openssl rand -base64 32`（44 字符超上限）；用 `python scripts/generate-secrets.py --write`。
- 轮换 `JWT_SECRET` 会使所有会话失效，必须在演示彩排前做。
- 凭据一旦贴进对话即已外泄，唯一止血是控制台轮换。

## 4. 存储

| 项 | 当前事实 |
| --- | --- |
| 运行期根 | `data/aicourse-platform/`（`storage/`、`minio-data/`） |
| 冷备根 | `data/backups/` |
| 对象存储 | MinIO bucket `aicourse-uploads`；资源行 32；对象 174（2026-11-18） |
| 上传路径 | `/uploads/**` 由后端代理读取 MinIO；不再落仓库 `uploads/` |
| 兼容 | 旧 `uploads` 路径只读兼容；新写入统一走 `StorageLayout` |
| 迁移 | 存量已迁 MinIO；历史脚本 `scripts/legacy/migrate-uploads.py` 只留档 |

MinIO 原生启动：

- 二进制发现顺序：`MINIO_BIN` → `MINIO_HOME/minio(.exe)` → `~/minio/minio(.exe)` → `PATH`。
- 数据目录：`MINIO_DATA_DIR` → `AICOURSE_DATA_DIR/minio-data` → 历史默认 `~/.aicourse-platform/minio-data`；本项目必须显式设 `AICOURSE_DATA_DIR=./data/aicourse-platform`。
- 本机当前由 `start-all.py` 在 `MINIO_ENABLED=true` 时拉起，非 Docker。

## 7. 健康与排障

### 7.1 健康判据

```bash
curl -fsS http://localhost:8080/actuator/health
curl -fsS http://localhost:8002/health
curl -fsS http://localhost:9000/minio/health/live
start.bat status
```

### 7.2 常见故障

| 现象 | 先查 |
| --- | --- |
| 后端起来但前端 401/403 | Vite 是否用 `localhost`；CORS 白名单；`JWT_SECRET` 是否变过 |
| e2e 大面积 403/429 | 后端是否 `RATELIMIT_LOGIN_LIMIT=200`；是否 `functional` 姿态 |
| 上传 500 / 读取 404 | MinIO 是否起；bucket 是否存在；`MINIO_*` 是否成对；`/uploads` 代理 |
| RAG 只出 `EXTRACTIVE` | DeepSeek 额度/Key；日志 402；不是代码问题 |
| HyDE 不生效 | `RAG_HYDE_ALLOW_OLLAMA=true`；重启 8002 |
| 覆盖率 0% | 并发构建互截 `jacoco.exec`；必须串行 + clean |
| Python import 直接死 | `pyarrow` 版本；torch 与 `pyarrow.dataset` DLL 冲突；预加载 |
| 重排模型报 Unrecognized processing class | `HF_ENDPOINT=https://hf-mirror.com` |

## 9. 回滚

1. 停入口/摘流量。
2. 回滚应用镜像/包到上一版本。
3. 数据库只回滚到兼容边界；已应用迁移不自动降级。
4. 恢复上一版配置与密钥（注意 JWT 轮换影响）。
5. 健康检查 + 关键链路冒烟。
6. 记录回滚耗时与数据损失。

目标：5 分钟内完成应用回滚；数据库回滚单独授权、单独演练。

### 9.3 恢复演练

1. 在隔离库/隔离 bucket 恢复最近一批 MySQL 与 MinIO 备份，禁止覆盖生产。
2. 启动后端与前端，跑登录、课程资源读取、RAG 问答三条冒烟链路。
3. 记录恢复耗时、数据时间点、失败步骤与修复动作；演练记录归档到 `docs/operations/`。
4. 异地副本未接入前，演练结论只能写“本机隔离恢复通过”，不能写“生产可恢复”。
