## 2. 环境要求

### 2.1 软件版本

| 组件 | 要求 | 依据／备注 |
| --- | --- | --- |
| JDK | **21** | `backend/pom.xml` 的 `maven.compiler.release=21`；启动器会校验主版本 |
| Maven | 由 `backend/mvnw.cmd` 提供 | 不要求系统级 Maven |
| Node.js | **20.19+**（CI 用 20；本机实测 24.18） | Vite 8 的运行时下限；`start.bat frontend` 只校验 node 可执行 |
| npm | 随 Node 安装 | 启动器通过 `npm-cli.js` 调用，避免 `npm.cmd` 挂起 |
| Python | **3.11** | 两个 FastAPI 引擎与 `scripts/start-all.py`；CI 固定 3.11 |
| MySQL | **8.4**（本机服务，端口 3306） | 库名 `ai_course_platform`；容器形态固定 `mysql:8.4.11` |
| Redis | **7.x**（本机服务，端口 6379） | 缓存、限流、验证码、AI 配额；后端启动时 fail-fast 校验 |
| Neo4j | 5.x（可选，端口 7474／7687） | KG 真图库后端；缺省时 `kg_service` 回退内存图 |
| 浏览器 | 现代 Chromium／Edge | 开发验收与 Playwright 测试 |

### 2.2 端口与进程

| 端口 | 进程 | 启动者 | 判据 |
| --- | --- | --- | --- |
| 3306 | 本机 MySQL | 手工服务 | 端口 LISTENING |
| 6379 | 本机 Redis | 手工服务 | 端口 LISTENING；免密或口令二选一 |
| 7474／7687 | Neo4j（可选） | `start-engines.py`／手工 | Bolt 7687 端口在听 |
| 8001 | KG FastAPI | `start-engines.py` | 端口 + `/api/v1/graph/health` 有响应 |
| 8002 | RAG FastAPI | `start-engines.py` | 端口 + `/api/v1/rag/health` 有响应 |
| 8003 | 微调 FastAPI（可选） | 手工／队友交付 | `/api/v1/fine-tune/health` |
| 8080 | Spring Boot 后端 | `start.bat backend`／`start.bat` | `/api/actuator/health/probe` 返 **200** |
| 5173–5175 | Vite 开发服务器 | `start.bat frontend`／`start.bat` | 双栈回环探测（Vite 实测只绑 `[::1]`） |
| 3307／6379／16379 等 | Compose 映射口 | `docker compose` | **仅回环**；当前搁置 |

> ⚠️ **前端只允许 5173／5174／5175**：`vite.config.ts` 是 `strictPort: true`，且后端 CORS 白名单只开这三个口。落到 5176+ 后登录会被 403 拒绝；三个口全被占时应先关掉其他 dev server，而不是换端口。

> ⚠️ **8080 上只允许一个后端实例**：两个实例共用一套 MySQL／Redis，却各算各的限流、各写各的日志（DR-36 实测）。启动器的处置是**接管不重启**（旧 `start-backend.bat` 那道"要不要强起第二个"的确认已取消，见 §3.3），要换后端就先停掉旧窗口。

## 3. 开发/验收本机启动（C 路径）

### 3.1 首次准备

```bat
:: 1) 配置密钥（值绝不回显、绝不提交）
copy .env.example .env
python scripts\generate-secrets.py --write

:: 2) 安装前端依赖
cd frontend
npm ci
cd ..

:: 3) 确认本机 MySQL / Redis 已启动
net start MySQL84
net start Redis
```

数据库首次初始化：本机 MySQL 需先有 `ai_course_platform` 库。建库与最小权限账户见 `scripts/init-app-db-user.sh`（容器形态由 `docker-entrypoint-initdb.d` 自动执行；本机需手工执行）。表结构与种子由 Flyway 在后端首启时自动迁移，不要手工灌 `index.sql`。

Python 引擎依赖（仅启用 KG／RAG 时需要）：

```bat
pip install -r python-services\kg_service\requirements.txt
pip install -r python-services\rag_service\requirements-engine.txt
```

> `.env` 生成器的边界：`generate-secrets.py --write` **只改已存在的键行**。键缺失时它把生成值打到终端而不是补写；因此先以 `.env.example` 补齐键名，再执行。它也会顺带改掉 MySQL root 口令——轮换单个口令时不要用它。

### 3.2 一键启动（开发/验收入口）

```bat
start.bat
```

`start.bat` 只做两件事：找到 Python 解释器、把子命令与开关原样转交给 `scripts/start-all.py`。**所有判定都在 Python 一侧**（2026-10-27 起，旧 `start-all.bat`／`start-backend.bat`／`start-frontend.bat` 三份已合并到这一个入口）。行为口径：

- **一个窗口五路日志**：`[neo4j] [kg] [rag] [api] [web]` 前缀输出，同时镜像到 `logs/<name>.log`。
- **接管不重启**：端口已在监听的服务一律不拉起、不杀掉。这样不会产生「双实例各算限流」的分叉。
- **子树收尸**：Ctrl+C 用 `taskkill /T /F` 收掉 `mvnw.cmd → java` 两代进程；只杀父进程会让 java 被重生并抢不到 8080。
- **依赖缺失只上报**：MySQL／Redis 是手工本机服务，缺了就 fail-fast 并退回项目主，**绝不拉容器**。
- **就绪判据**：引擎＝端口在听**且**探针有响应（uvicorn 先绑口后装载）；后端＝`/api/actuator/health/probe` 返 200；前端＝5173／5174／5175 双栈探测。
- **启动序**：Neo4j → KG → RAG → 后端 → 前端。后端只在启动那一刻探测 8001／8002／7687，引擎后起必须重启后端才会切到 `mode=ENGINE`。

子命令与开关（非法输入退出码 2 并打用法）：

| 命令 | 起什么 | 依赖门 |
| --- | --- | --- |
| `start.bat`（＝`all`） | 引擎 + 后端 + 前端 | MySQL 3306、Redis 6379、JDK 21 必需；缺 Node 只降级 |
| `start.bat backend` | 引擎 + 后端 | 同上，不查 Node |
| `start.bat frontend` | 只起 Vite | 只查 Node 与开发口；**不校验** `JWT_SECRET`／`MYSQL_ROOT_PASSWORD` |
| `start.bat status` | 什么都不起，只报五进程状态 | 无（旧写法 `--status` 继续可用） |
| `--no-color` | 关掉 ANSI 着色 | 与 `enable_vt_colors()` 共同决定；合并前该开关只写在文档里、`main()` 从不读它 |

### 3.3 分步启动（`backend` / `frontend` 子命令）

```bat
start.bat backend
start.bat frontend
```

`backend` 模式的六步与拒绝条件（判定与 `all` 共用同一套函数，不存在第二份实现）：

1. 读取 `.env`；`JWT_SECRET`、`MYSQL_ROOT_PASSWORD` 缺失**直接退出**（无弱默认值）。
2. 定位 JDK 21；找不到退出，且**不会静默回落**到别的 JDK。
3. 校验本机 3306／6379；缺任一退出，并明确提示「不要起容器」。
4. 检查 `DEEPSEEK_API_KEY` 形状（是否 `sk-` 开头、是否纯 ASCII）；**只告警、不阻塞**，值从不打印。
5. 调 `scripts/start-engines.py` 只补未监听的引擎，并按端口自动置位 `KG_ENABLED`／`RAG_ENABLED`（`.env` 显式值优先）。
6. 预检 8080 后 `mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local`。

`frontend` 模式的四步：定位 Node → `node_modules` 不存在才装依赖 → 探测后端 `/probe`（不通仍启动，但会先说明"每个 API 都会失败"）→ 在 5173／5174／5175 中挑一个空闲口启动 Vite。

> **8080 被占用时不再询问"要不要强起第二个实例"**：旧 `start-backend.bat` 有这道 `choice` 确认，合并后统一按"接管不重启"处理（DR-36 的结论是双实例在演示中必炸，询问只是把事故延后一次点击）。要换后端就先停掉旧窗口。

> **`local` profile 不是配置文件**：`src/main/resources` 下没有 `application-local.*`，主源码也没有 `@Profile` bean。它唯一的作用是**避免误激活 `prod`**（prod 会排除演示种子目录）。不要去找 local 配置文件。

### 3.4 引擎单独启动与重启语义

```bat
python scripts\start-engines.py                 :: 只补没在跑的
python scripts\start-engines.py --status        :: 只看状态
python scripts\start-engines.py --only kg rag   :: 只起指定引擎
python scripts\start-engines.py --reseed 1 4007 :: 起完再灌 KG 图与 RAG 语料（幂等）
```

四条必须记住的引擎事实：

1. **两个 FastAPI 只读进程环境，不读 `.env`**（无 dotenv）。`NEO4J_URI`、`DEEPSEEK_API_KEY`、`HF_HUB_OFFLINE` 必须由启动器导出；手工起 uvicorn 时要自己先 `set` 这些变量。
2. **`HF_HUB_OFFLINE=1` 必须置位**：缺它时 sentence-transformers 会联网向 HuggingFace 校验版本，本机无外网通道时**不报错而是挂起**，表现为 Java 侧 60 秒后「AI 服务暂时不可用」。本机访问 HF 须走镜像（见项目记忆／`.env` 说明）。
3. **后端只在启动时探测引擎**：先起引擎、再起后端；反序时后端会停留在本地兜底（KG 本地 BFS、RAG 503），重启后端才切 `ENGINE`。
4. **`start-engines.py` 的图库路径是 Windows-only**：`bin/neo4j.bat` 写死，Linux 分支带 `pragma: no cover`。A 路径（Linux VM）不能直接用该启动器，必须容器化或 systemd 化（§6.3 第 2 条）。

### 3.5 发布/验收前检查清单

- [ ] 前端落在 5173／5174／5175，且页面标题属于本项目（防止把别的 Vite 应用当成本项目）。
- [ ] 演示账号可登录；若启用了 `DEMO_ACCOUNTS_ENABLED=false`，确认已改过密码。
- [ ] AI 问答至少跑通一次；凭据有效性用 `python scripts/probe-llm-chain.py engine`，**不要**看 `/health` 的 `llmProvider`。
- [ ] 教室／机房共用出口时，按人数上调限流阈值（本机启动器读 `.env` 的 `RATELIMIT_*`；容器形态当前传不进去，见 §5.5）。

## 4. 配置与密钥

### 4.1 配置分层与优先级

```
命令行参数  >  系统环境变量（含 .env 导入）  >  configtree 文件  >  application-prod.yml  >  application.yaml
```

- 基础配置：`backend/src/main/resources/application.yaml`。
- 生产收紧：`application-prod.yml`，由 `SPRING_PROFILES_ACTIVE=prod` 激活；Compose 已固定激活。
- 本机启动器：读取 `.env` 并把键注入当前进程；`start.bat` 的 all/backend 模式（`scripts/start-all.py` 的 `backend_env()`）会**强制**把 `COOKIE_SECURE=false`、`REQUIRE_HTTPS=false`、`CSRF_ENABLED=false` 交给后端——这是开发态护栏，`.env` 里怎么填都不改变本机行为。
- 文件式密钥：`application.yaml` 已声明 `optional:configtree:/run/secrets/`；目录不存在时静默跳过（本机 Windows 属预期）。

> **铁律**：环境变量 > configtree 文件。改用文件式密钥后，**必须删除同名明文 env**，否则文件值被静默覆盖且不报错。这是本项目反复出现的「写了键 ≠ 会生效」同型问题。

### 4.2 `.env` 键清单（按域归纳；模板共 51 键）

> 只列键名与消费者，不记录任何值。当前值状态一律用 `python scripts/audit-stats.py` 的派生结论行读取。

| 域 | 键 | 消费者／作用 | 缺省与边界 |
| --- | --- | --- | --- |
| 数据库 | `MYSQL_ROOT_PASSWORD` | MySQL 容器、备份守护、本机后端数据源 | Compose `:?` 必填；本机启动器必填；无弱默认 |
| 数据库 | `MYSQL_APP_PASSWORD` | 最小权限账户 `aicourse_app` 与后端数据源 | 可空；空时回退 root 口令（首次部署可用，轮换需手工 `ALTER USER`） |
| 认证 | `JWT_SECRET` | JWT 签名 | Compose `:?`；本机必填；**只要求 ≥32 字节**，无字符类别要求 |
| 缓存 | `REDIS_PASSWORD` | Redis `requirepass` 与后端连接 | Compose `:?`；本机 Redis 免密时启动器自动摘除，避免对无密 Redis 发 AUTH |
| 种子 | `APP_ADMIN_INITIAL_PASSWORD` | 首启替换内置 admin 弱口令 | Compose `:?`；**8–32 位且四类字符齐全**；不合规即拒启 |
| 种子 | `DEMO_ACCOUNTS_ENABLED` | 演示账号加固器 | yaml 默认 `true`，Compose 默认 `false`；与 `prod` 同时为 true 会 fail-fast |
| AI | `DEEPSEEK_API_KEY` | LLM 调用 | 可空＝AI 如实 503；值必须**纯 ASCII** 且 `sk-` 形状（§4.4） |
| AI | `AI_PROVIDER`／`DEEPSEEK_BASE_URL`／`DEEPSEEK_MODEL` | 供应商与端点 | 默认 `deepseek`／官方端点／`deepseek-chat`；接自建网关必须改这三键 |
| AI | `OLLAMA_BASE_URL`／`OLLAMA_MODEL`／`OLLAMA_THINK` | 本地 Ollama（`AI_PROVIDER=ollama` 时生效） | 默认 `http://localhost:11434`／`deepseek-r1:8b`；**无 API Key**。`OLLAMA_THINK` 三态：留空=模型模板决定，`true`/`false` 显式开关。容器内 `localhost` 指容器自身，Compose 默认已改为 `http://host.docker.internal:11434` |
| 邮件 | `MAIL_USERNAME`／`MAIL_PASSWORD`／`MAIL_HOST`／`MAIL_PORT`／`MAIL_FROM_NAME`／`MAIL_SSL_ENABLE`／`MAIL_STARTTLS_ENABLE`／`MAIL_DEV_LOG_CODE` | 验证码／通知邮件 | `EmailServiceImpl` 读顶层 `mail.*`，`spring.mail.*` 同源绑定同一组变量（后者供 mail 健康指示器）；`MAIL_PASSWORD` 是 SMTP 授权码；**465 用 `SSL_ENABLE=true`+`STARTTLS_ENABLE=false`，587 反之，两者互斥**；`MAIL_DEV_LOG_CODE=true` 且未配账号时验证码只打后端日志，prod 强制 `false`（缺凭据即失败） |
| 安全 | `COOKIE_SECURE`／`REQUIRE_HTTPS` | Cookie Secure 与强制 HTTPS | 本机启动器强制 false；Compose 默认 false；prod 默认 true |
| 安全 | `CSRF_ENABLED` | 双提交 CSRF 开关 | 本机强制 false；Compose 默认 true；**prod 硬编码 true，改本键无效** |
| 安全 | `TRUST_PROXY_HEADER` | 限流／登录节流的客户端 IP 来源 | prod 默认 true；应用被直连暴露时必须 false |
| 跨域 | `CORS_ALLOWED_ORIGINS` | HTTP CORS 白名单；**WebSocket 握手同用** | 留空＝无跨域；同域上线也要填真实域名（§5.5） |
| 引擎 | `KG_ENABLED`／`KG_BASE_URL` | 知识图谱引擎 | 默认 false；后端启动时探测 8001 |
| 引擎 | `RAG_ENABLED`／`RAG_BASE_URL` | 检索增强引擎 | 默认 false；后端启动时探测 8002 |
| 引擎 | `FT_ENABLED`／`FT_BASE_URL`／`FT_LLM_PROVIDER` | 微调引擎 | 默认 false；8003。`FT_LLM_PROVIDER=engine`（默认）走基座+LoRA 真实推理 `mode=ENGINE`；`ollama` 走本机 Ollama `mode=OLLAMA`，复用 `OLLAMA_BASE_URL/OLLAMA_MODEL`；非法值返回 503 不静默回落 |
| 运维 | `BACKUP_RETENTION_DAYS`／`BACKUP_INTERVAL_SECONDS` | `mysql-backup` 保留与周期 | 默认 14 天／86400 秒 |
| 运维 | `BACKUP_REMOTE_SYNC` | 异地同步目标 | **当前不成立**：镜像无 `rclone`，脚本探测不到即 WARN 跳过 |
| 监控 | `APP_ACTUATOR_SECURED` | 监控端点鉴权总开关 | 默认 true；内网开发可 false，生产必须 true |

### 4.2.1 本机（非 Docker）运行口径补充（2026-11-05）

- **Ollama 切换**：`AI_PROVIDER=ollama` 只是 env 默认值；Java 的 `RoutingLLMProvider` 优先读 DB `system_configs.ai.provider`，且 `SystemConfigServiceImpl` 对该键有 `@Cacheable`。因此必须二选一：①管理员调用 `POST /admin/ai/provider {"provider":"ollama"}`（带 `@CacheEvict`，即时生效）；②直改 DB 后**重启后端**清缓存（只改库不重启，Java 仍按旧值解析）。同时重启 RAG 8002（它读进程环境）。有效性量具：8002 `/api/v1/rag/health` 的 `llm.provider=ollama`／`available=true`；真实生成须 `/api/v1/rag/ask` 返回 `gen_mode=LLM`（抽取式降级为 `EXTRACTIVE`）；Java 侧 `GET /admin/ai/current` 应显示 `router(ollama)`。
- **微调 8003**：非 Docker 本机启动为（cwd=`python-services/fine_tune_service`）`python -m uvicorn lora_service:app --host 127.0.0.1 --port 8003`（单 worker）；依赖 `requirements-engine.txt`，`FT_DATA_DIR` 指向该目录 `data`。`/api/v1/fine-tune/health` 的 `engine_available=false` 即未真正就绪，不得以占位返回冒充。
  - 生成路径由 `FT_LLM_PROVIDER` 切换，两种能力互不覆盖：`engine`（默认）走基座 `Qwen/Qwen2.5-0.5B` + LoRA adapter 真实推理，`/infer` 返回 `mode=ENGINE`、`model=qwen-7b-lora-*`；`ollama` 走本机 `deepseek-r1:8b`（复用 `OLLAMA_BASE_URL/OLLAMA_MODEL`，可在 `FT_OLLAMA_BASE_URL/FT_OLLAMA_MODEL/FT_OLLAMA_TIMEOUT` 单独覆盖），返回 `mode=OLLAMA`、`model=deepseek-r1:8b`。`/health` 同步返回 `provider`、`provider_valid` 与 `ollama` 探活段；非法取值不静默回落，`/infer` 直接 503。
  - 现有 adapter 基于 Qwen2.5-0.5B，**不能直接换到 deepseek-r1:8b**（隐藏维度/词表不同，权重加载即报维度不匹配）；要在 8B 上做 LoRA 必须重新训练并满足显存/数据条件，不属于 `ollama` 模式。
- **验证码通道**：邮件走真实 SMTP（QQ 邮箱口径已实测：`MAIL_HOST=smtp.qq.com`、`MAIL_PORT=465`、`MAIL_SSL_ENABLE=true`、`MAIL_STARTTLS_ENABLE=false`），发信成功即 `Transport.send` 无异常（SMTP 已接受），接口 200 仅代表请求受理。凭据只落在 `.env`（`git check-ignore` 命中）；`.env.example` 仅空值。`MAIL_DEV_LOG_CODE` 配好真实凭据后置 `false`；未配置时才允许 `true` 把验证码打到后端日志，prod 强制 `false`（缺凭据直接失败）。注册仍由服务端 DB 校验一次性验证码，前端无法本地伪造通过。

### 4.3 生成、审计与轮换

```bat
:: 生成全部强密钥并写入 .env（只改已存在键行）
python scripts\generate-secrets.py --write

:: 只读派生结论：键数、缺失键名、口令强度、是否仍等于 git 历史值
python scripts\audit-stats.py
```

纪律：

- **任何情况下不回显、不粘贴、不提交密钥值**。需要判断状态时只引用 `audit-stats.py` 的派生行（键名、长度、`OK/EMPTY/FAIL`）。
- 口令类（`APP_ADMIN_INITIAL_PASSWORD`、`GRAFANA_ADMIN_PASSWORD` 等）必须 8–32 位且同时含大小写字母、数字、特殊字符。`openssl rand -base64 32` 输出 44 字符，**会超出上限**，不要用于口令。
- 轮换单个口令时不要跑 `generate-secrets.py --write`（它会顺带换掉其他键）。图库口令的轮换必须与 `.env` 同批完成，且不能只改 `.env` 不改库内账户。
- 容器形态改 `.env` 不等于改库内口令：`init-app-db-user.sh` 只在**空卷首启**执行。存量卷换口令须手工 `ALTER USER`，或删卷重建。

### 4.4 形状门与 ASCII 约束

- `DEEPSEEK_API_KEY` 值必须**纯 ASCII**。把中文说明粘在同一行键值后面会让 `Authorization` 头无法承载，请求在发出前就失败（DR-82）。说明另起注释行。
- 启动器的「已配置 AI Key」判据是 `sk-` 前缀**且**不等于占位串；不满足时只告警，不阻塞开发/验收。
- `/health` 的 `llmProvider` 只判「非空白」，**不判有效性**。它可以 UP 而真实调用全 401。唯一有效性量具：`python scripts/probe-llm-chain.py engine`，须打到 `gen_mode = LLM`。
- 选 `AI_PROVIDER=ollama` 时无 Key 形状约束：`OLLAMA_BASE_URL` 与 `OLLAMA_MODEL` 非空即视为已配置。**Java 侧 `/health` 不探测 `ollama serve` 是否在跑**；Python RAG `/api/v1/rag/health` 的 `llm` 块会探测（`available` + `detail`，但不改变服务 `status`）。有效性可用 `OLLAMA_LIVE_TEST=true` 跑 `OllamaProviderLiveTest`，或直接 `curl http://localhost:11434/api/tags`。

### 4.5 文件式密钥（configtree）规则

#### 4.5.1 文件名必须逐字等于「属性被读取的形式」

`configtree` 是**精确 map 查找**，不做 `大写蛇形 → 点分` 的松散绑定；而系统环境变量会做松散绑定。后果：同一个值，写成环境变量能填上，写成 `/run/secrets/<大写蛇形>` 却填不上——占位符有默认值则**静默回落默认值**，没有默认值则启动失败。

| 密钥 | 正确文件名 | 错误写法 | 依据 |
| --- | --- | --- | --- |
| `JWT_SECRET` | `JWT_SECRET` | — | yaml 用 `${JWT_SECRET}` 占位符 |
| 数据源口令 | `SPRING_DATASOURCE_PASSWORD` | — | yaml 用 `${SPRING_DATASOURCE_PASSWORD}` |
| Redis 口令 | **`spring.data.redis.password`**（或嵌套目录 `spring/data/redis/password`） | `SPRING_DATA_REDIS_PASSWORD` | yaml 无占位符，只靠属性绑定 |
| 种子 admin 口令 | `app.admin.initial-password` | `APP_ADMIN_INITIAL_PASSWORD` | `@Value("${app.admin.initial-password:}")` |
| Actuator 口令 | `app.actuator.basic.password` | `APP_ACTUATOR_BASIC_PASSWORD` | `@Value("${app.actuator.basic.password:}")` |
| `DEEPSEEK_API_KEY` | `DEEPSEEK_API_KEY` | — | yaml 用 `${DEEPSEEK_API_KEY:}` |

> 容器侧口令不在 configtree 范围：MySQL／Redis／Neo4j／Grafana 的口令由各自镜像 entrypoint 读取，须用各镜像的 `*_FILE` 机制或 secret 卷，**不能**以为「挂了 `/run/secrets` 就全量去明文」。

#### 4.5.2 三套接线方案

| 方案 | 适用 | 落地方式 | 状态 |
| --- | --- | --- | --- |
| Compose secrets | 单机 VM | 删 backend 明文键 → 声明 `secrets:`，Redis 用 `target: spring.data.redis.password` | ✅ 2026-10-07 真容器端到端闭环（DR-24 三向取证） |
| K8s Secret 卷 | 集群 | `volumeMounts` 挂 `/run/secrets`，`items[].path` 写精确文件名；不要同时设同名 env | 🖐 接线级，未实跑 |
| Vault Agent 旁车 | 有 Vault | `deploy/vault/agent.hcl` + 3 个 `.ctmpl`，渲染到共享 `/run/secrets`，默认 5 分钟重渲染 | 🖐 接线级，无 Vault 实例，未端到端 |

Compose 方案的关键步骤（不可用「覆盖文件置 null」替代）：

1. 准备 `deploy/secrets/*.txt`，内容末尾**不要换行**（Prometheus 读 `password_file` 会把换行算进口令）。
2. 在 backend 服务中**删除**同名明文键（`SPRING_DATASOURCE_PASSWORD`、`SPRING_DATA_REDIS_PASSWORD`、`JWT_SECRET`）。`:?` 必填插值会被 Compose 提前求值，覆盖文件的 `null` 顶不掉它，明文仍会进容器。
3. 追加 `secrets:` 声明；Redis 那条必须 `target: spring.data.redis.password`。
4. 只删 backend 的键，**不要删 `.env` 里的数据库口令**——mysql 容器初始化仍需要。

#### 4.5.3 验证命令（上线前逐条跑）

```bash
# ① 无密钥目录也能启动（本机预期行为）
java -jar backend/target/backend-0.0.1-SNAPSHOT.jar --server.port=8080

# ② 文件式密钥可被读取（临时目录替代 /run/secrets，目录必须以 / 结尾）
mkdir -p /tmp/ai-secrets
printf '%s' "$(openssl rand -base64 32)" > /tmp/ai-secrets/JWT_SECRET
printf '%s' '1234'                       > /tmp/ai-secrets/SPRING_DATASOURCE_PASSWORD
SPRING_CONFIG_IMPORT=optional:configtree:/tmp/ai-secrets/ \
  java -jar backend/target/backend-0.0.1-SNAPSHOT.jar --server.port=8080

# ③ 反证：env 确实覆盖文件（必须删除明文键的理由）
JWT_SECRET=wrong-value-should-win \
SPRING_CONFIG_IMPORT=optional:configtree:/tmp/ai-secrets/ \
  java -jar backend/target/backend-0.0.1-SNAPSHOT.jar

# ④ 键名精确性反证：大写蛇形名对大分属性不可见
printf '%s' 'file-value' > /tmp/ai-secrets/APP_ADMIN_INITIAL_PASSWORD
SPRING_CONFIG_IMPORT=optional:configtree:/tmp/ai-secrets/ \
  java -jar backend/target/backend-0.0.1-SNAPSHOT.jar
# 期望：admin 口令替换不生效；改名为 app.admin.initial-password 后才生效
```

| # | 局限 | 影响 | 处置 |
| --- | --- | --- | --- |
| 1 | MySQL／Redis／Neo4j／Grafana 容器自身口令仍来自 `.env` 明文 | 主机 `.env` 仍存留多枚明文口令 | 用各镜像 `*_FILE`／secret 卷机制 |

## 9. 备份与恢复

### 9.1 自动备份（`--profile ops`）

- `mysql-backup` 以守护循环执行 `mysqldump --single-transaction --routines --triggers` + gzip + 完整性校验，产物落卷 `mysql-backups` 的容器内 `/backups`。
- 周期 `BACKUP_INTERVAL_SECONDS`（默认 86400），保留 `BACKUP_RETENTION_DAYS`（默认 14）。
- 单轮失败会打日志并退避 300 秒重试；历史上「从未成功备份过一次」的缺陷（入口在只读挂载上 `chmod`）已修并取证（DR-29），换新环境仍要现场核对卷内确有 `.sql.gz`。

### 9.2 手工备份与恢复

```bash
# 备份（容器形态）
docker exec aicourse-mysql sh -c \
  'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers ai_course_platform' \
  | gzip > ai_course_platform-$(date +%F).sql.gz

# 恢复（唯一现存口径；先停后端写入）
gunzip -c ai_course_platform-2026-10-27.sql.gz \
  | docker exec -i aicourse-mysql sh -c \
    'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" ai_course_platform'

# 上传卷导出
docker run --rm -v aicourse_uploads-data:/v -v "$PWD":/backup alpine:3 \
  tar czf /backup/uploads-data-$(date +%F).tar.gz -C /v .
```

> 卷名以 `docker volume ls` 实际输出为准（Compose 项目名作前缀）。旧文档里的 `aicourse_backend_uploads`／`backend_uploads` 不存在，照抄会导出一份空备份。

### 9.3 恢复演练（转 A 前必须做一次）

1. 在隔离库恢复最近一份 `.sql.gz`；
2. 校验 `flyway_schema_history` 版本集合、`users`／`courses` 行数与源库一致；
3. 导出 `uploads-data` 并在恢复环境挂载，抽检一份文件可下载且 sha256 一致；
4. 记录耗时与失败点；恢复脚本仍属缺件（§6.3 第 12 条）。

### 9.4 已知缺口

- **异地同步不成立**：`BACKUP_REMOTE_SYNC` 依赖容器内 `rclone`，`mysql:8.4.11` 镜像不带该二进制；脚本探测不到即 WARN 跳过。候选：带 rclone 的 sidecar／云厂商整机快照／宿主机 cron 导出到对象存储。
- **无恢复工具**：`git ls-files | grep -i restore` 为空。
- **备份与数据库同机**：主机丢＝数据丢，直到异地同步落地。

## 10. 升级与回滚

### 10.1 本机升级

```bat
:: 后端
cd backend && mvnw.cmd -B -o clean package -DskipTests && cd ..
:: 前端
cd frontend && npm ci && npm run build && cd ..
```

- 改后端代码后必须重新打包再起 e2e／压力脚本；`target/backend-0.0.1-SNAPSHOT.jar` 不是最新时，脚本测的是旧行为。
- 前端依赖变动后跑 `npm ci`（不要 `npm install` 顺手升级）；Playwright 与 xlsx 是精确锁版本。

### 10.2 容器升级

```bash
docker compose build backend frontend
docker compose --profile full up -d
```

- 发布工作流只发 GHCR 镜像，不部署（§6.3 第 13 条）；VM 上要么原地 build，要么 override `image` 后 pull。

### 10.3 Flyway 只前向

- 已执行迁移的校验和冻结，**禁止编辑历史迁移**；新语义一律加新版本号（V8–V11 即先例）。
- prod 的干净库版本集合是 `{1,2,3,4,8,9,10,11}`；V5–V7 是演示种子，整目录不加载。
- `spring.flyway.ignore-migration-patterns` 默认含 `*:future`：**灌过 V5/V6 的旧库转生产不会被拦截**。生产库必须是全新库，或先按号段清理演示数据并删除历史中的 5/6/7 行。

### 10.4 回滚

- 代码：`docker compose down`（**严禁 `-v`**，那会删掉 `aicourse_mysql-data`）→ 切回上一 tag 镜像 → `up -d`。
- 数据库：**回滚镜像 ≠ 回滚库**。迁移已前滚过时，旧 jar 必须能兼容新 schema（加列可以；删列／改名会让旧 jar 直接报错）。需要回数据时走 §9.2 的恢复件。
- 本机回滚：停后端 → 切回上一提交 → 重新打包 → 起后端；前端 `npm ci` 后重启 Vite。

## 11. 故障排查

| 症状 | 先查 | 处置 |
| --- | --- | --- |
| 8080 起不来 | 端口是否被占；MySQL／Redis 是否在听 | 停旧后端；`net start MySQL84`／`net start Redis`。**不要起容器** |
| 后端起来但前端 403 | 前端是否落在 5176+ | 只允许 5173／5174／5175；关掉占用者 |
| `/probe` 200 但 `/health` 503 | `DEEPSEEK_API_KEY` 是否有效 | 这是预期：综合态含 `llmProvider`。用 `probe-llm-chain.py` 判凭据 |
| AI 回答总是抽取式 | `gen_mode`；引擎 8001／8002 是否在听 | 先起引擎再**重启后端**；查 `HF_HUB_OFFLINE` |
| KG 模式是 LOCAL | 7687 是否在听；`KG_ENABLED` | 起 Neo4j；后端重启后才会切 `ENGINE`；未持久化时重启丢图 |
| Redis `NOAUTH` | 本机 Redis 是否设密码；`.env` 的 `REDIS_PASSWORD` | 免密 Redis 不要传 `SPRING_DATA_REDIS_PASSWORD`；启动器已自动探测，手工起时注意 |
| 上传／下载 500 | `uploads-data` 属主 | 容器形态 `chown -R 10001:10001`；本机查目录权限与磁盘 |
| Prometheus 抓取 401 | `APP_ACTUATOR_BASIC_PASSWORD` 与 `password_file` | 两处一致；文件无尾换行；Linux 下 644 |
| Grafana 面板「看着都好」但指标缺失 | 是否只看了其他 job | 401 的 job 会静默缺数；先看 Prometheus Targets |
| 告警发不出去 | `alertmanager.yml` 的 webhook | 改文件，不改 `.env` |
| WebSocket 无通知 | 反代是否转发 Upgrade；`Origin` 是否在白名单 | 补 `Upgrade`／`Connection` 两行；填 `CORS_ALLOWED_ORIGINS`；同域也填 |
| 容器里改了 `.env` 不生效 | 键是否被 compose 注入 | 容器只读注入的 env；未注入的键（如 `RATELIMIT_*`）改了也无效 |
| Flyway 校验失败 | 是否编辑过历史迁移 | 不得改历史校验和；恢复原文件或加新版本 |
| 演示账号登录失败 | 是否被加固器停用 | 查启动日志的 `[seed] 演示账号加固完成…`；用管理员改密或显式开启演示开关（仅本机） |
| 慢查询／N+1 | 接口 SQL 与索引 | 见 `docs/后端开发规范.md` §7／§17；先用日志定位再改 |
| 端口认错应用 | 5173 是否属于别的项目 | 看页面标题；启动器会按 `<title>` 认主 |
