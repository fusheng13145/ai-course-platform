# 第一部分 项目总览与背景

## 1. 项目定位与目标

**定位**：融合知识图谱与大语言模型（RAG）的智能在线教育平台，以《计算机网络》等专业课程为试点，面向**学生 / 教师 / 管理员**三端，提供个性化学习、教学支持与全面管理能力。

**核心能力域**：多角色 RBAC、课程/章节/选课管理、题库与在线考试（防作弊）、作业批改与查重、知识图谱可视化与学习路径规划、AI 智能问答/出题/批改/学情建议、数据分析与学情报告、WebSocket 实时通知。

**关键考核指标（申报口径）**：降低 AI 幻觉、可量化评测、工程规范可验证、安全合规。

### 1.1 时代背景与四大现实痛点
- 个性化学习资源供给不足；
- 教师重复性批改与答疑负担重；
- 知识点孤立、缺乏关联与路径引导；
- AI 回答不可信、无溯源、易编造。

### 1.2 项目意义与核心内容
以"知识图谱 + LLM"双引擎驱动：知识图谱建模学科知识点关联，LLM 提供自然语言交互与生成能力，二者经 RAG 检索增强形成可溯源、低幻觉的 AI 助教。

### 1.3 外部研究支撑（精华）
- **同类系统对比**：`大创赛/类似项目/DeepSeek-RAG-Chatbot` 的 GraphRAG 实体抽取用正则 `\b[A-Z][a-z]+...`，**仅支持英文实体**，且为单机通用文档问答，与本项目的**中文知识图谱**（`knowledge_points` / `knowledge_point_relations`）在语言适配、领域建模、工程规模上不可类比，**不作为对标依据**。
- **论文支撑**：杜彩丽 IPA/IREM（细粒度知识点抽取）、中职计算机网络多源异构 KG 等，与 PRD 接口矩阵共同构成中文 KG 关系建模依据。

## 2. 参赛与申报要点
- 大赛：中国国际大学生创新大赛 2026。
- 申报/答辩要点：差异化"知识图谱 + RAG"能力、可量化幻觉率评测（`evaluation/`）、工程规范性（质量门禁/契约测试）、安全合规（五层纵深）。

# 第二部分 需求与技术基线

## 3. 用户角色与进阶 RBAC
- **三角色**：管理员（ADMIN）、教师（TEACHER）、学生（STUDENT）。
- **进阶 RBAC + 数据权限**：全局 `SecurityConfig` 提供"登录 + URL 角色"基线（`/admin/**`→ADMIN、资源写操作→TEACHER/ADMIN、`anyRequest().authenticated()`），方法级 `@PreAuthorize` 做细粒度约束；部分控制器在 **Service 层做 userId 归属校验**（对象级/水平授权，见第九部分安全评估）。

## 4. 三端功能需求（索引）
完整需求—代码追踪矩阵见 **第四部分 §14**。要点：
- **学生端**：选课、学习、AI 助手（多轮/流式/溯源）、考试（防切屏）、错题本、笔记、学情看板、知识图谱可视化。
- **教师端**：建课/资源/任务点、题库/组卷/批改、监考、学情驾驶舱、AI 出题/润色。
- **管理员端**：用户/角色/权限、系统配置、操作/登录审计、数据看板、Excel 批量导入、备份。

## 5. AI 能力体系（F-AI）
- 多轮会话持久化、结构化输出、异步化、AI 监控与配额；
- 智能问答（多轮/流式/溯源）、AI 出题/总结/润色、学情建议；
- 供应商路由（DeepSeek / OpenAI / Qwen 热切换，`llm/` 包 6 类）；
- RAG 检索（BM25 + GraphRAG，引擎侧由队友 8002 交付）；
- 知识图谱：抽取（extract）、可视化、路径规划（本地 BFS 兜底）。

## 6. 核心业务流程
注册/登录 → 选课 → 学习（章节/资源/笔记）→ 作业/考试（防作弊/查重）→ AI 答疑/出题 → 学情分析 → 教师批改 → 数据看板。AI 问答链路：前端 → `AIServiceImpl` → （RAG 启用则 `RagContract` → Python 8002，失败回退纯 LLM；路径规划经 `LocalKnowledgeGraphProvider` 本地 BFS 兜底）。

## 7. 非功能需求与产品演进
- 非功能：安全性（BCrypt/JWT/RBAC/限流/输出转义）、可观测性（Prometheus/Grafana/Loki）、可用性（优雅降级）、可维护性（架构守护/契约测试）。
- 演进路线：消费侧完善 → 接入 Python 引擎（KG/RAG/LoRA）→ 量化评测闭环 → 生产加固。

## 11. 核心设计决策
- **安全五层纵深**：JWT 无状态 + RBAC + CSRF 双提交 Cookie + 安全响应头（HSTS/CSP/frame-deny/Referrer-Policy）+ 监控端点独立 Basic 鉴权（fail-closed）。详见第九部分。
- **AI 集成架构**：`com.aicourse.integration` 标准化对接层，`ContractPaths` 常量（调用约定唯一事实来源，全仓引用 93 处）+ `KnowledgeGraphContract` / `RagContract` 强类型 record + 本地/HTTP 双实现；引擎缺失时本地 BFS 兜底或返回 `503` 降级。
- **Redis 四大职责**：缓存聚合、IP 级限流、AI 用量配额、验证码；启动 `RedisStartupValidator` 强校验。
- **自愈数据库**：Flyway 接管迁移（`db/migration/V1__init_schema.sql`，48 表 + 种子）；已运行实例自动 baseline 不重复执行。
- **前端设计令牌**：CSS 变量双主题（`:root` / `[data-theme='dark']`），禁止硬编码色值；加载/错误/空三态齐全。

## 12. 标准化集成层（KG/RAG 契约概览）

## 18. 编码规范（合并 CONTRIBUTING 与架构约定）
- **后端**：类 `UpperCamelCase`、方法/变量 `lowerCamelCase`、常量 `UPPER_SNAKE`；类级 Javadoc 说明职责；写操作 `@Transactional(rollbackFor = Exception.class)`；Controller 方法声明角色约束（`@PreAuthorize` 或 Security 配置），禁止绕过 RBAC；集成契约必须引用 `ContractPaths`，禁止硬编码路径/字段；禁止 `System.out`（统一 `@Slf4j`，业务 `warn`/系统 `error`）。

全部前缀 `/api/v1/fine-tune`。
- `GET /health` → `200 {"status":"ok"}`（非 200 不可达）。
- `POST /start`：`{course_id, base_model:"qwen-7b", config:{epochs, learning_rate:5e-5, lora_rank:8, lora_alpha:16, lora_dropout:0.05, max_seq_length:2048, batch_size:4}}` → `{"task_id":"ft_...", "status":"pending"}`。

## 34. 状态码、重试与降级
| 概念 | 取值 | 含义 |
|------|------|------|
| `code` | 503 | 引擎未接入/不可用（降级占位） |
| `mode` | ENGINE / LOCAL / UNAVAILABLE | Python 计算 / 本地兜底(BFS) / 无兜底降级 |
| `error` | `MSG_KG_UNAVAILABLE` / `MSG_RAG_UNAVAILABLE` | 降级说明 |

- 通用：`Content-Type: application/json`；健康检查 200 即可；错误 `{error, code:503}`。
- 重试：非超时异常按 `max-retries` 递增重试；**读超时直接降级不重试**（避免雪崩）。`HttpRagProviderBoostTest.ask_socketTimeout_noRetry` 锁定语义。
- 降级实际行为：KG 路径规划→本地 BFS 始终返回真实路径；KG ingest/subgraph 不可达→503；RAG 未启用→503（`DisabledRagProvider`）；RAG 启用不可达→503 且 `AIServiceImpl.ragAsk` 自动回退纯 LLM；微调不可用→`LLMFineTuneServiceImpl` 返回 503。
- Java 端强类型 record：`KnowledgeGraphContract`（PathPlanRequest/PathEdge/PathPlanResult/IngestResult/SubGraphResult/Mode）、`RagContract`（RagAskRequest/RagRetrieveRequest/RagQueryResult/RagDocument/RagDocumentList/IndexResult/RagRetrievalResult/RagSource，响应 `@JsonInclude(NON_NULL)`）。
