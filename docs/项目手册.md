## 1. 项目概览

### 1.1 一句话

面向高校课程教学的 **AI 课程平台**：以"课程—章节—任务/试卷—提交/作答—批阅—学情分析"为主干，叠加知识图谱、RAG 问答、AI 出题/批改/学习建议与 LoRA 微调能力，服务学生、教师、管理员三类角色。

### 1.2 交付语境

- 当前目标是 **大创赛交付与答辩**：优先保证"演示能跑、链路能讲、证据能查"，不以公网大规模运营为当前验收面。
- 示范课程固定为 **计算机网络（courseId=4007）**，演示数据由 Flyway 演示种子（V5–V7）提供，生产环境必须排除该号段。
- 主形态为 **桌面 Web 三端**（学生 / 教师 / 管理），窄屏仅保证侧栏抽屉化，不承诺移动端完整体验。
- 部署形态当前为 **本机原生进程**（MySQL / Redis / JDK / Maven / Vite / Python），Docker 编排自 2026-10-08 起有意搁置。

### 1.3 系统边界

| 层 | 组成 | 说明 |
| --- | --- | --- |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + Vue Router | 单页应用，`/api` 反向代理到后端 |
| 后端 | Spring Boot 3.5 + Java 21 + MyBatis-Plus | 业务、鉴权、事务、审计、调度 |
| 数据 | MySQL 8.4 + Redis 7.4 | 业务数据与缓存/限流/会话 |
| AI 引擎 | Python FastAPI：KG 8001 / RAG 8002 / LoRA 8003 | 独立进程，经 `integration/` 契约层调用 |
| 图谱库 | Neo4j 5.26 | KG 持久化；不可达时回落内存图 |
| 可观测 | Actuator + Prometheus/Grafana/Loki/Alertmanager（monitor profile，搁置） | 当前仅本机按需启用 |

### 1.4 当前能力一句话版

- **教学主链**：建课 → 章节 → 任务/试卷 → 发布 → 学生提交 → 批阅/退回 → 成绩与学情，已闭环（2026-10-26 起 QA 真实冒烟 15+ 步）。
- **AI 主链**：问答 / 出题 / 批改 / 学习建议四链路在真实 Key 下 4/4 真实生成（2026-10-18）；失败统一 503 降级，不伪造成功。
- **知识图谱**：课程级知识点与关系、力导向图、最短路径、AI 抽取；KG 不可达时本地 BFS 兜底。
- **视觉与无障碍**：三端统一设计令牌、24 张视觉基线、Phase 0–4 已完成；焦点管理、键盘可达、reduced-motion 降级在位。
- **工程门禁**：后端 3022 例（单元口径）、前端 1988 例、流程 e2e 54 例、视觉 84 例、CI 12 作业；类型棘轮已清零并保留全绿门（读数与口径见 `docs/测试文档.md` §2）。

## 2. 角色与权限

### 2.1 三类角色

| 角色 | 代码 | 核心诉求 | 默认落点 |
| --- | --- | --- | --- |
| 学生 | `STUDENT` | 学课程、做任务/考试、看成绩与反馈、问 AI | `/student` |
| 教师 | `TEACHER` | 建课与内容、组卷与批阅、看学情、管知识库 | `/teacher` |
| 管理员 | `ADMIN` | 用户/班级/权限、课程治理、内容审核、系统日志与 AI 用量 | `/admin` |

角色不是硬编码在前端常量里：登录后由 `/auth/permissions` 下发角色与按钮权限，路由守卫按权限判定；后端以 JWT 中的权限快照 + 每次请求从 DB 读取的现行角色共同约束（DR-59），改角色即时生效（DR-60 的缓存逐出）。

### 2.2 权限模型

- **方法级**：Controller 方法上的 `@PreAuthorize` 是主闸门；类级注解只作兜底，不能替代方法级声明（DR-16）。
- **对象级**：课程、资源、提交、成绩等资源必须校验"当前用户是否拥有该对象"，不能只校验"已登录"。资源列表端点曾因缺对象级 ACL 越权（DR-13），现返回真实 403。
- **前端**：权限只决定"看不看得到入口"，不承担安全职责；任何前端隐藏都必须有后端对应校验。
- **管理端导航**：7 个治理分区、23 条路径、13 个图标（DR-48），含数据看板、课程与教学、用户与班级、权限、内容审核、AI 用量、系统运维。

### 2.3 账号与演示数据

- 演示账号共 **170 个**（V1 的 8 个 + V5/V6 号段），统一由加固器收敛为 `DEMO_ACCOUNTS_ENABLED` 控制；生产必须 `false`，且必须提供 `APP_ADMIN_INITIAL_PASSWORD`，否则启动 fail-fast（DR-9）。
- 演示种子与结构迁移分目录：`db/migration`（V1–V4、V8–V11）为结构，`db/seed-demo`（V5–V7）为演示数据；生产只跑结构目录（DR-18/DR-62）。
- 生产库核对判据是**版本集合排除 5/6/7**、`users=8`、无 course 4007，而不是"最高版本=4"（DR-62）。

## 3. 功能清单（按域）

### 3.1 认证与账号

登录、注册、找回密码、刷新令牌、退出、会话保活、密码策略（8–32 位复杂度）、登录失败锁定（5 次 / 15 分钟，按 IP+账号）、登录限流（默认 10 次 / 60 秒 / IP）、强制下线、在线会话查看。

### 3.2 课程与教学

课程创建/编辑/停启用、课程目录与封面、章节树、选课与退课、课程成员与班级、课程通知、课程资源（上传、版本、回滚、下载）、课程看板。

### 3.3 任务、试卷与考试

- **任务**：作业发布、截止时间、延期、提交（文本 + 多附件）、退回重做。
- **试卷**：手动选题、自动组卷、总分校验、发布/草稿、试卷统计、题目回显。
- **考试**：考试会话、倒计时、自动保存、超时交卷重试、强制交卷、监考与风险事件、客观题自动判分、主观题 AI 预批 + 教师确认。
- **批阅**：待批阅列表 → 逐份批阅 → 打分/评语/退回；AI 预批建议分只回填，不直接改分（2026-10-26 口径）。
- **学生端**：任务与试卷提交入口、成绩与评语可见、错题本（快照填充已修）。

### 3.4 成绩与学情

成绩方案、成绩项录入、总评计算、课程成绩分布、班级/课程/学生多维分析、学习路径、薄弱点分析、AI 学习建议、学习时长与进度。

### 3.5 知识图谱与知识库

知识点 CRUD、关系维护、课程级图谱、力导向可视化、前置/后继路径、AI 抽取知识点、知识库文档上传与 RAG 检索、图谱同步。KG 引擎不可达时后端回落本地 BFS，并在响应中标注降级。

### 3.6 AI 能力

| 能力 | 入口 | 真实链路 | 降级 |
| --- | --- | --- | --- |
| 智能问答 | 学生/教师 AI 助手 | RAG 8002 检索 + LLM 生成，SSE 流式 | 503 / 纯 LLM / 抽取式 |
| AI 出题 | 题库、试卷 | LLM 生成 JSON → 题目落库 | 503 |
| AI 批改 | 提交批阅 | LLM 建议分 + 评语 → 教师采纳 | 503 |
| 学习建议 / 学情 | 学生分析页 | LLM 生成文本 | 503 |
| 知识点抽取 | 知识图谱 | LLM 抽取 → KG 写入 | 503 |
| LoRA 微调 | 管理端/引擎 | 8003 真实 PEFT 训练、权重导出、adapter 推理 | 503 |

统一语义（DR-74-B）：返回非空字符串＝真实生成；`null`＝Key 未配置；调用失败＝`LLMUnavailableException` → HTTP 503，分类为 `NOT_CONFIGURED` / `CREDENTIAL_REJECTED` / `QUOTA_OR_THROTTLED` / `UPSTREAM_UNREACHABLE` / `EMPTY_RESPONSE`；4xx 不重试；已删除"调用失败仍返回 200 + 兜底文案"的旧行为。

### 3.7 互动与协作

讨论区（话题/回复/关闭）、签到、投票、课堂互动记录、通知与提醒、站内信/铃铛未读、全局搜索（`Ctrl/⌘+K`、`/`）。

### 3.8 管理治理

用户与角色、班级管理、权限管理、学期注册与归档、课程审核、内容审核（隐藏/恢复/删除/封禁作者）、AI 用量按课程聚合、登录日志、操作日志、在线会话、系统配置、数据库维护任务。

### 3.9 新人引导

三端各 5 步的激活引导：学生末步直接打开"加入新课程"对话框，教师落 `/teacher/ai`，管理员落 `/admin/logs`。状态键 `ai-course:onboarding:v2:<userId>`，出口三态 `done` / `skipped` / `paused@n`；Esc 与点洞外＝暂停并记步，可从第 n 步续看；v1 键只读迁移不删。详见 DR-95 与 [前端开发规范](./前端开发规范.md) 的无障碍章节。

## 6. 协作与贡献规范

### 6.1 分支与推送

- 长期分支：本地 `main`；上游 `origin/leyon` 为日常工作分支，`origin/main` 为里程碑分支。
- 日常推送：`git push origin main:leyon`；里程碑达成并经授权后才推 `origin/main`。
- **禁止** `git push --all`。本地曾有 `leyon@694f659` 分支包含 108 个机器产物与 3 份 `.auth` 会话文件，任何全量推送都会泄露凭据（K-12）。
- 推送授权按批次给，一次授权不覆盖下一次；不建 `review-*` 临时分支（2026-10-23 项目主口径）。
- 严禁 `git rm` / `git mv`：仓库位于中文路径（`大创赛`），历史上曾因 `mv`/`restore` 造成整树静默丢失。文件迁移一律"先写新文件、再删旧文件、最后 `git add`"。
- 不重写历史。凭据泄露的处理是轮换密钥（DR-83），不是 `filter-branch`。

### 6.2 提交与评审

- 一事项一提交，便于单提交 revert；格式化与逻辑修改分开提交。
- 提交信息用中文，类型前缀沿用 `fix:` / `docs:` / `feat:` / `test:` / `chore:`。
- 每个批次结束必须更新对应文档与台账；结构性数字变化回写 §8，不散落在正文。
- PR 模板要求写清：改了什么、为什么、验证命令与读数、风险与回退。单人主导期允许直接提交，但验证证据不可省。
- **单一写者文件**：`anchors.spec.ts`、`visual-helpers.ts`、`ci.yml`、`typecheck-baseline.json`、`eslint.config.js`。同一时间只允许一个批次修改，避免冲突与归因污染。

### 6.3 密钥与敏感信息

- 本机密钥只进 `.env`（gitignore），从不回显、从不入库、从不贴进提交信息。
- 密钥一旦粘进对话，就已发送给模型服务并落本机转录；止血只能到供应商控制台轮换（DR-90）。
- `.env` 键位卫生的判据是"有没有非注释代码消费者"，不是"与 `.env.example` 键集合相等"；照抄补齐会覆盖 CORS 白名单并剥夺引擎自动探测（DR-64）。
- Key 必须为 ASCII；含中文备注会触发 `UnicodeEncodeError`，且旧代码会静默吞掉（DR-82）。
- 生产凭据必须与 git 历史值不同；`scripts/audit-stats.py` 的"仍等于历史值的凭据类键"必须为 0（DR-83）。

### 6.4 证据纪律

1. **先量后治**：性能、包体、类型债、覆盖率都必须先有基线读数。
2. **结论必须可重生成**：给出命令、时点、读数；像素证据与判据证据分层。
3. **负读数要配正读数**：证明"没有"之前，先证明搜索面正确。
4. **本地绿 ≠ CI 绿**：CI 不可观测的部分必须显式标注"未取证"。
5. **不得用整体口号代替逐条读数**："全绿""已清零"必须能指到命令与输出。
6. **数字归属分类**：本批次真实变化 / 文档漂移校正 / 跨轮次累计变化，三者不得混写。
7. **可重放**：视觉、e2e、审计脚本都要能在新机器上按文档重跑；不可重放的只能作辅助证据。

### 6.5 文档维护

- 九份文档各有单一职责，同一事实只在一处展开，其余用链接与条目号引用。
- 仓库根的 `agent.md` 是**开发代理的操作约束**（职责边界、验证链、密钥纪律、不可宣称清单），与本文同为"不承载判据"层：任何架构／规范／测试／部署的判据本体仍归九份文档，冲突以九份文档为准。
- 新增/删除文档必须同步本手册开头的九份清单与 §9 文档导航；不再保留独立索引文件。

### 6.6 Windows 本机约定

- `.bat` 必须纯 ASCII + CRLF；中文注释会让 `cmd` 报"不是内部或外部命令"（DR-37）。
- 反斜杠路径在脚本中统一用正斜杠或双反斜杠；含空格路径必须加引号。

| DR-96 | 三份启动器（`start-all.bat`／`start-backend.bat`／`start-frontend.bat`）合并为**一份 `start.bat` + 子命令**（`all`／`backend`／`frontend`／`status`），判定逻辑只留 `scripts/start-all.py` 一处。原 batch 里那套"注入口径 + 择口 + 探活"是 Python 的**第二份复刻**，两套并行必然分叉（这正是本手册反复登记的同型问题）。三条行为变化：① 8080 被占时不再询问"要不要强起第二个实例"，统一接管不重启（DR-36 的结论）；② 无 Python 的纯 batch 兜底取消（Python 3.11 是既定前置）；③ `--no-color` 此前只写在文档、`main()` 从不读它，现由 `color_enabled()` 真正消费。守卫用例 85 → **97**（旧 4 条 batch 形态守卫并入 `test_start_all.py` 并扩为带阴性对照的集合）。**已实跑**：`start.bat status`、非法子命令（退出码 2 经薄壳正确传播）、`start.bat status --no-color`、`python -m pytest scripts/tests`、前端 lint/typecheck。**未实跑**：`start.bat backend`／`start.bat frontend` 的真实起栈（引擎、后端、前端的进程与端口行为仍只有 `all` 模式的 DR-53 那轮真跑取证背书）。 |
