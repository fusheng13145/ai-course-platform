# 第一部分 项目总览与背景

## 1. 项目定位与目标

### 1.1 项目概述

- **项目名称**：基于知识图谱 + LLM 的 AI 助教系统设计
- **项目类型**：大学生创新创业训练计划项目 · 校级一般项目（创新训练项目）
- **所属学科**：工学 / 计算机类（一级：计算机科学与技术；二级：计算机应用技术）
- **项目来源**：B（教师科研项目选题）——《生成式人工智能赋能网络类课程教学改革研究》（江苏科技大学教育教学改革课题）
- **经费与周期**：申请金额 2000 元（学校拨款）；起止 2026 年 4 月至 2027 年 4 月（1 年）
- **团队**：项目负责人李昂、虞子晗；技术支持赵元将、张佳言、曾丽娟；指导教师滕玮
- **开源基座**：基于 `ai-smart-course-platform`（MIT 协议）二次开发，技术匹配度 90%
- **总体目标**：设计并实现基于知识图谱与大语言模型的 AI 助教系统，为专业课程提供智能化教学辅助服务，提升教学互动性与个性化水平，以《计算机网络》为样例课程

### 1.2 时代背景与四大现实痛点

教育数字化已上升为国家战略；LLM 生成式 AI 带来创新可能；知识图谱为知识结构化表示与逻辑推理提供底层支撑。本项目针对四大现实痛点：

1. **知识碎片化**：知识点繁杂，传统教材难以直观展示内在逻辑联系
2. **辅导资源不足**：师生比失衡，难以提供及时精准的个性化答疑
3. **大模型"幻觉"**：通用模型缺乏领域深度，存在知识错误，难以满足教学严谨性
4. **管理效率低下**：教师被成绩统计、案例搜索等事务性工作消耗大量精力

### 1.3 项目意义与核心内容

**意义**：提升教学质量（知识结构化可视化）、实现个性化学习（行为数据 + 图谱）、增强教学严谨性（RAG 限定回答范围、答案可溯源）、解放教师生产力（自动化成绩管理、智能案例推荐）。

**四大核心内容**：

1. 构建**细粒度课程知识图谱**（从多源异构数据抽取细粒度知识点及复杂关系）
2. 优化**基于 GraphRAG 的问答引擎**（融合知识图谱的检索增强生成）
3. 开发 **AI 助教系统原型**（智能问答、知识可视化、案例推荐、个性化路径规划、成绩管理）
4. **模型微调与系统效果评估**（LoRA 高效微调 + 多维度指标评估）

### 1.4 关键考核指标

| 指标 | 目标值 |
|------|--------|
| 知识图谱构建准确率 | ≥ 85% |
| 智能问答响应准确率 | ≥ 90% |
| 最终用户满意度 | ≥ 85% |

### 1.5 预期成果

1. 功能完善的 AI 助教 Web 应用原型
2. 高质量数据集：5000+ 实体图谱 / 10000+ 问答对
3. 完整技术文档（需求说明书、技术方案等全套资料）
4. 学术成果：软件著作权 + 学术论文

### 3.1 同类系统对比结论（DeepSeek RAG Chatbot 3.0）

| 对比维度 | DeepSeek RAG Chatbot 3.0 | 本项目（AI 助教系统） |

| 图谱存储 | 内存 NetworkX（会话级） | 关系型表（knowledge_points / knowledge_point_relations），规划 Neo4j |
| RAG 实现 | BM25 + FAISS + HyDE + Cross-Encoder + GraphRAG（Python/LangChain） | Java 自包含 Okapi BM25（中文 bigram）+ DeepSeek API；规划 FAISS/HyDE/Cross-Encoder |
| 用户体系 | 单用户本地 | **三端（学生/教师/管理员）+ RBAC + JWT** |
| 教学功能 | 仅有问答 | 问答 + 知识可视化 + 作业考试 + 成绩管理 + 学习路径 + 社区互动 + 查重监考 |

| 优势 | 全本地、免 API 费用、开箱即用 | 教学场景完整闭环、细粒度图谱、答案可溯源、可扩展 |

> **方法学边界**：该参考项目 GraphRAG 实体抽取采用正则 `\b[A-Z][a-z]+...`，仅支持英文实体，且为单机通用文档问答工具；与本项目中文知识图谱（`knowledge_points` / `knowledge_point_relations`）在语言适配、领域建模、工程规模上均不可类比，不作为本项目中文 KG 方案的对标或引用依据。

**四篇论文支撑的三大核心方法**：

1. **IPA（两阶段间接提示法）**：自主学习模块（组合式提示模拟学习者阅读）+ 专家指导模块（Sentence-BERT 语义筛选）+ 反馈优化模块（词频提炼"主语-谓语"高频表达构造标准目标句）
2. **IREM（隐式关系抽取模型）**：上下文信息重构（LLM 生成"判断依据"，隐式关系转显式实体提及）+ 共现词汇提取（jieba）+ BERT 表征学习 + 五分类（包含/前驱/同一/兄弟/其他）
3. **LoRA 微调**：注入低秩矩阵仅训练约 0.1% 参数，降低硬件门槛、媲美全量微调；基座 deepseek-r1:7b / Llama3-8B-Chinese-Chat 等

**可借鉴实现范式**：HyDE → 混合检索 → GraphRAG 增强 → 重排完整链路（可作为 P1 规划落地方案）；BM25/FAISS 权重配比 0.4/0.6；RAG/重排/GraphRAG 全部做成可配置开关便于消融评估；对话记忆纳入最近 5 轮保持多轮连贯。

# 第二部分 需求与技术基线

本平台对标对象为**超星学习通**，以「AI 原生 + 体验代差」建立优势；每条需求标注两档进阶目标：**对标超星**（达到同等能力）/ **超越超星**（AI 深度嵌入、自适应、多模态、体验打磨）。

| North Star 指标 | 目标 |
|-----------------|------|
| 教师建课耗时 | 降低 ≥ 50% |
| 客观题批改自动化 | ≥ 95% |
| 学生疑问 AI 首解率 | ≥ 70% |
| 专业问答准确率 | ≥ 90% |
| 知识幻觉发生率 | ≤ 5% |

**差异化标签**："对标超星"（补齐通用教学管理能力）与"超越超星"（图谱 + GraphRAG + 个性化路径的 AI 原生能力）。

- **权限变更**：实时生效（Redis 缓存角色）。

## 6. 三端功能需求

**学生端**：智能问答（GraphRAG 课程答疑，答案可溯源）、知识图谱可视化（浏览知识点网络、自主选择学习路径）、个性化路径规划（learning-path/generate）、作业/考试/错题（错题本 + BFS 知识点路径规划）、社区互动（发帖/投票/签到/任务）、成绩与资源（查成绩/看视频/下载资源）。

**教师端**：课程与章节管理、知识点与关系维护、资源管理；作业/试卷/成绩管理（出题、组卷、阅卷、成绩策略）；AI 辅助（智能出题 generate-question、内容总结 generate-summary、学习建议）；查重与监考（作业查重 plagiarism、在线监考）。

**管理员端**：用户/角色/权限管理（RBAC）、系统配置、操作与登录日志；课程与班级全局管理、数据看板（ECharts 可视化）；AI 提供商切换（switchProvider）、AI 用量统计与导出。

|------|-------------|----------|

| 学情诊断与预警 | 掌握度诊断/薄弱点归因/预测式预警/干预建议 | F-AI-301~304 |
| 个性化学习路径 | 路径生成/自适应调节/分层练习/节奏预测 | F-AI-401~404 |
| AIGC 检测与查重 | 文本查重/AIGC 率/多模态查重/申诉流 | F-AI-501~504 |
| 智能体平台 | 低代码搭建校级/课程智能体，智能体市场/工具插件 | F-AI-601~603 |
| AI 基础设施 | 多供应商路由降级/统一 API 契约/审计日志/成本熔断/微调接入 | F-AI-701~705 |

**核心 AI 功能实现方案（6 项）**：① AI 智能出题（DeepSeek 生成 JSON 试题入库）；② 知识点关系抽取（置信度 ≥ 80% 自动入库）；③ 双视角学情分析（班级/个人 AI 报告 + ECharts）；④ 个性化学习路径（拓扑排序 + 学情数据）；⑤ 智能问答（图谱 + 向量检索 + 大模型生成）；⑥ 作业查重（向量化相似度）。

**实现机制一览**：

| 能力 | 实现机制 |
|------|----------|
| 问答生成 | AIServiceImpl 调用 LLMProvider（DeepSeek），支持 correct/polish/问答/出题/总结/建议等模式 |
| 检索召回 | RAGServiceImpl 以 Okapi BM25（中文 bigram，k1=1.5/b=0.75）对 knowledge_points 召回，融合图谱关系做 GraphRAG 增强 |
| 学习建议 | 基于学习统计与薄弱点 JSON，调用大模型生成建议（generateLearningAdviceJson） |
| 查重引擎 | PlagiarismCheckServiceImpl 的 executeCheck/getCheckResult，按 EXACT/PARAPHRASE/STRUCTURE 三级判定相似度（CJK bigram + Jaccard v2.0） |
| 路径规划 | KnowledgeController.path/plan 以 BFS 在知识点关系图上求起点到目标最优路径 |

## 8. 核心业务流程

1. **知识库构建流程**：上传课程资料 → 分块 → 向量化/特征化 → IPA+IREM 抽取知识点与关系 → 图谱存储
2. **智能问答流程**：提问 → 历史融合 → HyDE → 混合检索 → GraphRAG 增强 → 重排 → Prompt → 生成可溯源答案
3. **学习路径流程**：学习行为采集 → 薄弱点识别 → 路径规划（双算法/BFS）→ 推荐与跟踪

## 13. 核心设计决策

### 13.1 安全体系（五层纵深）

| 层 | 机制 | 说明 |
|----|------|------|
| 认证 | JWT（无状态）+ 会话失效 | jjwt 0.12.6；按 userId 失效全部活跃会话 |
| 授权 | RBAC + 对象级权限 | 管理员/教师/学生三角色；`RoleUtil` 统一判定 |
| 防护 | CSRF（可选开关）+ 输出转义 | 双提交 Cookie；前端 XSS 过滤（dompurify）；escapeHtml → markdown → sanitizeHtml 三段式 |
| 限流 | `RateLimitFilter`（IP 固定窗口） | 登录 60s/10 次、AI 60s/20 次；Redis 原子计数，瞬断降级本地内存 |
| 配额 | `AiQuotaInterceptor`（按用户） | 日请求数 / token 预算原子计数 |

另含：密码 BCrypt、验证码 5min TTL（5 次尝试上限）、操作日志审计、监控端点独立 Basic 鉴权链（与业务 JWT 隔离）。

### 13.2 AI 集成架构

```
业务层（AIServiceImpl 等） ──▶ LLMProvider 接口
                                 ├── DeepSeekProvider（默认）
                                 ├── OpenAiCompatibleProvider 基类
                                 ├── OpenAIProvider / QwenProvider
                                 └── ai.provider 配置热切换
```

- **供应商路由**：DeepSeek/OpenAI/Qwen 热切换，业务零改动
- **异步化**：所有 `/ai/**` 接口返回 `Callable`，由 `AsyncMvcConfig` 专用线程池执行（CallerRunsPolicy + 120s 超时），长耗时 LLM 调用不阻塞 Tomcat 线程
- **结构化输出**：`response_format=json_object` + JSON-Schema 系统指令；配合 `extractJsonObject` 健壮解析
- **流式对话**：SSE（Server-Sent Events）逐 token 推送
- **用量与成本**：AI 调用按 8 类分桶计数（chat/question/content/correct/rag/recommend/analyze/extract_graph），输出 Micrometer Counter 与 token 估算

### 13.3 Redis 四大职责（必选组件）

| 职责 | 载体 | 说明 |
|------|------|------|
| 业务缓存 | `RedisCacheManager` + `@Cacheable` | 课程/知识点/题库/用户/学情聚合/RAG 检索等 12 组缓存 |
| IP 限流 | `RateLimitFilter` | 原子计数，瞬断降级本地内存兜底 |
| AI 用量配额 | `AiQuotaService` | 日请求/token 预算原子计数 |
| 验证码 / 调度锁 | 缓存 + ShedLock | 找回密码 5min TTL；多实例定时任务互斥 |

启动强校验：`RedisStartupValidator` PING 重试 10 次（间隔 3s），失败即中止启动（fail-fast）。

### 13.4 自愈数据库

`SchemaMigration` 在应用启动时自动建表补列；数据库迁移由 Flyway 接管（`spring.flyway.enabled=true` + `baseline-on-migrate`），迁移脚本位于 `backend/src/main/resources/db/migration/`。

### 13.5 前端设计令牌

100+ CSS 变量（Element Plus `:root` / 暗色 `[data-theme="dark"]`），双主题零侵入切换；三端统一令牌色。

## 14. 标准化集成层（知识图谱 / RAG 接口预留）

### 14.1 职责边界

| 能力 | 引擎归属 | 本端（Java）职责 |
|------|----------|------------------|
| 知识图谱引擎（构建 / 多跳推理 / GraphRAG） | 团队另一成员（Python 8001） | 消费侧 CRUD + 契约接口 + 本地 BFS 兜底 + HTTP 代理 |
| RAG 检索引擎（BM25 / 向量 / embedding / 融合） | 团队另一成员（Python 8002） | 契约接口 + `503` 降级 + AI 问答回退纯 LLM |
| LoRA 微调（8003） | 团队另一成员（Python，默认关闭） | `LLMFineTuneServiceImpl` 真实调用 |

> **语义界定**：知识图谱能力在本仓库 Java 端完整可用——`KnowledgeController` 27 个端点（图谱可视化、关系维护、掌握度查询、AI 抽取等业务功能）直读 MySQL `knowledge_points` / `knowledge_point_relations`；图谱构建、多跳推理、GraphRAG 检索等引擎侧能力由 Python 8001（队友交付）承接，本端经 `com.aicourse.integration` 标准化契约对接并提供本地 BFS 兜底。

### 14.2 包结构与委派模型

```
com.aicourse.integration
├── ContractPaths                  # 配置键 / 端点路径 / JSON 字段名 / 状态码（唯一事实来源）
├── kg/
│   ├── KnowledgeGraphContract     # 契约接口：healthCheck / planLearningPath / ingest / getSubGraph
│   ├── LocalKnowledgeGraphProvider # 默认占位：本地 BFS 兜底，不依赖 Python
│   └── HttpKnowledgeGraphProvider # enabled=true 时调 Python 8001 /api/v1/graph/*
└── rag/
    ├── RagContract                # 契约接口：ask / addDocument / deleteDocument / listDocuments
    │                              #          / updateDocument / buildIndex / clearIndex / retrieve
    ├── DisabledRagProvider        # 默认占位：全部返回 503，不依赖 Python
    └── HttpRagProvider            # enabled=true 时调 Python 8002 /api/v1/rag/*
```

委派链：`KnowledgeGraphService`（业务接口）→ `KnowledgeGraphServiceImpl`（门面，按 `knowledge-graph.enabled` 委派）→ `LocalKnowledgeGraphProvider`（默认，本地 BFS 兜底）/ `HttpKnowledgeGraphProvider`（启用，调 Python 8001）。RAG 侧同构。

### 14.3 关键约定

- **切换零改动**：引擎接入后仅置 `knowledge-graph.enabled=true` / `rag.enabled=true`，业务代码不变
- **降级不中断**：KG 路径规划引擎不可达时由消费侧本地 BFS 兜底（直读 `knowledge_point_relations`），始终返回真实路径；RAG 不可用时 AI 问答自动回退纯 LLM
- **强类型契约**：接口用 record 定义请求/响应数据结构；响应 `@JsonInclude(NON_NULL)`
- **Sentinel 保护**：下游调用挂资源 `kg:http` / `rag:http`（QPS 流控 + 慢调用熔断）
- **超时不重试**：读超时直接降级，避免雪崩放大；非超时异常按 `max-retries` 递增间隔重试
- **Python 侧对齐**：Python 实现须严格按 `ContractPaths` 字段名对齐，新增字段须同步更新常量

## 25. 编码规范

### 25.1 后端

- **命名**：类 `UpperCamelCase`、方法/变量 `lowerCamelCase`、常量 `UPPER_SNAKE`、包名全小写
- **注释**：类级 Javadoc 说明职责与边界；契约类（`integration/`）注释必须说明调用约定与降级语义
- **日志**：`@Slf4j`；业务异常 `log.warn`，系统异常 `log.error`；禁止 `System.out`
- **事务**：写操作在 Service 实现类加 `@Transactional(rollbackFor = Exception.class)`；跨表写操作注意事务边界
- **鉴权**：Controller 方法必须声明角色约束（`@PreAuthorize` 或 Security 配置）；禁止绕过 RBAC 直连数据
- **集成契约**：涉及 Python 对接的 HTTP 调用，必须引用 `ContractPaths` 常量，禁止硬编码路径/字段名

### 25.2 前端

- 组合式 API（`<script setup>`）；组件命名 `PascalCase.vue`
- 样式优先使用设计令牌 CSS 变量（双主题自动适配），禁止内联渐变/硬编码色值（大屏看板场景除外）
- 所有请求经 `api/` 模块封装，禁止页面内散落 `axios` 调用
- 加载态 / 错误态 / 空态三态齐全；无 mock 业务数据

## 33. 常见故障处理

### 33.1 后端启动失败

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| `CommunicationsException: Communications link failure` | MySQL 未启动或密码错误 | 检查 MySQL 状态与 `.env` |
| `PatternParseException: Invalid mapping pattern` | springdoc 版本不兼容 | 检查 springdoc 版本 |
| `JWT signature does not match` | JWT_SECRET 不一致 | 确保所有实例相同 JWT_SECRET；`start-backend.bat` 行尾保持 CRLF |
| `RedisConnectionFailureException` | Redis 未启动 | 启动 Redis 或检查 `SPRING_DATA_REDIS_HOST` |

### 33.2 前端无法访问后端

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 跨域错误 (CORS) | 前端 origin 不在白名单 | 检查 `cors.allowed-origins` |
| 401 未授权 | Cookie 未携带或令牌过期 | 清除浏览器 Cookie 重新登录 |
| 403 CSRF 校验失败 | 未配置 `withXSRFToken` | 确认 `request.ts` 配置 |

### 33.3 AI 功能不可用

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| AI 问答返回"知识库原文" | `DEEPSEEK_API_KEY` 未配置 | 在 `.env` 中设置有效 Key |
| AI 调用超时 | 网络问题或 API 服务异常 | 调大 `AI_READ_TIMEOUT`，检查 `api.deepseek.com` 可达性 |
| `AI quota exceeded` | 用户当日调用次数/Token 超额 | 调大 `AI_QUOTA_DAILY_REQUESTS` / `AI_QUOTA_DAILY_TOKENS` |

# 第八部分 Python 微服务集成契约

> 本部分是 Java 后端（消费侧）与 Python 微服务（引擎侧）之间「知识图谱 / RAG / LoRA」对接契约的单一事实来源。所有 HTTP 路径、JSON 字段名、状态码与模式语义，均以 Java 端 `com.aicourse.integration.ContractPaths` 常量为准；Python 端实现须严格对齐，避免两端字段漂移。

## 39. 契约总则与职责边界

| 侧 | 职责 | 状态 |
|----|------|------|
| Java 后端（本端） | **消费侧 + 标准化对接适配层**：定义契约接口、数据结构与调用约定；默认以「本地占位」运行，不依赖 Python；`enabled=true` 时经 HTTP 代理对接 Python | 已落地（`com.aicourse.integration` 包） |
| Python 知识图谱服务（8001） | 图谱引擎（图谱构建、多跳推理、GraphRAG） | `python-services/kg_service/` 基线实现（FastAPI，内存存储，本地联调用） |
| Python RAG 检索服务（8002） | 检索引擎（BM25 / 向量检索 / embedding / 融合） | 契约预留（Java 端未启用时返回 503，AI 问答自动回退纯 LLM） |
| Python LoRA 微调（8003） | 模型微调 | Java 端 `LLMFineTuneServiceImpl` 真实调用；Python 端由队友交付 |

**接入方式**：Python 服务就绪后，将 `knowledge-graph.enabled` / `rag.enabled` / `fine-tune.enabled` 置 `true` 即生效，无需改动业务代码；未接入时本地占位 / 503 降级，问答链路与路径规划端点始终可用。

请求：`{ "source_id": 1, "target_id": 12, "max_hops": 2 }`

响应：
```json

  "path": [1, 5, 12],
  "edges": [
```

## 44. 状态码与模式语义

| 概念 | 取值 | 含义 |
|------|------|------|
| `code` | `503` | 引擎未接入 / 不可用（降级占位） |
| `mode` | `ENGINE` | 由 Python 引擎计算返回 |
| `mode` | `LOCAL` | 引擎未启用/不可达，由本端消费侧本地兜底（如本地 BFS） |
| `mode` | `UNAVAILABLE` | 引擎不可用且本地无兜底数据，仅返回降级占位 |
| `error` | `MSG_KG_UNAVAILABLE` / `MSG_RAG_UNAVAILABLE` | 降级说明文案（见 `ContractPaths`） |

通用约定：所有请求/响应 `Content-Type: application/json`；健康检查返回 200 即可（body 可为 `{}`）；错误响应 `{ "error": "...", "code": 503 }`。

## 45. 重试与超时

`HttpKnowledgeGraphProvider` / `HttpRagProvider` 复用 Sentinel 资源（`kg:http` / `rag:http`，方法级流控 + 慢调用熔断）：

- **非超时异常**（如连接拒绝）：按 `max-retries` 重试，间隔随次数递增
- **读超时**：不重试，直接降级（避免雪崩放大）
- 重试耗尽或超时：KG 的 `ingest` / `getSubGraph` 与 RAG 全部方法返回 503 降级占位；KG 的 `planLearningPath` 回退本地 BFS

> 「超时不重试」语义由 `isReadTimeout(Exception)` 判定，契约测试 `HttpRagProviderBoostTest.ask_socketTimeout_noRetry` 锁定。

## 46. 降级策略（实际行为）

| 场景 | 实际行为 |
|------|----------|
| KG 路径规划（默认 / 引擎不可达 / 引擎未找到路径） | 消费侧本地 BFS 兜底（直读 `knowledge_point_relations`），始终返回真实路径 |
| KG `ingest` / `getSubGraph`（引擎不可达） | 返回 503 占位（`mode=UNAVAILABLE`） |
| RAG 未启用（默认） | 所有方法返回 503 占位（`DisabledRagProvider`） |
| RAG 启用但不可达 / 调用失败 | 返回 503 占位；`AIServiceImpl.ragAsk` 检测到 `code:503` 自动回退纯 LLM |
| 微调服务（8003）未启用/不可用 | `LLMFineTuneServiceImpl` 返回 `{"error":"微调服务暂不可用","code":503}` |
