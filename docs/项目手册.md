# 第一部分 项目总览与背景

## 1. 项目定位与目标

**定位**：融合知识图谱（Knowledge Graph）与大语言模型（LLM）的智能在线教育平台，以《计算机网络》等专业课程为试点，面向**学生 / 教师 / 管理员**三端，提供个性化学习、教学支持与全面管理能力。

**核心能力域**：多角色 RBAC、课程/章节/选课管理、题库与在线考试（防作弊）、作业批改与查重、知识图谱可视化与学习路径规划、AI 智能问答/出题/批改/学情建议、数据分析与学情报告、WebSocket 实时通知。

**关键考核指标（申报口径）**：降低 AI 幻觉、可量化评测、工程规范可验证、安全合规。

### 1.1 时代背景与四大现实痛点

1. 个性化学习资源供给不足；
2. 教师重复性批改与答疑负担重；
3. 知识点孤立、缺乏关联与路径引导；
4. AI 回答不可信、无溯源、易编造。

### 1.2 项目意义与核心内容

以"知识图谱 + LLM"双引擎驱动：知识图谱建模学科知识点关联，LLM 提供自然语言交互与生成能力，二者经 RAG 检索增强形成**可溯源、低幻觉**的 AI 助教。

### 1.3 外部研究支撑

- **同类系统对比（不构成对标）**：`大创赛/类似项目/DeepSeek-RAG-Chatbot` 的 GraphRAG 实体抽取使用正则 `\b[A-Z][a-z]+...`，**仅支持英文实体**，且为单机通用文档问答；与本项目的**中文知识图谱**（`knowledge_points` / `knowledge_point_relations` 双表建模）在语言适配、领域建模与工程规模上不可类比，**不作为对标依据**。
- **论文支撑**：杜彩丽 IPA/IREM（细粒度知识点抽取）、中职计算机网络多源异构 KG 等，与 PRD 接口矩阵共同构成中文 KG 关系建模依据。

## 2. 参赛与申报要点

- **大赛**：中国国际大学生创新大赛 2026。
- **答辩证据链主轴**：差异化"知识图谱 + RAG"能力 → 可量化幻觉率评测（`evaluation/`，60 题 QA 集）→ 工程规范性（质量门禁 + 契约测试 + ArchUnit）→ 安全合规（五层纵深防御）。

# 第二部分 需求与技术基线

## 3. 用户角色与进阶 RBAC

- **三角色**：管理员（ADMIN）、教师（TEACHER）、学生（STUDENT），常量集中于 `common/RoleConstants`。
- **三级授权模型**：
  1. **URL 级基线**（`config/SecurityConfig`）：`/admin/**` → `hasRole(ADMIN)`；资源写操作（POST/PUT/DELETE/PATCH）→ `hasAnyRole(TEACHER, ADMIN)`；`anyRequest().authenticated()` 兜底。
  2. **方法级细粒度**：`@PreAuthorize` 全仓 **165 处**（静态计数），覆盖 44 个控制器中的 **38** 个。
  3. **对象级（水平授权）**：部分控制器在 Service 层做 `userId` 归属校验，并有专用组件 `security/ExamSessionAccessControl`、`security/SubmissionAccessControl`。
- **已知缺口**：**3 个控制器零 `@PreAuthorize`**——`AuthController`、`FineTuneController`、`NoteController`。其中 `AuthController` 为公开端点（合理）、`FineTuneController` 经 `/admin/**` URL 规则兜底、`NoteController` 在 Service 层做归属校验，**均有合理兜底，无待收敛项**。此前 `AIController`、`LearningPathNodeController`、`MonitorController`、`SearchController` 的缺口已于 2026-09-06/07 补齐类级 `@PreAuthorize("isAuthenticated()")`。

## 4. 三端功能需求（索引）

完整需求—代码追踪矩阵见 **§14**。要点：

- **学生端**（43 个视图）：选课、学习、AI 助手（多轮/流式/溯源）、考试（防切屏）、错题本、笔记、学情看板、知识图谱可视化。
- **教师端**（94 个视图）：建课/资源/任务点、题库/组卷/批改、监考、学情驾驶舱、AI 出题/润色。
- **管理员端**（82 个视图）：用户/角色/权限、系统配置、操作与登录审计、数据看板、Excel 批量导入、备份。

## 5. AI 能力体系（F-AI）

- 多轮会话持久化（`ai_chat_sessions` / `ai_chat_messages`）、结构化输出、异步化、AI 监控与配额；
- 智能问答（多轮/流式/溯源）、AI 出题/总结/润色、学情建议；
- **供应商路由**：`llm/` 包 6 类——`LLMProvider`（接口）、`DeepSeekProvider`、`OpenAiProvider`、`OpenAiCompatibleProvider`、`QwenProvider`、`RoutingLLMProvider`（热切换）；
- **RAG 检索**：BM25 + GraphRAG，引擎侧由队友以 Python 8002 交付，本端为消费侧；
- **知识图谱**：抽取（extract）、可视化、路径规划（引擎缺失时本地 BFS 兜底）。

## 6. 核心业务流程

主链路：注册/登录 → 选课 → 学习（章节/资源/笔记）→ 作业/考试（防作弊/查重）→ AI 答疑/出题 → 学情分析 → 教师批改 → 数据看板。

**AI 问答链路**：前端 `api/ai.ts` → `AIController` → `AIServiceImpl` → 若 `rag.enabled=true` 则 `RagContract` → Python 8002；不可达时**自动回退纯 LLM**。
**路径规划链路**：`KnowledgeController` → `KnowledgeGraphContract` → 引擎 8001；未启用/不可达/未找到路径时经 `LocalKnowledgeGraphProvider` 直读 `knowledge_point_relations` 做**本地 BFS 兜底**，始终返回真实路径。

## 7. 非功能需求与产品演进

- **安全性**：BCrypt 口令、JWT 无状态、RBAC、双提交 Cookie CSRF、IP 限流、Sentinel 流控熔断、输出转义（前端 `dompurify`）。
- **可观测性**：Prometheus 抓取 + Grafana 看板 + Alertmanager 告警 + Loki/Promtail 日志集中化 + 4 个自定义 HealthIndicator。
- **可用性**：引擎缺失时优雅降级（本地兜底 / 503 语义降级），核心端点始终可用。
- **可维护性**：ArchUnit 架构守护 6 条、契约测试护栏 7 个文件、`ContractPaths` 单一事实来源。
- **演进路线**：消费侧完善 → 接入 Python 引擎（KG/RAG/LoRA）→ 量化评测闭环 → 生产加固。

## 11. 核心设计决策

**① 安全五层纵深**

1. JWT 无状态认证（`security/JwtRequestFilter` + `JwtAuthenticationEntryPoint`）；
2. RBAC 三级授权（URL / 方法 / 对象级，见 §3）；
3. CSRF 双提交 Cookie——`SecurityConfig` **显式关闭 Spring 内置 csrf**，改由 `security/DoubleSubmitCsrfFilter` 承担（受 `app.security.csrf.enabled` 控制，默认 true，引导端点豁免）；
4. 安全响应头：`frameOptions().deny()` + HSTS + `ReferrerPolicy.NO_REFERRER` + CSP；
5. 监控端点独立 Basic 鉴权——`/actuator/prometheus` 要求 `hasRole("ACTUATOR")`，其余 actuator 端点 `denyAll()`；口令留空即 **fail-closed**（拒绝而非放行）。

**② AI 集成架构（标准化适配层）**
`com.aicourse.integration` 为对接层：`ContractPaths` 常量类是调用约定的**单一事实来源**（main 侧引用 93 处、test 侧 62 处，合计 155 处）；`KnowledgeGraphContract` / `RagContract` 为强类型 `record` 契约；每个能力提供**本地 + HTTP 双实现**（`LocalKnowledgeGraphProvider` / `HttpKnowledgeGraphProvider`、`DisabledRagProvider` / `HttpRagProvider`）。引擎缺失时本地 BFS 兜底或返回 503 降级。

> ✅ **契约纪律已收敛**：LoRA 微调的 8 条 `/api/v1/fine-tune/*` 路径已统一纳入 `ContractPaths`（`FT_HEALTH` / `FT_START` / `FT_TASK_STATUS` / `FT_TASKS` / `FT_TASK_CANCEL` / `FT_INFER` / `FT_TASK_EXPORT` / `FT_TASK`），`LLMFineTuneServiceImpl` 与 `PythonServicesHealthIndicator` 均经常量引用，硬编码已清零（实测经 `grep`，见 §46.1 第 7 项）。

**③ Redis 五大职责**：缓存聚合、IP 级限流、AI 用量配额、验证码、ShedLock 调度锁。启动时 `RedisStartupValidator` 强校验连通性，失败即中止启动。

**④ 自愈数据库**：Flyway 接管迁移（`V1__init_schema.sql`，48 表 + 种子），`baseline-on-migrate=true` + `baseline-version=1` 使已运行实例自动 baseline、不重复执行；`encoding: UTF-8`（迁移脚本含中文注释）。另有 `config/SchemaMigration` 做补充校正。

**⑤ 文件存储双通道**：默认本地磁盘（`file.upload-path` + `UploadResourceConfig` 静态映射）；设 `minio.enabled=true` 并提供 `endpoint`/`MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY` 后切换至 MinIO（bucket `aicourse-uploads`），实现类 `MinioFileStorageServiceImpl`，接口 `FileStorageService`。

**⑥ 前端设计令牌**：CSS 变量双主题（`:root` / `[data-theme='dark']`，定义于 `styles/theme.css`），禁止硬编码色值；加载/错误/空三态齐全；输出经 `dompurify` 转义。

## 19. 编码规范

### 19.1 后端

- **命名**：类 `UpperCamelCase`、方法/变量 `lowerCamelCase`、常量 `UPPER_SNAKE`、包名全小写
- **传输对象后缀**：入参一律 `*DTO`，出参一律 `*VO`。`dto/` 只收 `*DTO`，`vo/` 只收 `*VO`；无后缀值对象（如 `ClientInfo`）置于 `common/`。禁止 `*Request` 与 `*DTO` 两套后缀并存，禁止同一类名同时出现在 `dto/` 与 `vo/`（同名类仅靠包名区分，通配符导入即歧义）
- **分层归属**：按下列判定表定位，不得在两个包内随机并存

  | 场景                                 | 归属                                          |
  | ------------------------------------ | --------------------------------------------- |
  | 需被 Mock、或存在多实现              | `service/`（接口） + `service/impl/`（实现）  |
  | 无多实现需求、承载业务协作           | `service/component/<域>/`，后缀 `Component`   |
  | 无状态工具函数                       | `util/`，后缀 `Util`                          |

  `service/` 顶层只放接口，禁止直接存放具体实现类；`service/component/` 禁止出现 `*Support` / `*Util`
- **注释**：类级 Javadoc 说明职责与边界；契约类（`integration/`）注释必须说明调用约定与降级语义
- **日志**：`@Slf4j`（禁止以全限定名内联 `LoggerFactory.getLogger(...)`）；业务异常 `log.warn`，系统异常 `log.error`；禁止 `System.out`/`System.err`/`printStackTrace`（2026-09-03 静态核实：0 处）
- **异常**：业务异常统一抛 `BusinessException`，禁止 `throw new RuntimeException`；集成层与降级路径必须 `log.warn` 留痕，禁止静默吞异常（`InterruptedException` 须恢复中断标志后退出）
- **依赖注入**：统一构造器注入（`@RequiredArgsConstructor`），禁止 `@Autowired` 字段注入
- **事务**：写操作在 Service 实现类加 `@Transactional(rollbackFor = Exception.class)`；跨表写操作注意事务边界（全仓 190 处）
- **鉴权**：Controller 方法必须声明角色约束（`@PreAuthorize` 或 Security 配置）；禁止绕过 RBAC 直连数据
- **集成契约**：涉及 Python 对接的 HTTP 调用，必须引用 `ContractPaths` 常量，禁止硬编码路径/字段名

### 19.2 前端

- 组合式 API（`<script setup>`）
- **组件命名**：页面级组件（路由入口）用全词 `PascalCase.vue`，不缩写，如 `ExamPapers.vue`；局部子组件允许 2–3 字母域缩写前缀，前缀须取自下表，不得临时新造
- **测试文件**：与源同扩展名（`.test.ts`），置于对应 `__tests__/` 目录，位置镜像被测源
- **类型检查**：`vue-tsc --noEmit`（`npm run typecheck`）为必备检查，CI 以棘轮门禁阻断新增类型错误；错误基线记录于 `frontend/scripts/typecheck-baseline.json`，**只许下调、不得上调**。`strict` 为收敛目标：当前为关闭状态，存量清零后再开启（`strict:true` 口径存量远大于现状，属分阶段迁移）
- **样式**：优先使用设计令牌 CSS 变量（双主题自动适配），禁止内联渐变/硬编码色值（大屏看板场景除外）
- **数据访问**：所有请求经 `api/` 模块封装，禁止页面内散落 `axios` 调用
- **关注点分离**：HTTP 层不得操作 DOM 或承载 UI 状态；日志统一走 `utils/logger`，禁止裸 `console.*`
- **三态**：加载态 / 错误态 / 空态齐全；无 mock 业务数据

### 19.3 测试

- 一个被测类对应一个测试类，命名 `<Target>Test`（单元）/ `<Target>IT`（集成）；同一被测类不得存在多份测试类
- **禁止以覆盖率指标命名测试**（`*CoverageTest` / `*BoostTest`）——覆盖率是测试的副产物，不是测试的目的
- 覆盖率统计须排除纯数据载体（`dto/` / `vo/` / `entity/` / `enums`）的 `getter`/`setter`/`equals`/`hashCode`/`toString`，以及反射驱动的批量执行类测试；否则读数不可用于质量判定
- 覆盖率阈值调整前须先给出剔除上述填充量后的真实基线，遵循「只许上调、不得下调」
- 测试位置镜像被测源（`api/` 的测试置于 `api/__tests__/`，不得置于 `views/__tests__/`）

## 22. 开发协作约定

### 22.1 分支策略

- 仓库仅保留两个长期分支：`main` 与 `leyon`
- **日常改动默认推送到 `leyon`**，无需逐次确认
- `main` 分支受保护：任何推送 / 合并 / 重置操作必须经项目负责人明确同意后方可执行
- 阶段性成果才推送；本地提交遵循「里程碑完成才推送」约定

### 22.2 提交与推送

- 推送前确认网络代理通道可用（GitHub 依赖代理出网）
- 在受限执行环境（如 AI 沙箱）中 `refs/heads/*` 本地分支引用写入可能不持久，表现为 commit "看似成功"却落在 detached HEAD、push 报 "src refspec ... does not match any"：
  - 处置：按提交哈希直接推送远端引用 `git push origin <hash>:refs/heads/<branch>`；推送后重建本地分支 `git branch <branch> origin/<branch>` 并 `git checkout <branch>`
  - 严禁在受限环境中执行 `git gc --prune=now` 等破坏性清理命令

## 23. 常见开发问题

| 现象                                         | 原因 / 处理                                                               |
| -------------------------------------------- | ------------------------------------------------------------------------- |
| 后端启动报 `RedisConnectionFailureException` | Redis 未启动；`net start Redis` 或 `docker compose up -d redis`           |
| `JWT signature does not match`               | JWT_SECRET 不一致；注意 `start-backend.bat` 行尾须保持 CRLF，否则密钥截断 |

| JaCoCo check 失败                            | 覆盖率低于门禁；先补测试再上调阈值，不得下调门禁                          |
| 修改了 Python 契约字段                       | 必须同步更新 `ContractPaths` 常量 + 本手册第八部分契约章节                |

## 27. 常见故障处理

### 27.1 后端启动失败

| 现象                                                   | 可能原因               | 解决                                                           |
| ------------------------------------------------------ | ---------------------- | -------------------------------------------------------------- |
| `CommunicationsException: Communications link failure` | MySQL 未启动或密码错误 | 检查 MySQL 状态与 `.env`                                       |

### 27.2 前端无法访问后端

| 现象              | 可能原因                | 解决                        |
| ----------------- | ----------------------- | --------------------------- |
| 跨域错误 (CORS)   | 前端 origin 不在白名单  | 检查 `cors.allowed-origins` |
| 401 未授权        | Cookie 未携带或令牌过期 | 清除浏览器 Cookie 重新登录  |
| 403 CSRF 校验失败 | 未配置 `withXSRFToken`  | 确认 `request.ts` 配置      |

| 现象                    | 可能原因                    | 解决                                                     |
| ----------------------- | --------------------------- | -------------------------------------------------------- |

| AI 调用超时             | 网络问题或 API 服务异常     | 调大 `AI_READ_TIMEOUT`，检查 `api.deepseek.com` 可达性   |
| `AI quota exceeded`     | 用户当日调用次数/Token 超额 | 调大 `AI_QUOTA_DAILY_REQUESTS` / `AI_QUOTA_DAILY_TOKENS` |

# 第八部分 Python 微服务集成契约

> 本部分是 Java 后端（消费侧）与 Python 微服务（引擎侧）之间「知识图谱 / RAG / LoRA」对接契约的单一事实来源。所有 HTTP 路径、JSON 字段名、状态码与模式语义，均以 Java 端 `com.aicourse.integration.ContractPaths` 常量为准（main 侧引用 93 处）；Python 端实现须严格对齐，避免两端字段漂移。

## 33. 契约总则与职责边界

| 侧                          | 职责                                                                                                                                             | 状态                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| Java 后端（本端）           | **消费侧 + 标准化对接适配层**：定义契约接口、数据结构与调用约定；默认以「本地占位」运行，不依赖 Python；`enabled=true` 时经 HTTP 代理对接 Python | 已落地（`com.aicourse.integration` 包）                                          |
| Python 知识图谱服务（8001） | 图谱引擎（图谱构建、多跳推理、GraphRAG）                                                                                                         | `python-services/kg_service/` 基线实现（FastAPI，内存存储，本地联调用，11 端点） |
| Python RAG 检索服务（8002） | 检索引擎（BM25 / 向量检索 / embedding / 融合）                                                                                                   | 契约预留（Java 端未启用时返回 503，AI 问答自动回退纯 LLM；9 端点占位骨架）       |
| Python LoRA 微调（8003）    | 模型微调                                                                                                                                         | Java 端 `LLMFineTuneServiceImpl` 真实调用；Python 端由队友交付                   |

**接入方式**：Python 服务就绪后，将 `knowledge-graph.enabled` / `rag.enabled` / `fine-tune.enabled` 置 `true` 即生效，无需改动业务代码；未接入时本地占位 / 503 降级，问答链路与路径规划端点始终可用。

## 38. 状态码与模式语义

| 概念    | 取值                                         | 含义                                                  |
| ------- | -------------------------------------------- | ----------------------------------------------------- |
| `code`  | `503`                                        | 引擎未接入 / 不可用（降级占位）                       |
| `mode`  | `ENGINE`                                     | 由 Python 引擎计算返回                                |
| `mode`  | `LOCAL`                                      | 引擎未启用/不可达，由本端消费侧本地兜底（如本地 BFS） |
| `mode`  | `UNAVAILABLE`                                | 引擎不可用且本地无兜底数据，仅返回降级占位            |
| `error` | `MSG_KG_UNAVAILABLE` / `MSG_RAG_UNAVAILABLE` | 降级说明文案（见 `ContractPaths`）                    |

通用约定：所有请求/响应 `Content-Type: application/json`；健康检查返回 200 即可（body 可为 `{}`）；错误响应 `{ "error": "...", "code": 503 }`。

## 39. 重试与超时

`HttpKnowledgeGraphProvider` / `HttpRagProvider` 复用 Sentinel 资源（`kg:http` / `rag:http`，方法级流控 + 慢调用熔断）：

- **非超时异常**（如连接拒绝）：按 `max-retries` 重试，间隔随次数递增
- **读超时**：不重试，直接降级（避免雪崩放大）
- 重试耗尽或超时：KG 的 `ingest` / `getSubGraph` 与 RAG 全部方法返回 503 降级占位；KG 的 `planLearningPath` 回退本地 BFS

> 「超时不重试」语义由 `isReadTimeout(Exception)` 判定，契约测试 `HttpRagProviderBoostTest.ask_socketTimeout_noRetry` 锁定。
