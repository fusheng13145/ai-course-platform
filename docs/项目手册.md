# 第一部分 项目总览与背景

## 1. 项目定位与目标

**定位**：融合知识图谱（Knowledge Graph）与大语言模型（LLM）的智能在线教育平台，以《计算机网络》等专业课程为试点，面向**学生 / 教师 / 管理员**三端，提供个性化学习、教学支持与全面管理能力。

**核心能力域**：多角色 RBAC、课程/章节/选课管理、题库与在线考试（防作弊）、作业批改与查重、知识图谱可视化与学习路径规划、AI 智能问答/出题/批改/学情建议、数据分析与学情报告、WebSocket 实时通知。

**关键考核指标（申报口径）**：降低 AI 幻觉、可量化评测、工程规范可验证、安全合规。

### 1.1 时代背景与四大现实痛点
1. 个性化学习资源供给不足；
2. 教师重复性批改与答疑负担重；
3. 知识点孤立、缺乏关联与路径引导；
4. AI 回答不可信、无溯源、易编造。

### 1.2 项目意义与核心内容
以"知识图谱 + LLM"双引擎驱动：知识图谱建模学科知识点关联，LLM 提供自然语言交互与生成能力，二者经 RAG 检索增强形成**可溯源、低幻觉**的 AI 助教。

### 1.3 外部研究支撑
- **同类系统对比（不构成对标）**：`大创赛/类似项目/DeepSeek-RAG-Chatbot` 的 GraphRAG 实体抽取使用正则 `\b[A-Z][a-z]+...`，**仅支持英文实体**，且为单机通用文档问答；与本项目的**中文知识图谱**（`knowledge_points` / `knowledge_point_relations` 双表建模）在语言适配、领域建模与工程规模上不可类比，**不作为对标依据**。
- **论文支撑**：杜彩丽 IPA/IREM（细粒度知识点抽取）、中职计算机网络多源异构 KG 等，与 PRD 接口矩阵共同构成中文 KG 关系建模依据。

## 2. 参赛与申报要点
- **大赛**：中国国际大学生创新大赛 2026。
- **答辩证据链主轴**：差异化"知识图谱 + RAG"能力 → 可量化幻觉率评测（`evaluation/`，60 题 QA 集）→ 工程规范性（质量门禁 + 契约测试 + ArchUnit）→ 安全合规（五层纵深防御）。

# 第二部分 需求与技术基线

## 3. 用户角色与进阶 RBAC
- **三角色**：管理员（ADMIN）、教师（TEACHER）、学生（STUDENT），常量集中于 `common/RoleConstants`。
- **三级授权模型**：
  1. **URL 级基线**（`config/SecurityConfig`）：`/admin/**` → `hasRole(ADMIN)`；资源写操作（POST/PUT/DELETE/PATCH）→ `hasAnyRole(TEACHER, ADMIN)`；`anyRequest().authenticated()` 兜底。
  2. **方法级细粒度**：`@PreAuthorize` 全仓 **164 处**（静态计数），覆盖 44 个控制器中的 37 个。
  3. **对象级（水平授权）**：部分控制器在 Service 层做 `userId` 归属校验，并有专用组件 `security/ExamSessionAccessControl`、`security/SubmissionAccessControl`。
- **已知缺口**：**7 个控制器零 `@PreAuthorize`**——`AIController`、`AuthController`、`FineTuneController`、`LearningPathNodeController`、`MonitorController`、`NoteController`、`SearchController`。其中 `AuthController` 为公开端点（合理）、`FineTuneController` 经 `/admin/**` URL 规则兜底、`MonitorController` 由独立 Basic 鉴权保护、`NoteController` 在 Service 层做归属校验；`LearningPathNodeController` 与 `SearchController` 仅靠 `authenticated()` 兜底，属**待收敛项**（见 §38）。

## 4. 三端功能需求（索引）
完整需求—代码追踪矩阵见 **§14**。要点：
- **学生端**（43 个视图）：选课、学习、AI 助手（多轮/流式/溯源）、考试（防切屏）、错题本、笔记、学情看板、知识图谱可视化。
- **教师端**（94 个视图）：建课/资源/任务点、题库/组卷/批改、监考、学情驾驶舱、AI 出题/润色。
- **管理员端**（82 个视图）：用户/角色/权限、系统配置、操作与登录审计、数据看板、Excel 批量导入、备份。

## 5. AI 能力体系（F-AI）
- 多轮会话持久化（`ai_chat_sessions` / `ai_chat_messages`）、结构化输出、异步化、AI 监控与配额；
- 智能问答（多轮/流式/溯源）、AI 出题/总结/润色、学情建议；
- **供应商路由**：`llm/` 包 6 类——`LLMProvider`（接口）、`DeepSeekProvider`、`OpenAiProvider`、`OpenAiCompatibleProvider`、`QwenProvider`、`RoutingLLMProvider`（热切换）；
- **RAG 检索**：BM25 + GraphRAG，引擎侧由队友以 Python 8002 交付，本端为消费侧；
- **知识图谱**：抽取（extract）、可视化、路径规划（引擎缺失时本地 BFS 兜底）。

## 6. 核心业务流程
主链路：注册/登录 → 选课 → 学习（章节/资源/笔记）→ 作业/考试（防作弊/查重）→ AI 答疑/出题 → 学情分析 → 教师批改 → 数据看板。

**AI 问答链路**：前端 `api/ai.ts` → `AIController` → `AIServiceImpl` → 若 `rag.enabled=true` 则 `RagContract` → Python 8002；不可达时**自动回退纯 LLM**。
**路径规划链路**：`KnowledgeController` → `KnowledgeGraphContract` → 引擎 8001；未启用/不可达/未找到路径时经 `LocalKnowledgeGraphProvider` 直读 `knowledge_point_relations` 做**本地 BFS 兜底**，始终返回真实路径。

## 7. 非功能需求与产品演进
- **安全性**：BCrypt 口令、JWT 无状态、RBAC、双提交 Cookie CSRF、IP 限流、Sentinel 流控熔断、输出转义（前端 `dompurify`）。
- **可观测性**：Prometheus 抓取 + Grafana 看板 + Alertmanager 告警 + Loki/Promtail 日志集中化 + 4 个自定义 HealthIndicator。
- **可用性**：引擎缺失时优雅降级（本地兜底 / 503 语义降级），核心端点始终可用。
- **可维护性**：ArchUnit 架构守护 6 条、契约测试护栏 7 个文件、`ContractPaths` 单一事实来源。
- **演进路线**：消费侧完善 → 接入 Python 引擎（KG/RAG/LoRA）→ 量化评测闭环 → 生产加固。

## 11. 核心设计决策

**① 安全五层纵深**
1. JWT 无状态认证（`security/JwtRequestFilter` + `JwtAuthenticationEntryPoint`）；
2. RBAC 三级授权（URL / 方法 / 对象级，见 §3）；
3. CSRF 双提交 Cookie——`SecurityConfig` **显式关闭 Spring 内置 csrf**，改由 `security/DoubleSubmitCsrfFilter` 承担（受 `app.security.csrf.enabled` 控制，默认 true，引导端点豁免）；
4. 安全响应头：`frameOptions().deny()` + HSTS + `ReferrerPolicy.NO_REFERRER` + CSP；
5. 监控端点独立 Basic 鉴权——`/actuator/prometheus` 要求 `hasRole("ACTUATOR")`，其余 actuator 端点 `denyAll()`；口令留空即 **fail-closed**（拒绝而非放行）。

**② AI 集成架构（标准化适配层）**

## 19. 编码规范

### 19.1 后端

- **命名**：类 `UpperCamelCase`、方法/变量 `lowerCamelCase`、常量 `UPPER_SNAKE`、包名全小写
- **注释**：类级 Javadoc 说明职责与边界；契约类（`integration/`）注释必须说明调用约定与降级语义
- **日志**：`@Slf4j`；业务异常 `log.warn`，系统异常 `log.error`；禁止 `System.out`/`System.err`/`printStackTrace`（2026-09-03 静态核实：0 处）
- **事务**：写操作在 Service 实现类加 `@Transactional(rollbackFor = Exception.class)`；跨表写操作注意事务边界（全仓 190 处）
- **鉴权**：Controller 方法必须声明角色约束（`@PreAuthorize` 或 Security 配置）；禁止绕过 RBAC 直连数据
- **集成契约**：涉及 Python 对接的 HTTP 调用，必须引用 `ContractPaths` 常量，禁止硬编码路径/字段名

### 19.2 前端

- 组合式 API（`<script setup>`）；组件命名 `PascalCase.vue`
- 样式优先使用设计令牌 CSS 变量（双主题自动适配），禁止内联渐变/硬编码色值（大屏看板场景除外）

- 加载态 / 错误态 / 空态三态齐全；无 mock 业务数据

## 26. 日志分析

| 环境 | 位置 |
|------|------|
| Docker | `docker compose logs -f <service>` |

## 27. 常见故障处理

### 27.1 后端启动失败

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| `CommunicationsException: Communications link failure` | MySQL 未启动或密码错误 | 检查 MySQL 状态与 `.env` |
| `PatternParseException: Invalid mapping pattern` | springdoc 版本不兼容 | 检查 springdoc 版本 |
| `JWT signature does not match` | JWT_SECRET 不一致 | 确保所有实例相同 JWT_SECRET；`start-backend.bat` 行尾保持 CRLF |
| `RedisConnectionFailureException` | Redis 未启动 | 启动 Redis 或检查 `SPRING_DATA_REDIS_HOST` |

### 27.2 前端无法访问后端

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| 跨域错误 (CORS) | 前端 origin 不在白名单 | 检查 `cors.allowed-origins` |
| 401 未授权 | Cookie 未携带或令牌过期 | 清除浏览器 Cookie 重新登录 |
| 403 CSRF 校验失败 | 未配置 `withXSRFToken` | 确认 `request.ts` 配置 |

### 27.3 AI 功能不可用

| 现象 | 可能原因 | 解决 |
|------|---------|------|
| AI 问答返回"知识库原文" | `DEEPSEEK_API_KEY` 未配置 | 在 `.env` 中设置有效 Key |
| AI 调用超时 | 网络问题或 API 服务异常 | 调大 `AI_READ_TIMEOUT`，检查 `api.deepseek.com` 可达性 |
| `AI quota exceeded` | 用户当日调用次数/Token 超额 | 调大 `AI_QUOTA_DAILY_REQUESTS` / `AI_QUOTA_DAILY_TOKENS` |

# 第八部分 Python 微服务集成契约

> 本部分是 Java 后端（消费侧）与 Python 微服务（引擎侧）之间「知识图谱 / RAG / LoRA」对接契约的单一事实来源。所有 HTTP 路径、JSON 字段名、状态码与模式语义，均以 Java 端 `com.aicourse.integration.ContractPaths` 常量为准（main 侧引用 93 处）；Python 端实现须严格对齐，避免两端字段漂移。

## 33. 契约总则与职责边界

| 侧 | 职责 | 状态 |
|----|------|------|
| Java 后端（本端） | **消费侧 + 标准化对接适配层**：定义契约接口、数据结构与调用约定；默认以「本地占位」运行，不依赖 Python；`enabled=true` 时经 HTTP 代理对接 Python | 已落地（`com.aicourse.integration` 包） |
| Python 知识图谱服务（8001） | 图谱引擎（图谱构建、多跳推理、GraphRAG） | `python-services/kg_service/` 基线实现（FastAPI，内存存储，本地联调用，11 端点） |
| Python RAG 检索服务（8002） | 检索引擎（BM25 / 向量检索 / embedding / 融合） | 契约预留（Java 端未启用时返回 503，AI 问答自动回退纯 LLM；9 端点占位骨架） |

## 38. 状态码与模式语义

| 概念 | 取值 | 含义 |
|------|------|------|
| `code` | `503` | 引擎未接入 / 不可用（降级占位） |
| `mode` | `ENGINE` | 由 Python 引擎计算返回 |
| `mode` | `LOCAL` | 引擎未启用/不可达，由本端消费侧本地兜底（如本地 BFS） |
| `mode` | `UNAVAILABLE` | 引擎不可用且本地无兜底数据，仅返回降级占位 |
| `error` | `MSG_KG_UNAVAILABLE` / `MSG_RAG_UNAVAILABLE` | 降级说明文案（见 `ContractPaths`） |

通用约定：所有请求/响应 `Content-Type: application/json`；健康检查返回 200 即可（body 可为 `{}`）；错误响应 `{ "error": "...", "code": 503 }`。

## 39. 重试与超时

`HttpKnowledgeGraphProvider` / `HttpRagProvider` 复用 Sentinel 资源（`kg:http` / `rag:http`，方法级流控 + 慢调用熔断）：

- **非超时异常**（如连接拒绝）：按 `max-retries` 重试，间隔随次数递增
- **读超时**：不重试，直接降级（避免雪崩放大）
- 重试耗尽或超时：KG 的 `ingest` / `getSubGraph` 与 RAG 全部方法返回 503 降级占位；KG 的 `planLearningPath` 回退本地 BFS

> 「超时不重试」语义由 `isReadTimeout(Exception)` 判定，契约测试 `HttpRagProviderBoostTest.ask_socketTimeout_noRetry` 锁定。
