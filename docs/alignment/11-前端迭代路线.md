# 前端迭代路线

> 编制时间：2026-11-04  
> 范围：`frontend/src/ui/`、`frontend/src/api/`、前端测试/构建/运行配置。  
> 未完成事项与逐条状态以 [前端待办项](../前端待办项.md) 为准；后端契约缺口以 [后端待办项 B-13](../后端待办项.md) 为准。本文负责把前端工作排序并与后端集成。

## 1. 目标与边界

前端交付《计算机网络》单课的学生/教师/管理员关键体验，并确保界面状态忠实反映后端事实。核心页面是课程空间、课程内 AI 助教、知识图谱、诊断与路径、资料维护、练习考试和必要的后台管理。课程外全局 AI 助手、语音、多课程、移动端完整体验等按现有产品决策冻结或后置。

前端负责呈现、交互、可访问性、请求封装和端到端体验；不得自行复制业务规则、推导伪数据、掩盖 403/503/格式错误或改变后端权限结果。API 模块是唯一业务请求入口。

### F1：三端核心框架与课程空间

- 保持登录/登出、角色路由、全局错误页、权限守卫和 API host 适配稳定。
- 学生课程空间优先保证章节/资源、作业、考试、成绩、错题与通知的真实状态；教师课程空间优先保证课程内容、题库、布置/批阅和知识点维护；管理员只保留单课交付需要的账号/权限/课程治理入口。
- 每个页面具备加载、成功、空态、失败、重试和无权限状态；列表分页与后端 envelope 归一集中在共享工具，不在页面散落多套兼容逻辑。
- 对真实业务数据显式标注来源；演示/示例数据不得伪装成线上数据。

**出口**：三角色关键路由和一条课程级业务流程可在真后端运行；权限拒绝、空数据和网络错误均有正确反馈。

### F2：AI 问答与图谱交互（核心差异化）

1. **课程内问答**：使用 `/ai/qa/ask` 或最终冻结的问答契约；显示回答、来源、回答状态与生成模式；无来源、未知、不可用与普通成功必须视觉上可区分。
2. **图谱**：展示课程节点/关系，支持选择节点、查看邻接关系、路径规划与路径高亮；不把本地示例图当真实图谱。
3. **图谱溯源**：回答引用节点/关系时可定位到图谱视图；仅在后端返回稳定图谱 ID 和来源类型后显示可点击链接。
4. **薄弱诊断/路径**：展示知识点、掌握度、数据时间/来源、路径步骤和理由；诊断不可用或映射不足时显示明确状态，不自行计算替代分数。
5. **课程范围与降级提示**：后端返回 `mode/gen_mode/status` 等状态字段后，前端按契约映射提示，不仅靠 `sources.length` 推断服务状态。

**出口**：真实课程数据端到端联调；图谱点击与路径高亮可操作；AI 正常/空资料/超纲/服务不可用均有对应 UX 和自动化用例。

### F3：资料、练习考试与角色闭环

- 教师上传课程资料、查看索引/失败状态；学生检索/预览依产品范围实现。
- 完成单课必需的题库、布置、答题、自动保存/续考、提交、批阅、成绩与错题闭环；每一步展示后端确认状态。
- 资源上传、考试状态转换等高风险操作带确认、幂等提示与错误恢复；禁止用前端假状态先行宣称成功。
- B-13 相关页面依唯一对照表推进：后端未提供时保留诚实空态或隐藏入口，产品裁定后再开发。

**出口**：教师创建/维护内容到学生完成任务再到成绩/错题反馈的端到端流程通过；API 请求体与返回结构由测试锁定。

### F4：验证、可访问性与交付体验

- 每批按范围运行 lint、typecheck、单测、build、API 引用、体积门；关键交互增加 Playwright e2e，视觉测试只对已登记稳定锚点作结论。
- 维持 XSS、URL 协议、键盘/焦点、颜色对比和错误提示的机械守卫；审计整改以 `docs/前端待办项.md` 当前项为准。
- 把前端 E2E 纳入可重复联调入口；测试夹具使用固定角色/课程/数据，并清理由测试创建的数据。
- 容器部署需要的 `VITE_*` 配置在构建期显式注入；本机开发配置与生产配置分开说明。

**出口**：相关自动化门禁在干净环境可重跑；e2e 能使用真服务验证关键流程；构建配置可被目标部署形态消费。

### F5：演示、证据与扩展

- 核心链路稳定后，整理标准演示题、正常命中/无依据/下游故障案例及图谱路径案例。
- 记录实际来源与产品限制，生成答辩/软著截图、录屏和测试报告；视觉一致不能替代行为证据。
- 多课程适配以课程 ID 和后端契约驱动，逐步去除单课硬编码；必须等后端第二门课程数据与导入流程就绪。

## 3. 前后端接口消费约定

- API 事实源为 `frontend/src/api/**` 对应的后端 OpenAPI/架构契约，不在 Vue 页面直写 `axios` 请求。
- 每个页面列出其端点、权限角色、必需字段、分页/排序口径、错误码、空态和服务降级语义。
- 新字段必须先出契约，再更新 API 类型、归一化工具、单测与页面；后端兼容期内前端可双读，但需设定删除旧字段的条件。
- AI sources、graph node IDs、learning path IDs 必须使用后端稳定标识；不得依赖展示名称作业务关联。
- 请求超时、取消、重复提交和重试策略由共享 API 层/业务规则统一处理，不由每个页面自行实现。

## 4. 双线依赖与并行规则

| 前端工作 | 可先并行完成 | 等待后端后才能关闭 |
| --- | --- | --- |
| 问答 UI | 布局、输入校验、loading/空态/错误态、契约 mock 测试 | 真实来源/图谱引用、防幻觉状态与 Java↔Python 真链路 |
| 图谱 UI | 画布交互、可访问性、固定 schema fixture | 真实课程节点/边、多跳路径字段与权限过滤 |
| 诊断路径 UI | 页面骨架、步骤组件、契约样例 | 真实掌握度定义、知识点 ID 映射、路径解释 |
| 资料库 UI | 上传进度组件、状态展示、交互测试 | 索引任务状态、学生检索端点及文件权限 |
| 考试 UI | 本地答题状态、恢复/重试组件测试 | 服务端状态机、幂等提交、超时/断线规则 |

等待接口期间可以用 mock，但 mock 文件必须标注对应 API 契约版本，并由契约测试验证；生产路径不得保留 mock fallback。

## 6. 任务状态与联合关闭标准

每项使用 `未开始 / 进行中 / 受阻 / 已完成 / 明确下线`。受阻项写明后端 B 编号和缺失契约；“页面存在”不等于“功能完成”。前端项关闭至少具备：

1. 当前 `src/ui` 代码入口与单测；
2. API 契约/类型与成功、空态、错误态映射；
3. 需要时的浏览器 e2e 真栈证据；
4. 相应质量门通过结果；
5. 跨线联合验收流程通过或明确记录尚未集成的依赖。

任务编号继续沿用 `F-Mx-yy` 与前端待办编号；已有状态以 `docs/前端待办项.md` §11.10/§11.11 为准，本文不另建重复状态台账。
