## 1. 项目定位

本项目是面向高校课程学习的知识图谱 + 大语言模型 AI 助教系统，首期聚焦《计算机网络》单门课程，解决学生“学不会、错题后不知道补什么、课程问题缺少可靠解释”的痛点。核心差异是用结构化知识图谱承载课程概念与关系，用检索依据约束 AI 回答，并把诊断与学习路径解释到知识点。

“替代学习通/泛雅”是远期愿景，不是当前交付目标；当前应交付可演示、可验收、可扩展的单课垂直产品。多课程、社群、激励、移动端和 LoRA 微调属于后续或可砍范围，不应挤占主链路资源。

## 2. 目标用户与主要闭环

| 用户 | 当前必须支持的任务 | 结果 |
| --- | --- | --- |
| 学生 | 进入课程、查看知识结构、提问、查看错题/薄弱点、获得下一步学习路径、完成练习/考试 | 回答有来源；诊断与路径能解释到图谱知识点 |
| 教师 | 维护课程资料与知识点、布置/批阅练习考试、查看学生学习情况 | 教学内容可进入知识库；AI 产出作为建议而非不可审核的最终决策 |
| 管理员 | 管理账号、角色权限与课程运行所需配置 | 权限由后端执行，关键操作可审计 |

优先闭环：学生提问 → 检索课程资料并关联图谱 → 返回带来源的回答或诚实说明未知 → 错题/掌握情况映射到图谱 → 生成有理由的学习路径 → 学生继续练习。教师和管理员能力围绕该单课闭环提供最小支撑。

## 3. 成功判据

以下判据沿用 `01-决策对齐总表.md` 与 `08-迭代规划与任务分工.md`，不得仅凭页面存在或接口返回成功判定完成：

1. 学生、教师、管理员的关键流程端到端可走通，且权限隔离有效。
2. 《计算机网络》图谱可交互，节点、关系与多跳路径均可验证。
3. 问答命中课程知识库目标不低于 90%，展示检索/图谱来源；无依据或下游不可用时明确说明不知道，不回退到无来源的自由生成。
4. 薄弱诊断来自答题/错题与图谱节点的映射，推荐路径展示知识点和理由；映射失败须显式降级，不能静默套固定分数公式。
5. 关键验证有可重放命令与时间/环境记录；真人验收属于产品验收证据，不替代自动化门禁。
