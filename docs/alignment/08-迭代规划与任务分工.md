## 一、最终目标与验收总度量

达成「基于知识图谱 + LLM 的 AI 助教系统」单课（《计算机网络》）垂直利器，可交付、可演示、可答辩、可申软著，且严守三条红线。最终验收以 `01-决策对齐总表.md` 验证度量为准：

| 验收度量 | 目标 | 关联红线 |
| --- | --- | --- |
| 端到端跑通 | 三端关键流程全链路可用 | — |
| 图谱可交互 | 节点/边/多跳路径可点击、可高亮 | ① |
| 问答命中知识库 | ≥ 90% | ③ |
| 路径可解释 | 推荐路径含知识点与理由 | ② |
| 真人测试 | 完成并留痕 | — |
| 防幻觉兜底 | 答不出如实说"不知道"，绝不编造 | ③ |

| 角色 | 负责人 | 职责范围 | 交付物 |

- 契约基准：`docs/系统架构设计.md` 的「集成契约」章节 + `python-services/kg_service/test_kg_contract.py`。

- **知识转移风险**：现有 Java 后端代码原为李昂所写，本次分工整体移交队友，须在 M1 前完成接口文档化与一次知识转移沟，避免 R1（本人细节不全）复发。
