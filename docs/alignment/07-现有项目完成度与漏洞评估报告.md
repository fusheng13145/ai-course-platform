## 三、红线符合性结论（逐条 + 可能错在哪）

### 红线① 知识图谱构建流程必须真实存在，不得用 prompt 假装

- **可能错在哪**：① `neo4j_fake.py` 是否在生产充当伪图谱？② 图谱是否只是正则抽大写词（参照反面教材 `DeepSeek-RAG-Chatbot`）？
- **核验**：`neo4j_fake.py` 仅 `FakeDriver/FakeSession/FakeResult`，用于验证参数化与连接释放，**非生产伪图谱**；`Neo4jStore` 写真实 Cypher；Java 关系表已灌种真实课程概念（57 节点，含 `content`）。图谱构建为**人工策展式摄取（seeded + `/extract` + `create_node`/`create_relation`）**，非自动 LLM 抽取、也非正则假装。
- **结论：满足。** 备注：构建流程是"策展摄取"而非"自动抽取流水线"——这更诚实、合规（无虚假陈述），但需在结题文档中如实描述为"人工构建+图谱服务托管"，避免被误解为全自动 LLM 建图。

### 红线② 学生薄弱点诊断必须基于图谱，而非随机或规则写死

- **可能错在哪**：① 诊断是否真读图谱节点？② 名称匹配失败是否静默写死？
- **核验**：`LearningPathMasteryComponent.java:59-72` 先从 `knowledge_points` 建名称→ID 映射，匹配上时调 `calculateMastery`（真实图谱统计口径）；`:73-82` 名称匹配不上时回落 `100 - unmastered*25 - mastered*5` 硬编码扣分；`:84` `catch(Exception ignore)` 静默吞异常。
- **结论：条件满足（存在盲区）。** 主路径真实基于图谱；但名称不匹配分支与异常分支静默写死/丢弃，**属红线②的潜在失分点**，须修。

### 红线③ AI 问答须结合知识库精准回答，防幻觉 + 答不出如实说

- **可能错在哪**：① 默认部署问答是否零接地？② 全开时是否只接文档库、不接图谱？③ 答不出是否真兜底？
- **核验**：
  - `AiRagComponent.java:37-54`：`RAG_ENABLED=false`（默认）→ `ragService.ask` 返回 503 或被异常捕获 → `:52` 调 `core.completeAndSanitize` 纯 LLM，`:49` system prompt 仅"请基于课程知识回答"但**未注入任何资料**，`:53` `sources` 为空。即默认部署 = 纯 LLM 零接地。
  - 即便 `RAG_ENABLED=true`：`rag_engine.py:546 search()` 仅 BM25+FAISS 文档检索，**不触碰知识图谱**；`generate_answer`（`rag_engine.py:602-642`）三态 `LLM/EXTRACTIVE/UNAVAILABLE`，文档有料时接地、无料时返回空答案（不编造，合约良好）——但**图谱从未进入回答路径**，与"图谱驱动差异化"主张脱节。
- **结论：不满足。** 默认部署直接击穿红线③（纯 LLM 易幻觉）；全开时仅文档接地、图谱缺位，差异化主张落空。Python 侧 `UNAVAILABLE` 兜底设计本身合格，但 Java 纯 LLM 回落分支未复用该兜底语义。

## 四、可维护性隐患（评审子 Agent 独立挑刺，7 项）

1. **【最高危】默认 `KG_ENABLED`/`RAG_ENABLED=false`**（`application.yaml:368,391`）：生产级能力默关，评测/演示忘开即全走纯 LLM，红线③击穿。
2. **【误导 prompt】** `AiRagComponent.java:49`："请基于课程知识回答问题"与实际纯 LLM 分支无知识注入矛盾，prompt 自我标榜。
3. **【名称精确匹配 + 硬编码回落】** `LearningPathMasteryComponent.java:80` 写死扣分公式，名称不匹配静默写死，图谱诊断口径被绕过。
4. **【吞异常】** `LearningPathMasteryComponent.java:84` `catch(Exception ignore)` 静默降级，学情异常不可观测。
5. **【核心能力可关 + 缺端到端测试】** RAG/KG 默认关；契约测试仅覆盖 Python 侧占位回退，**无 Java↔Python 端到端用例**，开关组合回归靠人工。
6. **【错题路径字段恒 null】**（子 Agent 标注，待核）：错题→知识点映射链路某字段恒空，可能使诊断长期走兜底分支；需逐文件确认 `WrongQuestionGroupVO` 与 `getByKnowledgePoints` 实现。
7. **【壳子重、内核浅】** 50 控制器远超 MVP，外围治理/社群/运维占多数；核心 AI/QA 路径反而有上述缺陷，答辩易被质疑"为堆功能而堆功能"。

## 五、重构 vs 复用建议

### 5.1 应复用（保住，已是资产）

- **双存储图谱**：Java 关系表（57 节点真实）+ `Neo4jStore` 真实 Cypher 多跳 —— 红线①基石，保留。
- **rag_engine 三态防编造**：`LLM/EXTRACTIVE/UNAVAILABLE` 设计合格（无料不返回假答案），保留并推广到 Java 侧。

- **Sentinel 流控/熔断**（`application.yaml:333-359`）：AI 下游保护到位，保留。
- **实体/CRUD/三端骨架**：Vue3 + Spring Boot 分层清晰，作为脚手架复用。

### 5.2 必改（红线相关，不破不交付）

- **R1（红线③）**：在演示/校验/生产部署**显式开启** `KG_ENABLED`/`RAG_ENABLED=true`，配 `DEEPSEEK_API_KEY` 与课程索引；将默认 false 改为"未配置密钥时仍走有资料的抽取式+诚实兜底"，而非纯 LLM。**2026-11-05 已落地**：`.env.example` 不再写死 `false`，本机启动器按端口可达自动置 true；compose 保留 `${VAR:-false}` 兜底，生产仍须显式开启。
- **R2（红线③兜底）**：`AiRagComponent.java:49-53` 纯 LLM 回落分支要么注入课程资料/图谱子图，要么显式声明"无知识库"并输出"我不知道"，**禁止用客套话伪装 AI 已答**。
- **R3（差异化主张）**：把知识图谱真正接入 `rag_engine.ask`（当前 `search()` 不碰图）——落地 GraphRAG 多跳增强，否则"图谱驱动"在评测中必然失分。**2026-11-05 已落地**：`graph_sources()` 按 `RAG_GRAPH_ENABLED`（默认 true）拉课程节点，关键词命中后带 1 跳关系并入 ask 证据；KG 不可达静默退化。
- **R4（红线②盲区）**：`LearningPathMasteryComponent.java:80` 写死公式改为"图谱节点兜底统计"或显式降级标记，移除静默写死；`:84` 异常改为可观测日志 + 明确降级。
- **R5（文档对齐）**：开题稿/PPT 已把 LoRA/FAISS/Neo4j 当"已实现"陈述（C3），结题/答辩须对齐实际（策展式图谱、Python 引擎主体），防互联网+ 十不准"虚假陈述"。
