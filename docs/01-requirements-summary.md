# AI智能课程平台需求梳理

## 一、开发约束

- 新项目独立开发，旧项目只作为业务、文档、表结构和历史缺陷参考。
- 持久层统一使用 MyBatis-Plus，不引入 JPA 依赖，不使用 JPA 注解、Repository、EntityManager。
- 后端沿用旧项目主版本：Spring Boot 3.2.0、Java 17、MySQL 8、Spring Security + JWT、Redis 可选、DeepSeek AI。
- 统一响应、统一异常、权限框架、工具类设计沿用思想但重新手写。

## 二、角色与权限

| 角色 | 枚举 | 核心职责 |
|---|---|---|
| 管理员 | ADMIN | 用户管理、课程审核、权限管理、系统配置、备份、日志、监控、全平台分析 |
| 教师 | TEACHER | 课程、章节、资源、作业、考试、题库、知识点、学情分析、AI出题 |
| 学生 | STUDENT | 选课、学习、作业提交、考试、成绩查看、错题本、学习路径、AI问答 |

公开接口包括登录、注册、验证码、健康检查、占位图、Swagger。管理员接口限定 ADMIN；题库和教师分析限定 TEACHER/ADMIN；其他业务接口要求登录。

| 模块 | 功能范围 |

## 四、优先修复点

- 备份恢复必须使用可靠输入重定向，避免把 `<` 当作 ProcessBuilder 参数。
- 考试结果选项要解析 JSON 数组，不能把整个 options 写入 optionA。
- 会话创建使用线程池或 `@Async`，不使用裸线程。
- 管理员初始化只在用户不存在时执行，不允许每次启动重置密码。
- 监控、学情统计、进度统计必须基于真实数据。
- 知识图谱边基于 `knowledge_point_relations`，不能只按同课程硬连。
- 资源不存在统一抛 `ResourceNotFoundException`。
- 前端补齐考试作答路由，统一知识图谱版本，逐步移除 Mock 回退。

## 五、MP迁移规则

- Entity 使用 `@TableName`、`@TableId(type = IdType.AUTO)`、必要的 `@TableField`。
- Mapper 统一继承 `BaseMapper<T>`，复杂查询优先使用 `LambdaQueryWrapper`、`Page`，跨表统计用 XML。
- Service 接口继承 `IService<T>`，实现类继承 `ServiceImpl<Mapper,T>`。
- 分页统一使用 MP `Page<T>`，返回层再转换为 `PagedResponse<T>`。
- 枚举字段存储字符串；JSON字段先以 `String` 承载，后续可引入自定义 TypeHandler。
