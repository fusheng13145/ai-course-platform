# PRD：试卷创建—发布—批阅核心闭环（简单增量 PRD）

- 项目：ai-course-platform
- 日期：2026-10-26
- 作者：产品经理 许清楚（Xu）
- 需求来源（项目主原话）：「本项目核心需求包括试卷的创建、编辑和批阅功能，请优先实现这些功能模块，尽快落实可用的核心流程。」
- 口径：**增量 PRD**，只写变更与新增；后端 API 已全备，本批预计**后端零改或极小改**，工作量集中在前端页面流补链。

---

## 1. 产品目标

教师能在系统内独立完成：

> **创建试卷（手动选题或自动组卷）→ 发布 → 学生提交 → 教师批阅（打分 / 退回 / AI 辅助）** 的可用闭环。

- G1：批阅流程断链补全——后端 `grade`/`return`/`ai-grade` 均已就绪，但前端无任何批阅入口，本批必须打通「待批阅列表 → 逐份批阅」页面流（P0）。
- G2：试卷创建/编辑能力对齐后端——现役表单仅 4 字段，需补选题（questions）与发布（publish）入口（P0），自动组卷入口 P1。
- G3：学生端只补「提交与成绩可见」的最小缺口，不做任何增强。

## 2. 用户故事

**教师**
- T1：作为教师，我想在课程内新建/编辑试卷并从题库中**选题**组卷，以便控制试卷内容与总分。
- T2：作为教师，我想对选定题目**一键自动组卷**（按题型/数量/难度），以便快速生成试卷初稿再微调。
- T3：作为教师，我想在试卷列表中**发布**试卷，以便学生端可见并可作答/提交。
- T4：作为教师，我想看到课程的**待批阅列表**，并逐份打分、写评语，以便及时反馈。
- T5：作为教师，我想对不合格的提交**退回重做**（附退回理由），以便学生修改后重新提交。

**学生**
- S1：作为学生，我想在已发布的试卷/任务下**提交**我的作答，以便进入批阅流程。
- S2：作为学生，我想在成绩页**查看我的得分与教师评语**，以便了解学习效果。

## 4. UI 设计稿（文字线框）

### 4.1 批阅工作流挂载位置判定

**结论：挂在 `components/CourseGradesTab.vue`（课程空间内），而非独立的 `teacher/Grades.vue`。**

理由：
1. `CourseGradesTab.vue` 已有「待批阅任务」统计（`overview.pendingCount`）与 `pendingTasks` 数据流，入口天然存在，只差点击后的下钻页面——改造成本最低；
2. 批阅对象以课程/任务为维度（接口是 `/submissions/task/{taskId}`），批阅动作发生在课程上下文中最顺；
3. `teacher/Grades.vue` 偏全局成绩汇总视角，塞入逐份批阅操作流会让职责混杂。可在 Grades.vue 放一个跳转链接（P2）。

### 4.2 批阅工作流页面结构

```
CourseGradesTab（现有）
├─ 概览卡：待批阅数 pendingCount（已有）
└─ [新增] 待批阅任务列表
     └─ 每行：任务名｜提交 n/总 m｜未批 k｜[去批阅] → 点击下钻
          ↓
GradingWorkspace（新页面/新面板，P0-1 主体）
├─ 左列：学生提交列表（该任务下，按状态分组：待批/已批/已退回/已重交）
│        顶部筛选：全部｜待批阅｜已批阅｜已退回
├─ 右列：批阅详情（选中单个提交）
│    ├─ 学生作答内容展示（文本/附件）
│    ├─ [P1] AI 预批按钮 → 展示建议分+建议评语，可一键填入
│    ├─ 打分输入（≤ 总分）+ 评语 textarea
│    └─ 操作按钮：[提交批阅](POST grade)｜[退回重做](POST return，需填退回理由)
└─ 批阅提交后：左列该行状态实时更新，未批计数 -1
```

### 4.3 试卷创建/编辑与发布

```
CourseExams.vue（现有宿主）
├─ 试卷列表（已有）
│    └─ [新增] 行内操作列：[编辑]｜[发布]（草稿态显示；二次确认）｜状态标签：草稿/已发布
└─ CeExamFormDialog（扩展，P0-3）
     ├─ 原有：标题 / 描述 / 时长 / 总分
     ├─ [新增] 题目选择区：题库列表（按题型筛选）+ 勾选 + 已选题目清单
     │        底部实时合计：已选 n 题，合计 x 分（与「总分」字段校验一致性）
     └─ [P1] 「自动组卷」按钮：弹小表单（题型×数量×难度）→ 调 auto-compose 回填已选清单
```

### 4.4 学生端最小面

- 现状学生提交 API（`submitTask`、`getMySubmissions`）与 `student/academic/Grades.vue` 已存在。本批**只补缺**：确认学生端在「已发布试卷/任务」下有提交入口、成绩页能看到教师批阅后的分数与评语；若现状已有则零改动。实现前先做一次现状走查（见 Q5）。

## 5. 待确认问题（需项目主拍板）

1. **批阅对象口径**：本批批阅工作流面向「作业任务提交」（`/submissions` 体系）即可，还是同时要求覆盖「考试卷面」的批阅？考试卷面批阅走的是 exam-sessions 的 `manualGrade/autoGrade`（`api/exam.ts` 已封装），是另一条链路。**建议本批只做作业提交批阅，考试卷面批阅另行立项。**
2. **退回语义**：退回（return）后是否允许学生无限次重交（resubmit）？是否需要退回理由必填、以及退回后学生端是否有强提醒？
3. **AI 批阅优先级**：`ai-grade` 放 P0 还是 P1？主理人建议 P1，但从演示价值看 AI 辅助批阅是本项目亮点，若项目主希望「核心流程即卖点」可提到 P0（改动很小：一个按钮+结果回填）。
4. **成绩落账口径**：批阅打分后成绩是否需要同步写入 GradeController 体系（policy/item/final），还是批阅分数仅停留在 submission 上、总评由 `/grade/final` 单独计算？这决定 P0-1 是否需要在 grade 成功后追加一次成绩项落账调用。
5. **学生端现状走查**：S1/S2 的「只补缺」需要一次快速现状走查确认学生提交入口与成绩可见性到底缺多少——请项目主确认由谁在开发前执行（可并入开发任务第一步）。

## 6. 明确不做（本批）

- 成绩报告可视化、班级/课程维度成绩分析（P2-1）。
- 试卷复制、试卷统计分析入口（P2-2）。
- 考试监考、防作弊、考试会话相关任何增强。
- 题库管理本身的改造（选题只消费现有题库）。
- 移动端适配、i18n、主题美化等一切与闭环无关的工作。
- 孤儿组件 `ExamFormDialog.vue` 的启用或删除（保持原样，仅保留追溯记录）。

## 附：验收最小集（P0 完成定义）

1. 教师可新建试卷并勾选题目，保存后列表可见、可再次编辑回显已选题目。
2. 教师可对草稿试卷点击发布，状态变为已发布。
3. 教师在 CourseGradesTab 看到待批阅任务，下钻后可对任一提交打分提交，未批计数随之变化。
4. 教师可退回一个提交并填写理由；学生重新提交后该提交回到待批队列。
5. 全程不新增/修改任何后端 Java 代码（若发现接口字段缺口，先回报再定）。
