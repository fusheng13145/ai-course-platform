# §2 运行方式（四套已验证配方）

## 2.1 后端（含 8080 冲突时的并行端口方案 ★）

- 常规：`start.bat backend` → 8080。
- **8080 被占用时（现状：被 `课程作业\超市销售管理系统` 占用）**：用打包 jar 在 8081 拉起（本机当前常驻 PID 见 §10）：
  ```
  cd backend && mvn -q package -DskipTests
  # env（完整清单见 docs/前端待办项.md §2.0d）：
  #   SPRING_DATASOURCE_URL=jdbc:mysql://localhost:3306/ai_course_platform?...allowPublicKeyRetrieval=true
  #   SPRING_DATASOURCE_USERNAME=aicourse_app  SPRING_DATASOURCE_PASSWORD=<.env>
  #   JWT_SECRET/DEMO_ACCOUNTS_ENABLED=true/COOKIE_SECURE=false/REQUIRE_HTTPS=false
  #   CSRF_ENABLED=false/RATELIMIT_LOGIN_LIMIT=200/NO_PROXY=localhost,127.0.0.1
  java -jar target/backend-0.0.1-SNAPSHOT.jar --server.port=8081
  # 探针：curl --noproxy '*' http://127.0.0.1:8081/api/actuator/health/probe  → 200
  ```
- 前端代理指并行后端：`VITE_PROXY_TARGET=http://127.0.0.1:8081`（`vite.config.ts` 支持，缺省 8080 不变）。
- 健康探针**必须打 probe 组**（readinessState+database+redis+diskSpace），别打综合 /health
  （无 DEEPSEEK_API_KEY 时综合状态恒 503，不是故障）。

# §9 后续维护要点（纪律即资产）

1. **文档-代码对账是本仓最高纪律**：改动落地必须同步对应台账（DR 编号在 项目手册 §7；批次记录在 前端/后端待办项）；
   "待扩展≠已具备"，禁预填"通过"。
2. **不可宣称清单**（AGENT.md §7）逐条遵守——尤其：本机绿≠CI 绿、本机压测≠生产容量、"引擎可用"≠"8B 已微调"。
3. **每批收尾验证链**：lint → format:check → typecheck → test → build → size:gate →（涉像素）视觉两轮（§7-10）。
4. **棘轮只许向紧**：体积预算/覆盖率阈值/类型基线不降；视觉字面量豁免清单改动须先落账。
5. **DR 台账**：每个缺陷/决策登记编号并留实跑读数——这是本项目十轮迭代零回归的机制基础。
6. **接手首周建议**：跑齐 §2.2 全部门禁建立自己的基线读数 → 按 §5.1 排第一批 → 从 DR 台账倒序读 10 条理解近期决策。
