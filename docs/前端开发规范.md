# 前端开发规范

> **文档定位**：本文件规定前端（Vue 3 + TypeScript + Vite）的目录、组件、状态、请求、样式、可访问性、测试与构建约定，是页面开发与代码评审的落地依据。系统结构与技术决策见 [系统架构设计.md](系统架构设计.md)；后端接口约定见 [后端开发规范.md](后端开发规范.md)；质量门读数见 [测试文档.md](测试文档.md)。
>
> **适用范围**：`frontend/src/**`、`frontend/e2e/**`、`frontend/scripts/**`、`frontend/*.ts`。历史 `lang="js"` 组件在改动时逐步迁移到 TypeScript，不要求一次性重写。

---

## 1. 环境与脚本

| 项 | 要求 |
| --- | --- |
| Node.js | ≥ 20.19 |
| 包管理 | npm（锁文件入库） |
| 开发 | `npm run dev`（5173；视觉 5175） |
| 构建 | `npm run build` |
| 单测 | `npm run test`（Vitest） |
| 端到端 | `npm run test:e2e`（Playwright，需后端就绪） |
| 类型 | `npm run typecheck`；门禁 `npm run typecheck:gate` |
| 代码规范 | `npm run lint`、`npm run format:check` |
| 包体 | `npm run build && npm run size:gate` |
| API 引用 | `npm run lint:api-refs` |

**依赖纪律**：

- Element Plus 固定 `2.14.7`、Playwright 固定 `1.63.0`；不得擅自升级。
- 新增依赖先证明必要性：能否用现有依赖/原生能力实现；评估包体、许可证、维护状态。
- 重量级库必须动态加载（如 xlsx）或按需引入（如 ECharts）；不得进入首屏主块。
- 不引入第二个 UI 组件库；基础控件统一 Element Plus，弹层等关键件用 `components/ui/`。

## 2. 目录与命名

```text
src/
├─ api/            43 个请求模块（按业务域）
├─ components/     复用组件；ui/ 为自研原语
├─ composables/    页面编排与复用逻辑（约 85 个）
├─ layouts/        三端壳层、侧栏/顶栏、菜单、图标
├─ router/         路由与守卫
├─ stores/         Pinia（仅 auth.ts 全局）
├─ styles/         设计令牌与主题
├─ types/          共享类型
├─ utils/          无状态工具
├─ views/          页面（student / teacher / admin / auth / common / error）
├─ onboarding/     引导步骤、锚点、几何、状态
└─ monitoring/     错误上报
```

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| Vue 组件文件 | PascalCase；按域前缀 | `CeExamFormDialog.vue`、`CgtGradeDialog.vue` |
| UI 原语 | `components/ui/Xxx.vue` | `Modal.vue`、`Drawer.vue`、`TabGroup.vue` |
| composable | `useXxx.ts`，导出同名函数 | `useFormSubmit.ts` |
| API 模块 | 小写域名 | `submission.ts`、`exam.ts` |
| store | `useXxxStore` | `useAuthStore` |
| 工具 | 小驼峰文件名 | `requestError.ts`、`loadingBar.ts` |
| 类型 | 大驼峰 `Xxx` / `XxxProps` | `SubmissionRow` |
| 测试 | `*.test.ts`，与源码同域 `__tests__/` | `Modal.teleport.test.ts` |
| e2e | `*.spec.ts`，按流程命名 | `teacher-grade.spec.ts` |

- 组件前缀按业务域固定（如 `Ce` 课程试卷、`Cgt` 课程成绩页、`Cd` 课程详情、`Lp` 学习路径、`Tsv` 教学监督、`Aia` AI 助手），不要新造无人认识的前缀。
- 页面组件命名 `Xxx.vue`，不放 `Page` 后缀；路由名与菜单标题对应。
- 禁止拼音命名与 `temp`/`data1` 式命名。

## 3. 单文件组件（SFC）

### 3.1 结构顺序

```vue
<template>
  <!-- 模板 -->
</template>

<script setup lang="ts">
// 逻辑
</script>

<style scoped>
/* 仅本组件样式 */
</style>
```

- 新组件一律 `<script setup lang="ts">`；`<script setup>` 不允许 `this`。
- 组件顶层只放：`defineOptions`、`props`、`emits`、`computed`、生命周期、方法；复杂逻辑抽 composable。
- `defineProps` / `defineEmits` 必须显式声明；禁止依赖 `$attrs` 隐式传参作为主要契约。
- 需要默认值的 prop 用 `withDefaults` 或运行时 `default`；Boolean prop 缺省且需要“未传 ≠ false”时显式 `default: undefined`（参见 `Modal`/`Drawer` 的 `modelValue`）。
- 不要用 Vue 保留名做 prop（`style`、`class`、`key`、`ref`）；需要样式变体时用 `variant`。
- 禁止直接修改 prop；需要派生值用 `computed`，需要双向绑定用 `v-model` + emit。
- `v-html` 必须配 DOMPurify 清洗；无清洗不得使用（ESLint 会警告）。
- `console.log/info/debug` 禁止提交（允许 `console.error/warn`）；调试代码删除或加 `eslint-disable` 并说明。

### 3.2 事件与 v-model

- 表单类组件默认 `modelValue` + `update:modelValue`；关闭类事件同时提供 `close` / `closed`（离场后）。
- 事件名用小驼峰（模板中用 kebab-case 监听）。
- 子组件不得直接调用父组件方法；通过事件或 provide/inject（限壳层）通信。
- 同一事件不要同时向父级转发两条语义重复的腿（参见 `Drawer` 的受控关闭约定）。

### 3.3 组件边界

- 页面只编排：取数、状态、布局、子组件组合；可复用逻辑下沉 composable，可复用视图下沉组件。
- 单文件建议 ≤ 500 行；超过按“列表 / 表单 / 弹层 / 图表”拆分。
- 业务组件不得反向依赖页面；`components/` 不 import `views/`。
- 弹层/抽屉/标签页只能使用 `components/ui/` 原语；禁止新增 `el-dialog` / `el-drawer` / `el-tabs`（守卫扫描全仓，当前 0 命中）。

## 4. UI 原语与弹层

### 4.1 可用原语

| 原语 | 用途 | 关键契约 |
| --- | --- | --- |
| `Modal` | 对话框 | `v-model`、`width`、`title`、`@close`、`@closed`；默认 Teleport 到 body；焦点陷阱、滚动锁、Esc 共享栈、z-index 分层 |
| `Drawer` | 侧滑抽屉 | 同 Modal 的可见性/宽度/标题/事件语义；`teleported` 默认 true |
| `TabGroup` | 标签页 | `variant` 区分样式；内容显隐等价 `el-tabs` 的“全部挂载、隐藏非活动”语义 |
| `StatCard` | 指标卡 | 统一数值/单位/趋势展示 |
| `CollapsePanel` | 折叠面板 | 受控展开状态 |
| `DropdownMenu` | 下拉菜单 | 键盘可达、点击外部关闭 |
| `TreeView` | 树 | 展开/选中/键盘导航 |
| `EmptyState` | 空态 | 图标、标题、描述、动作插槽 |
| `ExcelImportDialog` | 导入 | 文件选择、校验、错误行展示 |

### 4.2 弹层规则

- `Modal` / `Drawer` 的 `v-model` 为受控可见性；`false` 才关闭，未传按“打开”处理（兼容 `v-if` 调用点）。
- 不要给 `Modal` 根直接挂 `v-loading`：根是 Teleport 非元素节点，指令无处安放；在弹层内部包一层容器。
- 层叠：`--z-modal 2200`、`--z-drawer 2250`、`--z-shell-menu 2500`；Element Plus 内部弹层由根级 `el-config-provider :z-index="2300"` 保证在自研弹层之上。
- Esc 只关栈顶弹层；打开期间才监听 document；关闭后移除监听。
- 焦点：打开时聚焦首个可聚焦元素，关闭后归还触发元素；滚动锁按引用计数，多个弹层不互相解锁。
- 需要嵌在带 `transform/filter` 容器内的弹层，必须 Teleport 到 body（默认行为），不要关掉 `teleported` 除非明确需要继承层叠上下文。
- 删除/危险操作必须有二次确认；确认文案写清对象与后果，禁止“确定/取消”式模糊确认。

## 5. 路由与布局

- 路由 `meta` 必填：`requiresAuth`、`role`（需要时）、`title`、`breadcrumb`。
- 守卫顺序：登录态 → 角色 → 目标路由；未登录去 `/login`，角色不符去对应端首页，后端不可达去 `/503`，未知路径 `/404`。
- `/503` 必须 `requiresAuth: false`，否则守卫会再次发起会话探针形成轮询环。
- 页面切换时取消未完成请求（`cancelAllPendingRequests`），避免旧响应覆盖新页面。
- 三端壳层共用 `AppShell`；导航菜单与图标只在 `layouts/menus.ts` / `layouts/icons.ts` 定义，页面不重复写导航。
- 路由懒加载：页面级 `() => import(...)`；首屏只加载登录/壳层必要模块。

---

## 6. 状态管理

- 全局 store 只有 `auth`；其他状态放页面/composable。
- 权限判定以服务端 `/auth/permissions` 响应为准；本地缓存只用于渲染，`permissionsLoaded` 只由真实响应置位，不得由 localStorage 恢复。
- 前端角色只用于显示与路由分流，**不作为授权凭据**；按钮权限同样 fail-closed。
- 不在模块顶层保存可变单例（跨页泄漏）；需要共享时用 store 或显式参数。
- 不把令牌写入 localStorage/sessionStorage（令牌在 HttpOnly Cookie）；只持久化非敏感的用户展示信息。

## 7. 请求层

### 7.1 分层

```text
页面 / composable
  → api/<域>.ts（命名导出 + default 对象）
  → api/request.ts（axios 实例）
      baseURL `/api`、withCredentials、XSRF-TOKEN/X-XSRF-TOKEN
      请求取消、重试、统一错误提示、信封解包
```

- 页面不得直接 `import axios`；一律经 `api/` 模块。
- API 模块只做 URL/参数/方法封装，不写业务状态与提示。
- 每个模块同时提供命名导出与 default 对象，保持调用方两种写法兼容。
- 路径必须与后端一致；新增/修改后跑 `npm run lint:api-refs`。

### 7.2 错误处理

- 统一错误文案在 `api/request.ts` + `utils/requestError.ts`，页面不拼接 axios 原始英文错误。
- 401：清理登录态并跳转登录；403/404/429/500/503 按统一中文提示。
- 网络错误与 502/503/504 自动重试一次；非幂等方法不得盲目重试。
- 页面必须显式处理三态：加载中、空数据、加载失败；**失败不得渲染成“暂无数据”**。
- 列表失败用 `useListFeedback` 统一错误态与重试；弹窗失败保留用户输入。
- 不在 catch 中静默吞错；至少记录并给用户可操作提示。

### 7.3 表单

- 表单提交统一 `useFormSubmit`：防重复提交、首错定位、错误提示、提交中状态。
- 校验规则就近声明；跨字段校验在提交前统一执行。
- 提交按钮 `:loading` 绑定提交状态；成功后关闭弹层并刷新列表；失败保持打开。
- 危险操作二次确认；确认后仍有失败提示与回滚路径。

### 7.4 分页

- 服务端分页用于数据量无上限的列表（默认选择）。
- `useClientPagination` 只用于已经一次性取全的数据（如课程名册、成绩簇）；不得用它掩盖未分页的后端接口。
- 分页参数统一 `page`（从 1 开始）/`size`；与后端 `PagedResponse` 对齐。
- 需要“全量导出/统计”时使用显式的 `getAllXxx` 分页遍历，不把 `size` 调到超大。

## 8. 样式与设计令牌

### 8.1 令牌

| 族 | 用途 |
| --- | --- |
| 颜色/表面 | `--bg`、`--surface-*`、`--text-*`、`--line-*`、品牌色 |
| 圆角 | 五阶 16/12/10/6/999；默认控件 `--r-ctl` 10、small 9、tag 6 |
| 阴影 | `--sh-l1`/`--sh-l2`/`--sh-pop`；暗色卡面不投影，弹层保留 |
| 间距 | `--ac-spacing-*`；页面/卡片/控件三级 |
| 动效 | `--ease-spring`、`--t-xslow`；禁用动画走 `prefers-reduced-motion` |
| 层叠 | `--z-modal` / `--z-drawer` / `--z-shell-menu` |

规则：

- 颜色、圆角、阴影、间距优先用令牌；新增硬编码值前先确认令牌是否缺失，缺失则补令牌而不是就地写死。
- 局部样式用 `<style scoped>`；跨页共享类放 `styles/`；Element Plus 覆写集中在 `index.scss`，不得在页面用 `!important` 打架。
- 深色/浅色必须同时验证；不得只在一个主题下可读。
- 禁止用颜色作为唯一状态信号（配合文字/图标）。
- 响应式：以 1440×900 为设计基准，窄屏至少保证 375 宽可用；弹层宽度用 `width` 档或 min/max，不写死超出视口的 px。
- 不使用 `position: fixed` 的页面级元素覆盖壳层导航；需要时用弹层原语。

### 8.2 可访问性

- 图标按钮必须有 `aria-label`；装饰图标 `aria-hidden="true"`。
- 表单控件必须有 label 或 `aria-label`；错误提示与控件关联。
- 键盘可达：可点击元素优先用 `<button>`/`<a>`；自定义控件支持 Enter/Space。
- 焦点可见：不得全局移除 `:focus-visible` 轮廓；弹层内焦点陷阱、关闭后归还。
- 状态变化用 `aria-live` 播报（`useAnnouncer`）；加载态用 `aria-busy`。
- 文本对比度 ≥ 4.5:1（大字号 ≥ 3:1）；不得仅靠 hover 暴露关键操作。
- 动画尊重 `prefers-reduced-motion`；自动播放/轮播可暂停。

## 9. 性能

- 路由级懒加载；大组件/图表/导出库动态 `import()`。
- 列表渲染超过 ~100 行时考虑虚拟滚动或分页；不得无界渲染全量数据。
- 图片使用适当尺寸与懒加载；不在模板中做重计算，放 `computed`。
- 避免在 `watch` 中做深度遍历大对象；必要时用 `watchEffect` + 明确依赖。
- 新增第三方库前先看 `npm run build && npm run size:gate` 的增量；超预算必须说明理由并调整分块。
- 不把整库引入（如 `import _ from 'lodash'`）；按需导入。
- ECharts 实例在 `onBeforeUnmount` 销毁；事件监听在卸载时移除。

## 10. 测试

### 10.1 单元/组件测试（Vitest）

- 文件放 `__tests__/`，命名 `Xxx.test.ts`；与被测文件同域。
- 使用 `@vue/test-utils` 挂载；断言用户可见行为（文本、角色、事件），不测实现细节。
- 必须覆盖：空态、加载态、错误态、权限拒绝、边界输入。
- 弹层测试注意 Teleport：必要时 `stubs: { teleport: true }` 或挂到 `document.body`；`Transition` 需 `stubs: { transition: false }` 并 mock `requestAnimationFrame`。
- 不 mock 被测组件自身的子组件行为到“只剩快照”；关键交互要真实触发。
- 快照只用于稳定结构，不替代行为断言。

### 10.2 端到端（Playwright）

- 流程 spec 放 `e2e/`，按业务链路命名；选择器优先 `getByRole` / `getByLabel` / 稳定的 `data-testid`，避免依赖样式类与 DOM 层级。
- 前置：后端 8080 就绪、`RATELIMIT_LOGIN_LIMIT=200`、前端 5173；`.auth` 夹具与端口绑定，跨端口需重绑。
- 不写固定 `sleep`；用 `expect(...).toBeVisible()` / `waitFor`。
- 每个 spec 独立登录态，不依赖执行顺序；测试数据可重复创建/清理。
- 新增页面若纳入视觉回归，需同时加锚点、遮罩与基线，不能只加流程用例。

### 10.3 视觉回归

- 配置：`playwright.visual.ts`，1440×900、DPR 1、`reducedMotion: reduce`、冻结时钟；独立端口 5175。
- 基线：12 锚点 × 明暗 = 24 张；`threshold: 0`、`maxDiffPixelRatio: 0.0001`。
- 全页：`expandViewportToContent` 扩展到内容实高（封顶 8000），只改高度、不重跑 settle。
- 钉桩：固定接口响应；动态角标必须遮罩；新增动态元素先加遮罩再录基线。
- 变更样式/令牌/结构后，受影响基线全量重录并逐张看图；至少连续两轮通过才算绿。
- 不把视觉证据（截图、report、sequence）当作文档常驻内容。

### 10.4 类型与静态检查

- 新代码必须通过 `vue-tsc`；`typecheck:gate` 棘轮只降不升（当前 0）。
- `any` 仅限无法定型的边界，且加注释说明；优先 `unknown` + 收窄。
- Props/Emits/返回值显式定型；API 响应信封在 api 层定型，页面不重复 `as any`。
- ESLint 0 问题、Prettier 干净；`v-html` 警告必须消除或说明清洗来源。

---

## 11. 注释与文档

- 注释只写“为什么/边界”，一两句封顶；不复述模板结构，不写“阶段 N”“§章节”“台账编号”等出处。
- 复杂兼容逻辑（如 Teleport、焦点陷阱、v-model 双通道）可写简短说明，但以“读代码的人需要知道什么”为准。
- 修改行为时同步更新：页面说明、路由 meta、API 模块注释、相关测试；跨端影响写入待办。
- 不提交调试输出、被注释代码块、无负责人的 TODO。
