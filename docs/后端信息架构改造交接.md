## 0. 一页结论

当前后端是**以课程为中心**的模型：`courses.teacher_id` 表示唯一授课教师，`users.class_id` 指向 `classrooms`，`classrooms.course_id` 又把行政班和课程绑在一起，`course_enrollments` 只有学生—课程关系，任务、试卷、讨论、成绩方案都只挂 `course_id`。它能支撑现有单课程闭环，但不能表达目标 IA 的四个核心区分：

1. **组织实体**：学校 → 学院 → 专业 → 行政班；目前没有 `schools / colleges / majors / admin_classes`，`users.department / users.major / classrooms.major` 是自由文本。
2. **行政班 ≠ 教学班**：目前 `classrooms` 同时承担行政班和“课程绑定班级”，`classrooms.course_id` 是混淆点；目标要拆成 `admin_classes` 与 `teaching_classes`。
3. **课程 ≠ 教学班**：一个课程可有多个教学班，一个教学班只有一个主讲教师；目前 `courses.teacher_id` 是唯一教师，没有教学班维度。
4. **管理员有作用域**：目前 `ADMIN` 是单一角色，`/admin/**` 只有 `hasRole('ADMIN')`，没有校级/院系级数据范围；`role_permissions` 也只有角色键。

**建议方案**：采用 expand–contract（先加表/列、回填、切换、最后收紧约束），新增 10 张表，分 V12–V16 五个结构迁移版本 + 一个后置清理迁移；保留现有课程/任务/考试/成绩主链，避免一次性重写。最关键的 5 个决定：

- 单校部署，显式 `schools` 根；**不引入 `tenant_id` / 多租户**。
- 保留 `ADMIN` 角色，新增 `users.admin_scope`（`SCHOOL` / `COLLEGE`）与 `users.college_id`；JWT 过滤器按数据库现行用户附加 `SCOPE_ADMIN_*` authority。
- `courses.teacher_id` 保留为**课程负责人/创建教师**；新增 `teaching_classes.lead_teacher_id` 作为教学班主讲。一个课程可有多个教学班、多个主讲。
- `classrooms` 迁移为 `admin_classes`；`course_enrollments` 增加 `teaching_class_id`，继续作为学生—课程成员表（一个学生在一门课中只属于一个教学班）。
- 课程级内容（章节、资源、题库、知识点、成绩方案）留在课程；任务、试卷、讨论、成绩明细增加教学班目标/快照。

## 1. 目标模型

### 1.1 实体链

```text
School 1 ── n College 1 ── n Major
   │
   └─ 1 ── n AdminClass（行政班）
                 │ advisor_teacher_id（教师职责，不是角色）
                 └─ n Student（users.admin_class_id）

Semester 1 ── n Course（学期开课）
                 │ college_id
                 │ teacher_id = 课程负责人 / 创建教师
                 └─ 1 ── n TeachingClass（教学班）
                             │ lead_teacher_id（唯一主讲）
                             ├─ n TeachingClassAdminClass（来源行政班，多对多）
                             └─ n CourseEnrollment（学生成员，一个学生一门课一条）
```

### 1.2 术语与边界

| 术语 | 定义 | 不承担什么 |
| --- | --- | --- |
| 学校 `schools` | 单校部署的根实体，锚定学院、学期、课程与管理员范围 | 不做多租户隔离；不把学校当成第二个后台 |
| 学院 `colleges` | 课程审批的组织归属；院系管理员的数据边界 | 不是课程；不是行政班 |
| 专业 `majors` | 学院下的专业归属，用于行政班/学生画像 | 不单独承载课程名单 |
| 行政班 `admin_classes` | 学生学籍归属、年级/专业、班主任工作对象 | **不绑定课程**；不放课程名单；不承载批阅/成绩 |
| 学期 `semesters` | 课程开课的时间归属；沿用现有 `semesters` 表 | 不再允许 `courses.semester` 自由文本作为事实源 |
| 课程 `courses` | 某一学期的开课；课程级内容、课程审批 | 不再承担“唯一授课教师/唯一班级”的语义 |
| 教学班 `teaching_classes` | 课程下的开课单元，一个主讲、名单、容量、状态 | 不是行政班；不承载跨课程组织信息 |
| 课程负责人 `courses.teacher_id` | 创建/负责课程的教师；可管理课程内容与教学班 | 不等于所有教学班的主讲 |
| 主讲教师 `teaching_classes.lead_teacher_id` | 教学班唯一主讲，负责本班教学活动与批阅 | 不自动拥有同课程其他教学班的数据 |
| 班主任 `admin_classes.advisor_teacher_id` | 教师职责：班级画像、学生预警、班级通知 | **不是登录角色**；不批阅、不改成绩、不编辑课程内容 |
| 管理员作用域 `users.admin_scope` | `SCHOOL` 校级 / `COLLEGE` 院系级 | 不是新的登录角色；不替代 `ADMIN` 角色 |
| 教学班来源 `teaching_class_admin_classes` | 教学班从哪些行政班导入名单 | 不是学生成员表；不替代 `course_enrollments` |

### 1.3 课程级内容与教学班活动

| 数据 | 归属 | 目标做法 |
| --- | --- | --- |
| 章节 `course_chapters` | 课程级 | 保留 `course_id`，所有教学班共享 |
| 资源 `resources` | 课程级 | 保留 `course_id` / `chapter_id`；需要班级可见性时另加目标（本批不默认做） |
| 题库 `questions` | 课程级 | 保留 `course_id`，不按教学班拆题库 |
| 知识点/图谱 | 课程级 | 保留 `course_id`，不按教学班复制 |
| 成绩方案 `grade_policies` | 课程级 | 保留 `course_id`；成绩明细按学生/教学班过滤 |
| 作业/任务 `tasks` | 课程级定义 + 教学班发布目标 | 新增 `visibility`（`COURSE` 默认 / `CLASSES`）；`CLASSES` 时用 `task_teaching_classes`；提交与批阅带 `teaching_class_id` 快照 |
| 试卷 `exam_papers` | 课程级定义 + 教学班目标 | 新增 `visibility`（`COURSE` / `CLASSES`）；`CLASSES` 时用 `exam_teaching_classes`；考试场次带 `teaching_class_id` 快照 |
| 讨论 `discussion_topics` | 课程级或教学班级 | 新增可空 `teaching_class_id`；为空表示课程级讨论 |
| 提交 `submissions` | 学生 + 任务 + 教学班 | 新增 `teaching_class_id` 快照 |
| 考试场次 `exam_sessions` | 学生 + 试卷 + 教学班 | 新增 `teaching_class_id` 快照 |
| 任务点完成 `task_completions` | 学生 + 任务 + 教学班 | 新增 `teaching_class_id` 快照 |
| 成绩明细 `grade_items` | 方案 + 学生 + 教学班 | 新增 `teaching_class_id` 快照 |
| 监考 `proctor_sessions` | 考试场次派生 | 不新增列；通过 `exam_sessions.teaching_class_id` 追溯 |

**原则**：课程级内容不复制到每个教学班；教学班只决定“谁可见、谁提交、谁批阅、统计按哪个班”。课程级任务/试卷用 `visibility=COURSE`，新建教学班自动继承；只有需要班级隔离时才用 `CLASSES` + 目标表。这样课程内容不会因班级增加而分叉，历史成绩也不会因学生转班而失去归属。

## 2. 现状盘点（as-is）

### 2.1 数据结构事实

| 现状 | 代码/表证据 | 后果 |
| --- | --- | --- |
| 用户只有 `class_id` 指向 `classrooms` | `User.classId`、`classrooms` | 学生只能有一个“班级”；没有学院/专业外键 |
| `classrooms.course_id` 可空 | `Classroom.courseId`、V1 | 行政班和课程绑定班共用一张表；同一行可能被当作两种实体 |
| 课程唯一教师 | `Course.teacherId`、`courses.teacher_id NOT NULL` | 无法表达“一课程多教学班、多主讲” |
| 课程学期是自由文本 | `Course.semester`、V1；V9 明确未绑定 | 学期无法被可靠筛选/归档；新表无法自动猜映射 |
| 课程编号全局唯一 | V1 `uk_courses_code` | 与“课程编号按学期唯一”的目标不一致 |
| 选课只有学生—课程 | `CourseEnrollment`、V1 `uk_course_enrollments_student_course` | 没有教学班名单；无法按班批阅/统计 |
| 课程审批只有结果字段 | `courses.approval_status / approval_time / approved_by / approval_comment` | 没有审批流水；`approveCourse`/`rejectCourse` 当前未写入 `approved_by`；`CourseController.list` 也没有审批状态/学院过滤，待审批队列需前端自行筛选 |
| 管理员只有 `ADMIN` | `RoleConstants` 只有 `ADMIN/TEACHER/STUDENT` | 没有校级/院系级数据边界 |
| 权限目录按角色 | `role_permissions(role, permission_key)` | 同一 `ADMIN` 无法区分校级/院系级权限 |
| 任务/试卷/讨论只挂课程 | `Task.courseId`、`ExamPaper.courseId`、`DiscussionTopic.courseId` | 没有教学班发布目标或班级快照 |
| 学情/教师班级按行政班聚合 | `TeacherChapterComponent.getCourseClasses` 按 `users.class_id` 分组；`ClassroomServiceImpl.countPendingByCourse` 同样 | “课程班级”实际是行政班，不是教学班 |
| 班主任接口接收任意 `advisorId` | `ClassroomController.getMyClassrooms(@RequestParam Long advisorId)`，未加 `@PreAuthorize` | 任意登录用户可查询其他班主任的班级；目标必须改为当前登录教师自查 |
| 行政班成员写权限过宽 | `ClassroomController.addStudent/removeStudent` 仅要求 `TEACHER/ADMIN`，无归属校验 | 任意教师可改组员；目标只允许管理员按作用域维护 |
| 学生课程列表未过滤审批状态 | `StudentController.getMyCourses` 只过滤 `is_active` | `PENDING` 选课也会出现在“我的课程” |
| 通知发送只有管理员 | `NotificationController.send` 为 `@PreAuthorize("hasRole('ADMIN')")` | 教师课程通知、班主任班级通知没有后端入口 |
| 管理与教学写权限混在一起 | `/admin/**` 只要求 `ADMIN`；大量教师写接口允许 `ADMIN` | 与原型“管理员只读课程内容/不代批阅/不改成绩”不一致 |

### 2.2 当前表与迁移

- 当前结构文档口径为 **55 张表**（WP1 后）：V1 48 张基础表，V8 增 `ai_call_logs`，V9 增 `semesters`，V10 增 `ai_generation_restrictions`，V11 为内容审核加列不增表，V12 增 `schools`／`colleges`／`majors`／`admin_classes` 四表。V1 文件头注释仍写“50 张”，是历史计数，引用时以 `docs/系统架构设计.md` §6.2 与迁移目录/守卫读数为准。
- 本方案新增 10 张表，V12 已落 4 张，全部实施后预期 **61 张**；最终数字以 `index.sql` 与 schema 守卫实际读数为准。
- 当前迁移目录最高版本为 `V12__org_foundation.sql`；V1 校验和冻结，不可回改；V13 起按 WP3–WP10 依次取号。
- V9 的 `semesters` 只解决“学期注册/归档”，**刻意没有**与 `courses.semester` 建外键；本方案必须补上这层绑定，但不能用猜测映射。
- 集成测试/开发全量初始化脚本实际为 `backend/src/main/resources/index.sql`；`IndexSqlMigrationGuardTest` 会检查它是否包含迁移建出的表与列。新增表必须同步，否则守卫会红。
- `ContractTestSchemaBootstrapTest` 与 `DemoSeedMigrationIsolationTest` 也需要随新表/种子更新。

## 3. 目标数据库设计

### 3.1 新增表（10 张）

> 以下为**最终形态**的结构草案，实施时按 `docs/后端开发规范.md` §15 拆成 Flyway 新版本；**不要修改 V1**。V12 首次建表时，`admin_classes.college_id/major_id`、`teaching_classes.lead_teacher_id` 等可先允许 `NULL`，回填校验通过后由 V16 收紧。所有表统一 `utf8mb4_unicode_ci`，时间字段 `created_at`/`updated_at`。

#### 3.1.1 `schools`

```sql
CREATE TABLE schools (
  id BIGINT NOT NULL AUTO_INCREMENT,
  code VARCHAR(32) NOT NULL COMMENT '学校编码',
  name VARCHAR(128) NOT NULL COMMENT '学校名称',
  status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/ARCHIVED',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_schools_code (code)
) COMMENT='学校根（单校部署，一行）';
```

#### 3.1.2 `colleges`

```sql
CREATE TABLE colleges (
  id BIGINT NOT NULL AUTO_INCREMENT,
  school_id BIGINT NOT NULL,
  code VARCHAR(32) NOT NULL,
  name VARCHAR(128) NOT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_colleges_school_code (school_id, code),
  KEY idx_colleges_school (school_id),
  CONSTRAINT fk_colleges_school FOREIGN KEY (school_id) REFERENCES schools(id) ON DELETE RESTRICT
) COMMENT='学院';
```

#### 3.1.3 `majors`

```sql
CREATE TABLE majors (
  id BIGINT NOT NULL AUTO_INCREMENT,
  college_id BIGINT NOT NULL,
  code VARCHAR(32) NOT NULL,
  name VARCHAR(128) NOT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_majors_college_code (college_id, code),
  KEY idx_majors_college (college_id),
  CONSTRAINT fk_majors_college FOREIGN KEY (college_id) REFERENCES colleges(id) ON DELETE RESTRICT
) COMMENT='专业';
```

#### 3.1.4 `admin_classes`（行政班）

```sql
CREATE TABLE admin_classes (
  id BIGINT NOT NULL AUTO_INCREMENT,
  school_id BIGINT NOT NULL,
  college_id BIGINT NOT NULL,
  major_id BIGINT NOT NULL,
  name VARCHAR(100) NOT NULL COMMENT '如：计科 2301',
  code VARCHAR(50) NOT NULL COMMENT '行政班编号',
  grade_year VARCHAR(16) NULL COMMENT '年级，如 2023',
  advisor_teacher_id BIGINT NULL COMMENT '班主任（教师职责，不是角色）',
  student_count INT NOT NULL DEFAULT 0,
  max_students INT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/ARCHIVED',
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_admin_classes_school_code (school_id, code),
  KEY idx_admin_classes_college (college_id),
  KEY idx_admin_classes_major (major_id),
  KEY idx_admin_classes_advisor (advisor_teacher_id),
  CONSTRAINT fk_admin_classes_school FOREIGN KEY (school_id) REFERENCES schools(id) ON DELETE RESTRICT,
  CONSTRAINT fk_admin_classes_college FOREIGN KEY (college_id) REFERENCES colleges(id) ON DELETE RESTRICT,
  CONSTRAINT fk_admin_classes_major FOREIGN KEY (major_id) REFERENCES majors(id) ON DELETE RESTRICT,
  CONSTRAINT fk_admin_classes_advisor FOREIGN KEY (advisor_teacher_id) REFERENCES users(id) ON DELETE SET NULL
) COMMENT='行政班：学生归属与班主任工作对象，不绑定课程';
```

#### 3.1.5 `teaching_classes`

```sql
CREATE TABLE teaching_classes (
  id BIGINT NOT NULL AUTO_INCREMENT,
  course_id BIGINT NOT NULL,
  name VARCHAR(120) NOT NULL COMMENT '如：计科 2301 教学班',
  code VARCHAR(50) NULL COMMENT '可选，教学班编号',
  lead_teacher_id BIGINT NOT NULL COMMENT '唯一主讲教师',
  capacity INT NULL COMMENT '容量；NULL 表示不限制',
  status VARCHAR(16) NOT NULL DEFAULT 'DRAFT' COMMENT 'DRAFT/ACTIVE/CLOSED',
  created_by BIGINT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE KEY uk_teaching_classes_course_name (course_id, name),
  KEY idx_teaching_classes_course (course_id),
  KEY idx_teaching_classes_lead (lead_teacher_id),
  KEY idx_teaching_classes_status (status),
  CONSTRAINT fk_teaching_classes_course FOREIGN KEY (course_id) REFERENCES courses(id) ON DELETE CASCADE,
  CONSTRAINT fk_teaching_classes_lead FOREIGN KEY (lead_teacher_id) REFERENCES users(id) ON DELETE RESTRICT,
  CONSTRAINT fk_teaching_classes_creator FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
) COMMENT='教学班：课程下的开课单元，一个主讲';
```

#### 3.1.6 `teaching_class_admin_classes`

```sql
CREATE TABLE teaching_class_admin_classes (
  id BIGINT NOT NULL AUTO_INCREMENT,
  teaching_class_id BIGINT NOT NULL,
  admin_class_id BIGINT NOT NULL,
  status VARCHAR(16) NOT NULL DEFAULT 'ACTIVE' COMMENT 'ACTIVE/REMOVED',
  imported_by BIGINT NULL,
  imported_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
```

### 3.3 关键不变量

1. 一个学生只能属于一个行政班：`users.admin_class_id` 对 `STUDENT` 非空；行政班归档不自动清空历史成员。
2. 一个学生在一门课程中只能有一条有效成员关系：保留 `course_enrollments` 的 `UNIQUE (student_id, course_id)`，并增加 `teaching_class_id`。
3. 一个教学班只有一个主讲：`teaching_classes.lead_teacher_id` 非空且对应用户角色为 `TEACHER`；课程负责人可以管理课程内容，但不能绕过教学班主讲读取其他班成绩。
4. 一个课程可有多个教学班，一个教学班必须有课程；教学班只能在课程 `APPROVED` 后进入 `ACTIVE`。
5. 课程级内容只有一份；任务/试卷用 `visibility=COURSE` 时自动对所有教学班可见，`visibility=CLASSES` 时通过目标表选班；提交/考试/成绩保存教学班快照。
6. 行政班与教学班多对多；行政班导入是快照，重新同步必须可审计（保留 `imported_at`、来源关系）。
7. 管理员作用域只影响管理端数据范围；不改变教师/学生登录角色。
8. 班主任是教师职责：`admin_classes.advisor_teacher_id` 指向教师用户，不新增角色、不签发额外 JWT 角色。

## 4. 权限与数据作用域

### 4.1 管理员的角色与作用域

**推荐保留 `ADMIN` 角色，新增作用域字段**，不新建 `SCHOOL_ADMIN/COLLEGE_ADMIN` 登录角色：

- `users.admin_scope`：`SCHOOL`（校级）或 `COLLEGE`（院系级）。
- `users.college_id`：院系级管理员必填；校级管理员可为空。
- `JwtRequestFilter` 读取数据库现行用户后，额外附加 authority：
  - `SCOPE_ADMIN_SCHOOL`（`admin_scope=SCHOOL`）
  - `SCOPE_ADMIN_COLLEGE`（`admin_scope=COLLEGE`）
- 仍保留 `ROLE_ADMIN`，兼容现有 `/admin/**` 和所有已有 `@PreAuthorize("hasRole('ADMIN')")`。
- 数据范围由服务层统一解析，不能只依赖前端导航隐藏；禁止在 Controller 中重复手写 if/else。
- 新增 `AdminScopeService` / `AdminScopeGuard`：`isSchool()`、`assertSchoolOnly()`、`assertCollegeAccess(collegeId)`、`currentCollegeFilter()`。
- 角色/权限目录 `role_permissions` 增加 `scope`；现有行回填 `ALL`，新增校级/院系级权限项。权限解析规则：有效权限 = `scope='ALL'` ∪ 当前管理员作用域对应的 `scope`（校级 `SCHOOL`，院系级 `COLLEGE`）。权限项只用于菜单/按钮可见性；**实际授权仍以角色 + 作用域 + 对象 ACL 为准**。

**理由**：现有 JWT、路由、种子账号都围绕 `ADMIN`；改成两个新角色会让所有存量 token、`/admin/**`、`RoleConstants`、测试与种子一起迁移。作用域字段把“等级”和“登录身份”分开，改动面更小。

### 4.2 教学侧 ACL

新增统一访问控制组件（建议放 `service/component/auth` 或 `security` 包）：

| 方法 | 规则 |
| --- | --- |
| `assertCourseContentOwner(courseId, userId)` | `courses.teacher_id == userId`（课程负责人）或管理员（按作用域） |
| `assertTeachingClassLead(teachingClassId, userId)` | `teaching_classes.lead_teacher_id == userId`，或管理员只读/治理 |
| `assertTeachingClassMember(teachingClassId, studentId)` | `course_enrollments` 有效且 `teaching_class_id` 匹配且 `approval_status=APPROVED` |
| `assertAdminClassAdvisor(adminClassId, userId)` | `admin_classes.advisor_teacher_id == userId` |
| `assertCollegeAccess(collegeId)` | 校级放行；院系级仅 `user.college_id` 相同 |

- `TeacherController.assertCourseOwner` 当前按 `course.teacher_id` 判断且管理员直接放行；目标要拆成“课程内容负责人”和“教学班主讲”两个判断。
- `CourseEnrollmentController.assertEnrollmentCourseOwner` 当前按课程教师判断；目标按教学班主讲判断。
- `SubmissionController`、`GradeController`、`ExamPaperController`、`TaskController` 等对象级判断全部改为教学班维度。
- 管理员对教学写操作默认拒绝（见 4.4），读取按作用域过滤。

### 4.3 班主任

- 班主任不是角色：不新增 `ADVISOR` 到 `RoleConstants`，JWT 不签发 `ROLE_ADVISOR`。
- 班主任入口只接受当前登录教师：
  - `GET /advisor/classes` 由服务端按 `advisor_teacher_id = currentUserId` 查询。
  - 不允许 `GET /classrooms/my?advisorId=...` 这种把他人 ID 作为查询参数的写法；现有接口在切换期保留兼容时也必须校验 `advisorId == currentUserId`。
- 班主任只读：班级画像、学生预警、班级通知；不调用批阅/成绩写入/课程内容写入。
- 行政班成员变更（加/移学生、改班主任）只允许管理员按作用域执行；教师只能读取自己作为班主任的行政班，不得通过 `ClassroomController` 的旧写接口改组员。
- 班主任可查看的班级画像建议返回**聚合**（人数、课程进度、均分、预警数、学生预警摘要），不返回可编辑成绩；如需学生个人成绩，必须另外定义产品口径。

### 4.4 管理员只读边界

目标原型明确“管理员看课程、教学班与审批；不代教师批阅、不改成绩”。当前后端大量写接口使用 `hasAnyRole('TEACHER','ADMIN')`，并且 `assertCourseOwner` 对管理员直接放行。改造时必须收紧：

| 操作 | 目标 | 处理 |
| --- | --- | --- |
| 创建/编辑课程、章节、资源、题库 | 教师课程负责人 | 管理员不再作为写角色；保留只读 |
| 创建教学班、导入名单、发布任务/试卷 | 教师课程负责人/教学班主讲 | 管理员只读监管；治理动作仅限停用/关闭 |
| 批阅提交、改成绩 | 教学班主讲 | 管理员只读；不提供“代批阅” |
| 课程审批、停用课程、教学班治理 | 管理员 | 保留；按作用域 |
| 用户/组织/角色/学期/系统配置 | 管理员 | 保留；校级/院系级分别授权 |
| 内容审核/封禁 | 管理员 | 保留；院系级可审本院内容 |

实施时要盘点所有 `@PreAuthorize("hasAnyRole('TEACHER','ADMIN')")` 与 `assertCourseOwner` 的管理员旁路，改成显式矩阵，并增加“管理员写教学数据返回 403、管理员读返回 200”的测试。不要只改前端菜单。

## 5. 接口调整

### 5.1 总原则

- 保持现有 `/api` 前缀、`ApiResponse<T>`、`PagedResponse<T>` 和 `ApiCode`；新增端点使用 DTO/VO，不直接把 Entity 当请求体/响应体（现有存量接口可逐步收敛）。
- **新增字段优先，破坏性改名后置**：先让新前端使用新端点/新 VO，旧端点保留一个过渡周期。
- 所有管理端点必须解析当前管理员作用域；所有课程/教学班端点必须做对象级 ACL。

- 下表混合“现有路径”和“目标新增路径”：标有“现有/兼容”的沿用当前 controller 映射，其余为新增或调整；落地前逐条对照 `ContractPaths` 与 controller 实际映射，避免把目标路径误当成已存在端点。

## 6. 数据迁移方案

### 6.1 迁移前置：先出映射，不猜数据

V9 已明确 `courses.semester` 是自由文本、不能猜映射。本次同样不能自动猜：

```sql
-- 需要人工确认的映射清单
SELECT semester, COUNT(*) FROM courses GROUP BY semester ORDER BY semester;
SELECT department, COUNT(*) FROM users WHERE role='TEACHER' GROUP BY department;
SELECT major, COUNT(*) FROM users WHERE role='STUDENT' GROUP BY major;
SELECT major, COUNT(*) FROM classrooms GROUP BY major;
SELECT course_id, COUNT(*) FROM classrooms WHERE course_id IS NOT NULL GROUP BY course_id;
SELECT COUNT(*) FROM course_enrollments e
LEFT JOIN users u ON u.id=e.student_id
WHERE u.class_id IS NULL;
```

| 场景 | 期望 |
