# AI 课程平台 — 开发指南

> 版本：v1.0 | 更新日期：2026-08-16 | 维护者：项目技术负责人
>
> **定位**：面向开发者（含新成员）的本地开发手册——环境准备、启动方式、代码结构、编码规范、测试与质量门禁、CI 流水线。部署运维见 `docs/运维手册.md`；架构设计见 `docs/架构手册.md`。

## 1. 环境准备

| 环境 | 版本要求 | 说明 |
|------|---------|------|
| JDK | **21**（唯一目标版本） | `pom.xml` 编译 `release=21`；系统 `JAVA_HOME` / `PATH` 已统一指向 `C:\Program Files\Java\jdk-21` |
| Maven | 3.8+ | 项目内嵌 `mvnw` wrapper，无需系统安装 |
| Node.js | 20.19+ | Vite 8 要求；CI 与 Docker 使用 Node 20 |
| MySQL | 8.0+ | 本机服务（3306）或 Docker 兜底（宿主 3307） |
| Redis | 7.x | **必选**：缓存/限流/AI 配额/验证码依赖；启动时强校验连通性 |

> 本机未安装 MySQL / Redis 时：`docker compose up -d mysql redis` 拉起基础设施容器（MySQL 宿主端口 3307），`start-backend.bat` 自动检测并切换数据源。

## 2. 启动项目

### 2.1 数据库初始化（首次）

```bash
mysql -u root -p -e "CREATE DATABASE ai_course_platform CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root -p ai_course_platform < backend/src/main/resources/index.sql
```

### 2.2 后端

```bash
# 首选：一键脚本（自动加载 .env、校验 JDK 21、检测 MySQL/Redis，缺 Redis 报错提示）
start-backend.bat

# 或手动
cd backend
./mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=local   # local 配置含本地开发用 DeepSeek Key
```

> `application-local.yaml` 已被 `.gitignore` 忽略，无需手动设置环境变量即可体验真实 AI 对话。生产环境通过 `DEEPSEEK_API_KEY` 注入密钥。

### 2.3 前端

```bash
start-frontend.bat        # 自动安装依赖并启动 Vite dev server（:5173）
# 或手动
cd frontend && npm install && npm run dev
```

### 2.4 访问地址

| 服务 | 地址 |
|------|------|
| 前端 | http://localhost:5173 |
| API | http://localhost:8080/api |
| Swagger | http://localhost:8080/api/swagger-ui.html |

### 2.5 Python 微服务（可选）

```bash
# 知识图谱基线（8001，FastAPI，内存存储，本地联调用）
cd python-services/kg_service && pip install -r requirements.txt
uvicorn kg_service:app --host 0.0.0.0 --port 8001

# 启用 Java 端对接（默认关闭）
KG_ENABLED=true KG_BASE_URL=http://localhost:8001 ./mvnw -o spring-boot:run -Dspring-boot.run.profiles=local
# RAG（8002）同理：RAG_ENABLED=true RAG_BASE_URL=http://localhost:8002
```

> Python 服务契约（端点/字段/状态码/降级/重试）见 `docs/集成契约-知识图谱与RAG.md`。

## 3. 代码结构导航

### 3.1 后端（backend/src/main/java/com/aicourse）

| 包 | 职责 | 约定 |
|----|------|------|
| `controller/` | HTTP 入口（44 个） | 仅做参数校验与响应封装，业务逻辑下沉 Service；`/ai/**` 返回 `Callable` 异步执行 |
| `service/` | 业务接口（60） | 接口 + 实现分离；事务注解置于实现类 public 方法 |
| `service/impl/` | 业务实现（60） | 含 `exam/` 子包；`KnowledgeGraphServiceImpl` / `RAGServiceImpl` 为集成层门面 |
| `mapper/` | MyBatis-Plus Mapper（49） | 单表 CRUD 继承 `BaseMapper`，复杂查询用注解 SQL 或 XML |
| `entity/` | 实体（48） | 与表一一对应；`@TableName` / `@TableId` / `@TableField(fill=...)` |
| `integration/` | ★ 标准化集成层 | KG/RAG 契约 + 本地占位 / HTTP 远端双实现（见架构手册 §6） |
| `security/` | JWT 认证 + RBAC | `JwtRequestFilter` / `SecurityConfig` / `RoleUtil` |
| `config/` | 配置类 | Sentinel / 缓存 / 异步 / CORS / 自愈建表 |
| `llm/` | LLM 供应商抽象 | `LLMProvider` + DeepSeek/OpenAI/Qwen 三实现 |
| `flowcontrol/` | IP 限流 | `RateLimitFilter` 固定窗口计数 |
| `health/` | 健康探针 | DB / Redis / LLM / Python 四类 `HealthIndicator` |

### 3.2 前端（frontend/src）

| 目录 | 职责 |
|------|------|
| `api/` | 40 个 API 模块，统一走 `request.js`（axios 封装：XSRF、AbortController 防抖、502/503/504 重试） |
| `views/` | 73 个页面（admin / teacher / student / common 四类） |
| `layouts/` | 三端布局 |
| `stores/` | Pinia 状态 |
| `router/` | 路由与守卫（角色菜单过滤） |
| `utils/` | 工具函数（含主题令牌、导出） |

## 4. 编码规范

### 4.1 后端

- **命名**：类 `UpperCamelCase`、方法/变量 `lowerCamelCase`、常量 `UPPER_SNAKE`、包名全小写。
- **注释**：类级 Javadoc 说明职责与边界；契约类（`integration/`）注释必须说明调用约定与降级语义。
- **日志**：`@Slf4j`；业务异常 `log.warn`，系统异常 `log.error`；禁止 `System.out`。
- **事务**：写操作在 Service 实现类加 `@Transactional(rollbackFor = Exception.class)`；跨表写操作注意事务边界。
- **鉴权**：Controller 方法必须声明角色约束（`@PreAuthorize` 或 Security 配置）；禁止绕过 RBAC 直连数据。
- **集成契约**：涉及 Python 对接的 HTTP 调用，**必须**引用 `ContractPaths` 常量，禁止硬编码路径/字段名。

### 4.2 前端

- 组合式 API（`<script setup>`）；组件命名 `PascalCase.vue`。
- 样式优先使用设计令牌 CSS 变量（双主题自动适配），禁止内联渐变/硬编码色值（大屏看板场景除外）。
- 所有请求经 `api/` 模块封装，禁止页面内散落 `axios` 调用。
- 加载态 / 错误态 / 空态三态齐全；无 mock 业务数据（兜底函数命名 `handleLoadError`，仅作空数据兜底）。

## 5. 测试

### 5.1 后端（JUnit5 + Mockito + Testcontainers）

```bash
cd backend
# 单元测试（Controller MockMvc / Service Mockito）——无需 Docker、无需环境变量
mvn test -Dtest='!*IT,!Phase1Phase3IntegrationTest' -DfailIfNoTests=false

# 全量（含 Testcontainers 集成测试，需要 Docker daemon）
mvn verify
```

- 测试专用 profile：`application-contract-test.yml` / `application-local.yml` 根治环境依赖，复用本机 MySQL/Redis。
- 集成测试（`*IT`、`Phase1Phase3IntegrationTest`）基于 Testcontainers；本机无 Docker 时用 `-Dtest` 排除跳过。
- **集成层契约测试**（禁止删除或绕过，CI 离线可运行）：
  - `KnowledgeGraphServiceImplTest` / `RAGServiceImplTest` / `RAGServiceImplCoverageTest`（门面委派）
  - `LocalKnowledgeGraphProviderTest` / `DisabledRagProviderTest`（本地占位）
  - `HttpKnowledgeGraphProviderContractTest` / `HttpRagProviderContractTest`（HTTP 契约，JDK `HttpServer` 桩）
  - `HttpRagProviderBoostTest`（重试语义：超时不重试 / 非超时重试 / 耗尽降级）

### 5.2 前端（vitest + ESLint）

```bash
cd frontend
npm run lint          # ESLint（errors 应为 0）
npx vitest run        # 单元测试全量
npm run build         # 构建校验（Vite + Rolldown，无 broken import）
```

### 5.3 质量门禁（随 `mvn verify` 执行）

| 工具 | 门禁 | 说明 |
|------|------|------|
| JaCoCo | LINE ≥ 40% / BRANCH ≥ 25%（当前基线） | 报告 `backend/target/site/jacoco`；**阈值只许上调、不得下调**（生产收敛目标：指令覆盖 ≥ 85%） |
| SpotBugs | 0 error | `spotbugs-exclude.xml` 白名单过滤 |
| ArchUnit | 架构约束 | 分层依赖 / 包依赖方向检查 |

> 覆盖率基线为渐进收敛制：随测试补全逐步上调阈值，注释记录真实实测值（INSTRUCTION 42% / BRANCH 26% / LINE 43% 为 2026-08 实测基线）。CI 中 `mvn verify jacoco:report` 强制门禁，不达标即失败。

## 6. CI 流水线（.github/workflows/ci.yml）

| Job | 触发 | 内容 |
|-----|------|------|
| `frontend-quality` | push/PR 到 main、master | ESLint + Prettier + `npm audit`（高危阻断） |
| `frontend-build` | 同上 | `npm run build`（Vite 生产构建） |
| `backend` | 同上 | JDK 21 + Maven `verify`：单元测试 + Testcontainers 集成测试 + JaCoCo 门禁；MySQL/Redis 用 Actions service 容器 |
| `backend-security` | 同上 | OSV-Scanner 依赖漏洞扫描（SARIF 报告） |
| `docker` | 仅 main 推送 / 手动 | `docker compose build` 镜像构建校验 |
| `python-kg-contract` | 同上 | Python 8001 基线契约冒烟测试（FastAPI TestClient） |

> 推送前确认本机 Clash 7890 代理在线（GitHub 依赖代理通道）；本地提交遵循「阶段性成果才推送」约定。

## 7. 常见开发问题

| 现象 | 原因 / 处理 |
|------|------------|
| 后端启动报 `RedisConnectionFailureException` | Redis 未启动；`net start Redis` 或 `docker compose up -d redis` |
| `JWT signature does not match` | JWT_SECRET 不一致；注意 `start-backend.bat` 行尾须保持 CRLF，否则密钥截断 |
| 前端 403 CSRF | `request.js` 需 `withXSRFToken: true` |
| 测试运行提示缺 Docker | 跳过集成测试：`-Dtest='!*IT,!Phase1Phase3IntegrationTest'` |
| JaCoCo check 失败 | 覆盖率低于门禁；先补测试再上调阈值，不得下调门禁 |
| 修改了 Python 契约字段 | 必须同步更新 `ContractPaths` 常量 + 集成契约文档 §4/§5 |
