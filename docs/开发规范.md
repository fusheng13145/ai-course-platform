## §1 后端（Spring Boot / Java 21）

### 1.1 分层

```text
Controller → Service → Mapper → MySQL/Redis/MinIO
     ↘ integration/ → Python 引擎
common: 响应、异常、审计、工具、契约常量
```

- Controller：参数校验、权限注解、调用 Service、组装响应；**不写业务规则**。
- Service：业务规则、事务边界、缓存、对象级 ACL。
- Mapper：SQL 与结果映射；不写业务分支。
- `integration/`：外部引擎/存储的 HTTP 契约；不散落 `RestTemplate`。
- 禁止 Controller 直接调 Mapper；禁止 Service 返回 `Entity` 给前端。

### 1.2 命名与包

- 包：`com.aicourse.<域>.<层>`；域用单数，层用 `controller/service/mapper/dto/vo/entity/config`。
- 类：`XxxController`、`XxxService`、`XxxServiceImpl`、`XxxMapper`、`XxxRequest`、`XxxResponse`。
- 方法：动词开头；布尔用 `is/has/can`；避免 `data/info/obj` 泛名。
- 常量：`UPPER_SNAKE`；错误码集中管理，不散落魔法字符串。

### 1.3 Controller

- 类级 `@RestController` + `@RequestMapping("/api/...")`；方法级 HTTP 动词注解。
- 每个写端点必须 `@PreAuthorize`；类级注解只作兜底。
- 请求体 `@Valid`；路径/查询参数做范围与格式校验。
- 返回统一 `ApiResponse<T>`；分页统一 `PageResponse<T>`。
- 不把异常吞成 200；业务错误用明确 4xx，依赖不可用用 503。
- 上传/下载端点必须校验资源归属与课程 ACL。

### 1.4 DTO / VO / Entity

- Entity 只映射表；不直接序列化给前端，避免泄露内部字段。
- DTO 只承接入参；VO 只承接出参；转换集中在 Assembler/Converter。
- 字段命名与前端契约一致；新增/改名字段必须同步契约测试与前端类型。
- 金额/分数用 `BigDecimal`；时间用 `LocalDateTime`/`Instant`，不传裸字符串。
- 可空字段明确默认值；列表不返回 `null`，用空数组。

### 1.5 Service 与事务

- 跨表写操作必须 `@Transactional(rollbackFor = Exception.class)`。
- 事务内不调用长耗时外部服务；必须先落状态再异步/后置。
- 幂等：提交、交卷、批阅、支付类操作必须可重复调用不重复写。
- 缓存：键带业务前缀与 TTL；更新 DB 后逐出相关键；不缓存权限的旧值。
- 对象级 ACL：课程、资源、提交、成绩、讨论、AI 会话、RAG 文档均按归属/课程校验。
- 管理端跨院访问按 `collegeId` 收敛；空值回退教师学院，不放大范围。

### 1.6 Mapper / SQL

- 简单 CRUD 用 MyBatis-Plus；复杂查询用 XML，SQL 可读、可解释。
- 禁止 `SELECT *` 进生产代码；明确列名。
- 分页必须带稳定排序；深分页用游标/索引优化。
- 批量写控制批次大小；避免 N+1，必要时批量查询后在内存组装。
- 动态 SQL 必须防注入；排序字段白名单。
- 慢 SQL 阈值与日志保留；新增查询要说明索引依据。

### 1.7 异常与响应

| 情况        | 处理                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------- |
| 参数错误    | 400 + 字段级 message                                                                                                      |
| 未认证      | 401                                                                                                                       |
| 无权限/越权 | 403；不得用 404 掩盖越权                                                                                                  |
| 资源不存在  | 404                                                                                                                       |
| 状态冲突    | 409                                                                                                                       |
| 依赖不可用  | **503**；分类 `NOT_CONFIGURED` / `CREDENTIAL_REJECTED` / `QUOTA_OR_THROTTLED` / `UPSTREAM_UNREACHABLE` / `EMPTY_RESPONSE` |
| 未知异常    | 500；日志带 traceId，不把堆栈返回前端                                                                                     |

- 统一异常处理器；禁止 `catch (Exception e) {}` 静默吞。
- 4xx 不重试；5xx/网络错误有限退避；503 直接降级。
- LLM 返回非空字符串才算真实生成；失败不得返回兜底文案冒充成功。

### 1.8 日志与审计

- 日志用 SLF4J；禁止 `System.out`、`printStackTrace`。
- 不打印凭据、令牌、密码、完整请求体中的敏感字段。
- 关键操作留审计：登录、权限变更、管理操作、AI 调用、敏感读写。
- 日志带 traceId/用户 ID（脱敏）；异常带上下文，不堆无意义字符串。
- 审计表只追加；不物理删除。

### 1.9 安全

- 密码 8–32 位，含大小写、数字、特殊字符；不明文存储。
- JWT 密钥从环境读取；不硬编码；轮换会使会话失效。
- CSRF 生产开启；CORS 白名单；Vite 用 `localhost`。
- 上传：类型/大小/分片校验；路径穿越防护；对象键不拼用户输入。
- 限流：登录按 IP+账号；AI/上传按用户；429 打日志。
- 凭据只进 `.env` / `deploy/secrets/`；不打印、不提交、不贴对话。

### 1.10 外部集成

- 统一 `integration/` 契约；超时、重试、降级集中配置。
- 契约路径常量放 `ContractPaths`；Java/Python 两侧同步改。
- Python 返回 503 时 Java 不重试，直接降级并标注。
- RAG/KG/FT 的请求与响应必须有契约测试；字段增删两侧同批。
- 外部调用不继承系统代理时显式 `trust_env=False`（本机脚本场景）。

### 1.11 配置与迁移

- 配置只从 `application.yaml` + 环境变量读取；不散落 `@Value` 魔法串。
- 新增键同步 `.env.example`；语义变更必须写迁移说明。
- Flyway 只前向；已应用校验和冻结；不改历史 SQL。
- 新增迁移号连续；结构迁移与演示种子分目录；生产排除演示种子。
- `index.sql` 与迁移链保持一致；结构计数以 `audit-stats.py` 为准。

### 1.12 测试

- 修真实缺陷必须补测试；测试名写行为，不写实现细节。
- 单测不依赖真实外部服务；契约测试用 WireMock/固定桩。
- 断言钉语义与结构，不钉会迁移的行号/路径。
- 覆盖率门禁 85/77；不写无意义断言凑数。
- 本机只跑 `-DskipITs`；IT 由 CI/目标环境取数。

## §2 前端（Vue 3 / TypeScript）

### 2.1 文件与组件

- 单文件组件 `<script setup lang="ts">`；组件名 PascalCase，文件名与组件名一致。
- 页面放 `src/ui/pages/**`；通用组件放 `src/ui/components/**`；composable 放 `src/ui/composables/**`。
- 页面只做编排；业务逻辑放 composable/store；纯展示组件不直接请求 API。
- Props/Emits 显式类型；禁止 `any` 进入公共 API；必要时 `unknown` + 收窄。
- 列表渲染必须稳定 `key`；避免 `v-if` 与 `v-for` 同元素。

### 2.2 UI 与样式

- 只用系统令牌；不引第三方组件库；不写第二套“看起来一样”的组件。
- 字族以 Inter 优先；标题 18px/600、正文 14px/400、辅助信息 12px；无衬线标题。
- 非课程卡片采用指定浅色色板；间距只用 4/8/16/24/32px，控件圆角 4px，弹窗与非课程卡片 6px。
- 无渐变大背景、无入场动画、无 hover 位移、无辉光；分隔只用 1px 线。
- 颜色、间距、圆角、阴影走令牌；禁止散落十六进制/魔法像素。
- `CourseFolderCard.vue` 与 `CoursesView.vue` 的课程卡片、封面及课程网格是冻结区；全局令牌通过 `coursera.css` 的 `.cf` 隔离块保持其原始外观。
- 响应式：关键页在 360/390/414 无横向滚动；表格可横向滚动但不破布局。
- 退役类名出现即红：`page-kicker` / `page-sub` / `card-kicker` / `card-sub` / `card-hint` / `ai-caveat` / `eyebrow` / `lede` / `av-*`。

### 2.3 页面与文案

- 一页 = `PageHead(title)` + 动作 + 内容；页头无副标题/kicker/来源章。
- 加文案先过三问：动作标签？数据？改不了的事实？都不是就删。
- 空态一行 `<b>`；错误态一行 + 重试；不写“XX 会出现在这里”。
- 按钮文案用动词；危险动作明确后果；不可撤回操作二次确认。
- 不在页面写实现细节、接口路径、内部编号。

### 2.4 路由与导航

- 学生外层：我的课程 / 系统消息 / 学业档案 / 工作台。
- 教师外层：我的课程 / 系统消息 / 工作台。
- 作业、课件、讨论、成绩、考试、知识图谱、AI 助教、AI 语料全部在课程之下。
- 在线监考并入考试；AI 语料并入 AI 助教；不单独占外层入口。
- 路由守卫按权限判定；无权限入口不渲染；后端仍必须校验。
- 面包屑只在课程空间内表达“课程 → 章节/页面”。

### 2.5 状态与请求

- Pinia 按域拆分；store 不直接操作 DOM。
- 请求层统一：baseURL、超时、401 跳登录、403 提示、503 降级提示。
- 不在组件里拼 URL；API 模块按域拆分，类型与后端契约同步。
- 并发请求去重/取消；页面卸载取消未完成请求。
- 错误提示可执行：说明发生了什么 + 下一步；不暴露堆栈。

### 2.6 无障碍与性能

- 可交互元素必须键盘可达；焦点可见；模态框焦点陷阱与 Esc 关闭。
- 图标按钮有 `aria-label`；图片有 `alt`；表单有 label。
- `prefers-reduced-motion` 降级；不做纯 hover 才能发现的操作。
- 首屏只请求必要数据；长列表虚拟化；图片懒加载；避免大包。
- 体积门 `size:gate` 必须通过；新增依赖先评估体积。

### 2.7 测试

- 组件测试用 Testing Library；断言用户可见行为，不测内部实现。
- 路由/守卫/请求错误必须有测试；视觉改动跑视觉基线。
- e2e 用真实登录 + 真实路由；数据桩明确；不把 mock 当真实链路。
- 视觉结论只有 md5 相等且字节差 0 才能说“逐字节相同”。
- 守卫 `copyLaw.test.ts` + `visualLaw.test.ts` + `courseraLaw.test.ts` 出现即红；公共分页、进度与编号徽章由 `courseraComponents.test.ts` 锁定行为；不删守卫换绿。

## §3 协作

| 项     | 规则                                                      |
| ------ | --------------------------------------------------------- |
| 分支   | `feature/<描述>` / `fix/<描述>`；从 `main` 切             |
| 提交   | 一个批次一个主题；信息写“改了什么 + 为什么”               |
| PR     | base `main`；squash merge；合并后删 head；PR 由项目主提交 |
| 日常   | 只本地提交，不推送；推送/PR 仅在里程碑                    |
| 合并前 | 相关门禁全绿；迁移/契约/文档同批；无凭据与产物            |
| 回滚   | 应用可回滚；数据库只到兼容边界；已应用迁移不自动降级      |
