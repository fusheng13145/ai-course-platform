## 1. 环境与构建

| 项 | 要求 |
| --- | --- |
| JDK | 21 |
| Maven | 3.8+ |
| 编码 | UTF-8；Windows 批处理另见 §18 |
| 本地启动 | `start.bat backend`（长驻）或 `start.bat`（全栈单窗口） |
| 编译 | `mvn -B -o clean package -DskipTests`（离线仓库已预热） |
| 全量门禁 | `mvn -B -o clean verify -DskipITs` |
| 工作目录 | Maven 命令在 `backend/` 下执行，除非明确说明 |

**构建纪律**：

- 不引入未经授权的依赖升级；版本号集中在 `pom.xml` 的 `<properties>`。
- 新增依赖必须同时评估：许可证、已知漏洞（Trivy/OSV）、包体与启动时间。
- Lombok 可用（`@Slf4j`、`@Data` 等），但实体/DTO 的公开契约字段不得依赖 Lombok 隐式行为做序列化假设；需要精确控制时手写 getter/setter。

## 2. 目录与分层

```text
com.aicourse
├─ controller/         HTTP 入口
├─ dto/                入参对象
├─ vo/                 出参对象
├─ entity/             表映射
├─ mapper/             数据访问
├─ service/            业务接口
│  ├─ impl/            业务实现
│  └─ component/       子域组件（ai/auth/exam/learning/student/submission/sys/teacher/analytics）
├─ config/             横切配置
├─ security/           JWT、CSRF、ACL、AI 配额
├─ flowcontrol/        Sentinel
├─ integration/{kg,rag}/ Python 适配
├─ llm/                大模型供应商
├─ scheduler/          定时任务
├─ websocket/          通知推送
├─ health/             健康指示器
├─ common/             响应、分页、角色、工具常量
├─ constant/           业务状态常量
├─ exception/          业务异常与全局处理
├─ util/               无状态工具
└─ aspect/             切面
```

### 2.1 依赖方向（ArchUnit 强制）

| 规则 | 说明 |
| --- | --- |
| `controller` ✗→ `mapper` | 控制器只能经 service 访问数据 |
| `service` ✗→ `controller` | 业务不得反向依赖 Web 层 |
| `entity` ✗→ service/controller/mapper | 实体是纯数据映射 |
| `util` ✗→ service/controller/mapper | 工具保持无业务依赖 |
| `config` ✗→ `controller` | 配置不感知接口 |
| `service.impl` ✗→ 其他 `service.impl` | 通过接口或 `component` 协作 |

新增跨层调用前先问：能否通过接口注入或组件下沉解决；不能则改设计，不要放宽 ArchUnit。

### 2.2 服务拆分

- 对外能力：`XxxService` 接口 + `XxxServiceImpl` 实现；控制器只依赖接口。
- 子域复用：放 `service/component/<域>/XxxComponent`，构造器注入，不暴露给控制器。
- 单一实现且无替换需求时可不建接口，但同域已有接口风格时保持一致。
- 单个类建议 ≤ 500 行；超过时按子域拆组件或拆编排层，而不是继续加方法。

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 包 | 全小写，单数域名词 | `service.component.exam` |

| 服务 | `XxxService` / `XxxServiceImpl` | `SubmissionService` |

| 实体 | 表名单数大驼峰 | `submissions` → `Submission` |
| 配置 | `XxxProperties` / `XxxConfig` | `CorsProperties` / `CacheConfig` |
| 过滤器 / 拦截器 | `XxxFilter` / `XxxInterceptor` | `DoubleSubmitCsrfFilter` |
| 定时任务 | `XxxScheduler` | `ExamTimeoutScheduler` |
| 健康指示器 | `XxxHealthIndicator` | `LlmProviderHealthIndicator` |
| 测试 | `XxxTest` / `XxxControllerTest` / `XxxServiceTest` / `XxxIntegrationTest` / `XxxContractTest` / `XxxGuardTest` | 见 §17 |

- 拼音命名、无意义缩写（`tmp`、`data1`、`obj`）。

- 控制器方法名与 HTTP 语义脱节（如 `get` 却执行写操作）。

## 4. 控制器规范

### 4.1 基本形态

```java
@RestController
@RequestMapping("/submissions")
@Tag(name = "作业提交")
@Slf4j
public class SubmissionController {

    private final SubmissionService submissionService;

    public SubmissionController(SubmissionService submissionService) {
        this.submissionService = submissionService;
    }

    @GetMapping("/{id}")
    public ApiResponse<Submission> getById(@PathVariable Long id, Authentication auth) {
        accessControl.assertReadable(id, auth);
        return ApiResponse.success(submissionService.getById(id));
    }
}
```

要求：

- 构造器注入，字段 `private final`；禁止字段注入。
- 统一返回 `ApiResponse<T>`；分页返回 `ApiResponse<PagedResponse<T>>`。
- 入参用 `@Valid @RequestBody XxxDTO`；查询参数用 `@RequestParam` 并给默认值。
- 登录主体统一 `Long userId = (Long) auth.getPrincipal()`。
- 每个控制器类加 `@Tag`；关键端点加 `@Operation`（描述业务语义，不写实现细节）。
- 控制器保持薄：只做参数接收、权限校验、服务调用、响应包装；不写业务分支与 SQL。

### 4.2 权限

| 场景 | 写法 |
| --- | --- |
| 角色限制 | `@PreAuthorize("hasAnyRole('TEACHER','ADMIN')")` |
| 本人或管理员 | `@PreAuthorize("#userId == authentication.principal or hasRole('ADMIN')")` |
| 对象级 | 调用 `ExamPaperAccessControl` / `ExamSessionAccessControl` / `SubmissionAccessControl` 的 `assertXxx` |
| 仅登录 | `@PreAuthorize("isAuthenticated()")` |

- 角色字符串只用 `RoleConstants.ADMIN/TEACHER/STUDENT`，不得散落字面量。
- **新增任何按 ID 访问的端点，必须同时声明角色与对象归属校验**；仅靠前端隐藏入口不算。
- 管理端代操作必须显式解析操作者身份，不得静默冒用目标用户。

#### 4.2.1 三个“零方法级注解”控制器的书面结论（B-08，2026-11-17）

> 统计口径：只数**源码注解**，不把 javadoc 里的 `{@code @PreAuthorize}` 计入；URL 层规则先于方法层，二者相与，只可能更严。

| 控制器 | 方法级注解 | 真实防线 | 结论 |
| --- | --- | --- | --- |
| `AuthController` | 0 | `/auth/**` 在 `SecurityConfig.publicPaths()` 中 `permitAll`（登录/注册/刷新/登出/改密/验证码/重置密码必须未登录可达）；`/me`、`/permissions`、`/logout`、`/change-password`、`/password` 在方法内用 `requireLogin` / 显式 principal 判空返回 401 | **有意公开前缀 + 方法内显式登录校验**；不得把 `/auth/**` 读成“全部公开”：需要登录的子路径不会以匿名身份执行业务 |
| `FineTuneController` | 1（类级 `@PreAuthorize("hasRole('ADMIN')")`） | 类级注解 + `SecurityConfig` 的 `/admin/** hasRole(ADMIN)` URL 规则，双层相与 | **管理面双层防护**；历史“命中 0”已被 DR-110 补类级注解修正，`FineTuneControllerTest` 的 401/403 直接覆盖 |
| `NoteController` | 0 | `/notes/**` 落到 `anyRequest().authenticated()`；`NoteServiceImpl.getOwned/updateOwned/deleteOwned/setFavorite` 全部按 `userId` 比对，跨用户抛 `NOT_FOUND`（不泄露“存在但无权”） | **登录 + 对象级 userId 隔离**；`NoteControllerTest` 6 端点 200/401，`NoteServiceImplTest` 覆盖跨用户拒绝 |

**边界**：这三条不是“缺鉴权”，而是防线不在方法级注解上。新增 `/auth/**` 子路径若需要登录，必须像现有 `/me` 一样在方法内显式校验；新增 `/notes/**` 子路径必须继续走 `userId` 对象级校验。

### 4.3 分页与排序

```java
@GetMapping
public ApiResponse<PagedResponse<Submission>> list(
        Authentication auth,
        @RequestParam(defaultValue = "1") long page,
        @RequestParam(defaultValue = "10") long size) {
    Page<Submission> result = submissionService.page(Page.of(page, size), wrapper);
    return ApiResponse.success(PagedResponse.of(result));
}
```

- 页码从 1 开始；`size` 必须有上限（MyBatis-Plus 全局 1000）。
- 排序字段必须白名单化，禁止把用户输入直接拼进 `orderBy`。
- 列表默认按 `created_at DESC`；需要稳定排序时追加 `id DESC`。

### 4.4 文件与上传

- 普通上传用 `MultipartFile`，校验类型/大小/文件名；禁止把原始文件名直接作为落盘路径。
- 分片上传走 `FileUploadSessionController`：会话创建 → 分片上传 → 合并；归属、索引、MD5、字节数全部校验。
- 下载/预览必须经过权限校验；`/uploads/**` 不是匿名静态目录。

## 5. DTO / VO / Entity

### 5.1 DTO（入参）

- 只包含允许客户端写入的字段；**绝不**直接使用实体接收请求体。
- 校验注解就近声明，消息用中文；跨字段规则放服务层。
- 更新类 DTO 与创建类 DTO 分开（避免“创建时必填、更新时可选”互相妥协）。
- 涉及枚举/状态的值，用字符串常量或枚举校验，不使用魔法数字。

```java
public class SubmissionCreateDTO {
    @NotNull(message = "任务ID不能为空")
    private Long taskId;

    @NotBlank(message = "提交内容不能为空")
    @Size(max = 20000, message = "提交内容不能超过20000字")
    private String content;

    private List<String> fileUrls;
}
```

### 5.2 VO（出参）

- 面向页面需要组织字段；不把实体内部字段（如密码哈希、删除标记）透出。
- 列表 VO 与详情 VO 分开；大字段（正文、附件）不进入列表。
- 字段命名与前端契约一致（camelCase）；日期格式统一。
- 新端点优先返回 VO；存量返回实体的端点改动时逐步收敛，不在同一批扩大暴露面。

### 5.3 Entity

- `@TableName("表名")`；主键 `@TableId(type = IdType.AUTO)`。
- 非表字段加 `@TableField(exist = false)`。
- 创建/更新时间用 `@TableField(fill = FieldFill.INSERT/INSERT_UPDATE)` 配合 `MyMetaObjectHandler`。
- 逻辑删除字段（若有）统一 `@TableLogic`；不要手写 `deleted = 0` 条件散落各处。
- 实体不写业务方法；不依赖 Service。

## 6. Service 规范

### 6.1 事务

- 写操作在 service 实现层加 `@Transactional(rollbackFor = Exception.class)`。
- 只读查询加 `@Transactional(readOnly = true)`（有性能收益的路径）。
- 事务内不做远程调用、不发消息、不写大文件；必须做时拆到事务外并考虑补偿。
- 控制器不开事务；组件方法被同类内部调用时注意代理失效，必要时拆到独立组件。

### 6.2 业务校验顺序

1. 参数格式（Bean Validation）；
2. 资源存在性；
3. 状态机合法性（如“未发布试卷不可作答”）；
4. 归属/权限（对象级 ACL）；
5. 业务规则（配额、次数、时限）；
6. 落库与副作用。

错误消息面向用户，写清“哪个对象、什么状态、该怎么办”，不泄露内部实现。

### 6.3 异步

- 轻量副作用可用 `CompletableFuture.runAsync`，但必须捕获异常并记录，不得让异常吞掉主流程。
- 需要可靠执行的任务用定时任务 + 状态表 + ShedLock，不依赖内存线程池。
- 异步任务不得持有请求上下文（`SecurityContext`、`RequestContextHolder`）；需要用户身份时显式传参。

### 6.4 缓存

- 读缓存用 `@Cacheable(cacheNames = "...", key = "...")`；写路径用 `@CacheEvict` / `@Caching`。
- 缓存键必须稳定、可读，包含业务维度（如 `'teacher_' + #teacherId`）。
- 用户/权限变更必须即时逐出（`users`、`permissions`）；不得等 TTL。
- 缓存值必须是可序列化的 VO/简单结构；不要把实体代理或 `Page` 直接塞入。
- 新增缓存前先确认：读远多于写、能接受短暂不一致、逐出路径完整。

## 7. Mapper 与 SQL

- 单表 CRUD 用 `BaseMapper` + `LambdaQueryWrapper`；复杂查询写 XML（`resources/mapper/*.xml`）。
- 禁止字符串拼接 SQL；动态条件用 MyBatis 的 `#{}` 与 `<if>`。
- 分页统一 `Page.of(page, size)`；不要手写 `LIMIT` 偏移。
- 批量写入控制单批大小（建议 ≤ 500），避免超长 SQL。
- 列表查询注意 N+1：需要关联数据时用批量查询 + 内存组装，或一次 JOIN。
- 慢 SQL 由 `MyBatisSlowSqlInterceptor` 记录；新增复杂查询应在测试库用真实数据量验证。
- 统计类 SQL 必须限定课程/时间范围，禁止全表扫描式聚合进入请求路径。

## 8. 异常与错误码

### 8.1 异常类型

| 类型 | 用途 | HTTP |
| --- | --- | --- |
| `BusinessException(code, message)` | 可预期的业务失败 | 按 code |
| `ResourceNotFoundException` | 资源不存在 | 404 |
| `LLMUnavailableException` | 大模型不可用/未配置/凭据被拒/额度/上游/空响应 | 503 |
| 其他未捕获异常 | 程序缺陷 | 500（不返回堆栈） |

- 业务失败优先抛 `BusinessException`，不要返回 `ApiResponse.error` 当控制流。
- 不写 `catch (Exception e) { return null; }` 式吞异常；捕获后要么恢复，要么包装成带语义的异常。
- 外部调用异常必须转换成上述类型之一，并在日志中保留上游状态码与简短原因（不含密钥）。

### 8.2 错误码

统一使用 `ApiCode`：200/400/401/403/404/405/409/413/429/500/503。新增码先加常量，再在 `GlobalExceptionHandler` 建立映射，最后同步前端提示。

### 8.3 全局处理

- 所有异常出口集中在 `GlobalExceptionHandler`（19 个处理器）；新增异常类型时补处理器与测试。
- 校验失败返回首个字段错误（中文），不返回整段堆栈或类名。
- 数据库唯一约束冲突映射 409；完整性失败映射 400。
- 大模型失败必须保留 `LLMUnavailableException.Kind`，不得统一压成“AI 服务异常”。

## 9. 响应与分页

```json
{ "code": 200, "message": "success", "data": {}, "timestamp": "2026-10-27T12:00:00" }
```

- 成功：`ApiResponse.success(data)` 或 `ApiResponse.success("提示", data)`。
- 分页：`PagedResponse.of(page)`，字段含列表、总数、页码、页大小。
- 删除成功可返回 `ApiResponse.success()`；不要返回 204 空体（前端拦截器按信封解包）。
- 不在 `message` 中放敏感信息；不把内部异常消息直接透给用户。

## 10. 日志

- 使用 `@Slf4j`；禁止 `System.out/err`。
- 级别：`error` 程序缺陷或不可恢复；`warn` 可恢复的外部失败/降级；`info` 关键业务节点；`debug` 排查细节。
- 格式：中文短句 + 关键 ID，如 `log.info("AI预批改完成: submissionId={}", savedId)`。
- 异常日志保留堆栈（`log.warn("...", e)`）；业务可预期失败不打印堆栈。
- **禁止**打印：密码、令牌、Cookie、API Key、Neo4j 口令、完整请求体（含个人信息）。
- 高频路径（列表、轮询）不打 `info`；需要观测时用指标。
- 日志中的用户输入要截断（如题干前 50 字），避免日志注入与膨胀。

## 11. 安全编码

| 风险 | 规则 |
| --- | --- |
| SQL 注入 | 一律参数化；动态排序白名单 |
| IDOR/BOLA | 按 ID 访问必须对象级 ACL；学生只能看本人，教师只能看本人课程 |
| XSS | 后端不信任前端；富文本入库前过滤/转义策略统一；前端展示再清洗。**纯文本字段（如 AI 问答回答、检索出处）不做 HTML 转义**——落库原文、按原文下发，转义归渲染层；把它们预转义会让实体码出现在文本里、并污染多轮上下文（B-13 ⑭） |
| CSRF | 写接口保持双提交校验；新增豁免端点必须评审 |
| 越权提升 | 不接受客户端传入的 `role`、`score`、`status` 等敏感字段；服务端赋值 |
| 文件上传 | 类型/大小/路径校验；禁止可执行文件直出；下载经鉴权 |
| 密钥 | 只从环境/文件式密钥读取；不写入代码、日志、测试资源 |
| 反序列化 | 只反序列化已知 DTO；禁用多态类型 |
| 限流 | 新增高成本端点评估是否接入 IP 限流/用户配额 |
| 审计 | 管理端写操作写 `operation_logs`；登录写 `login_logs` |

补充：

- 新增公开端点必须加入 `SecurityConfig` 的显式白名单，并说明理由。
- 生产默认关闭 Swagger；测试环境开启。
- Actuator 端点按环境收紧；`/actuator/prometheus` 需 Basic 鉴权，口令为空时 fail-closed。

## 12. 外部集成

### 12.1 Python 引擎

- 路径常量只从 `ContractPaths` 取，禁止在 Java 里硬编码 `/api/v1/...`。
- 适配器实现接口（`KnowledgeGraphContract` / `RagContract`），控制器与业务不直接依赖 HTTP 客户端。
- 超时、重试、降级按 [系统架构设计.md](系统架构设计.md) §8.6；降级结果必须带 `mode` / `gen_mode`。
- 新增端点：Python 服务 + `ContractPaths` + Java 适配器 + 契约测试四件齐全。

### 12.2 大模型

- 只通过 `LLMProvider` 调用；供应商差异在实现层消化。
- 失败抛 `LLMUnavailableException`，禁止返回空字符串/伪 JSON 让上层误判成功。
- 提示词必须**点名 JSON 键名**与类型；要求模型只输出 JSON（可容忍 ```json 栅栏，解析前剥离）。
- JSON 落库前校验：`questions` 的选项/答案为 MySQL `JSON` 列时，标量必须带引号、数组必须序列化；空串不是合法 JSON。
- 调用必须记 `ai_call_logs`（类型、模型、耗时、token、结果）；配额拦截在 `AiQuotaInterceptor`。
- 不在提示词中拼接密钥、内部路径或未脱敏的个人信息。

### 12.3 邮件/外部 HTTP

- 邮件发送失败不得回滚主业务；记录告警并允许重试。
- 外部 HTTP 客户端显式设置连接/读超时；禁止默认无限等待。
- 响应体只解析需要的字段；不把上游原始错误直接透给用户。

## 14. 并发与定时任务

- 定时任务类放 `scheduler/`，方法加 `@Scheduled`；多实例互斥用 `@SchedulerLock`，并设置 `lockAtMostFor` / `lockAtLeastFor`。
- 每个清理任务独立 `try/catch`，单项失败不影响其他项；失败记 `warn` 并继续。
- 任务必须可重入、可重复执行；不依赖“上次运行成功”。
- 长任务拆分批次，避免单次事务过大；需要断点续跑时落状态表。
- 异步线程池使用项目统一配置（`AsyncMvcConfig`），不自行 `new Thread`。

## 3. 单文件组件（SFC）

### 3.1 结构顺序

```vue
<template>
  <!-- 模板 -->
</template>

<script setup lang="ts">
// 逻辑
</script>

<style scoped>
/* 仅本组件样式 */
</style>
```

- 新组件一律 `<script setup lang="ts">`；`<script setup>` 不允许 `this`。
- 组件顶层只放：`defineOptions`、`props`、`emits`、`computed`、生命周期、方法；复杂逻辑抽 composable。
- `defineProps` / `defineEmits` 必须显式声明；禁止依赖 `$attrs` 隐式传参作为主要契约。
- 需要默认值的 prop 用 `withDefaults` 或运行时 `default`（如 `Modal` 的 `width: '720px'`、`closeOnBackdrop: true`）；Boolean prop 缺省且需要"未传 ≠ false"时显式 `default: undefined`。
- 不要用 Vue 保留名做 prop（`style`、`class`、`key`、`ref`）；需要样式变体时用 `variant`。
- 禁止直接修改 prop；需要派生值用 `computed`，需要双向绑定用 `v-model` + emit。
- `v-html` 必须配 DOMPurify 清洗；无清洗不得使用（ESLint 会警告）。
- `console.log/info/debug` 禁止提交（允许 `console.error/warn`）；调试代码删除或加 `eslint-disable` 并说明。

### 3.2 事件与 v-model

- 表单类组件默认 `modelValue` + `update:modelValue`；关闭类事件同时提供 `close` / `closed`（离场后）。
- 事件名用小驼峰（模板中用 kebab-case 监听）。
- 子组件不得直接调用父组件方法；通过事件或 provide/inject（限壳层）通信。
- 同一事件不要同时向父级转发两条语义重复的腿：`Modal` 关闭时发 `update:open(false)`（给 `v-model:open`）与 `close`（给动作回调）两条即止，页面不再造第三条。

### 3.3 组件边界

- 页面只编排：取数、状态、布局、子组件组合；可复用逻辑下沉 composable，可复用视图下沉组件。
- 单文件建议 ≤ 500 行；超过按“列表 / 表单 / 弹层 / 图表”拆分。
- 业务组件不得反向依赖页面；`src/ui/components/` 不 import `src/ui/views/`。
- 浮层只用 §4.1 列出的自研原语；全仓不得出现 `el-*` 标签或 `element-plus` 引用（守卫 `noElementPlus.test.ts` 当前 0 命中，且带阴性对照）。

### 4.2 浮层规则

- 可见性受控：用 `:open` + `@update:open`（或 `v-model:open`）；关闭由组件发事件，页面不要再造第二条关闭腿。
- 浮层一律 Teleport 到 body（组件已内置），避免被父级 `transform`／`filter` 困住层叠上下文。
- 层叠档位目前是 `styles/record.css` 里的固定值：modal `2400`／palette `220`／notif `210`；新增浮层先对齐档位，不要就地写更大的数。
- 焦点与滚动统一走 `composables/useOverlayA11y.ts`（`trapFocus`／`lockViewportScroll` 引用计数／`announce`）；自研浮层必须复用，不得各写一套。
- 不要给 Teleport 根挂指令（如 `v-loading`）：根不是普通元素节点，指令无处安放；在浮层内部包一层容器。
- 删除／危险操作必须有二次确认；确认文案写清对象与后果，禁止"确定/取消"式模糊确认。

## 5. 路由与布局

- 路由 `meta` 必填：`requiresAuth`、`title`；需要角色分流的再加 `role`，页面另带 `pageKey`（导航登记）或 `errorCode`（错误页档）。
- 守卫只有一份实现：`src/router/guard.ts` 的 `installRouterGuard(router, resolvePaths)`，由 `ui/router.ts` 传入本端落点。顺序＝登录态 → 角色 → 目标路由；未登录去 `/login`，角色不符去对应端首页，后端不可达去 `/503`，未知路径 `/404`。
- `/503`、`/403`、`/404` 与登录／注册／法务页必须 `requiresAuth: false`，否则守卫会再次发起会话探针形成轮询环。
- 页面切换时取消未完成请求（`cancelAllPendingRequests`），避免旧响应覆盖新页面；重试路径不得复用已中止的 `signal`。
- 壳层只有 `src/ui/Shell.vue` 一套；导航结构与页面登记集中在 `ui/nav.ts`，"提不提供某页"由 `ui/notProvided.ts` 处置（`provided`／`hidden`／`unavailable`），页面不重复写导航。
- 路由懒加载：页面级 `() => import(...)`；首屏只加载登录/壳层必要模块。

---

## 6. 状态管理

- 全局 store 只有 `auth`；其他状态放页面/composable。
- 权限判定以服务端 `/auth/permissions` 响应为准；本地缓存只用于渲染，`permissionsLoaded` 只由真实响应置位，不得由 localStorage 恢复。
- 前端角色只用于显示与路由分流，**不作为授权凭据**；按钮权限同样 fail-closed。
- 不在模块顶层保存可变单例（跨页泄漏）；需要共享时用 store 或显式参数。
- 不把令牌写入 localStorage/sessionStorage（令牌在 HttpOnly Cookie）；只持久化非敏感的用户展示信息。

## 7. 请求层

### 7.1 分层

```text
页面 / composable
  → api/<域>.ts（命名导出 + default 对象）
  → api/request.ts（axios 实例）
      baseURL `/api`、withCredentials、XSRF-TOKEN/X-XSRF-TOKEN
      请求取消、重试、统一错误提示、信封解包
```

- 页面不得直接 `import axios`；一律经 `api/` 模块。
- API 模块只做 URL/参数/方法封装，不写业务状态与提示。
- 每个模块同时提供命名导出与 default 对象，保持调用方两种写法兼容。
- 路径必须与后端一致；新增/修改后跑 `npm run lint:api-refs`。

### 7.2 错误处理

- 统一错误文案在 `api/request.ts` + `utils/requestError.ts`，页面不拼接 axios 原始英文错误。
- 401：清理登录态并跳转登录；403/404/429/500/503 按统一中文提示。
- 网络错误与 502/503/504 自动重试一次；非幂等方法不得盲目重试。
- 页面必须显式处理三态：加载中、空数据、加载失败；**失败不得渲染成“暂无数据”**。
- 列表失败用 `useListFeedback` 统一错误态与重试；弹窗失败保留用户输入。
- 不在 catch 中静默吞错；至少记录并给用户可操作提示。

### 7.3 表单

- 提交态由所在页面/composable 自持（如 `submitting` ref）：按钮 `:disabled` 绑定它、文案切"提交中…"，并在 `finally` 复位——旧端的 `useFormSubmit` 已随旧端下线，不再有共享封装。
- 校验规则就近声明；跨字段校验在提交前统一执行；失败要把焦点／滚动定位到首个错误控件。
- 成功后关闭浮层并刷新列表；失败保持浮层打开并保留用户输入。
- 危险操作二次确认统一走 `utils/dangerConfirm.ts` 的 `confirmDanger()`；确认后仍需处理失败提示与回滚路径。

### 7.4 分页

- 服务端分页用于数据量无上限的列表（默认选择）。
- `useClientPagination` 只用于已经一次性取全的数据（如课程名册、成绩簇）；不得用它掩盖未分页的后端接口。
- 分页参数统一 `page`（从 1 开始）/`size`；与后端 `PagedResponse` 对齐。
- 需要“全量导出/统计”时使用显式的 `getAllXxx` 分页遍历，不把 `size` 调到超大。

## 8. 样式与设计令牌

### 8.1 令牌

| 族 | 令牌 | 说明 |
| --- | --- | --- |
| 表面／文字／线 | `--bg`、`--surface`／`--surface-2`／`--surface-3`、`--ink`／`--ink-2`…`--ink-4`、`--line`／`--line-strong` | 明暗两套在 `record.css` 分层覆写 |
| 品牌与语义色 | `--accent`（＋`--accent-ink`／`--accent-strong`／`--accent-soft`／`--accent-2`）、`--ok`／`--warn`／`--danger`／`--info` 各带 `-soft`、`--tone-1…5` | 状态色成对使用（实心＋soft 底） |
| 字体 | `--font-body`／`--font-display`／`--font-mono` | `--font-display` 即 `--font-body`：标题与读数不另起衬线 |
| 圆角 | `--r-card`、`--r-ctl`、`--r-chip`、`--r-xs`／`--r-sm`／`--r-md`／`--r-lg`／`--r-bar`／`--r-circle` | 暗色档把 card 16→12、ctl 10→8 |
| 阴影 | `--sh-card`、`--sh-pop` | 卡面不投影，浮层保留 |
| 几何 | `--nav-w`、`--header-h`、`--status-h` | 窄屏在媒体查询里改档，不在页面写死 |
| 动效 | `--ease`、`--t-fast` | 只用于浮层与状态反馈；壳层与内容不做入场动画 |
| 焦点 | `--focus` | 不得移除 `:focus-visible` 轮廓 |

**间距没有令牌族**：现状是 `gap`／`padding` 的字面值。新增间距沿用同区块既有档位，**不要引用 `--ac-spacing-*` 这类已随旧端作废的令牌名**。

规则：

- 颜色、圆角、阴影优先用令牌；新增硬编码值前先确认令牌是否缺失，缺失则补令牌而不是就地写死。
- 局部样式用 `<style scoped>`；跨页共享类放 `src/ui/styles/`（`record.css` 基础层＋`form`／`auth`／`typography`／`shell-fix`），选择器以 `body[data-app="ui"]` 作用域起头。已无组件库覆写层，`!important` 全 样式共 8 处，新增必须写明压过什么。
- 深色/浅色必须同时验证；不得只在一个主题下可读。
- 禁止用颜色作为唯一状态信号（配合文字/图标）。
- 响应式：以 1440×900 为设计基准，窄屏至少保证 375 宽可用；浮层宽度用 `width` prop 或 min/max，不写死超出视口的 px。
- 不使用 `position: fixed` 的页面级元素覆盖壳层导航；需要时用浮层原语。

### 8.2 界面纪律：文案与密度（2026-11-17）

目标：像 Linear 官网／苹果备忘录那样干净——**页面靠布局自解释，不靠解释性文字**。

每加一句话先过三问：

1. 它是动作标签、数据，还是改不了的事实（不可撤回／仅查询／需输入新值）？三者皆不是 → 删。
2. 删掉后页面还看得懂吗？看不懂 → 改布局（分组、顺序、列、行高），不是把话加回来。
3. 它是空态还是错误态？两者都只给一行；错误态另给「重试」。

落地约束：

- 一页 = `PageHead(title)` + 动作 + 内容。页头没有副标题、kicker、来源章；`PageDef` 不再有 `desc` 字段。
- 以下类名已退役，模板里再出现即判红：`page-kicker`／`page-sub`／`card-kicker`／`card-sub`／`card-hint`／`ai-caveat`／`eyebrow`／`lede`／`av-story`／`av-feat`／`av-motto`。
- 空态：`<b>一句</b>`；不再写「XX 会出现在这里」。
- 数据驱动的 note（`{{ note }}`、截断提示、错误原文）保留，但走既有语义类（`card-foot`／`callout`／`hint`），不新造说明段。
- 视觉：一套系统字族、四档字号（22／14／13／12）；标题无衬线；无渐变、无入场动画、无 hover 位移与辉光；分隔只用 1px 线。
- 守卫：`frontend/src/ui/__tests__/copyLaw.test.ts`（含阴性对照），红线与 `noDemoLayer` 同级。

### 8.3 可访问性

- 图标按钮必须有 `aria-label`；装饰图标 `aria-hidden="true"`。
- 表单控件必须有 label 或 `aria-label`；错误提示与控件关联。
- 键盘可达：可点击元素优先用 `<button>`/`<a>`；自定义控件支持 Enter/Space。
- 焦点可见：不得全局移除 `:focus-visible` 轮廓；弹层内焦点陷阱、关闭后归还。
- 状态变化用 `aria-live` 播报（浮层与异步结果走 `useOverlayA11y.ts` 的 `announce()`，轻量反馈走 `Toasts` 的 `aria-live="polite"` 容器）；加载态用 `aria-busy`。
- 文本对比度 ≥ 4.5:1（大字号 ≥ 3:1）；不得仅靠 hover 暴露关键操作。
- 动画尊重 `prefers-reduced-motion`；自动播放/轮播可暂停。

## 9. 性能

- 路由级懒加载；大组件/图表/导出库动态 `import()`。
- 列表渲染超过 ~100 行时考虑虚拟滚动或分页；不得无界渲染全量数据。
- 图片使用适当尺寸与懒加载；不在模板中做重计算，放 `computed`。
- 避免在 `watch` 中做深度遍历大对象；必要时用 `watchEffect` + 明确依赖。
- 新增第三方库前先看 `npm run build && npm run size:gate` 的增量；超预算必须说明理由并调整分块。
- 不把整库引入（如 `import _ from 'lodash'`）；按需导入。
- 图形是内联 SVG（`Sparkline`／`Sprite`），没有第三方图表实例；但 `requestAnimationFrame`、定时器和 `document`／`window` 监听必须在 `onBeforeUnmount` 移除。

## 10. 测试

### 10.1 单元/组件测试（Vitest）

- 文件放 `__tests__/`，命名 `Xxx.test.ts`；与被测文件同域。
- 使用 `@vue/test-utils` 挂载；断言用户可见行为（文本、角色、事件），不测实现细节。
- 必须覆盖：空态、加载态、错误态、权限拒绝、边界输入。
- 弹层测试注意 Teleport：必要时 `stubs: { teleport: true }` 或挂到 `document.body`；`Transition` 需 `stubs: { transition: false }` 并 mock `requestAnimationFrame`。
- 不 mock 被测组件自身的子组件行为到“只剩快照”；关键交互要真实触发。
- 快照只用于稳定结构，不替代行为断言。

### 10.2 端到端（Playwright）

- 流程 spec 放 `e2e/`，按业务链路命名；选择器优先 `getByRole` / `getByLabel` / 稳定的 `data-testid`，避免依赖样式类与 DOM 层级。
- 前置：后端 8080 就绪、`RATELIMIT_LOGIN_LIMIT=200`、前端 5173；`.auth` 夹具与端口绑定，跨端口需重绑。
- 不写固定 `sleep`；用 `expect(...).toBeVisible()` / `waitFor`。
- 每个 spec 独立登录态，不依赖执行顺序；测试数据可重复创建/清理。
- 新增页面若纳入视觉回归，需同时加锚点、遮罩与基线，不能只加流程用例。

### 10.3 视觉回归

- 配置：`playwright.visual.ts`，1440×900、DPR 1、`reducedMotion: reduce`、冻结时钟；独立端口 5175。
- 基线：5 锚点 × 明暗 = 10 张（`e2e/visual/v2-anchors.spec.ts`）；`threshold: 0`、`maxDiffPixelRatio: 0.0001`。

### 10.4 类型与静态检查

## §3 协作规范（分支、PR、门禁）

> 来源：原 `docs/脱敏核查-2026-11-07.md`。核查口径：对「日志 / 回显 / 导出」三个泄露面逐点核对。

### 4.2 受控例外（不做脱敏的点及理由，**必须保持**）

| 点 | 理由 | 既有防线 |
| --- | --- | --- |
| ADMIN 用户列表返回原文联系方式 | 管理运营刚需（检索 / 联系用户） | 仅 ADMIN 可达 + 院系 scope 门禁 + 操作日志留痕 |
