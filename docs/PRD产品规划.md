## 1. 产品定位

### 1.1 一句话

**把"教、学、练、考、评、析"收进一个平台，并用 AI 把教师最耗时的三件事（出题、批改、学情分析）变成可审核的建议，而不是不可控的自动决策。**

### 1.2 目标用户

| 用户 | 典型场景 | 核心痛点 | 产品回应 |
| --- | --- | --- | --- |
| 学生 | 上课前后自学、做作业、考试、查漏 | 不知道学什么、错了不知道为什么、反馈慢 | 学习路径、错题本、AI 问答、即时成绩与评语 |
| 教师 | 建课、布置任务、组卷、批阅、看学情 | 重复劳动多、批阅量大、学情靠感觉 | 自动组卷、AI 预批（教师确认）、多维分析 |
| 管理员 | 建账号、分班、管权限、审内容、看用量 | 权限边界不清、内容风险、AI 成本不可见 | RBAC、审核台、按课程 AI 用量 |
| 平台运营/运维 | 部署、监控、审计、容量与合规 | 系统黑盒、故障不可观测、数据不可控 | 监控告警、审计、备份恢复、SLO 与降级语义 |

### 1.3 差异化

1. **闭环而非单点**：从建课到批阅到学情是一条真实可走通的链，不是若干演示页。
2. **AI 可审核**：AI 出题、批改、建议都落为"建议/草稿"，最终由教师确认；失败明确 503，不伪造成功。
3. **知识图谱 + RAG 双引擎**：课程内知识点关系可解释；问答有检索依据，不是纯聊天。
4. **生产可信度**：门禁、视觉基线、审计台账、降级语义齐全；上线验收能指到命令与读数。

### 1.4 目标语境与阶段边界

- **Phase 1（首要目标）**：单租户生产系统，按 **≥10,000 注册用户** 设计容量；并发/峰值以目标环境压测为准，不提前承诺 QPS/SLA。
- **Phase 2（后续扩展）**：多租户 SaaS（`tenant_id`、租户隔离、配额/计费、租户管理）；Phase 1 **不落 `tenant_id`**，但新增代码不得硬编码单租户假设，保留租户上下文、缓存与存储命名空间的扩展点。
- **部署形态**：开发/验收可用本机原生；生产 Phase 1 必须具备 TLS/反代、容器或等价编排、密钥管理、备份恢复、监控告警、回滚与灰度能力。私有化部署作为后续可选项，不作为 Phase 1 的前置条件。
- **合规优先级**：上线前至少具备隐私告知、访问控制、审计、数据导出/删除、保留期等最低合规能力；脱敏、私有化部署等高级合规排在 KG+LLM 主链之后，但不得晚于对外生产承诺。
- **Phase 1 明确不做**：多租户/计费、小程序、桌面端；列入 Phase 2/后续路线。示范课程与示例数据仅用于开发/验收环境，不进入生产库。

## 2. 角色与用户故事

### 2.1 学生

- S1 我想看到我选的课、章节进度和待办，知道今天该做什么。
- S2 我想在课程里提交作业/试卷（文本 + 附件），并能看到是否提交成功。
- S3 我想在截止前收到提醒，断网/关页后回来还能续上。
- S4 我想考试时看到剩余时间，超时能自动交卷且不丢答案。
- S5 我想看到分数、教师评语和错题解析，知道下一步补什么。
- S6 我想问 AI 课程问题，答案要能指到课程资料。
- S7 我想看自己的知识图谱和薄弱点，按推荐路径学习。

### 2.2 教师

- T1 我想建课、排章节、传资源、发通知。
- T2 我想从题库选题组卷，或按题型/数量/难度自动组卷，再微调。
- T3 我想发布试卷，学生只看到已发布的卷。
- T4 我想看到待批阅列表，逐份打分/写评语/退回重做。
- T5 我想让 AI 先给建议分和评语，我再采纳或修改。
- T6 我想看课程/班级/学生的成绩分布与薄弱点。
- T7 我想维护课程知识点与关系，让 AI 能基于图谱回答。
- T8 我想监控考试过程，看到风险事件并及时处理。

### 2.3 管理员

- A1 我想创建/停用账号、分班、分配角色与权限。
- A2 我想管课程目录、审核课程与内容、处理违规。
- A3 我想看 AI 用量（按课程/用户）和平台运行状态。
- A4 我想查登录/操作日志、在线会话，能强制下线。
- A5 我想管学期，支持归档与批量归档。

### 2.4 关键约束

- 权限必须"后端为准、前端只做可见性"；对象级权限不可省。
- AI 不得替教师做最终评分；不得把失败包装成成功。
- 学生数据只对本人、授课教师、管理员可见；导出与日志不得泄露。

**结论（主题口径）**：本系统的 AI 助教主线**已在教师侧闭环**（知识结构化 → 学情诊断 → 路径规划 → 答疑 → 作业考试），并有两套引擎（KG 8001／RAG 8002／微调 8003）在跑；**学生侧课程空间内的 AI 助手与知识图谱也已接真**。剩余待扩展项集中在跨课程全局助手、图谱节点按掌握度着色、AI 用量治理（依赖 B-13④ 聚合端点）与语音输入，其中只有 AI 用量治理涉及新增后端契约。

### 4.2 统一语义

- 非空字符串＝真实生成；`null`＝Key 未配置；失败＝`LLMUnavailableException` → HTTP 503。
- 错误分类：`NOT_CONFIGURED` / `CREDENTIAL_REJECTED` / `QUOTA_OR_THROTTLED` / `UPSTREAM_UNREACHABLE` / `EMPTY_RESPONSE`；4xx 不重试。
- 出题 JSON 必须过"栅栏剥离 → JSON 列序列化 → 键名完整性"三道；空题干视为失败（DR-87/88/89）。
- AI 预批只回填，不写最终成绩；教师提交批阅才是权威动作。
- 对外宣称边界：微调"引擎可用"≠"可售"；问答"已建语料课程可用"≠"任意课程开箱可答"。

### 4.3 质量与安全

- 提示词必须点名期望 JSON 键；变更需回归出题/批改两条链路。
- 用户输入不得直接拼进系统指令；输出进前端必须走既有 XSS 防护（`v-html` 仅白名单场景）。
- 成本：按课程/用户记录 AI 调用；配额限制教师出题；暂无计费。
- 评测：RAG 60 题幻觉率基线未建立；LoRA 语料 108 条 × 3 epoch 会过拟合，不作为可售能力。

## 5. 核心流程

### 5.1 登录与会话

```
打开站点 → 会话探针 /auth/permissions
  ├─ 200 → 按角色进默认页
  ├─ 401 → 登录页（账号+密码+验证码）
  └─ 后端不可达 → /503（3s 轮询 ×40，恢复后回跳）
登录 → 限流 10/60s/IP → 失败 5 次锁定 15min（IP+账号）
     → JWT + 刷新令牌 + CSRF 双提交 → 进入工作台
```

### 5.2 课程学习


### 5.3 试卷创建—发布—批阅闭环（2026-10-26 落地）

**目标**：教师独立完成"创建试卷（手动选题或自动组卷）→ 发布 → 学生提交 → 教师批阅（打分/退回/AI 辅助）"。

| P0-2 | 试卷发布：行内发布 + 二次确认 + 草稿/已发布状态 | `CourseExams.vue` | ✅ |

| P2 | 成绩报告可视化、试卷复制/统计 | — | ⏳ |

**已定口径**：

- 批阅对象＝**作业任务提交**（`/submissions`）；考试卷面批阅是另一条链路，另行立项。
- AI 预批只回填建议，不直接改分；教师确认才生效。
- 退回需填理由；学生重交后回到待批队列。
- 批阅分数停留在 submission；总评走既有成绩体系，本批未追加成绩项落账。
- 题型契约以真实库为准：`*_CHOICE` / `TRUE_FALSE` 风格，难度小写；`questionTypes` 为单一出处。

**验收最小集**：建卷并选题保存 → 编辑回显 → 发布 → 待批阅下钻 → 打分 → 退回并重交 → 未批计数变化；全链不新增后端 Java 代码（实际仅新增选题批量端点）。

### 6.2 安全

- 五层防护：网络/传输 → 认证 → 授权（方法级+对象级）→ 输入/输出 → 审计。
- 登录双保护：IP 限流 + 账号失败锁定；429 不打日志的问题已定性。
- CSRF 双提交；JWT 角色以 DB 现行值为准；刷新令牌单飞。
- 密钥只进 `.env`/Secret；历史凭据必须轮换；Key 必须 ASCII。
- 生产必须：`DEMO_ACCOUNTS_ENABLED=false`、CORS 不回落 localhost、Swagger 关闭、actuator 最小暴露、非 root 运行。
- 已知边界：`npm audit` 3 条 moderate 有意暂缓；git 历史凭据不重写，靠轮换。

### 6.3 可用性与降级

| 故障 | 行为 |
| --- | --- |
| 后端未就绪 | 前端 `/503` 页，轮询恢复 |
| KG 不可达 | 本地 BFS / 内存图，`mode` 标注 |
| RAG 不可达 | 纯 LLM 或抽取式，`gen_mode` 标注 |
| LLM 失败 | HTTP 503 + 分类，不返回假成功 |
| Redis 不可达 | 限流/缓存降级到进程内（能力受限但可用） |
| WebSocket 断链 | 30s 心跳，~31s 重连（已知） |

### 6.4 兼容与无障碍

- 桌面浏览器：Chrome / Edge 最新两个大版本；1440×900 为视觉基线几何。

- 键盘：所有对话框可 Tab 进入/退出，焦点陷阱；Esc 只关栈顶；`aria-live` 路由播报。
- 对比度：目标 WCAG AA；浅色侧栏 11/255 低于 24 阈值属已知残项。

## 7. 生产与多租户路线（Phase 1 / Phase 2）

### 7.1 形态判定

| 阶段 | 形态 | 定位 | 主要改造 |
| --- | --- | --- | --- |
| **Phase 1** | 单租户 Web（云主机/私有化均可承载） | **首要生产目标** | 生产安全、可观测、备份恢复、容量压测、最低合规；**不引入 `tenant_id`** |
| **Phase 2** | 多租户 Web SaaS | 后续扩展 | `tenant_id` 行级隔离、租户上下文、配额/计费、租户管理 |
| 后续 | 微信小程序 / 桌面 | 可选 | uni-app / Tauri；不进入 Phase 1 |

结论：**Phase 1 先交付单租户生产系统；Phase 2 在多租户需求确认后启动**。Phase 1 的代码不得把单租户假设写死，新增模块需保留租户上下文、缓存键与存储命名空间的扩展点。

### 7.2 阶段

| 阶段 | 目标 | 关键工作 | 验收 |
| --- | --- | --- | --- |
| **Phase 1** | 单租户生产系统 | 生产安全与 ACL 矩阵、可观测与告警、备份恢复、容量/长稳压测、最低合规、KG+LLM 主链与教学主链 | 生产就绪清单全绿；≥10,000 注册用户的容量证据来自目标环境 |
| **Phase 2** | 多租户 SaaS | `tenant_id` + `TenantLineInnerInterceptor` + ThreadLocal；缓存/文件按租户隔离；租户配额/计费/管理台 | F-18：任一跨租户遗漏即不通过；F-19 通过 |
| 后续 | 小程序 / 桌面 | uni-app、code2session、Tauri；重考试与防作弊仍留在 Web | 独立立项验证 |

### 7.3 前置与风险

- **Phase 1 不引入多租户**：`tenant_id` 零命中；Phase 2 从零引入，工期最高；Phase 1 只保留扩展点，不得声称已支持 SaaS。
- **高并发不是口号**：当前只有本机历史压测（1,694 req/s）读数，没有目标环境容量证据；Phase 1 必须完成 DB/Redis/LLM 并发压测、慢 SQL/N+1 治理和水平扩展验证。
- **生产部署未落地**：A 路径/容器/TLS/反代/密钥/备份恢复/监控告警仍是断链；开发本机 C 路径不能作为生产交付。
- **合规分级**：上线最低合规（隐私告知、访问控制、审计、导出/删除、保留期）必须先达标；脱敏、私有化部署等高级能力可排在 KG+LLM 之后，但不得晚于对外生产承诺。
- **AI 生产化**：KG/RAG/LLM 链路已真实接通过，但缺少生产级评测集、成本/配额治理与高并发降级验证；微调引擎不应作为可售能力。
- **无 MQ**：通知重试、异步判分靠应用内实现；Phase 1 需评估是否引入可靠队列。
- **密钥与凭据**：生产需 Secret Manager/文件式密钥、轮换与最小权限；不得沿用演示凭据。

| --- | --- | --- |

| **Phase 2 新增（多租户）** | 租户管理台、`tenant_id` 隔离、租户配额/计费、租户级 RBAC | Phase 2 的交付物；不得在 Phase 1 用假租户数据充数 |

## 10. 验收与度量

### 10.1 生产验收层

- 三端主要页面可登录、可操作、可返回；无空白页、无控制台报错。
- 教学主链、AI 四链路、KG/RAG 在目标环境有真实证据；不以本机演示代替。
- 核心流程验收脚本覆盖“教师建卷→发布→学生提交→教师批阅→成绩可见”。
- 所有对外宣称有降级边界：不把“引擎可用”说成“任意课程可用”，不把“预批”说成“自动评分”。
