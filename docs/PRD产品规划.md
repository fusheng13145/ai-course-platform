## 1. 产品定位

### 1.1 一句话

**把"教、学、练、考、评、析"收进一个平台，并用 AI 把教师最耗时的三件事（出题、批改、学情分析）变成可审核的建议，而不是不可控的自动决策。**

### 1.2 目标用户

| 用户 | 典型场景 | 核心痛点 | 产品回应 |
| --- | --- | --- | --- |
| 学生 | 上课前后自学、做作业、考试、查漏 | 不知道学什么、错了不知道为什么、反馈慢 | 学习路径、错题本、AI 问答、即时成绩与评语 |
| 教师 | 建课、布置任务、组卷、批阅、看学情 | 重复劳动多、批阅量大、学情靠感觉 | 自动组卷、AI 预批（教师确认）、多维分析 |
| 管理员 | 建账号、分班、管权限、审内容、看用量 | 权限边界不清、内容风险、AI 成本不可见 | RBAC、审核台、按课程 AI 用量 |
| 答辩/评审者 | 看演示、问边界 | 怕"演示造假、能力夸大" | 真实链路证据、降级语义、逐条读数 |

### 1.3 差异化

1. **闭环而非单点**：从建课到批阅到学情是一条真实可走通的链，不是若干演示页。
2. **AI 可审核**：AI 出题、批改、建议都落为"建议/草稿"，最终由教师确认；失败明确 503，不伪造成功。
3. **知识图谱 + RAG 双引擎**：课程内知识点关系可解释；问答有检索依据，不是纯聊天。
4. **工程可信度**：门禁、视觉基线、审计台账、降级语义齐全；答辩能指到命令与读数。

### 1.4 交付语境与非目标

- 当前是**大创赛交付**：优先"可演示、可解释、可复现"，不以公网大规模运营、计费、多租户为当前验收面。
- 示范课程固定 **计算机网络（4007）**；演示数据只进演示环境。
- 不做：多租户、计费、小程序、桌面端（列为 M1–M4 未来路线）；公网 TLS/容器化上线（列为 A 路径）。

## 2. 角色与用户故事

### 2.1 学生

- S1 我想看到我选的课、章节进度和待办，知道今天该做什么。
- S2 我想在课程里提交作业/试卷（文本 + 附件），并能看到是否提交成功。
- S3 我想在截止前收到提醒，断网/关页后回来还能续上。
- S4 我想考试时看到剩余时间，超时能自动交卷且不丢答案。
- S5 我想看到分数、教师评语和错题解析，知道下一步补什么。
- S6 我想问 AI 课程问题，答案要能指到课程资料。
- S7 我想看自己的知识图谱和薄弱点，按推荐路径学习。

### 2.2 教师

- T1 我想建课、排章节、传资源、发通知。
- T2 我想从题库选题组卷，或按题型/数量/难度自动组卷，再微调。
- T3 我想发布试卷，学生只看到已发布的卷。
- T4 我想看到待批阅列表，逐份打分/写评语/退回重做。
- T5 我想让 AI 先给建议分和评语，我再采纳或修改。
- T6 我想看课程/班级/学生的成绩分布与薄弱点。
- T7 我想维护课程知识点与关系，让 AI 能基于图谱回答。
- T8 我想监控考试过程，看到风险事件并及时处理。

### 2.3 管理员

- A1 我想创建/停用账号、分班、分配角色与权限。
- A2 我想管课程目录、审核课程与内容、处理违规。
- A3 我想看 AI 用量（按课程/用户）和平台运行状态。
- A4 我想查登录/操作日志、在线会话，能强制下线。
- A5 我想管学期，支持归档与批量归档。

### 2.4 关键约束

- 权限必须"后端为准、前端只做可见性"；对象级权限不可省。
- AI 不得替教师做最终评分；不得把失败包装成成功。
- 学生数据只对本人、授课教师、管理员可见；导出与日志不得泄露。

**结论（主题口径）**：本系统的 AI 助教主线**已经在教师侧闭环**（知识结构化 → 学情诊断 → 路径规划 → 答疑 → 作业考试），并有两套引擎（KG 8001／RAG 8002／微调 8003）在跑；**学生侧只差「把已有端点接上界面」**，不涉及新后端——这是下一阶段的首要待扩展项。

### 4.2 统一语义

- 非空字符串＝真实生成；`null`＝Key 未配置；失败＝`LLMUnavailableException` → HTTP 503。
- 错误分类：`NOT_CONFIGURED` / `CREDENTIAL_REJECTED` / `QUOTA_OR_THROTTLED` / `UPSTREAM_UNREACHABLE` / `EMPTY_RESPONSE`；4xx 不重试。
- 出题 JSON 必须过"栅栏剥离 → JSON 列序列化 → 键名完整性"三道；空题干视为失败（DR-87/88/89）。
- AI 预批只回填，不写最终成绩；教师提交批阅才是权威动作。
- 对外宣称边界：微调"引擎可用"≠"可售"；问答"已建语料课程可用"≠"任意课程开箱可答"。

### 4.3 质量与安全

- 提示词必须点名期望 JSON 键；变更需回归出题/批改两条链路。
- 用户输入不得直接拼进系统指令；输出进前端必须走既有 XSS 防护（`v-html` 仅白名单场景）。
- 成本：按课程/用户记录 AI 调用；配额限制教师出题；暂无计费。
- 评测：RAG 60 题幻觉率基线未建立；LoRA 语料 108 条 × 3 epoch 会过拟合，不作为可售能力。

## 5. 核心流程

### 5.1 登录与会话

```
打开站点 → 会话探针 /auth/permissions
  ├─ 200 → 按角色进默认页
  ├─ 401 → 登录页（账号+密码+验证码）
  └─ 后端不可达 → /503（3s 轮询 ×40，恢复后回跳）
登录 → 限流 10/60s/IP → 失败 5 次锁定 15min（IP+账号）
     → JWT + 刷新令牌 + CSRF 双提交 → 进入工作台
```

### 5.2 课程学习

```
教师建课 → 加章节 → 传资源 → 发任务/试卷 → 发通知
学生选课 → 学习中心看到待办 → 学章节/看资源 → 交作业/考试
教师批阅 → 学生看成绩/评语 → 错题本/学情 → AI 建议下一步
```

### 5.3 试卷创建—发布—批阅闭环（2026-10-26 落地）

**目标**：教师独立完成"创建试卷（手动选题或自动组卷）→ 发布 → 学生提交 → 教师批阅（打分/退回/AI 辅助）"。

| 优先级 | 需求 | 落点 | 状态 |
| --- | --- | --- | --- |
| P0-1 | 批阅工作流：待批阅列表 → 逐份批阅 → 打分/评语/退回 | 课程空间 `CourseGradesTab` 下钻 | ✅ |
| P0-2 | 试卷发布：行内发布 + 二次确认 + 草稿/已发布状态 | `CourseExams.vue` | ✅ |
| P0-3 | 表单接选题：题库勾选、已选分值合计、编辑回显 | `CeExamFormDialog.vue` | ✅ |
| P1-1 | AI 预批：建议分/评语回填 | 批阅详情 | ✅ |
| P1-2 | 自动组卷：题型×数量×难度 → 回填 | 试卷表单 | ✅（数量为上限，非精确值） |
| P1-3 | 查重结果展示 | 批阅详情 | ⏳ |

**已定口径**：

- 批阅对象＝**作业任务提交**（`/submissions`）；考试卷面批阅是另一条链路，另行立项。
- AI 预批只回填建议，不直接改分；教师确认才生效。
- 退回需填理由；学生重交后回到待批队列。
- 批阅分数停留在 submission；总评走既有成绩体系，本批未追加成绩项落账。
- 题型契约以真实库为准：`*_CHOICE` / `TRUE_FALSE` 风格，难度小写；`questionTypes` 为单一出处。

**验收最小集**：建卷并选题保存 → 编辑回显 → 发布 → 待批阅下钻 → 打分 → 退回并重交 → 未批计数变化；全链不新增后端 Java 代码（实际仅新增选题批量端点）。

### 5.4 AI 问答

```
学生提问 → 意图/课程解析 → RAG 检索 top-k（BM25+向量+RRF）
  → 有资料：LLM 生成（SSE 流式）→ 引用来源
  → 无资料：抽取式/明确不可用
  → 引擎不可达：503 或纯 LLM 降级（gen_mode 标注）
```

首次登录（v2 键不存在）→ 5 步引导
  ├─ 下一步/完成 → done
  ├─ 跳过 → skipped
  └─ Esc/点洞外 → paused@n（刷新从第 n 步续看）
侧栏菜单「新手引导」可重看；v1 键只读迁移

### 6.2 安全

- 五层防护：网络/传输 → 认证 → 授权（方法级+对象级）→ 输入/输出 → 审计。
- 登录双保护：IP 限流 + 账号失败锁定；429 不打日志的问题已定性。
- CSRF 双提交；JWT 角色以 DB 现行值为准；刷新令牌单飞。
- 密钥只进 `.env`/Secret；历史凭据必须轮换；Key 必须 ASCII。
- 生产必须：`DEMO_ACCOUNTS_ENABLED=false`、CORS 不回落 localhost、Swagger 关闭、actuator 最小暴露、非 root 运行。
- 已知边界：`npm audit` 3 条 moderate 有意暂缓；git 历史凭据不重写，靠轮换。

### 6.3 可用性与降级

| 故障 | 行为 |
| --- | --- |
| 后端未就绪 | 前端 `/503` 页，轮询恢复 |
| KG 不可达 | 本地 BFS / 内存图，`mode` 标注 |
| RAG 不可达 | 纯 LLM 或抽取式，`gen_mode` 标注 |
| LLM 失败 | HTTP 503 + 分类，不返回假成功 |
| Redis 不可达 | 限流/缓存降级到进程内（能力受限但可用） |
| WebSocket 断链 | 30s 心跳，~31s 重连（已知） |

### 6.4 兼容与无障碍

- 桌面浏览器：Chrome / Edge 最新两个大版本；1440×900 为视觉基线几何。
- 窄屏：<768px 侧栏抽屉；375×667 有引导五步 e2e，但不承诺全站完整。
- 键盘：所有对话框可 Tab 进入/退出，焦点陷阱；Esc 只关栈顶；`aria-live` 路由播报。
- 对比度：目标 WCAG AA；浅色侧栏 11/255 低于 24 阈值属已知残项。
- 动效：reduced-motion 下关闭非必要动画。

### 6.5 数据与合规

- 演示数据不进生产；新租户必须空库开通。
- 日志不记录密码、令牌、密钥；敏感字段脱敏。
- 账号注销/数据导出/隐私政策未实现（产品化阶段）。

## 7. 产品化路线（M1–M4）

### 7.1 形态判定

| 形态 | 可行性 | 定位 | 主要改造 |
| --- | --- | --- | --- |
| 多租户 Web SaaS | ★ 最优 | **主形态** | 租户隔离、计费、配额 |
| 微信小程序 | 可行 | 轻触达（课表/成绩/刷题/通知） | uni-app 重写、`code2session`、Bearer |
| 桌面（Tauri） | 可选低优先 | 内网一体机 | 打包前端 + 内网后端 |

结论：**多租户 Web SaaS 为主 + 小程序轻端**；桌面仅在特定内网场景。

### 7.2 阶段

| 阶段 | 目标 | 关键工作 | 验收 |
| --- | --- | --- | --- |
| M1 | 多租户数据隔离 + 租户上下文 | `tenant_id` 行级 + `TenantLineInnerInterceptor` + ThreadLocal；缓存 key 租户前缀；跨租户拒绝单测 | F-18：任一遗漏即不通过 |
| M2 | 认证 / 计费 / 配额 | 网关 tenant-scoped JWT；配额复用 Sentinel；计费台账；小程序 code2session 桥接 | F-19 |
| M3 | 微信小程序轻端 | uni-app；临时文件上传、订阅消息；重考试留在 Web | F-19 通过 |
| M4 | 桌面一体机（可选） | Tauri + 内网后端 | 离线场景验证 |

### 7.3 前置与风险

- **当前代码是单租户**：`tenant_id` 零命中，M1 从零引入，工期最高。
- 引擎容器化未完成：三份 Dockerfile 缺失，K8s 需先补镜像。
- 引擎契约层加 `tenantId` 即可复用，不必重写 KG/RAG。
- 演示数据隔离已解决，但"用演示库快照建生产库"仍会静默带数据；开通必须空库。
- 微调引擎有、用户侧无；算力仅 CPU 0.5B 验证，不宜作为可售项。
- 密钥需进 Secret Manager；Prometheus 也要文件式密钥。
- 无 MQ：通知重试/异步判分靠应用内实现；M2/M3 需决定是否引入。
- 合规：个人信息最小必要、加密、审计；账号注销/导出未做。

### 7.4 模块清单（复用 vs 新增）

| 面 | 内容 | 口径 |
| --- | --- | --- |
| **复用现有** | 课程管理、章节／资源管理、作业（批改／查重）、在线考试（防作弊）、题库、学情分析、知识图谱可视化与学习路径 | 已验证可用；图谱侧是可交互力导向图 + 「最短跳数」路径规划，「学情 + 路径推荐」可直接复用 |
| **不列入「已验证可用」** | AI 助教四项（问答／出题／批改／建议） | 缺可用凭据与留出评测集，端到端无 E2E 证据；失败按 503 如实降级（见 `docs/测试文档.md` §11） |
| **产品化新增（SaaS 必需）** | ① 多租户管理台（租户开通／停用／配置／成员映射）；② 租户配额与计费（按席位／课程／AI 调用量，以现有 flowcontrol＋Sentinel 限流为配额基础）；③ 租户级权限与数据隔离（RBAC 叠加 tenant 维度）；④ 运营统计与账单 | M1／M2 的交付物；②③任一遗漏即等于跨租户越权（F-18） |
| **部署形态** | K8s + RDS(MySQL) + 对象存储（MinIO／OSS）；Spring Boot + Vue 不变；Python KG／RAG 保持契约对接，租户维度只需在契约层加 `tenantId` | 架构侧论述见 `docs/系统架构设计.md` 的产品化章节 |
| **小程序轻端** | uni-app 重写；临时文件上传 + 订阅消息；`code2session` 换自有 token，弃 HttpOnly Cookie 的单租户假设 | 重考试与防作弊仍留在 Web |

## 10. 验收与度量

- 三端主要页面可登录、可操作、可返回；无空白页、无控制台报错。
