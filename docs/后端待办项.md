## 8. 推进纪律（后端每一批都必须遵守）

1. **契约三处同步**：改 Python 契约字段 → 同步 `ContractPaths` 常量 + Java Provider/消费侧 + `docs/系统架构设计.md` 的接口章节 → 契约测试仍绿。绕过任何一处，等于把「两侧同时改错」留到运行期。
2. **新增结构迁移的连带义务**：`db/migration` 加一支 → 同步契约测试的 `schema-locations` 清单 + `00-drop-post-v1-tables.sql`（+ 新建的表必须可从测试库清掉）→ `ContractTestSchemaBootstrapTest` 会替你记住这件事。
3. **集成层命名即路由**：`*IT`／`*ITCase`／`*IntegrationTest` 归 failsafe，其余归 surefire；放错目录会让本机 `verify` 与 CI 统计口径分家。
4. **覆盖率构建必须串行且 `clean`**（见 `docs/测试文档.md` §2.4）；在 I-06 落地前，任何并发覆盖率构建的读数都不可引用。
5. **阈值只朝紧的方向动**：JaCoCo 0.85/0.65、SpotBugs 豁免清单、限流阈值、视觉与 e2e 判据都一样——降阈值换绿算违约。
6. **降级必须可区分**：AI 链路「真实生成／未配置／失败」三态语义已定（503 族），新增降级路径不得伪装成成功；已被复核保留的两处降级（图谱抽取单阶段回退、看板区块显式标注「不可用」）不得被当成「可以包装成 200」的先例。
7. **缓存成对纪律**：写侧 `@CacheEvict` 与读侧键必须成对；不要用 SQL 直改业务表来「清数据」。
8. **鉴权两层都算数**：方法级 `@PreAuthorize` 是主闸门，URL 层规则只作兜底；任何前端隐藏都必须有后端对应校验。
9. **演示种子不入生产**：V5–V7 只在 `db/seed-demo`；生产核对判据是「版本集合排除 5/6/7 + `users=8` + 无 course 4007」，不是「最高版本=4」。
10. **不可复现项要标注**：真实 LLM 往返、Trivy 漏洞库、Actions 结果、Testcontainers 集成层——这四条的本机结论一律无效，引用必须标 CI 或标「未取证」。
11. **仓库与推送纪律**：不用 `git rm`／`git mv`（中文父目录教训）；**日常推 `leyon`**（`git push origin main:leyon`），**工作包按 §12.7 走 feature branch + PR**，合 `main` 单独授权；**绝不 `--all`**（见 §5 S-06）、**不 force-push**。

### 12.2 每批必跑的门禁（后端）


6. **同包分批，每批一 PR**：一个工作包的条目多、跨度大时，**允许拆成多批交付、每批各提一个 PR**（例：P-01 先交 ⑨⑪⑫⑳，再交 ⑩⑭⑯⑲）。分批复用本节 1–5 条的全部要求，另加两条：
   - 每批在 §2.1.1 状态列写清「**本批关闭哪几条、余量多少人日**」，让项目主能判断这个包何时可以宣布关闭；
   - 同一文件被不同批次重复改动时，**必须在 PR 描述里说明归属**，不得让后一批静默覆盖前一批的语义。
   **不允许**的做法：把一个包拆成多份去改同一处而不说明、或借分批复用之名绕过 §2.2／§2.4 的封闭范围纪律。
