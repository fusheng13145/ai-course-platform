# 引擎本机环境诊断（ENV-20261110-01，V9 批）

> **用途**：把"引擎真实链路证据"（E-04 LoRA 端到端联调、RAG 真实召回评测）的**精确环境阻断物**
> 归档成文——后续接手者按本文执行环境修复即可取证，不必再重复诊断。

---

## 1. 现象

| 尝试 | 结果 |
| --- | --- |
| 系统级 Python（3.11.9）直接 `import rag_engine` | `engine_available=False`，`dep_errors=["sentence-transformers: module 'pyarrow' has no attribute 'json_'"]` |
| `rag_service/.venv` 专用环境 | **同一错误** + 深层 `import torch` 抛 `OSError [WinError 1114] c10.dll 初始化失败` |
| 引擎以系统 Python 启动（uvicorn 8002） | 服务能起、健康探针 200（LLM 密钥就绪度如实上报），检索恒 `mode=UNAVAILABLE` |

## 2. 根因链（已查实）

1. **系统 site-packages 被多项目污染**：全局装了新版 pyarrow（≥21 移除了 `json_` 模块别名），
   与钉版的 `sentence-transformers==5.4.1`（经 pandas/datasets 触发）不兼容。
2. **`rag_service/.venv` 继承系统 site-packages**（等效 `--system-site-packages` 构建）——
   专用环境并不隔离，污染同步生效；且 pyarrow 先于 torch 加载时引发 **Windows DLL 初始化冲突**
   （c10.dll WinError 1114，pyarrow 的 Arrow DLL 与 torch DLL 在同进程的加载顺序冲突）。
3. 两个故障互相掩盖：修掉 pyarrow 别名错还剩 DLL 冲突，逐项排查成本高。

## 3. 修复路径（给接手者，一次做对）

1. **重建隔离 venv**（`python -m venv --clear .venv`，**不带 system-site-packages**）；
2. 按钉版清单安装：`pip install -r requirements.txt -r requirements-engine.txt`，
   其中 torch 用 CPU 索引先装（同 FT Dockerfile 的教训：`pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cpu` 先行）；
3. **显式钉 `pyarrow<21`**（或升级 pandas 至兼容版）——requirements-engine.txt 建议增补该钉；
4. 验证顺序：`engine_functional()` → 起 8002 → `seed-rag-corpus.py` 重放 → `/retrieve` 断言 `mode=ENGINE`
   → `evaluate.py --course 1` 产出真实 recall@k → FT `requirements-engine` 同法重建后跑 DR-78 同款真实训练冒烟。
