# 后端开发规范

> **文档定位**：本文件规定后端（Spring Boot / Java 21）的编码、分层、接口、数据、集成与测试约定，是代码评审与新增功能的落地依据。系统结构与技术决策见 [系统架构设计.md](系统架构设计.md)；运行步骤见 [部署文档.md](部署文档.md)；质量门读数见 [测试文档.md](测试文档.md)。
>
> **适用范围**：`backend/src/main/java/**`、`backend/src/test/java/**`、`backend/src/main/resources/**`。历史代码中与本规范不一致处，改动时按规范收敛，不得扩散。

---

## 1. 环境与构建

| 项 | 要求 |
| --- | --- |
| JDK | 21 |
| Maven | 3.8+ |
| 编码 | UTF-8；Windows 批处理另见 §18 |
| 本地启动 | `start.bat backend`（长驻）或 `start.bat`（全栈单窗口） |
| 编译 | `mvn -B -o clean package -DskipTests`（离线仓库已预热） |
| 全量门禁 | `mvn -B -o clean verify -DskipITs` |
| 工作目录 | Maven 命令在 `backend/` 下执行，除非明确说明 |

**构建纪律**：

- 不引入未经授权的依赖升级；版本号集中在 `pom.xml` 的 `<properties>`。
- 新增依赖必须同时评估：许可证、已知漏洞（Trivy/OSV）、包体与启动时间。
- Lombok 可用（`@Slf4j`、`@Data` 等），但实体/DTO 的公开契约字段不得依赖 Lombok 隐式行为做序列化假设；需要精确控制时手写 getter/setter。

## 2. 目录与分层

```text
com.aicourse
├─ controller/         HTTP 入口
├─ dto/                入参对象
├─ vo/                 出参对象
├─ entity/             表映射
├─ mapper/             数据访问
├─ service/            业务接口
│  ├─ impl/            业务实现
│  └─ component/       子域组件（ai/auth/exam/learning/student/submission/sys/teacher/analytics）
├─ config/             横切配置
├─ security/           JWT、CSRF、ACL、AI 配额
├─ flowcontrol/        Sentinel
├─ integration/{kg,rag}/ Python 适配
├─ llm/                大模型供应商
├─ scheduler/          定时任务
├─ websocket/          通知推送
├─ health/             健康指示器
├─ common/             响应、分页、角色、工具常量
├─ constant/           业务状态常量
├─ exception/          业务异常与全局处理
├─ util/               无状态工具
└─ aspect/             切面
```

### 2.1 依赖方向（ArchUnit 强制）

| 规则 | 说明 |
| --- | --- |
| `controller` ✗→ `mapper` | 控制器只能经 service 访问数据 |
| `service` ✗→ `controller` | 业务不得反向依赖 Web 层 |
| `entity` ✗→ service/controller/mapper | 实体是纯数据映射 |
| `util` ✗→ service/controller/mapper | 工具保持无业务依赖 |
| `config` ✗→ `controller` | 配置不感知接口 |
| `service.impl` ✗→ 其他 `service.impl` | 通过接口或 `component` 协作 |

新增跨层调用前先问：能否通过接口注入或组件下沉解决；不能则改设计，不要放宽 ArchUnit。

### 2.2 服务拆分

- 对外能力：`XxxService` 接口 + `XxxServiceImpl` 实现；控制器只依赖接口。
- 子域复用：放 `service/component/<域>/XxxComponent`，构造器注入，不暴露给控制器。
- 单一实现且无替换需求时可不建接口，但同域已有接口风格时保持一致。
- 单个类建议 ≤ 500 行；超过时按子域拆组件或拆编排层，而不是继续加方法。

## 3. 命名约定

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 包 | 全小写，单数域名词 | `service.component.exam` |
| 控制器 | `XxxController` | `ExamPaperController` |
| 服务 | `XxxService` / `XxxServiceImpl` | `SubmissionService` |
| 组件 | `XxxComponent` | `SubmissionWriteComponent` |
| 数据访问 | `XxxMapper` | `SubmissionMapper` |
| 入参 / 出参 | `XxxDTO` / `XxxVO` | `GradeDTO` / `FinalGradeVO` |
| 实体 | 表名单数大驼峰 | `submissions` → `Submission` |
| 配置 | `XxxProperties` / `XxxConfig` | `CorsProperties` / `CacheConfig` |
| 过滤器 / 拦截器 | `XxxFilter` / `XxxInterceptor` | `DoubleSubmitCsrfFilter` |
| 定时任务 | `XxxScheduler` | `ExamTimeoutScheduler` |
| 健康指示器 | `XxxHealthIndicator` | `LlmProviderHealthIndicator` |
| 测试 | `XxxTest` / `XxxControllerTest` / `XxxServiceTest` / `XxxIntegrationTest` / `XxxContractTest` / `XxxGuardTest` | 见 §17 |
| 常量 | 全大写下划线 | `ApiCode.NOT_FOUND` |
| 方法 | 动词开头，小驼峰 | `submitAssignment` / `assertReadable` |
| 布尔 | `is/has/can/should` 前缀 | `isLate` / `hasPermission` |

**禁止**：

- 拼音命名、无意义缩写（`tmp`、`data1`、`obj`）。
- 同一概念多种叫法（如 `studentId` / `stuId` / `userId` 混用；学生一律 `studentId`，登录主体一律 `userId`）。
- 控制器方法名与 HTTP 语义脱节（如 `get` 却执行写操作）。

## 4. 控制器规范

### 4.1 基本形态

```java
@RestController
@RequestMapping("/submissions")
@Tag(name = "作业提交")
@Slf4j
public class SubmissionController {

    private final SubmissionService submissionService;

    public SubmissionController(SubmissionService submissionService) {
        this.submissionService = submissionService;
    }

    @GetMapping("/{id}")
    public ApiResponse<Submission> getById(@PathVariable Long id, Authentication auth) {
        accessControl.assertReadable(id, auth);
        return ApiResponse.success(submissionService.getById(id));
    }
}
```

要求：

- 构造器注入，字段 `private final`；禁止字段注入。
- 统一返回 `ApiResponse<T>`；分页返回 `ApiResponse<PagedResponse<T>>`。
- 入参用 `@Valid @RequestBody XxxDTO`；查询参数用 `@RequestParam` 并给默认值。
- 登录主体统一 `Long userId = (Long) auth.getPrincipal()`。
- 每个控制器类加 `@Tag`；关键端点加 `@Operation`（描述业务语义，不写实现细节）。
- 控制器保持薄：只做参数接收、权限校验、服务调用、响应包装；不写业务分支与 SQL。

### 4.2 权限

| 场景 | 写法 |
| --- | --- |
| 角色限制 | `@PreAuthorize("hasAnyRole('TEACHER','ADMIN')")` |
| 本人或管理员 | `@PreAuthorize("#userId == authentication.principal or hasRole('ADMIN')")` |
| 对象级 | 调用 `ExamPaperAccessControl` / `ExamSessionAccessControl` / `SubmissionAccessControl` 的 `assertXxx` |
| 仅登录 | `@PreAuthorize("isAuthenticated()")` |

- 角色字符串只用 `RoleConstants.ADMIN/TEACHER/STUDENT`，不得散落字面量。
- **新增任何按 ID 访问的端点，必须同时声明角色与对象归属校验**；仅靠前端隐藏入口不算。
- 管理端代操作必须显式解析操作者身份，不得静默冒用目标用户。

### 4.3 分页与排序

```java
@GetMapping
public ApiResponse<PagedResponse<Submission>> list(
        Authentication auth,
        @RequestParam(defaultValue = "1") long page,
        @RequestParam(defaultValue = "10") long size) {
    Page<Submission> result = submissionService.page(Page.of(page, size), wrapper);
    return ApiResponse.success(PagedResponse.of(result));
}
```

- 页码从 1 开始；`size` 必须有上限（MyBatis-Plus 全局 1000）。
- 排序字段必须白名单化，禁止把用户输入直接拼进 `orderBy`。
- 列表默认按 `created_at DESC`；需要稳定排序时追加 `id DESC`。

### 4.4 文件与上传

- 普通上传用 `MultipartFile`，校验类型/大小/文件名；禁止把原始文件名直接作为落盘路径。
- 分片上传走 `FileUploadSessionController`：会话创建 → 分片上传 → 合并；归属、索引、MD5、字节数全部校验。
- 下载/预览必须经过权限校验；`/uploads/**` 不是匿名静态目录。

## 5. DTO / VO / Entity

### 5.1 DTO（入参）

- 只包含允许客户端写入的字段；**绝不**直接使用实体接收请求体。
- 校验注解就近声明，消息用中文；跨字段规则放服务层。
- 更新类 DTO 与创建类 DTO 分开（避免“创建时必填、更新时可选”互相妥协）。
- 涉及枚举/状态的值，用字符串常量或枚举校验，不使用魔法数字。

```java
public class SubmissionCreateDTO {
    @NotNull(message = "任务ID不能为空")
    private Long taskId;

    @NotBlank(message = "提交内容不能为空")
    @Size(max = 20000, message = "提交内容不能超过20000字")
    private String content;

    private List<String> fileUrls;
}
```

### 5.2 VO（出参）

- 面向页面需要组织字段；不把实体内部字段（如密码哈希、删除标记）透出。
- 列表 VO 与详情 VO 分开；大字段（正文、附件）不进入列表。
- 字段命名与前端契约一致（camelCase）；日期格式统一。
- 新端点优先返回 VO；存量返回实体的端点改动时逐步收敛，不在同一批扩大暴露面。

### 5.3 Entity

- `@TableName("表名")`；主键 `@TableId(type = IdType.AUTO)`。
- 非表字段加 `@TableField(exist = false)`。
- 创建/更新时间用 `@TableField(fill = FieldFill.INSERT/INSERT_UPDATE)` 配合 `MyMetaObjectHandler`。
- 逻辑删除字段（若有）统一 `@TableLogic`；不要手写 `deleted = 0` 条件散落各处。
- 实体不写业务方法；不依赖 Service。

## 6. Service 规范

### 6.1 事务

- 写操作在 service 实现层加 `@Transactional(rollbackFor = Exception.class)`。
- 只读查询加 `@Transactional(readOnly = true)`（有性能收益的路径）。
- 事务内不做远程调用、不发消息、不写大文件；必须做时拆到事务外并考虑补偿。
- 控制器不开事务；组件方法被同类内部调用时注意代理失效，必要时拆到独立组件。

### 6.2 业务校验顺序

1. 参数格式（Bean Validation）；
2. 资源存在性；
3. 状态机合法性（如“未发布试卷不可作答”）；
4. 归属/权限（对象级 ACL）；
5. 业务规则（配额、次数、时限）；
6. 落库与副作用。

错误消息面向用户，写清“哪个对象、什么状态、该怎么办”，不泄露内部实现。

### 6.3 异步

- 轻量副作用可用 `CompletableFuture.runAsync`，但必须捕获异常并记录，不得让异常吞掉主流程。
- 需要可靠执行的任务用定时任务 + 状态表 + ShedLock，不依赖内存线程池。
- 异步任务不得持有请求上下文（`SecurityContext`、`RequestContextHolder`）；需要用户身份时显式传参。

### 6.4 缓存

- 读缓存用 `@Cacheable(cacheNames = "...", key = "...")`；写路径用 `@CacheEvict` / `@Caching`。
- 缓存键必须稳定、可读，包含业务维度（如 `'teacher_' + #teacherId`）。
- 用户/权限变更必须即时逐出（`users`、`permissions`）；不得等 TTL。
- 缓存值必须是可序列化的 VO/简单结构；不要把实体代理或 `Page` 直接塞入。
- 新增缓存前先确认：读远多于写、能接受短暂不一致、逐出路径完整。

## 7. Mapper 与 SQL

- 单表 CRUD 用 `BaseMapper` + `LambdaQueryWrapper`；复杂查询写 XML（`resources/mapper/*.xml`）。
- 禁止字符串拼接 SQL；动态条件用 MyBatis 的 `#{}` 与 `<if>`。
- 分页统一 `Page.of(page, size)`；不要手写 `LIMIT` 偏移。
- 批量写入控制单批大小（建议 ≤ 500），避免超长 SQL。
- 列表查询注意 N+1：需要关联数据时用批量查询 + 内存组装，或一次 JOIN。
- 慢 SQL 由 `MyBatisSlowSqlInterceptor` 记录；新增复杂查询应在测试库用真实数据量验证。
- 统计类 SQL 必须限定课程/时间范围，禁止全表扫描式聚合进入请求路径。

## 8. 异常与错误码

### 8.1 异常类型

| 类型 | 用途 | HTTP |
| --- | --- | --- |
| `BusinessException(code, message)` | 可预期的业务失败 | 按 code |
| `ResourceNotFoundException` | 资源不存在 | 404 |
| `LLMUnavailableException` | 大模型不可用/未配置/凭据被拒/额度/上游/空响应 | 503 |
| 其他未捕获异常 | 程序缺陷 | 500（不返回堆栈） |

- 业务失败优先抛 `BusinessException`，不要返回 `ApiResponse.error` 当控制流。
- 不写 `catch (Exception e) { return null; }` 式吞异常；捕获后要么恢复，要么包装成带语义的异常。
- 外部调用异常必须转换成上述类型之一，并在日志中保留上游状态码与简短原因（不含密钥）。

### 8.2 错误码

统一使用 `ApiCode`：200/400/401/403/404/405/409/413/429/500/503。新增码先加常量，再在 `GlobalExceptionHandler` 建立映射，最后同步前端提示。

### 8.3 全局处理

- 所有异常出口集中在 `GlobalExceptionHandler`（19 个处理器）；新增异常类型时补处理器与测试。
- 校验失败返回首个字段错误（中文），不返回整段堆栈或类名。
- 数据库唯一约束冲突映射 409；完整性失败映射 400。
- 大模型失败必须保留 `LLMUnavailableException.Kind`，不得统一压成“AI 服务异常”。

## 9. 响应与分页

```json
{ "code": 200, "message": "success", "data": {}, "timestamp": "2026-10-27T12:00:00" }
```

- 成功：`ApiResponse.success(data)` 或 `ApiResponse.success("提示", data)`。
- 分页：`PagedResponse.of(page)`，字段含列表、总数、页码、页大小。
- 删除成功可返回 `ApiResponse.success()`；不要返回 204 空体（前端拦截器按信封解包）。
- 不在 `message` 中放敏感信息；不把内部异常消息直接透给用户。

---

## 10. 日志

- 使用 `@Slf4j`；禁止 `System.out/err`。
- 级别：`error` 程序缺陷或不可恢复；`warn` 可恢复的外部失败/降级；`info` 关键业务节点；`debug` 排查细节。
- 格式：中文短句 + 关键 ID，如 `log.info("AI预批改完成: submissionId={}", savedId)`。
- 异常日志保留堆栈（`log.warn("...", e)`）；业务可预期失败不打印堆栈。
- **禁止**打印：密码、令牌、Cookie、API Key、Neo4j 口令、完整请求体（含个人信息）。
- 高频路径（列表、轮询）不打 `info`；需要观测时用指标。
- 日志中的用户输入要截断（如题干前 50 字），避免日志注入与膨胀。

## 11. 安全编码

| 风险 | 规则 |
| --- | --- |
| SQL 注入 | 一律参数化；动态排序白名单 |
| IDOR/BOLA | 按 ID 访问必须对象级 ACL；学生只能看本人，教师只能看本人课程 |
| XSS | 后端不信任前端；富文本入库前过滤/转义策略统一；前端展示再清洗。**纯文本字段（如 AI 问答回答、检索出处）不做 HTML 转义**——落库原文、按原文下发，转义归渲染层；把它们预转义会让实体码出现在文本里、并污染多轮上下文（B-13 ⑭） |
| CSRF | 写接口保持双提交校验；新增豁免端点必须评审 |
| 越权提升 | 不接受客户端传入的 `role`、`score`、`status` 等敏感字段；服务端赋值 |
| 文件上传 | 类型/大小/路径校验；禁止可执行文件直出；下载经鉴权 |
| 密钥 | 只从环境/文件式密钥读取；不写入代码、日志、测试资源 |
| 反序列化 | 只反序列化已知 DTO；禁用多态类型 |
| 限流 | 新增高成本端点评估是否接入 IP 限流/用户配额 |
| 审计 | 管理端写操作写 `operation_logs`；登录写 `login_logs` |

补充：

- 新增公开端点必须加入 `SecurityConfig` 的显式白名单，并说明理由。
- 生产默认关闭 Swagger；测试环境开启。
- Actuator 端点按环境收紧；`/actuator/prometheus` 需 Basic 鉴权，口令为空时 fail-closed。

## 12. 外部集成

### 12.1 Python 引擎

- 路径常量只从 `ContractPaths` 取，禁止在 Java 里硬编码 `/api/v1/...`。
- 适配器实现接口（`KnowledgeGraphContract` / `RagContract`），控制器与业务不直接依赖 HTTP 客户端。
- 超时、重试、降级按 [系统架构设计.md](系统架构设计.md) §8.6；降级结果必须带 `mode` / `gen_mode`。
- 新增端点：Python 服务 + `ContractPaths` + Java 适配器 + 契约测试四件齐全。

### 12.2 大模型

- 只通过 `LLMProvider` 调用；供应商差异在实现层消化。
- 失败抛 `LLMUnavailableException`，禁止返回空字符串/伪 JSON 让上层误判成功。
- 提示词必须**点名 JSON 键名**与类型；要求模型只输出 JSON（可容忍 ```json 栅栏，解析前剥离）。
- JSON 落库前校验：`questions` 的选项/答案为 MySQL `JSON` 列时，标量必须带引号、数组必须序列化；空串不是合法 JSON。
- 调用必须记 `ai_call_logs`（类型、模型、耗时、token、结果）；配额拦截在 `AiQuotaInterceptor`。
- 不在提示词中拼接密钥、内部路径或未脱敏的个人信息。

### 12.3 邮件/外部 HTTP

- 邮件发送失败不得回滚主业务；记录告警并允许重试。
- 外部 HTTP 客户端显式设置连接/读超时；禁止默认无限等待。
- 响应体只解析需要的字段；不把上游原始错误直接透给用户。

## 13. 配置

| 项 | 规则 |
| --- | --- |
| 配置层级 | `application.yaml` 默认值 → profile → 环境变量 → `configtree` 文件式密钥 |
| 键命名 | 小写点分，业务前缀（`app.security.*`、`ratelimit.*`、`ai.*`） |
| 环境变量 | 大写下划线，与键对应；新增键必须同步 `.env.example` |
| 密钥 | 只走环境变量或 `/run/secrets/<精确文件名>`；不写入 yml 默认值 |
| 默认值 | 安全默认（HTTPS/HSTS 开启、CORS 不回落 localhost、Actuator 闭环） |
| 开关 | 布尔开关必须同时考虑“关闭后的降级行为”与“误配是否报错” |
| 读取 | 少量用 `@Value`，成组用 `@ConfigurationProperties`；不在业务代码散读 `Environment` |

**键位卫生**：新增 `.env.example` 键前先确认“有没有非注释代码消费者”；没有消费者的键不加。空值语义要明确（只判空还是判合法值），并写进配置注释。

## 14. 并发与定时任务

- 定时任务类放 `scheduler/`，方法加 `@Scheduled`；多实例互斥用 `@SchedulerLock`，并设置 `lockAtMostFor` / `lockAtLeastFor`。
- 每个清理任务独立 `try/catch`，单项失败不影响其他项；失败记 `warn` 并继续。
- 任务必须可重入、可重复执行；不依赖“上次运行成功”。
- 长任务拆分批次，避免单次事务过大；需要断点续跑时落状态表。
- 异步线程池使用项目统一配置（`AsyncMvcConfig`），不自行 `new Thread`。

## 15. 数据库与迁移

- 迁移脚本只增不改：已执行的版本（尤其 `V1`）校验和冻结，不可回改；修正用新版本。
- 结构脚本放 `db/migration`；演示数据放 `db/seed-demo`（prod 不加载）。
- 新增表/列必须同步：实体、Mapper、`index.sql`（集成测试 schema 源）、守卫测试。
- 字段命名下划线；布尔用 `is_` 前缀；时间用 `created_at` / `updated_at`。
- 金额/分数用 `DECIMAL`，不用 `FLOAT`；Java 侧用 `BigDecimal`。
