| 层 | 覆盖对象 | 入口 | 何时跑 | 判定强度 |
| --- | --- | --- | --- | --- |

| **前端单元／组件** | composables、stores、utils、router、API 封装、组件交互 | `npm run test`（vitest） | 每次前端改动 | ⚙️ CI `frontend-quality` |

| **视觉回归** | 12 个锚点页 × 明暗两主题 | `npx playwright test -c playwright.visual.ts` | 视觉改动、结构迁移、基线批次 | 🖐 本机实跑为准；**不在 CI 内** |
| **Python 引擎** | KG / RAG / 微调的 HTTP 契约与引擎逻辑 | `python -m pytest python-services/<svc>` | 引擎改动 | ⚙️ CI 三个独立作业 |
| **启动器** | 启动计划、环境导出、就绪判定、日志中继 | `python -m pytest scripts/tests -q` | 启动器改动 | ⚙️ CI `launcher-tests`（已接入，尚未实跑取证） |
| **全栈四件套** | 主链路、深度边界、安全、压力 | `scripts/e2e/*.py` | 里程碑、答辩前、后端大改后 | 🖐 人工判定；本机真跑读数见 §6 |
| **可观测性／无障碍** | 控制台近似读数、键盘与焦点 | 人工 + 浏览器控制台 | 视觉批次 | 🖐 近似体检，**不是门禁** |

**三条总纪律**：

1. **门禁绿 ≠ 功能对**。单元测试证明代码按断言工作；e2e 与视觉证明页面按真实路径工作；四件套证明全栈链路工作。任何一层都不能替代另一层。
2. **本机绿 ≠ CI 绿**。CI 的集成层、Trivy、Actions 运行结果在本机不可观测；`frontend-e2e` 仍是手动触发。
3. **不为了变绿改判据**。阈值、基线、限流阈值、超时都只能因**测量结论**调整，不能因某次红灯调整。

### 2.4 引用纪律（缺一条就会造出假读数）

- **用例数与覆盖率必须成对引用同一轮**。禁止拿本轮的用例数配上一轮的覆盖率。
- **覆盖率构建必须串行且 `clean`**。JaCoCo exec 落在 `${user.home}/jacoco-backend.exec`，全仓库 worktree 共用；并发跑 `prepare-agent` 会把文件截断成 0 字节，随后 `jacoco:report` 得到 0% 覆盖。报告份数也只在 `clean` 后取，否则 `surefire-reports/` 会累积陈旧 XML。
- **JaCoCo 以 XML 的 `<report>` 级 counter 为准**。同构建下用 `jacoco.csv` 逐类求和会多报约 12 行（+0.01pp），两口径不等价。
- **BRANCH 有 ±1 噪声**。同源码重复构建可能出现 5059/7177 与 5060/7177 这种差 1 个分支的读数；不得用 0.01pp 的移动论证「某次改动提升了覆盖」。
- **口径要标注「单元」还是「含 IT」**。2026-10-27 的 3022 例与 88.85%/70.49% 是 **`-DskipITs` 单元口径**；12 例集成层由 CI 取数。2026-10-18 的 3019+12 例与 89.08%/70.71% 是含 IT 口径，两者不能拼在一起引用。
- **体积读数要配 `dist/` 新鲜度**。旧产物上的绿不是当前源码的绿。
- **`Failures: 0` 不等于没有失败**。Spring 上下文加载失败记为 **Errors**；历史上的契约测试库缺列事故就表现为 `Failures: 0 / Errors: 11`。读 surefire 汇总时必须同时看 failures 与 errors。
- **「全绿」只在真的整轮跑过之后说**。`--list` 只能证明用例被收集，不证明通过。

## 3. 后端测试

### 3.1 两层：surefire 与 failsafe

| 层 | 插件 | 包含规则 | 依赖环境 | 本机现状 |
| --- | --- | --- | --- | --- |
| 单元／Web／契约 | maven-surefire | `*Test.java`（含 `ApiContractTest`、`ContractTestSchemaBootstrapTest`、`ArchitectureTest`） | 无 Docker；`service-test` 用 H2，`contract-test` 直连本机 MySQL／Redis | ✅ 每轮实跑 |
| 集成 | maven-failsafe | `*IT.java`、`*ITCase.java`、`*IntegrationTest.java` | Testcontainers 拉 `mysql:8.4.11` + `redis:7.4.11-alpine`；CI 另有 service 容器 | ⏸ **本机不跑**：Docker 编排自 2026-10-08 搁置；最近的 12 例本机实跑是 2026-10-18，此后由 CI `backend` 取数 |

```bash
# 本机日常（单元口径，含 JaCoCo / SpotBugs / ArchUnit）
cd backend && mvn -B -o clean verify -DskipITs

# 含集成层（需要 Docker；CI 的 backend 作业跑的就是含 IT 的 verify）
cd backend && mvn -B -o clean verify
```

`verify` 阶段依次触发：编译 → surefire → failsafe（含 IT 时）→ `jacoco:report` → `jacoco:check` → `spotbugs:check`。任何一步非 0 都会让构建失败。

**契约测试库的三条机械守卫**（`ContractTestSchemaBootstrapTest`，3 例）：

1. `db/migration` 下**每个**结构迁移都必须出现在 `schema-locations` 清单里，漏列即红；
2. `V1` 必须排在其余迁移之前（脚本按序执行，V1 建基线）；
3. 每条后续迁移新建的表都必须可从测试库清掉（`00-drop-post-v1-tables.sql` ∪ V1 的 DROP 清单），漏加即红。

> 这三条不是形式主义：历史上契约测试库只按 V1 初始化，导致 `users` 加列后 11 个用例在**上下文加载阶段**报 `Unknown column`，汇总显示 `Failures: 0 / Errors: 11`。第二次事故同型：测试库不可重入，第二次跑全套必红。判据是「契约测试绿 ≠ 测试库结构正确 ≠ 测试库可重复初始化」。

### 3.4 覆盖率与静态分析

- **JaCoCo**：LINE ≥ 85%、BRANCH ≥ 65%，`haltOnFailure=true`。exec 文件固定 `${user.home}/jacoco-backend.exec`；`prepare-agent` 为 `append=false`（每轮先清空），`prepare-agent-integration` 为 `append=true`（把 IT 数据追加进同一文件）。
- **阈值不降**：历史上去污染后的诚实基线曾低于门禁，处置方式是补真实测试，而不是下调 0.85／0.65。
- **SpotBugs**：4.8.6.6，effort `Max`、threshold `Low`、`failOnError=true`；`spotbugs-exclude.xml` 的 13 个 `<Match>` 是框架性豁免，新增豁免必须说明理由。
- **ArchUnit 6 条**：Controller 不得依赖 Mapper；Service 不得依赖 Controller；Entity 不得依赖 Service／Controller／Mapper；Util 不得依赖 Service／Controller／Mapper；Config 不得依赖 Controller；`service.impl` 不得依赖其他 `service.impl`。

### 3.5 后端常见坑

| 现象 | 根因 | 处置 |
| --- | --- | --- |
| `jacoco:report` 显示 0% | 另一条覆盖率构建并发跑 `prepare-agent`，把共享 exec 截断 | 覆盖率构建串行；不要在测试未结束时另起 `jacoco:report` |
| 报告用例数忽高忽低 | 非 `clean` 轮次累积了旧 `surefire-reports/*.xml` | `mvn clean verify` 后再取报告 |
| `ApiContractTest` 全部 Errors | 契约测试库结构或可重入性坏了（`Unknown column`／`Table already exists`） | 先跑 `ContractTestSchemaBootstrapTest`；修 `schema-locations` 或清理脚本，不要删测试 |
| 本机 IT 起不来 | Docker 未运行／镜像未就绪 | 本机走 `-DskipITs`；IT 结论引用 CI，并标注时点 |
| 测试读到开发库数据 | profile 用错（`contract-test` 指向 `ai_course_platform_test`） | 核对 `spring.datasource.url`；不要用 `local` profile 跑测试 |

### 4.2 vitest（单元／组件）

- 配置：`frontend/vitest.config.ts`，环境 `jsdom`，`globals:true`，`include` 只收 `src/**/*.{test,spec}.{js,ts,vue}`。

- 覆盖率**只统计 8 个 `.ts` 逻辑目录**（`api`／`composables`／`stores`／`utils`／`router`／`config`／`monitoring`／`layouts`），阈值 lines 30／functions 62／branches 78／statements 30，`clean:false`。**不能把这两个数当全仓覆盖率引用**：`.vue` 文件不在统计面内。
- vitest **不跑** `e2e/`；流程与视觉由 Playwright 两套配置承担。

**前置条件（缺一条，红灯会被误读成产品缺陷）**：

3. 演示数据在位（V5–V7 种子），后端连的是演示库而不是生产库。

**数据策略**：

- 大多数 spec 用 `loginAs` 走**真实登录**，再用 `page.route` 对业务接口打桩。这证明「路由 + 权限 + 页面渲染 + 交互」成立，不证明后端实现正确；后端正确性由 §3 与 §6 负责。

- `onboarding.spec.ts` 只用 `.auth` 夹具、不调 `loginAs`，打真实后端；它变红时先怀疑夹具过期或后端没起，再怀疑产品缺陷。

**12 个锚点**：`login`、`error-404`、`student-dashboard`、`student-courses-modal`、`student-knowledge-graph`、`student-learning-center`、`teacher-dashboard`、`admin-dashboard`、`admin-governance-analytics`、`admin-courses-table`、`admin-profile`、`admin-system-form`。

**阈值与「逐字节相同」的口径**：

- 交付阈值 `{ threshold: 0, maxDiffPixelRatio: 0.0001 }`。1440×900 下免检额 = 1440 × 900 × 0.0001 ≈ **129.6 px**。
- `threshold:0` 仍会跳过抗锯齿像素，所以「像素计数 0」**不等于**「逐字节相同」。
- 只有**与已提交基线 md5 相等且字节差 0** 时才允许说「逐字节相同」。这句话由 `assertZeroDiff` 用已入库的 `measure-diff.cjs` 按 `--threshold=0 --ratio=0` 取证，不靠 `toHaveScreenshot` 的绿。

**载荷钉死（payload pinning）**：

- 三个日期敏感锚点 `student-dashboard`、`admin-dashboard`、`admin-governance-analytics` 在导航前安装 `payload-pin.ts`，把该页所有 GET 钉到 `__fixtures__/*.json`。
- **canary 先于钉桩**：用 `page.request` 打一条不走 `page.route` 的真实请求，证明「真后端 + 真会话仍可用」。否则钉桩会让页面再也不打后端，会话过期也全绿。
- **反方向覆盖**：`assertAllApiGetsPinned` 要求该页发过的每条 GET 都被声明；产品新增一条 GET 而没进清单会红。
- **载荷非平凡**：被钉载荷必须至少有一个非空序列或非 0 数值；全 0 且未登记的锚点直接红。
- **零漂移**：钉住后另截一张图，按 t=0／r=0 要求 md5 相等。

**基线守卫**：

- `assertComparableRender` 在截图前检查 URL、主题、占位图、错误边界、页面时间（每张都必须落在同一冻结时刻）。
- 图谱锚点额外要求画布存在、角标节点数 > 0、画布非透明像素 ≥ 300——三条分别防「组件走了空态」「数据没到」「ECharts 没画」。
- `error-404` 明暗两张必须 **md5 不同**；相同即说明 `data-theme` 又丢了（页面没挂主题）。
- 反证矩阵：7 个锚点有「清空对应 API 后断言必须红」的用例；2 个锚点（`student-learning-center`、`admin-profile`）声明为无法由数据到达断言反证，单独留档。

**基线更新闸门**：`global-setup.ts` 的 `assertUpdateSnapshotsAllowed()` 会拒绝 `--update-snapshots`／`-u`／`--update`，除非显式设置 `PW_ALLOW_UPDATE_SNAPSHOTS=1`。补基线必须带 `-g "<锚点名>"` 过滤，不带过滤的更新会重写全部 24 张。

**量程探针与 `PW_VISUAL_NOPIN`**：

- `sensitivity.spec.ts` 是**量程探针**，不是基线门禁；它测「漂移多大时这套阈值会红」。
- `PW_VISUAL_NOPIN=1` **只有探针认**。`anchors.spec.ts` 在导入期就抛错拒绝该变量——因为「认了它但不装钉桩」会让零漂移判据整条消失，产出「一半随机红、一半假绿」的读数。
- `PW_PIN_SHIFT_DAYS=k` 用于模拟「服务端第 +k 天」；加在探针命令上是在验量程，加在 anchors 上是在验「钉歪一点整表就红」，两者不可混用。

**证据落点**：`frontend/e2e/visual/tools/evidence/` 整目录已在 `.gitignore`；动效观察图与量程证据也写在这里（落点以 `motion-observation.spec.ts`／`sensitivity.spec.ts` 的 `EVIDENCE_DIR` 为准）。跑完视觉套件后仍要 `git status` 复核，确认没有基线之外的文件被改写。

**已知的视觉盲区**：

- **免检额会吸收真实漂移**。2026-10-27 量程探针 `noise` 档（不注入）在 `admin-courses-table/light` 读到 **计数 58／字节差 164／Δmax 28/255 @1173,412／包围盒 x 1171..1390 y 385..416**，而该格 fullPage 几何（1440×2802）下的免检额是 **403.49 px** ⇒ 判绿。把本批三个样式文件临时换回 `27154a3` 版本重跑同一探针，**读数逐字相同**（58／164／28@1173,412），即这 58 px 与本批无关，是基线（2026-10-25 录制）之后就在攒的确定性漂移；包围盒落在 `CourseManagement.vue:90` 那个 `width:220px` 的 `el-input` 上。复现：`cd frontend && PW_LADDER=noise PW_PROBE_SLUGS=admin-courses-table PW_PROBE_THEME=light npx playwright test -c playwright.visual.ts sensitivity`。挂 `docs/前端待办项.md` P-13。
- 视觉套件只覆盖 12 个锚点页；锚点之外的页面（如督导、部分成绩页）出渲染缺陷不会被抓到。`TsvHeatmapCard.heatValue` 曾因自 TS 迁移起从未进入返回块而长期收到 `undefined`，该页不在锚点内，视觉门全绿也没发现。
- 明暗、焦点、键盘可达有部分覆盖，但**不是** axe 级无障碍扫描（见 §4.5）。
- 视觉绿只证明「这一帧与基线一致」，不证明交互流程正确。

### 6.2 两种后端姿态（不可混用）

```bash
# 功能／深度轮：CSRF 关、登录限流 200
python scripts/run-backend-for-e2e.py functional

# 安全轮：CSRF 默认开、限流默认 10 次/60 秒
python scripts/run-backend-for-e2e.py secure
```

- 启动器会先 `FLUSHDB`，再以 `--server.port=8080` 启动 jar，等待 `/api/actuator/health/probe` 返 200。
- 需要 `.env` 提供 `MYSQL_ROOT_PASSWORD`／`JWT_SECRET`；**不要把整个 `.env` 注入**——`MAIL_USERNAME`／`MAIL_PASSWORD` 会让验证码端点走真实 SMTP 并 500。
- 改了后端代码必须先 `mvn -o package -DskipTests` 重新打包，否则跑的是旧 jar。
- 姿态混用会让 CSRF 与限流用例全部失效：功能轮跑安全套件会「全绿但没测到」，安全轮跑功能套件会大面积 403／429。

### 6.3 四条硬前提（起错任何一条，红灯会被误读成产品缺陷）

| 前提 | 要求 |
| --- | --- |
| 端口 | 启动**必须显式** `--server.port=8080`；否则被外部配置覆盖，报「Port already in use」 |
| 环境变量 | `SPRING_DATASOURCE_PASSWORD`、`JWT_SECRET`；本地另需 `COOKIE_SECURE=false`、`REQUIRE_HTTPS=false` |
| 会话 | 认证是 HttpOnly Cookie（`ai_course_token`）；脚本必须维持 cookie jar，裸 `curl` 第二个请求就 401 |
| Redis | 测前 `FLUSHDB`（同时清缓存与限流计数）；只清缓存不清限流，429 会随机出现 |

**健康判据**：活性与编排探针一律走 `/api/actuator/health/probe`。未注入有效 AI Key 时综合 `/api/actuator/health` 返 503（DOWN）属设计，不是故障。

### 6.4 数据与安全边界

- 四件套会**真实写库**：主链路建课、深度轮自建 `CS-NET-DEEP` fixture 并自带清场、压力轮写任务完成与答卷自动保存。只在**演示库**跑，不要指向生产库或他人开发库。
- 脚本结果 JSON（`e2e_*_result.json`）落在脚本目录，已 gitignore；历史结果快照未入库，读数以本节表格为准。
- 压测前确认本机没有代理接管 localhost（脚本已显式禁代理）；压测后看「重新登录 + 列表／详情／进度 200 + 无重复写入」，不只看过程中的 QPS。
- **判红纪律**：先读代码与契约，再判断是不是产品缺陷。深度轮第一次 E 段实测就抓到过真实缺陷（非 multipart 请求 500，已修并留双回归位）；也有多次是脚本对状态机的假设过期。**「红灯 ≠ 产品坏了」，「绿灯 ≠ 契约对了」**。

- `pull_request`：全量跑，不受 `paths-ignore` 影响。
- 同一分支的重复运行 `cancel-in-progress:true`。
- 另有 `nightly`（AI 幻觉率评测）与 `release`（打 tag 时构建发布物）两个工作流；它们不部署。

**可观测边界（必须写进任何「CI 状态」表述）**：

- 本机没有 Actions runner 的观测通道；「CI 绿」只能由 Actions 页面或 `gh run` 取证，不能靠本地推断。
- 集成层（12 例）、Trivy 漏洞库、gitleaks 的**权威读数只在 CI**。
- 视觉套件与流程 e2e **不在默认 CI 门禁**；`frontend-e2e` 手动触发，且其注释声明「待种子账号就绪后再纳入 push/PR」。
- `docs/**` 的改动不会触发 CI；文档批次不能拿「CI 没红」当验证。

### 7.1 `trivy-scan` 为什么拆成三步（豁免文件的表达能力决定的）

| 步骤 | 挂哪个豁免 | 判据 |
| --- | --- | --- |
| ① vuln 诊断（table） | `.trivyignore` | `exit-code: 0`，只为把命中项打进日志——sarif 模式下日志不可见 |
| ② vuln 门禁（→ SARIF） | `.trivyignore` | HIGH/CRITICAL 阻断 |
| ③ misconfig 门禁（table） | **`.trivyignore.yaml`** | 同一套 severity，但豁免必须能限定路径 |

- **两套豁免文件不可混用**：plain `.trivyignore` 对 misconfig 只能按规则 ID **全局**放行，一条 `DS-0002` 会把仓库里所有镜像的同类缺陷一并盖掉；`.trivyignore.yaml` 的 `misconfigurations[].paths` 才能按路径精确生效。
- **实测三组对照**（2026-10-08，trivy 0.69.3）：`paths=['archive/**/Dockerfile']` → 命中 2 条（backend／frontend 仍点红，archive 被豁免）；`paths=['no_such_dir/**']`（阴性对照）→ 命中 3 条、一条都没盖；plain 文件写 `DS-0002` → 命中 0 条（全局放行，即被弃用的旧口径）。⇒ `paths` 真实生效，"挂了 ignore 文件"不等于"整体放行"。
- **当前唯一豁免**：`DS-0002`（镜像未指定非 root USER）**只允许指向 `archive/**`** 里的归档 Dockerfile；backend／frontend 两个在用镜像已于 2026-10-08 真正非 root 化（DR-34）。**复核触发条件**：归档件被复活（进 compose 或进 CI 构建）→ 立即删除该豁免并真修。往在用镜像上追加豁免即违反「能修绝不豁免」。
- **ID 形态陷阱**（实测无效，别再试）：misconfig 只认 Trivy 规则 ID（`DS-0002`），不认 AVD 编号（`AVD-DS-2022-0002` 零效果）；Dockerfile 内联 `#trivy:ignore:` 不生效；`--ignore-policy` 的 Rego 包名必须是 `package trivy`，`package trivy.misconfig` 被静默忽略。
- **版本必须显式钉**：三步都写 `version: "v0.69.3"`（= `trivy-action@v0.35.0` 的隐式默认）。不钉则 bump Action 会静默换扫描器版本，门禁判定漂移且**本机无法与 CI 对表**。
- **扫描前要预填 `~/.m2`**：trivy 自行向 Maven Central 取父 POM 被 429 时会 `FATAL` 直接点红，看起来像"依赖有漏洞"，其实是网络。
- **本机可观测性不对称**：misconfig 半边是纯文件系统判定，**本机可实跑**；vuln 半边依赖漏洞库（`mirror.gcr.io` 连接被拒、`public.ecr.aws` 在 Docker VM 内 DNS 失败），且编排搁置后容器扫描本机不跑 ⇒「vuln high → 0」必须标注为 **CI 口径**。

### 8.1 演示账号

- 共 **170 个**：V1 的 8 个基础账号 + V5／V6 的 162 个演示号段。统一由 `DemoAccountHardeningInitializer` 收敛，开关是 `app.demo-accounts.enabled`（环境变量 `DEMO_ACCOUNTS_ENABLED`，默认 `true`）。

- 演示种子（V5–V7）与结构迁移（V1–V4、V8–V11）分目录：`backend/src/main/resources/db/migration` 是结构，`db/seed-demo` 是演示数据；生产只跑结构目录。
- 生产库核对判据是**版本集合排除 5/6/7**、`users=8`、无 course 4007，而不是「最高版本=4」。

### 8.2 数据库隔离

| 场景 | 数据库 | 建法 |
| --- | --- | --- |
| 本机开发 | `ai_course_platform` | 手工／Flyway |
| 契约测试 | `ai_course_platform_test` | `createDatabaseIfNotExist=true`；`sql.init` 按清单重建 |
| Testcontainers IT | 容器内 `ai_course_platform` | `index.sql` + `application-test.yml` |
| Service 单测 | H2 内存 | `application-service-test.yml` |
| CI `backend` | service 容器 `ai_course_platform_test` + Testcontainers | 与 `docker-compose.yml` 的镜像 pin 一致 |

**禁止**在 `application-contract-test.yml` 里指向开发库；也禁止手工 `DROP DATABASE ai_course_platform` 来「清场」。测试库与开发库是两套。

### 8.3 种子数据格式约定（写新 fixture 时遵守）

- 日期时间用 `'YYYY-MM-DD HH:MM:SS'` 字符串（ISO 形态），不要依赖数据库本地化格式。
- 题型用大写枚举：`SINGLE_CHOICE`／`MULTIPLE_CHOICE`／`TRUE_FALSE`／`FILL_BLANK`／`ESSAY`。
- 多选／填空答案存 JSON 字符串（如 `'["计算机","Python程序设计"]'`），不要在 SQL 里拼逗号分隔的伪 JSON。
- 断言不要依赖自增 id 的具体值；用课程 code、用户名或查询结果定位。
- 新增结构迁移必须同时更新契约测试的 `schema-locations` 清单与清理脚本，由 `ContractTestSchemaBootstrapTest` 机械守住。

## 9. 证据纪律

| 规则 | 说明 |
| --- | --- |
| **结论必须可重生成** | 每个读数都要有对应命令；只有日志截图、没有命令的结论不算交付证据 |
| **数字带时点与口径** | 「3022 例」必须带「2026-10-27，`-DskipITs` 单元口径」 |

| **不改判据换绿** | 覆盖率阈值、视觉阈值、e2e 超时、登录限流都只能因测量结论调整；禁止用 `--update-snapshots` 吸收未知漂移 |

| **历史读数不冒充现状** | 归档文档里的读数只作史料；引用现状一律回本文 §2 |

## 12. 新增测试的落点与写法

### 12.1 后端

| 要测什么 | 放哪里 | 注意 |
| --- | --- | --- |
| Service 逻辑 | 与被测类同包的 `src/test/java/.../service/` | 用 `service-test`（H2）或 Mockito；不要连开发库 |
| Controller／Web 层 | `controller/` 下的 `*Test` | `@WebMvcTest` 或 `@SpringBootTest`；断言状态码 + 业务码 + 权限 |
| 外部引擎契约 | `integration/` 下的 `*ContractTest` | 用 JDK `HttpServer` 桩；路径与字段必须取自 `ContractPaths` |
| 真实容器集成 | 根包 `*IT`／`*IntegrationTest` | 继承 `AbstractIntegrationTest`；由 failsafe 执行；本机需 Docker |
| 架构约束 | `architecture/ArchitectureTest` | 新增分层规则要同时写正例与反例，避免规则从不触发 |
| 契约库结构 | `config/ContractTestSchemaBootstrapTest` | 新增结构迁移时同步清单与清理脚本 |

**后端新增用例的检查单**：

1. 用例名描述行为，不描述实现（`rejectsExpiredToken`，不是 `testToken2`）。
2. 断言失败信息能定位到「哪条业务规则」被破坏。
3. 涉及权限的用例，至少覆盖「有权限」「无权限」「未登录」三种。
4. 涉及降级的用例，断言**语义**（503 / 错误码），不要断言某句文案。
5. 新增测试后跑一次完整 `-DskipITs`，确认覆盖率不下降、SpotBugs 不新增。

### 12.2 前端单元／组件

- 文件与被测源同目录，命名 `*.test.ts`／`*.spec.ts`。
- 优先测纯逻辑（composables／stores／utils）；组件测试用 `@vue/test-utils`，不要为测一个分支启动整个路由。
- 不 mock 被测模块本身；只 mock 网络层与浏览器 API。
- 共享状态在每个用例前重置；vitest 串行跑不代表用例之间可以互相污染。

### 12.3 流程 e2e

- 新 spec 放 `frontend/e2e/`，命名 `<域>-<动作>.spec.ts`。
- 登录一律用 `loginAs`（真实登录）；需要绕过登录页时用 `setupMockLogin`，并在用例名或注释里说明为什么。
- 业务数据用 `page.route` 桩时，**每条被页面请求的接口都要显式桩**；漏桩会让请求打到真后端，红灯原因随环境变化。
- 断言等待用 `expect(locator).toBeVisible()`，禁止 `waitForTimeout`。
- 涉及权限的用例要覆盖「入口不可见」与「直达 URL 被拒」两条。

### 12.4 视觉锚点

新增一个锚点 = 五件事，缺一件就会产出假基线：

1. 在 `anchors.spec.ts` 的 `ANCHORS` 里声明 slug、路径、主题、掩码、`pinPaths`（若含「今天」日期）；
2. 在 `data-arrival.ts` 声明该页的数据到位断言（至少一条业务信号，不能只看标题）；
3. 若该页含随机源（力导向图等），声明 `pinRandom`；
4. 补反证用例：清空关键 API 后断言必须红；若确实无法反证，显式登记到 `NOT_FALSIFIABLE_BY_ARRIVAL_ASSERTION` 并写明理由；
5. 带 `-g "<slug>"` 生成基线，跑两轮确认确定性，再跑全表确认没有连带漂移。

**禁止**：直接用 `--update-snapshots` 全量重写、把阈值调宽、给不稳定的锚点加 `waitForTimeout`、把空态／错误态截图当基线。

### 12.5 Python 与启动器

- 引擎用例放各自服务目录；契约用例命名 `test_*_contract.py`，与 Java 侧 `ContractPaths` 对齐。
- 真实模型／真实训练用例必须带 `skipif`，并写清跳过条件与本地取证方式。
- 启动器用例放 `scripts/tests/`，从仓库根执行；新增环境变量导出规则时，同时补「名单包含所有引擎实际读取的键」这类集合护栏。
