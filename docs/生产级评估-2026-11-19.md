### 3.2 本轮修复

审计发现两处违反“实现包只做装配”的边界：

1. `security.AiQuotaInterceptor` 直接 import `service.impl.AiQuotaService`；
2. `service.component.ai.AiCoreComponent` 直接 import `service.impl.PromptGuard`。

处理：将 `AiQuotaService`、`PromptGuard` 迁移到 `com.aicourse.service.component.ai`，并删除 `PromptGuard` 中未使用的 logger；对应测试同步迁移。随后新增 2 条 ArchUnit 规则：

- `security` 不得依赖 `com.aicourse.service.impl`；
- `service.component` 不得依赖 `com.aicourse.service.impl`。

ArchUnit 规则由 **8 → 10**，全绿；`audit-stats.py` 复核：`service.impl` 76 → 74，`service.component` 41 → 43。

### 3.3 可扩展性判断

- 外部依赖以契约/Provider 隔离：`RagContract`、`KnowledgeGraphContract`、`LLMProvider`、`FileStorageService` 等；RAG 可切 Python / 纯 LLM，不靠改业务代码。

- **边界**：仍是单 Maven 模块，适合当前 620 个主类的规模；若后续拆多课程/多租户，需要另立模块化批次，不应在本期硬拆。

## 4. 错误处理

### 4.1 机器证据

| 项 | 读数 |
| --- | --- |
| 全局异常处理器 | `GlobalExceptionHandler` 19 个 `@ExceptionHandler` |
| 覆盖类型 | 业务异常、404、认证失败、403、参数校验、JSON 解析、方法级校验、类型不匹配、缺参、multipart、405、唯一约束、数据完整性、413、Sentinel 限流/熔断、未知异常 |
| LLM 不可用分类 | `LLMUnavailableException.Kind` 五类：未配置、凭据拒绝、额度/限流、上游不可达、空响应 |
| RAG HTTP 容错 | Sentinel 资源 `rag:http`；超时/连接失败/HTTP 503 不重试；其它异常有限重试后降级为 503 占位 |
| 本轮修复 | 题目推荐接口原先把 `LLMUnavailableException` 包成业务 400；已改为先透传，新增 503 断言 |

### 4.2 结论

- 对外错误语义统一：业务失败、鉴权失败、参数错误、上游不可用分别有明确状态码；AI 上游不可用不再被通用 `catch` 降级成 400。
- RAG 的超时/503 选择“不重试直接降级”，避免放大上游故障；与 `RagContract` 的 `503 / UNAVAILABLE` 语义一致。
- **边界**：`catch (Exception)` 仍有 182 处，分布于控制器、组件和服务；本轮抽检了 AI 主链路并修复一处 confirmed bug，未把“全部 catch 都恰当”作为已证明结论。
