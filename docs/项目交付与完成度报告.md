## 1. 项目概述

- **项目名称**：基于知识图谱 + LLM 的 AI 助教系统
- **项目来源**：江苏科技大学校级教育教学改革课题《生成式人工智能赋能网络类课程教学改革研究》
- **定位**：以《计算机网络》专业课程为试点，融合知识图谱与大语言模型（RAG），构建智能教学辅助系统，解决知识碎片化、个性化学习不足、大模型知识幻觉等痛点。
- **技术栈**：Spring Boot 3.4.4 + MyBatis-Plus + Spring Security（后端）；Vue 3 + Vite + Element Plus + ECharts + Pinia（前端）；MySQL 8.0；Redis 7（**必选**：缓存/限流/AI 配额/验证码依赖，启动时强校验连通性）；DeepSeek API（AI）。
> **⚠️ 职责边界声明（2026-08-11 起生效，2026-08-13 扩展至 RAG）**：知识图谱 / 知识库模块（图谱构建、多跳推理、GraphRAG）与 **RAG 检索引擎（BM25 / 向量检索 / embedding / 融合）均由团队另一成员负责**。本端（Java 后端）仅实现**消费侧**——`KnowledgeController` 的知识点/关系 CRUD、掌握度与关联查询、图谱可视化、`/extract` 摄取端点，并**预留标准化接口**（`KnowledgeGraphService` 方法签名、DTO 与调用约定；`RAGService` 接口 + HTTP 代理到 Python RAG 服务 8002，`rag.enabled=true` 启用、未接入时降级 `{"code":503}` 且 AI 问答自动回退纯 LLM），不实现图谱引擎与 RAG 引擎逻辑；图谱引擎相关端点（含批量导入 `/graph/{courseId}/import`）已于 2026-08-11 随引擎剥离一并移除，RAG 引擎实现类已于 2026-08-13 剥离。详见 `项目文档/知识图谱服务对接契约.md` 与 `docs/运维手册.md` §11。

- **源码体量（2026-08-02 权威口径）**：后端主代码 Java 源文件（**42 Controller** / **约 55 接口·59 实现类** / 48 Mapper / 48 Entity / 75 DTO）+ **79 个测试类 / 1370 个用例（2026-08-02 全量回归 0 失败 0 错误）**；前端 Vue3 源码 **75 个视图页面 + 41 个 API 模块**（含 request.js 请求封装），50 张数据表（index.sql）。
  - 较早期版本新增 AI 对话会话持久化相关 8 个文件：2 Entity（AiChatSession / AiChatMessage）+ 2 Mapper + 2 Service 接口/实现（AiChatSessionService / AiChatMessageService）。
  - 接口粒度说明：PRD 功能接口矩阵为 **93 个功能性接口**（公共 9 + 教师 28 + 学生 18 + 管理员 17 + AI 9 + 知识图谱 12）；代码层控制器端点**分布在 41 个控制器中**（经统一重构合并了知识图谱三控制器与课程教学控制器，端点总数以 springdoc 为准）。两者口径不同，功能基线 93 个均已达 100% 落地（详见 §3.1）。
  - 历史口径（40 控制器 / 73 视图 / 1334 测试等）已废弃，以本文档当前数值为准。

## 2. 技术架构

```
应用层：    智能问答 / 知识可视化 / 学情分析 / 系统管理
RAG 引擎层： 查询理解 / 分层检索 / 语义召回 / 生成融合
知识存储层： MySQL 关系库 + (Neo4j 图库预留) + (Milvus 向量库预留)
基础服务层： DeepSeek API / 嵌入模型 / 缓存 / 消息队列
```

## 4. 部署要点

> **完整部署步骤见 `docs/运维手册.md`**（环境要求 / Docker Compose / 本地开发 / 健康检查 / 备份恢复 / 故障处理 / 安全加固 / 性能调优）。本节仅列要点。

### 4.1 本地开发（Redis 必选）

```bash
# 后端（Windows 一键启动，已配置本地 DeepSeek Key）
start-backend.bat

# 或手动启动
cd backend && ./mvnw.cmd spring-boot:run

# 前端
cd frontend && npm install && npm run dev
```

- 前端：http://localhost:5173 ｜ API：http://localhost:8080/api ｜ Swagger：http://localhost:8080/api/swagger-ui.html
- **Redis（必选）**：缓存/限流/AI 配额/验证码均依赖 Redis。应用启动时 `RedisStartupValidator` 会强校验连通性（fail-fast，不启动 Redis 则启动失败），`REDIS_REQUIRED=false` 仅用于单元测试场景关闭该校验。
- 环境变量（根目录 `.env.example` 为模板）：`JWT_SECRET` / `DEEPSEEK_API_KEY` / `MAIL_USERNAME` / `MAIL_PASSWORD` / `REDIS_PASSWORD`（可选），安全开关 `COOKIE_SECURE` / `REQUIRE_HTTPS` / `CSRF_ENABLED`（默认 false，生产按需开启），Python 微服务地址 `KG_BASE_URL` / `RAG_BASE_URL` / `FT_BASE_URL`。

### 4.2 容器化部署（推荐）

```bash
# 启动所有服务（mysql + redis + backend + frontend；backend/frontend 归入 full profile）
docker compose --profile full up -d

# 仅启动基础设施（mysql + redis，供本地后端源码连接）
docker compose up -d mysql redis
```

> ⚠️ 早期交付文档中提到的 `docker build -t ai-course-platform .` + 单容器 `docker run -p 8080:8080 -p 5173:5173` 方式已废弃，请以 `docker-compose.yml` 为准。

### 11.2 发现问题及处置

**问题 1：README 演示账号与数据库不一致（中，影响演示体验）**

- 现象（2026-07-31）：README 第 169 行列出演示账号 `student` / `123456`，但数据库中实际不存在 `student` 用户，学生用户名为 `student1`~`student24`。
- **处置（已完成，2026-08-02）**：种子数据整体重建（seed 20260731，`seed-gen/gen_seed.py` + `part2.py` → `seed-sql/seed_00→01→02.sql` 按序执行），演示账号体系与 README 对齐——`admin / teacher / teacher2 / student / student2~5` 全部存在且密码统一为 `123456`，README 演示账号表已同步更新。

**问题 2：浏览器控制台"登出失败 500"警告（低，非关键）**

- 现象（2026-07-31）：前端 `request.js` 在 token 过期收到 401 时，先尝试 `/auth/refresh` 刷新，失败后调 `/auth/logout` 清 Cookie，logout 返回 500 时通过 `logger.warn` 记录警告。
- 分析：这是降级路径的容错处理，不影响主流程（最终仍会清除前端登录态并跳转登录页）。
- **处置（已复查，2026-08-02）**：`AuthController.logout` 与 `AuthServiceImpl.logout` 走正常会话失效流程（按 userId 失效全部活跃会话），无有效会话时幂等返回成功；前端 warn 为 token 过期场景的兜底日志，无需处理。若生产环境复现，可检查网关层 session 清理逻辑。
