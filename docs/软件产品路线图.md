## 总体愿景

将当前「大创赛项目」升级为 **开源通用 AI 教学辅助平台**，采用 **CE（社区版，开源免费）+ EE（企业版，托管付费）** 双轨模式。核心差异化：**知识图谱驱动 + LLM 深度集成**，面向高校/职业教育全学科场景。

## 一、技术架构演进

### 现状基线

```
单体 Spring Boot 3.4.4 + MySQL(单库) + Redis(单实例) + Vue 3 SPA
41 Controller / 63 Service 实现类 / 48 Mapper / 48 Entity / 74 DTO
75 前端页面 / 41 API 模块 / 50 数据表 / 无租户隔离 / 无 API 版本化
```

### 演进路线（4 阶段）

#### 阶段 1：模块化单体（M1-M3）

目标：**不拆微服务，但为未来拆分做准备**

```
backend/
├── modules/
│   ├── core/           # 认证、用户、权限（通用基座）
│   ├── course/         # 课程、章节、选课（学科无关）
│   ├── assessment/     # 题库、试卷、考试、作业、查重
│   ├── knowledge/      # 知识图谱、学习路径、RAG
│   ├── ai/             # LLMProvider、AI 对话、AI 建议
│   ├── analytics/      # 学情分析、数据看板
│   └── notification/   # 通知、WebSocket
├── platform/           # 多租户、插件、API 版本路由
└── Application.java
```

| 改造项 | 说明 |
|--------|------|
| **包结构重组** | 按 `modules/xxx` 分包，每个模块独立 Controller/Service/Mapper/Entity，消除跨模块直接依赖 |
| **API 版本化** | `/api/v1/...` → `/api/v2/...`，通过 `@RequestMapping` 前缀隔离，老版本标 `@Deprecated` |
| **配置外置** | 学科相关配置（题型枚举、评分规则）从硬编码改为 YAML + 数据库双源，支持按课程覆盖 |

#### 阶段 2：多租户架构（M4-M6）

目标：**SaaS 托管的基础——一套实例服务多学校**

| 决策项 | 推荐方案 | 理由 |
|--------|---------|------|
| **隔离策略** | 共享数据库 + `tenant_id` 字段 | 教育数据量中等，共享库成本最低；MyBatis-Plus 已有租户插件 `TenantLineInnerInterceptor` |
| **租户识别** | 子域名（`schoolA.eduplatform.com`）→ 路由解析 `tenant_id` | 用户感知清晰，SSL 证书可用通配符 |
| **数据隔离** | MyBatis-Plus 租户插件自动注入 `WHERE tenant_id = ?` | 零业务代码改动，SQL 层自动隔离 |
| **资源配额** | 每租户独立 AI 调用配额、存储配额、用户数上限 | 复用现有 `AiQuotaService`，扩展为按租户计量 |

```java
// TenantConfig.java - 多租户拦截器配置
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() {
    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
    TenantLineInnerInterceptor tenant = new TenantLineInnerInterceptor();
    tenant.setTenantLineHandler(new TenantLineHandler() {
        @Override
        public Expression getTenantId() {
            return new LongValue(TenantContext.get()); // 从子域名/Token解析
        }
        @Override
        public String getTenantIdColumn() { return "tenant_id"; }
    });
    interceptor.addInnerInterceptor(tenant);
    return interceptor;
}
```

> **当前状态**：多租户为规划能力，PRD §2.3 中 `tenant_id` 行级隔离尚未落地（PRD 13.4 已如实标注）。

#### 阶段 3：学科无关化抽象（M7-M9）

目标：**从「计算机网络课程专用」到「全学科通用」**

| 改造项 | 当前 | 目标 |
|--------|------|------|
| **题型枚举** | 硬编码 SINGLE_CHOICE/MULTIPLE_CHOICE/... | 数据库 `question_types` 表，按课程模板配置 |
| **评分规则** | 考试固定按分值判分 | 策略模式 `ScoringStrategy`，支持自定义评分脚本 |
| **知识图谱模板** | 计算机网络专用 | 学科模板包（数学/物理/外语...），每学科一套预设知识点结构 |
| **AI Prompt 模板** | 硬编码中文提示词 | `ai_prompts` 表，按学科/场景/语言配置，支持热更新 |

#### 阶段 4：可扩展插件体系（M10-M12）

目标：**社区贡献学科扩展，形成生态**

```
plugins/
├── math/              # 数学学科插件（公式渲染、符号题）
├── programming/       # 编程题插件（代码执行沙箱、OJ 集成）
├── language/          # 外语学习插件（语音评测、作文批改）
└── chemistry/         # 化学学科插件（分子式、方程式）
```

| 能力 | 实现 |
|------|------|
| **插件接口** | 定义 `EduPlugin` SPI：`registerQuestionTypes()` / `registerScoringStrategy()` / `registerKnowledgeTemplate()` |
| **热加载** | 插件独立 JAR，放入 `plugins/` 目录自动扫描注册（Spring `@ConditionalOnClass`） |
| **前端扩展点** | Vue 3 `defineComponent` + 动态组件 `<component :is="pluginComponent">`，插件提供远程组件 |

## 三、工程化与 DevOps

### 现状

```
有 Dockerfile + docker-compose.yml
有 79 测试类 / 1370 后端用例（2026-08-02 全量回归 0 失败 0 错误）+ 282 前端测试
前端 eslint 0 errors / vite build 通过
无 CI/CD / 无监控 / 无日志聚合 / 无自动化部署
```

### 建设路线

#### 阶段 1：CI/CD 基础（M1-M3）

```
开发者 Push ──→ GitHub Actions ──→ 构建+测试+Lint ──→ Docker 镜像 ──→ 部署 Staging
                                                                      ↓
                                                              手动审批 → Production
```

| 流水线 | 触发 | 步骤 |
|--------|------|------|
| **PR 检查** | Pull Request | 后端 `mvn test` + 前端 `vitest + eslint` + 构建验证 |
| **Staging 部署** | push to `develop` | 构建 Docker 镜像 → 推送 Registry → docker compose up |
| **Release 构建** | tag `v*.*.*` | 构建生产镜像 → 生成 Release Notes → 推送 |
| **Production 部署** | 手动审批 | 滚动更新 + 健康检查 + 失败回滚 |

```yaml
# .github/workflows/ci.yml 核心结构
jobs:
  backend-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { java-version: '21', distribution: 'temurin' }
      - run: cd backend && ./mvnw test -Dtest='!*IT,!Phase1Phase3IntegrationTest'
  frontend-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: '20' }
      - run: cd frontend && npm ci && npx vitest run && npx eslint . && npm run build
```

#### 阶段 2：质量门禁（M4-M6）

| 门禁项 | 工具 | 阈值 |
|--------|------|------|
| **后端覆盖率** | JaCoCo | LINE ≥ 70%（需引入并提升） |
| **前端覆盖率** | vitest c8 | ≥ 60% |
| **静态分析** | SpotBugs + ESLint | 0 errors |
| **安全扫描** | Trivy（镜像）+ npm audit | 0 Critical |
| **依赖检查** | Dependabot | 自动 PR |

#### 阶段 3：可观测性（M7-M9）

```
应用日志 ──→ Loki ──→ Grafana
应用指标 ──→ Prometheus ──→ Grafana
链路追踪 ──→ Tempo ──→ Grafana
告警通知 ──→ AlertManager ──→ 钉钉/邮件
```

| 维度 | 工具 | 关键指标 |
|------|------|---------|
| **日志** | Loki + Promtail | 错误率、慢查询、AI 调用延迟 |
| **指标** | Micrometer + Prometheus | QPS、响应时间 P99、JVM 内存、DB 连接池（Actuator prometheus 端点已就绪，独立 Basic 鉴权，非 ADMIN 角色） |
| **追踪** | OpenTelemetry + Tempo | 请求全链路（API→Service→DB→Redis→LLM） |
| **告警** | AlertManager | 5xx 错误率 > 1%、Redis 断连、磁盘 > 80% |

### 5.4 核心建议

1. **避免重复造轮子**：主题切换、缓存、权限、多轮对话、个性化推荐 5 项已完整实现，用户提案中对应的条目可直接划掉
2. **聚焦教育场景刚需**：笔记系统 + PDF 导出 + 智能润色 是与"AI 助教系统"定位最契合的三个扩展，且与现有架构（RBAC/课程体系/LLMProvider）零摩擦——**三者均已落地（2026-08-02）**
3. **增量优于重构**：响应式/加载态/数据可视化已有基础，针对性补齐即可，无需推倒重来
4. **i18n 和协作编辑不建议近期投入**：前者 ROI 低，后者架构成本高且非教育平台核心场景
