# 仓库协作规范

本规范适用于 `fusheng13145/ai-course-platform`。目标是：`main` 始终可发布、历史可追溯、分支可清理、变更可回滚。

## 1. 主干与角色

| 项 | 约定 |
|---|---|
| 唯一稳定主干 | `main` |
| 主干维护者 | `fusheng13145`（admin） |
| 默认评审人 | `zjyyy11`（write） |
| 合并方式 | **仅 squash merge**；禁止 merge commit 与 rebase merge |
| 合并后 | 自动删除 head 分支 |

`main` 禁止直接 push、禁止 force push、禁止删除。所有变更必须经 PR。

## 2. 分支模型

| 分支 | 用途 | 命名 | 生命周期 |
|---|---|---|---|
| `main` | 唯一稳定主干 | `main` | 永久 |
| 功能分支 | 新能力 | `feature/<短描述>` | 合入后删除 |
| 修复分支 | 缺陷/工作包修复 | `fix/<短描述>` | 合入后删除 |
| 文档分支 | 文档、台账、规范 | `docs/<短描述>` | 合入后删除 |
| 工程分支 | CI、依赖、构建 | `chore/<短描述>` | 合入后删除 |
| 发布分支 | 版本冻结与验收 | `release/<版本>` | 发布完成后删除或归档 |
| 实验分支 | 短期验证 | `experiment/<短描述>` | 到期删除，不合并 |
| 个人分支 | **不再使用** | — | 不保留 |

命名要求：小写英文、用 `-` 分隔、不超过 50 字符；禁止 `zjy111`、`leyon` 这类个人名分支；禁止无描述临时分支。

## 3. PR 规则

1. PR 的 base 必须是 `main`。
2. PR 标题使用 Conventional Commits 前缀：`feat:`、`fix:`、`docs:`、`chore:`、`refactor:`、`test:`、`ci:`。
3. PR 描述必须填写 `.github/pull_request_template.md`：变更摘要、改动内容、测试与验证、影响面与风险、合并门禁。
4. 每个 PR 至少 1 名非作者评审通过；默认评审人为 `@zjyyy11`。
5. CI 必须全绿；红 CI 不允许合并。
6. 合并前分支必须基于最新 `main`；禁止 force push。
7. 合并使用 squash；合并后删除 head 分支。
8. 禁止把凭据、`.env`、`frontend/**/.auth/*.json`、构建产物、探测图片提交到仓库。

## 4. 必过检查

以下 11 个作业为必过检查（与 `.github/workflows/ci.yml` 对应）：

- Backend (Maven + JUnit)
- Frontend Quality (lint + format + audit)
- Frontend Build (Vite)
- Secret Scan (gitleaks)
- Backend Security (OSV-Scanner)
- Trivy Security Scan (fs)
- Launcher Guard Tests (scripts/tests)
- Python KG Service Contract (8001)
- Python RAG Service Contract (8002)
- Python LoRA Fine-Tune Service Contract (8003)
- Deploy Readiness (static scripts)

`Docker Images Build` 仅在 main/workflow_dispatch 运行，`Frontend E2E` 目前仅 workflow_dispatch 触发，暂不设为 PR 必过；待其触发条件稳定后再纳入。

## 5. 分支生命周期

1. 从最新 `main` 拉出分支。
2. 小步提交，提交信息使用 Conventional Commits。
3. 推送分支并创建 PR，填写模板，请求 `@zjyyy11` 评审。
4. CI 全绿、评审通过后 squash 合入 `main`。
5. 合入后删除远端与本地分支；仓库已启用合并后自动删除 head 分支。
6. 发布分支在发布验收完成后删除；如需留存，使用 GitHub Release 记录版本与 commit，不保留长期分支。

## 6. 发布与 hotfix

- 发布：从 `main` 拉 `release/<版本>`，完成验收后合回 `main` 并打 GitHub Release；发布分支随后删除。
- hotfix：从 `main` 拉 `fix/<问题>`，修复后走同一 PR 门禁；紧急情况下也不允许绕过 CI 与评审，只能缩短评审时限。

## 7. 当前执行状态

自 2026-11-13 起，仓库已转为 public，`main-protection` ruleset 已启用并处于 `active`：

- Require PR；Require 1 approval；Dismiss stale approvals；Require code owner review；Require last push approval；Resolve conversations。
- Required status checks：§4 所列 11 项；Require branches up to date。
- Require linear history；Block force pushes；Block deletions。
- `bypass_actors` 为空：管理员默认不允许绕过；如确需紧急处理，必须在本文件追加记录并说明原因。
- 合并方式仅 squash；合并后自动删除 head 分支。
- Secret scanning 与 push protection 已启用。

此前 private + GitHub Free 时无法启用 branch protection/rulesets；该限制已通过转为 public 解除。

## 8. 清理规则

- 已合并 PR 的分支：合并后自动删除；存量残留一次性清理，不建 tag。
- 已确认无独有内容的个人/历史分支：删除前记录 SHA 与核验依据，不建 tag。
- 实验分支：到期删除；如需保留结论，写入 `docs/` 或 Issue，不保留分支。
- 任何删除远程分支的操作必须先核对 SHA，并在治理归档中留痕。
