## 1. 形态可行性评估（独立软件 / 网站 / 小程序）

| 形态 | 可行性 | 适用场景 | 复用度 / 改造量 | 结论 |
| --- | --- | --- | --- | --- |
| 多租户 Web SaaS（网站） | ★ 可行（最优） | 高校 / 培训机构多租户教学、社会培训、个人自学订阅 | 后端逻辑复用 80%+；需加租户隔离 / 计费 / 配额；flowcontrol 可扩为租户配额 | **主形态** |
| 微信小程序 | 可行 | C 端轻触达：查课表 / 成绩 / 刷题 / 通知；重考试防作弊不适合 | 后端 REST 复用；前端 uni-app / Taro 重写；加 code2session 桥接、临时文件上传、订阅消息；HttpOnly Cookie → 小程序登录态 + Bearer | **轻量入口** |
| 桌面软件（独立软件） | 可选（低优先） | 高校内网一体机（离线 / 内网管控） | Tauri 打包前端 Vue + 内网后端；考试 / AI 判分 / 防作弊强依赖服务端，离线价值低 | 非首选 |

**判定**：以「多租户 Web SaaS 为主形态 + 微信小程序为轻触达渠道」；桌面软件仅在特定内网场景作为可选交付。

### 优劣对比

- **Web SaaS**：开发成本最低（复用现有 Spring Boot + Vue）、分发最易（URL + 子域名）、易做多租户与计费；劣势是需自建运维 / 合规 / 客服体系。
- **微信小程序**：触达成本低（微信生态）、适合轻量学习；劣势是平台审核约束、不能承载重考试防作弊、需额外登录态改造（F-19）。
- **桌面软件**：满足内网 / 离线管控；劣势是离线价值低（核心 AI / 判分 / 防作弊依赖服务端）、分发与升级成本高。

## 4. 整体架构（多租户改造）

4.1 **数据层**：行级隔离 `tenant_id` + 租户上下文拦截器（MyBatis `TenantLineInnerInterceptor` 自动注入）；schema 隔离为备选（依合规 / 规模定）。
4.2 **认证层**：API 网关签发 **tenant-scoped JWT**（claim 含 tenantId）；小程序走微信 `code2session` 换自有 token，弃 HttpOnly Cookie 单租户假设。
4.3 **部署**：K8s + RDS(MySQL) + 对象存储（MinIO / OSS）；配额复用 Sentinel(flowcontrol)。
4.4 **复用**：Spring Boot + Vue 不变；Python KG / RAG 微服务保持契约对接（手册第八部分）。
   > 2026-10-06 更新：两引擎已**不再是占位骨架**——`kg_service`(:8001) 11 个端点 + Neo4j 图存储（`:Kp` 标签，未连通时回退内存图），`rag_service`(:8002) 9 个端点 + BM25/向量/RRF 检索；Java 侧以 `ContractPaths`（55 个契约常量）为唯一路径来源。产品化的租户维度接入只需在契约层加 `tenantId`，不必重写引擎。
   > 仍缺：三引擎（8001/8002/8003）的 Dockerfile 暂缓（DR-23 残项，LoRA 引擎侧已于 2026-10-18 交付＝DR-78），故**尚无容器化交付物**，K8s 部署需先补镜像。
   > **2026-10-08 运行验收**：本机以独立 Neo4j + `uvicorn` 两进程实跑，Java 侧 `path/plan`／`subgraph`／`ingest` 与 RAG `/retrieve`／`/ask` 均实测 `mode=ENGINE`（取证见手册 §18.5）。 导出到**引擎进程**（引擎不读 `.env`，DR-39），当前 `.env` 值是占位串、直连返 401（DR-38）；② RAG 语料现覆盖两门课——课程 1（2 篇）与示范课 4007（10 篇，2026-10-08 深夜按 §18.5 口径由 V6 种子派生），二者均实测 `mode=ENGINE`，商务口径上"AI 问答"可按**已建语料的课程**表述，但仍不宜说"任意课程开箱可答"：语料是版本控制副本里的文档，未重放的课程按契约返回不可用提示。语料正文的可重建性已由 `scripts/rag_corpus.json` + `scripts/seed-rag-corpus.py` 解决（DR-40），交付环境换机或清目录后不带参数跑一次即同时恢复两门课，不需手工重录。。⚠️ 2026-10-18 补：拿不到有效 Key 时的表现已改为**不再伪装成功**——Java 侧大模型调用失败一律 HTTP 503 + `code=503`，Python 侧 `/rag/ask` 以 `gen_mode` 区分 LLM / EXTRACTIVE / UNAVAILABLE（后者 `code=503`）；复跑量具 `scripts/probe-llm-chain.py engine|chains`（手册 DR-74-B / DR-75）
4.5 **小程序端**：uni-app 重写轻端；临时文件上传 + 订阅消息；重考试防作弊仍在 Web 端。

> ⚠️ 当前代码库为**单租户**（2026-10-06 复验：`grep -rli tenant backend/src/main/java` **仍零命中**，48 张表无 `tenant_id` 列），M1 多租户隔离为**从零引入**，工期与优先级最高（见第 6 节安全验收）。
