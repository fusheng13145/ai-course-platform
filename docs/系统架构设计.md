## 1. 架构总览

### 1.1 系统上下文

```text
                        ┌──────────────────────────────┐
                        │  浏览器（学生 / 教师 / 管理员） │
                        │  Vue 3 SPA（5173–5175）        │
                        └───────┬──────────────┬────────┘
                     HTTPS /api │              │ /api/ws（通知推送）
                                ▼              ▼
                  ┌──────────────────────────────────────┐
                  │ Spring Boot 3.5 单体（8080，/api）     │
                  │ 认证 / 课程 / 任务考试 / 成绩 / AI 编排 │
                  └──┬────────┬────────┬────────┬─────────┘
                     │        │        │        │
          JDBC/MySQL │        │ Redis  │ 文件系统 │ HTTP（契约调用）
                     ▼        ▼        ▼        ▼
              MySQL 8.4   Redis 7.4  uploads   ┌───────────────┐
              （51 表）   （缓存/限流） （分片）  │ KG  :8001      │──► Neo4j 5.26
                                                │ RAG :8002      │──► 本地语料
                                                │ FT  :8003      │──► PEFT 权重
                                                └───────────────┘
                     │
                     ├──► 大模型供应商（DeepSeek / OpenAI / Qwen；OpenAI 兼容协议）或本地 Ollama（原生 /api/chat）
                     ├──► SMTP（验证码 / 通知邮件）
                     └──► Prometheus / Grafana / Loki / Alertmanager（观测，编排形态）
```

### 1.2 架构风格

| 维度 | 选择 | 说明 |
| --- | --- | --- |
| 后端形态 | **模块化单体**（非微服务） | 48 个控制器共享一个 Spring 容器与一套事务/安全链；按包分层，不按服务拆分 |
| 前端形态 | **单页应用（SPA）** | Vue 3 + Vite；三端壳层（学生/教师/管理员）共用一套路由与请求管线 |
| AI 形态 | **Java 编排 + Python 边车** | 业务状态与鉴权留在 Java；图谱、检索、微调为独立进程，按 HTTP 契约调用 |
| 通信 | **同步 REST 为主** | REST 覆盖全部业务；SSE 仅用于 AI 问答流式输出；WebSocket 仅用于通知推送 |
| 数据 | **MySQL 为唯一事实源** | Redis 只做缓存、限流与 Sentinel 计数；Neo4j 只存图谱投影，可回落内存图 |
| 部署 | **原生进程优先，容器编排暂缓** | 本地以 `.bat` 启动器跑原生 MySQL/Redis/JDK/Vite；Compose 保留但自 2026-10-08 起搁置 |

### 1.3 进程、端口与职责

| 进程 | 默认端口 | 职责 | 启动方式 |
| --- | --- | --- | --- |
| 前端 Vite | 5173（视觉 5175） | SPA 开发服务器与代理 | `start.bat frontend` / `npm run dev` |
| 后端 Spring Boot | 8080（context-path `/api`） | 全部业务 API、WebSocket、Actuator | `start.bat backend` / `start.bat` |
| MySQL | 3306 | 权威业务库 | 本机服务 |
| Redis | 6379 | 缓存、限流、Sentinel 数据源 | 本机服务 |
| KG 服务 | 8001 | 知识图谱 CRUD、路径规划、子图、抽取 | `scripts/start-engines.py` |
| RAG 服务 | 8002 | 文档索引、检索、问答 | 同上 |
| 微调服务 | 8003 | 数据集、训练任务、权重导出 | 同上（重依赖可选） |
| Neo4j | 7474 / 7687 | 图存储（KG 引擎后端） | 本机服务或 Compose |
| Prometheus / Grafana / Loki / Alertmanager | 9090 / 3000 / 3100 / 9093 | 指标、面板、日志、告警 | 仅 Compose 形态 |

后端所有对外路径都带 `/api` 前缀（含 WebSocket 的 `/api/ws`）。CORS 白名单覆盖 5173–5175，仅本地开发回退；生产必须显式配置。

### 1.4 运行形态

| 形态 | 状态 | 适用 |
| --- | --- | --- |
| 原生本机（默认） | **在用** | 开发、验收、单机联调 |
| Docker Compose | **搁置**（2026-10-08 起，卷保留、容器/镜像为 0） | 生产必须容器化或等价编排；启用前按部署文档 §6 清理断链 |
| Kubernetes + RDS + 对象存储 | **Phase 2 目标形态**（未实施） | 多租户 SaaS 交付；Phase 1 单租户生产用 TLS/反代 + 容器或等价编排 |

### 3.2 后端包职责

| 包 | 职责 | 边界约束 |
| --- | --- | --- |
| `controller` | HTTP 入口、参数校验、权限注解、响应包装 | 不得直接依赖 `mapper`（ArchUnit 强制） |
| `service` / `service.impl` | 业务编排、事务、缓存、外部集成 | 不得依赖 `controller`（ArchUnit 强制） |
| `service.component.*` | 按子域拆分的可复用业务组件（认证、考试、学习、提交、AI 等） | 通过接口注入，不一定单例边界 |
| `mapper` | MyBatis-Plus 数据访问 | 不承载业务规则 |
| `entity` | 表映射对象 | 不依赖 service/controller/mapper（ArchUnit 强制） |
| `dto` / `vo` | 入参 / 出参契约 | 不直接暴露内部实体为主；新代码必须显式定型 |
| `config` | 横切配置（安全、缓存、CORS、限流、上传、TLS 等） | 不依赖 controller |
| `security` | JWT 过滤器、CSRF、对象级 ACL、AI 配额 | 与 `config.SecurityConfig` 协作 |
| `integration.kg` / `integration.rag` | Python 引擎的 HTTP 适配与本地降级实现 | 契约常量统一来自 `ContractPaths` |
| `llm` | 大模型供应商实现与路由 | 失败一律抛 `LLMUnavailableException` |
| `scheduler` | 定时任务 | 与业务服务解耦，异常隔离 |
| `websocket` | 通知推送端点与握手鉴权 | 只推通知，不承载业务写入 |
| `flowcontrol` | Sentinel 初始化与 Web 过滤 | 与 IP 限流分层 |
| `health` | 数据库/Redis/LLM/Python 健康指示器 | 供 Actuator 聚合 |
| `common` / `constant` / `util` / `exception` | 响应封装、常量、工具、全局异常 | `util` 不得依赖 service/controller/mapper（ArchUnit 强制） |

### 3.3 前端目录职责

| 目录 | 职责 | 约束 |
| --- | --- | --- |

## 4. 关键架构决策

| 编号 | 决策 | 理由 | 代价 / 约束 |
| --- | --- | --- | --- |
| ADR-01 | **JWT 存 HttpOnly Cookie，Authorization 头优先** | 避免前端可读令牌；同源 SPA 无需额外 OAuth 流程 | 必须配双提交 CSRF；跨端（小程序）需另立 Bearer 方案 |
| ADR-02 | **每次请求从 DB 读现行角色** | 降权/改角色即时生效，不等令牌过期 | 每请求一次用户查询（走缓存） |
| ADR-03 | **方法级 RBAC + 对象级 ACL 双层** | 角色注解挡住“哪类人”，ACL 挡住“哪条数据” | 新增资源必须同时声明两层 |
| ADR-04 | **自定义双提交 CSRF 过滤器** | 保留 Cookie 认证同时阻断跨站写请求 | 引导端点需豁免；前端 axios 自动回填 |
| ADR-05 | **Redis 缓存按域设 TTL，写路径即时逐出** | 读多写少；避免 30 分钟旧角色/旧权限 | 缓存键必须带业务域；跨租户时需加前缀 |
| ADR-06 | **演示种子与结构迁移物理隔离** | 生产库不得写入 170 个演示账号 | 开通生产必须空库；`ignore-migration-patterns` 会静默忽略缺失迁移 |
| ADR-07 | **`ContractPaths` 为 Java 侧唯一路径来源** | 55 个常量对齐 Python 契约，避免字符串漂移 | 新增端点须同步常量与两侧测试 |
| ADR-08 | **`mode` / `gen_mode` 显式区分引擎与生成语义** | 不允许把降级结果伪装成成功 | 失败统一 HTTP 503；前端按语义展示 |
| ADR-09 | **外部能力默认降级、失败关闭** | KG 可回内存图；RAG 可禁用；LLM 无 Key 不伪造 | 降级必须可观测；对外宣称不得高于证据 |
| ADR-10 | **开发环境原生进程优先；生产必须容器或等价编排** | 本机链路已稳定，原生进程适合开发验收；但缺少制品化、回滚与环境一致性，不满足生产发布要求 | Phase 1 上线前须补齐 Dockerfile／等价编排、镜像扫描与发布回滚，并重跑门禁 |
| ADR-11 | **浮层收敛到自研原语，不引入第三方组件库** | Element Plus 的 dialog/drawer/tabs 在 teleport、焦点与动效上不一致，全量样式又拖累包体 | 全仓 `el-*`／`element-plus` 0 命中，由 `noElementPlus.test.ts` 锁死；新增浮层必须复用 `Modal`／`useOverlayA11y` |
| ADR-12 | **视觉回归以钉桩基线 + 阈值 0 为门** | 像素级回归能抓住令牌与结构漂移 | 需维护夹具、遮罩与 10 张基线（5 锚点 × 明暗）；双轮运行 |
| ADR-13 | **多租户为 Phase 2 “预留未实施”** | Phase 1 单租户生产；Phase 2 租户隔离从零引入 | 48/51 表无 `tenant_id`；Phase 2 前不得宣称 SaaS 就绪 |
| ADR-14 | **不引入消息队列（Phase 1 暂定）** | 现有异步任务可用应用内线程池 + ShedLock + 定时补偿 | 通知重试与异步判分无可靠投递；Phase 1/2 若需须重新决策 |

> ADR 编号为本文件内部序号，不等同手册中的 DR 缺陷编号；二者交叉见手册 §7。

## 5. 后端架构

### 5.1 请求处理链

```text
HTTP 请求
  │
  ├─ RateLimitFilter（@Order(HIGHEST_PRECEDENCE)）
  │    登录 / AI / 验证码 / 注册四类路径按 IP 计数；Redis 优先，内存兜底
  │
  ├─ DoubleSubmitCsrfFilter（HIGHEST_PRECEDENCE + 10）
  │    写方法校验 X-XSRF-TOKEN 与 XSRF-TOKEN Cookie 一致；引导端点豁免
  │
  ├─ Spring Security 过滤链（无状态）
  │    CSP / frame-deny / HSTS / CORS / 路径级授权 / Actuator 保护
  │
  ├─ JwtRequestFilter（位于 UsernamePasswordAuthenticationFilter 之前）
  │    Bearer 优先、Cookie 回退 → 校验签名与过期 → 校验 user_sessions 活跃 → 载入 DB 现行角色
  │
  ├─ @PreAuthorize（方法级 RBAC）→ 对象级 ACL（资源/试卷/考试会话/提交）
  │
  ├─ Controller → Service → Mapper → MySQL
  │
  └─ GlobalExceptionHandler（19 个 @ExceptionHandler）→ ApiResponse
```

### 5.2 分层依赖规则（ArchUnit 7 条）

1. `controller` 不得依赖 `mapper`；
2. `service` 不得依赖 `controller`；
3. `entity` 不得依赖 service/controller/mapper；
4. `util` 不得依赖 service/controller/mapper；
5. `config` 不得依赖 `controller`；
6. `security` 不得依赖 `controller`；
7. `service.impl` 不得依赖其他 `service.impl`（通过接口/组件协作）。

### 5.3 响应与错误契约

成功响应统一为：

```json
{ "code": 200, "message": "success", "data": {}, "timestamp": "2026-10-27T12:00:00" }
```

- 分页使用 `PagedResponse<T>`（列表 + 总数 + 页码/页大小）。
- 错误由 `GlobalExceptionHandler` 统一映射；业务码定义在 `common.ApiCode`。
- **大模型失败**：一律 `HTTP 503` + `code=503`，`LLMUnavailableException` 携带五类原因：`NOT_CONFIGURED` / `CREDENTIAL_REJECTED` / `QUOTA_OR_THROTTLED` / `UPSTREAM_UNREACHABLE` / `EMPTY_RESPONSE`。4xx 不重试；空响应不返回伪成功。
- **Python 引擎不可用**：KG 回退本地图；RAG 返回不可用语义；微调直接 503。降级事实必须体现在 `mode` / `gen_mode`。

### 5.4 事务、并发与幂等

| 场景 | 机制 |
| --- | --- |
| 多表写入 | `@Transactional` 于 service 层；控制器不开事务 |
| 定时任务多实例 | ShedLock（考试超时 `PT28S/PT20S`；数据清理 `PT15M`） |
| 分片合并 | 分片落盘 → 按索引拼接 `.merging` → `Files.move(REPLACE_EXISTING)` 原子替换；字节数不符置 FAILED |
| 重复提交 | 前端按钮 loading/禁用 + 后端状态机校验；不依赖幂等键 |
| 考试自动收卷 | 30 秒轮询 + 时限判定 + 兜底时长；无期限依据时不收卷 |
| 缓存一致性 | 写后逐出（用户/权限为即时逐出） |

### 5.5 定时任务

| 任务 | 频率 | 内容 |
| --- | --- | --- |
| `ExamTimeoutScheduler` | 每 30 秒 | 超时考试自动交卷（ShedLock 互斥） |

### 5.6 实时通道

- 端点：`/api/ws`，握手阶段校验 JWT（`JwtHandshakeInterceptor`），按 `userId` 注册到 `WebSocketSessionManager`。
- 客户端可发 `ping`，服务端回 `pong`；业务消息只用于通知推送（`NotificationServiceImpl` 调用 `sendToUser`）。
- 子协议协商：`NegotiatedSubProtocol`；跨域来源复用 CORS 白名单。
- 不承载考试作答或业务写入：断线不影响业务正确性。

### 5.7 关键领域状态机

> 本节是「状态怎么流转」的唯一持有处。控制器与 Service 的校验以本节为准；新增状态或改变边必须先改本节再改代码（见 `docs/后端待办项.md` §8 纪律）。

#### 5.7.1 互动投票（`interaction` 域）

```
PENDING ──publish──▶ ONGOING ──close/到期──▶ CLOSED
```

| 规则 | 说明 |
| --- | --- |
| **创建是两步式** | `POST /interaction/vote` 创建后状态为 `PENDING`，**必须再调 `POST /interaction/vote/{id}/publish`** 才进入 `ONGOING`。后端**不提供**「创建即发布」的合并端点（2026-11-01 项目主裁定：维持两步式，前端 的 `publishVote` 保持不变） |
| 载荷形态 | `options` 为 **JSON 字符串**、`voteMode` 取 `SINGLE_CHOICE` / `MULTIPLE_CHOICE`；直接发数组会绑定失败 |
| 可投票窗口 | 仅 `ONGOING` 接受投票；`PENDING` 与 `CLOSED` 一律拒绝 |
| 关闭 | 到期自动关闭或发起人手动关闭；`CLOSED` 不可回到 `ONGOING` |

#### 5.7.2 作业提交（`submission` 域）

```
（无）──提交──▶ SUBMITTED ──批阅──▶ GRADED
                  │                   │
                  └─退回─▶ RETURNED ──┘（允许重交）
```

| 规则 | 说明 |
| --- | --- |
| 多次提交 | 同一学生同一任务允许多次提交，`attemptNumber` 递增；**读取一律「最新一次为准」**（`attempt_number DESC, created_at DESC` 取一条，不抛多行异常） |
| 退回的位置 | 只能在 `SUBMITTED` 上退回；`GRADED` **不可退回、不可重交** |
| 重交 | 仅 `RETURNED` / `SUBMITTED` 允许重交 |
| AI 预批的边界 | 异步 AI 预批**只写 AI 派生列**（`ai_feedback` / `submission_data`），不得整行 `updateById` 回写 `status`/`score`——否则会覆盖教师在该窗口内做的批阅 |
| 顺序耦合 | 「退回」必须排在「打分」之前；历史上 `GRADED` 的旧尝试不影响「最新一次为准」的口径 |

#### 5.7.3 试卷（`exam_paper` 域）

```
DRAFT ──submit──▶ PENDING_REVIEW ──approve──▶ PUBLISHED ──archive──▶ ARCHIVED
  ▲                    │                        │                     │
  │                 reject                      │                     │
  └──── REJECTED ◀─────┘                        └──── 有考试记录则 409 ─┘
```

| 规则 | 说明 |
| --- | --- |
| 删除守卫 | `DELETE /exam-papers/{id}` 在**存在 `exam_sessions` 记录**时返回 **409**（2026-11-01 项目主裁定）。原因：`fk_exam_questions_paper`、`fk_exam_sessions_paper` 均 `ON DELETE CASCADE`，`fk_proctor_sessions_exam` 又对 `exam_sessions` 级联——物理删会连坐销毁题目行、考试会话与监考事件 |
| 无记录时 | 允许物理删除（200） |
| 审核态 | 枚举为 `DRAFT` / `PENDING_REVIEW` / `REJECTED` / `PUBLISHED` / `ARCHIVED`。教师 `POST /exam-papers/{id}/publish` 语义为**提交审核**（`DRAFT/REJECTED → PENDING_REVIEW`，学生不可见）；管理员同端点仍为直接发布。`PATCH /exam-papers/{id}/approve` 仅管理员、仅待审核态，`PENDING_REVIEW → PUBLISHED` 并通知选课学生；`POST /exam-papers/{id}/reject` 仅管理员，`PENDING_REVIEW → REJECTED`，原因仅进通知与日志，**不落库** |

| `GET /teacher/dashboard/overview`、`GET /teacher/dashboard/ai-overview` | 主聚合不含 `aiOverview`；AI 总览独立返回 | 主聚合只做统计，**不同步调用 LLM**；AI 教学总览由独立端点返回 `{ summary, ... }`，前端在主统计首屏后异步补数，模型失败只给兜底文案、不影响首页 |
| `POST /exam-papers/{id}/publish`、`PATCH /exam-papers/{id}/approve`、`POST /exam-papers/{id}/reject` | 状态机见 §5.7.3 | 教师 `publish`＝提交审核（`PENDING_REVIEW`），学生不可见；管理员 `publish`＝直接发布。审核通过/驳回仅管理员且仅 `PENDING_REVIEW` 可操作；驳回原因只进通知与日志，不落库 |

### 8.2 语义字段

| 字段 | 取值 | 含义 |
| --- | --- | --- |

| 供应商 | 协议 | 鉴权 | 默认端点 / 模型 | 配置键（环境变量） |
| --- | --- | --- | --- | --- |
| DeepSeek（默认） | OpenAI 兼容 `/chat/completions` | API Key | `https://api.deepseek.com/v1` / `deepseek-chat` | `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` |
| OpenAI | OpenAI 兼容 | API Key | `https://api.openai.com/v1` / `gpt-4o-mini` | `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` |
| Qwen | OpenAI 兼容 | API Key | DashScope 兼容端点 / `qwen-plus` | `QWEN_API_KEY` / `QWEN_BASE_URL` / `QWEN_MODEL` |
| Ollama | 原生 `POST /api/chat` | **无**（本机服务） | `http://localhost:11434` / `deepseek-r1:8b` | `OLLAMA_BASE_URL` / `OLLAMA_MODEL` / `OLLAMA_THINK`（三态：留空=模型模板决定） |

- **选择方式**：`ai.provider`（环境变量 `AI_PROVIDER`，默认 `deepseek`）或管理端 `POST /api/admin/ai/provider` 热切换，取值均为 `deepseek` / `openai` / `qwen` / `ollama`（`local` 是 `ollama` 的别名）。未选中 Ollama 时对既有三供应商链路零影响。
- **可用性判据**：前三个以 `api-key` 非空为「已配置」；Ollama 无 Key，以 `base-url` 与 `model` 非空为「已配置」。未配置时业务层按 `NOT_CONFIGURED` 返回 503，不伪造内容。
- **Ollama 思考内容分离**：deepseek-r1 属思考型模型。`message.thinking` 与内联 `<think>…</think>` / `[THINK]…[/THINK]` 一律不进入正式输出，仅记录长度；`message.content` 为空（只思考或输出被截断）按 `EMPTY_RESPONSE` 返回 503，不回退把推理过程当答案。流式 NDJSON 同样逐行过滤，跨 chunk 的思考标签由状态机处理。
- **失败语义**：服务未启动 → 提示 `ollama serve`；HTTP 404 → 提示 `ollama pull <model>`；读超时 → 提示调大 `AI_READ_TIMEOUT`。三类均以 `UPSTREAM_UNREACHABLE` 映射为 503，不静默降级为伪成功。
- **实测（2026-11-05）**：本机 Ollama `deepseek-r1:8b` 真实调用返回 `content="4"`、`thinking` 712 字符、`done_reason=stop`，正式答案与思考内容确已分离；`OllamaProviderLiveTest` 默认跳过，置 `OLLAMA_LIVE_TEST=true` 才执行。
- **Python RAG 同源开关**：`AI_PROVIDER`／`OLLAMA_BASE_URL`／`OLLAMA_MODEL`／`OLLAMA_THINK` 与 Java 侧同名同义；RAG 问答实测 `1+1` 返回 `"2"`（约 11.8s），`llm_health()` 探测 `available=True`。
- **微调服务生成路径（8003，2026-11-05）**：`FT_LLM_PROVIDER` 独立于 Java 的 `AI_PROVIDER`，取值 `engine`（默认，Qwen2.5-0.5B + LoRA）／`ollama`（转发本机 Ollama）。`/health` 返回 `provider`／`provider_valid`／`ollama`；`/infer` 返回 `mode=ENGINE|OLLAMA` 与 `elapsed_ms`；非法值 503 不回落。实测 engine 49.31s、ollama 11.27s。**注意**：adapter 与 0.5B 基座维度绑定，切 provider **不等于**在 8B 上完成 LoRA——后者须重新训练。
- **KG 边界**：KG 为图存储／路径规划，无 LLM 调用路径，不强行接入。

## 9. 安全架构

### 9.1 五层防御

```text
① 网络/传输     HTTPS、HSTS、CSP、frame-deny、CORS 白名单
② 接入         IP 限流（登录/AI/验证码/注册）、双提交 CSRF、请求体校验
③ 认证         JWT 签名/过期、会话活跃校验、DB 现行角色、登录失败节流与锁定
④ 授权         方法级 @PreAuthorize + 对象级 ACL（课程/试卷/考试会话/提交）
⑤ 数据与审计   密钥文件式注入、演示账号加固、操作/登录/AI 调用日志、上传路径规范化
```

### 9.2 认证与会话

- 令牌：JWT（HS256），有效期 7 天；会话记录 24 小时过期；`user_sessions` 每次请求校验活跃。
- 登录失败：5 次失败锁 15 分钟（IP + 账号维度），与 IP 限流（10 次/60 秒）叠加。
- 令牌提取：`Authorization: Bearer` 优先，缺失回退 `ai_course_token` Cookie；Cookie 为 HttpOnly。
- 登出：撤销会话 + 清 Cookie；改密/降权即时生效（DB 现行角色）。

### 9.3 授权

| 层 | 机制 | 示例 |
| --- | --- | --- |
| 方法级 RBAC | `@PreAuthorize("hasRole('TEACHER')")` 等 | 管理端、教师端接口 |
| 对象级 ACL | `CourseAccessControl` / `ExamPaperAccessControl` / `ExamSessionAccessControl` / `SubmissionAccessControl` | 非本人课程/试卷/提交一律拒绝。`CourseAccessControl` 判的是「课程内容的归属与选课关系」：管理员放行、教师须为该课授课教师、学生读任务须已审批选课且任务已发布；已在任务／题目／知识点三域写面与任务读面接入，并提供 `readableCourseIds` 供列表按角色收窄。**读面边界**：章节读接口仍「登录即可读」，题目／知识点读面仍按原角色门，全量矩阵属 `后端待办项` B-05，不在 ACL 层声称已覆盖 |
| 路径级兜底 | `SecurityConfig` 的请求匹配 | `/uploads/**` 需认证；Actuator 按环境收紧 |

#### 9.3.1 管理员作用域矩阵（V12 / WP1–WP2）

> **口径（§9 决策 1A）**：保留单一 `ADMIN` 角色，不新建登录角色；作用域存 `users.admin_scope`（`SCHOOL`/`COLLEGE`）与 `users.college_id`，权限行按 `role_permissions.scope`（`ALL`/`SCHOOL`/`COLLEGE`）区分。

| 身份 | `users.admin_scope` | 请求期 authority | 有效权限行 | 数据可见范围 | 接入状态（WP1/WP2） |
| --- | --- | --- | --- | --- | --- |
| 校级管理员 | `SCHOOL` | `ROLE_ADMIN` + `SCOPE_ADMIN_SCHOOL` | `scope=ALL` ∪ `scope=SCHOOL` | 全校 | ✅ 组织树（`/admin/org/tree`）；✅ WP2 校级专有写端点（学期/权限/系统设置/导入）与用户/课程管理全校放行；✅ 统计/日志/会话读端点保持全校口径；✅ 备份/恢复、健康、日志文件、系统总览、AI 监控为校级专有 |
| 院系管理员 | `COLLEGE` | `ROLE_ADMIN` + `SCOPE_ADMIN_COLLEGE` | `scope=ALL` ∪ `scope=COLLEGE` | 本院（`college_id` 必填） | ✅ 组织树按 `college_id` 过滤；✅ 用户（`/users`、`/admin/users`）与课程（列表/详情/读写/审批/删除/切换/重提）跨院 403、同院放行；✅ 学期/权限/系统设置写端点 403；✅ **已定（2026-11-06）：院系仅本院**——操作日志/登录日志/用户会话/统计/看板/AI 用量按本院收窄，健康、日志文件、系统总览、AI 监控、备份与恢复等平台级端点 403 |
| 旧 ADMIN（V12 回填前/为 `NULL`） | 空（视为 `SCHOOL`） | `ROLE_ADMIN` + `SCOPE_ADMIN_SCHOOL` | `scope=ALL` ∪ `scope=SCHOOL` | 全校 | 兼容旧账号，行为与回填后一致；WP2 中与校级管理员等价 |
| 教师 / 学生 | 非 ADMIN 忽略该列 | 仅 `ROLE_*` | 仅 `scope=ALL` | 角色原范围 | 与改造前等价 |

- **存量 token 兼容**：scope authority **不写入 JWT 载荷**，由 `JwtRequestFilter` 每请求按 DB 现行用户派生；因此加 claim 不会使已登录会话失效，**无需重签**，改作用域即时生效（与 ADR-02 一致）。
- **判定组件**：`AdminScopeGuard`（`isSchoolAdmin`/`isCollegeAdmin`/`assertSchoolOnly`/`assertCollegeAccess`/`assertUserAccess`/`assertUserManageable`/`assertCourseAccess`/`currentCollegeFilter`/`currentAdminScope`），WP2 起由控制器显式调用；`JwtRequestFilter` 未改动。
- **统计/日志/监控口径（已定 2026-11-06：院系仅本院）**：`OperationLogController`、`LoginLogController`、`UserSessionController`、`SystemAdminController` 的统计类端点与 `AnalyticsController` 平台级端点，院系管理员按 `users.college_id`（用户域）/`courses.college_id`（课程域）收窄；管理员看不到的学院数据不返回。无法按学院归集的部分（健康检查、日志文件、系统总览、AI 监控属平台级，操作日志无学院归属）对院系管理员显式 403，**不静默返回全校数据**。AI 用量仅统计绑定本院课程的调用，未绑定课程的调用不计入并在响应 `scopeNote` 说明。
- **校级专有**：`/admin/backup`、`/admin/system/backup/{fileName}/restore`、`/admin/health`、`/admin/logs`、`/admin/system/logs*`、`/admin/system/overview`、`/admin/ai-monitor` 由 `assertSchoolOnly()` 拒绝院系管理员；备份与恢复口径不变。
- **未接入（留后续包）**：组织四表 CRUD（WP4/WP5）；AI 治理类写端点仍角色级。课程学院归属已由 V13 的 `courses.college_id`（按负责人回填）承担，读路径在未回填时回退授课教师学院。

### 9.4 CSRF / CORS / 响应头

- CSRF：写方法强制 `X-XSRF-TOKEN` 与 Cookie 一致；登录/注册/刷新/登出/验证码豁免；GET/HEAD/OPTIONS/TRACE 不校验。
- CORS：白名单来自 `cors.allowed-origins`；本地默认 5173–5175；生产必须显式配置，未配置时不得回退 localhost。
- 响应头：CSP、`X-Frame-Options: DENY`、HSTS（生产）、Referrer-Policy；Cookie `Secure`/`SameSite` 随环境配置。

### 9.5 限流与配额

| 维度 | 阈值 | 作用 |
| --- | --- | --- |
| 登录 IP | 10 次/60 秒 | 暴力破解 |
| AI IP | 20 次/60 秒 | 成本代理防护 |
| 验证码 IP | 5 次/60 秒 | 邮件轰炸 |
| 注册 IP | 20 次/3600 秒 | 批量自建账号 |

| 用户 AI 日配额 | 100 次 / 200k tokens | `AI_QUOTA_*`；Sentinel 兜底 |

IP 取值统一走 `TrustedClientIpResolver`，由 `app.security.trust-proxy-header` 单点控制，避免代理头伪造。

## 10. 前端架构

### 10.1 壳层与路由

- 壳层只有一套：`src/ui/Shell.vue`（侧栏 `Sidebar`、顶栏 `Topbar`、通知抽屉 `NotifDrawer`、命令面板 `Palette`）；旧端三端 `*Layout` 与 `AppShell` 已随删除批（`15fb858`）不存在。
- 路由守卫：`src/router/guard.ts` 的 `installRouterGuard` 由 `ui/router.ts` 装配——未登录 → `/login`；角色不符 → 对应端首页；后端不可达 → `/503`；未知路径 → `/404`。
- 导航与页面登记集中在 `ui/nav.ts`，"某页提不提供"集中在 `ui/notProvided.ts`（`provided`／`hidden`／`unavailable`）；`layouts/menus.ts`／`layouts/icons.ts` 已随旧端不存在，页面不得自行造导航。

### 10.2 状态管理

- 全局仅 `stores/auth.ts`：用户、角色、权限按钮、登录/登出。
- 页面状态与业务逻辑放 `composables/`；跨页共享通过参数或 store，禁止模块级可变单例。

### 10.3 请求管线

```text
组件 / composable
  → api/<域>.ts（43 个模块）
  → api/request.ts（axios 实例）
      ├─ baseURL `/api`、withCredentials
      ├─ 自动回填 X-XSRF-TOKEN
      ├─ 401 → 清理登录态并跳转
      ├─ 403/404/429/500/503 → 统一中文提示
      └─ 信封解包（data / PagedResponse）
  → 视图状态（三态：加载 / 空 / 错误）
```

- 错误文案归一在 `utils/requestError.ts`；页面只负责展示与重试。
- 列表页统一使用 `useListFeedback` / `useClientPagination`；提交态由所在页面自持（`:disabled` + `finally` 复位），旧端的 `useFormSubmit` 已随旧端下线。
- 浮层焦点与播报统一走 `ui/composables/useOverlayA11y.ts`（`trapFocus` / `lockViewportScroll` 引用计数 / `announce`）；`Ctrl/⌘+K` 由 `Palette` 自身接线，Esc 由 `Modal` 处理。旧端的 `useDialogFocus`／`useA11y`／`useAnnouncer`／`useKeyboardShortcuts` 不在树内。

### 10.4 组件分层与原语

| 层 | 内容 | 规则 |

## 11. 部署拓扑与可观测性

### 11.1 本地原生拓扑

```text
start.bat
  └─ scripts/start-all.py
       ├─ 环境探测（MySQL/Redis/JDK/Maven/Node/Python）
       ├─ 后端：mvn spring-boot:run 或 java -jar（8080）
       ├─ 前端：npm run dev（5173）
       └─ 引擎（可选）：uvicorn 8001/8002/8003，导出 ENGINE_EXPORTS 旋钮
```

- 配置：`SPRING_PROFILES_ACTIVE=local`（默认），密钥走 `.env`。
- 后端不可达时前端落 `/503` 页，探针静默。
- 会话重启会带走后端与引擎进程；`start.bat backend` 长驻，且对已在监听的端口只接管不重启。

### 11.2 Compose 拓扑（搁置）

- 12 个服务：`mysql`、`redis`、`backend`、`frontend`、`mysql-backup`、`prometheus`、`node-exporter`、`alertmanager`、`grafana`、`loki`、`promtail`、`neo4j`。
- 16 个卷保留，容器与镜像为 0（2026-10-08 起）。
- 已知未闭合：`COOKIE_SECURE` / `REQUIRE_HTTPS` 默认值与本地 HTTP 姿态不一致；GHCR 镜像与本地构建的关系；RATELIMIT 相关环境变量注入；WebSocket origin 回退。启用前必须逐项核对。

### 11.3 目标生产拓扑（未实施）

```text
客户端 → Nginx/TLS 终止 → Spring Boot（多实例）→ RDS MySQL
                              ├→ Redis（共享缓存/限流）
```

### 12.1 高并发与容量设计（Phase 1）

- **无状态 API + 外部会话/缓存**：应用实例可水平扩展；会话、限流、缓存依赖 Redis，不在进程内保存唯一状态。
- **数据库**：连接池按目标并发配置；高频查询建索引；先量后治慢 SQL/N+1；是否读写分离由目标环境压测决定。
- **AI 链路**：LLM/RAG/KG 调用与教学主链解耦，长调用异步/排队，失败可降级；避免首页/列表被同步 AI 阻塞。
- **考试峰值**：交卷、自动保存、监考事件按突发流量设计；幂等、限流、重试与队列/补偿策略必须可观测。
- **容量证据**：≥10,000 注册用户、并发/峰值/长稳必须在目标环境压测；本机历史读数只作开发基线，不作生产承诺。
