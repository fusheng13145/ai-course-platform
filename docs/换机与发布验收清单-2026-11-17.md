# 换机 / 发布前自动验收清单（B-10）

- **日期**：2026-11-17
- **脚本**：`scripts/acceptance_check.py`
- **本机实跑**（2026-11-17，Windows 笔记本）：

| 检查项 | 端口 | HTTP | 结果 |
| --- | --- | --- | --- |
| 后端 API `/api/auth/me` | 8080 | 200 | PASS |
| 前端 Vite `http://localhost:5173/` | 5173 | 200 | PASS |
| 知识图谱 `/api/v1/graph/health` | 8001 | 200 | PASS |
| RAG `/api/v1/rag/health` | 8002 | 200 | PASS |
| 微调 `/api/v1/fine-tune/health` | 8003 | 未起 | SKIP（可选） |
| `.env` 存在 / `JWT_SECRET` 非空 | - | - | PASS（只检查存在性，不回显值） |

**判据**：

- 端口可 TCP 连接；
- 后端 `GET /api/auth/me` 返回 401 或 200 都算「服务已起」（401 是未登录，不是故障）；
- 前端 `GET /` 返回 200 且包含 `<div id="app">`；
- KG/RAG/微调各自 `/health` 返回 200；
- 微调默认不列为必须项（`start.bat` 不编排 8003）；要用微调时显式 `--require ...,fine_tune`。

## 用法

```powershell
cd <repo>
python scripts/acceptance_check.py
python scripts/acceptance_check.py --require backend,frontend,kg,rag
python scripts/acceptance_check.py --format json
```

退出码：`0` = 所有必须项通过；`1` = 有必须项失败。可直接接 CI 的 `post-deploy` 作业。

## 换机启动的最小步骤

1. 装 JDK 21、Node 20+、Python 3.11+、MySQL 8、Redis、Neo4j；确认 3306/6379/7687 可连。
2. 复制 `.env.example` 为 `.env`，填 MySQL 口令与 `JWT_SECRET`（不要提交 `.env`）。
3. `start.bat backend` → `start.bat frontend`，或 `start.bat` 单窗口全栈。
4. `python scripts/acceptance_check.py`，必须全 PASS 再进入演示。
5. 换机后首跑必须 `mvn -B -o clean verify -DskipITs`（本机不跑 IT，IT 读数在 CI）。

> **不可主张**：本清单只验证「进程在 + 健康端点通 + 前端可挂载」，不等于「全功能验收通过」；浏览器侧仍要跑 `scripts/e2e/` 四件套。换机首次启动的数据库迁移、Redis 空库、Neo4j 空图，都会让「健康但功能空」，必须另跑业务 smoke。
